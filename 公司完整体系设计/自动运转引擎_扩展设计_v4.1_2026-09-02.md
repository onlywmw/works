## 一、自动运转引擎（§5.7 移入 · 完整）

### 1.1 流水线（100 单自转）

```text
设计师（人：立单/裁决/仲裁）→ 100 单在库（DRAFT）
  ↓
【调度器】设计师机常驻·30s 一圈：
  a. 读 status/*.md + 工单库 → 可派单（DRAFT 且前置已结）
  b. 排序：优先级(P0>P1) → 依赖 → 负载（目标角色队列最短）
  c. 写派单文件 → inbox\<角色>\ + 提交状态（ASSIGNED）
  ↓
【worker×4】角色机守护：
  d. inbox 有新单 → 拉起 Reasonix（角色配置：prompt+知识库+只写目录）
  e. 代理执行（独立 worktree/会话）→ 产出 DELIVERY/ACCEPTANCE_LOG
  f. 提交状态（DELIVERED——不含 seq，见 §三）→ 清 inbox → 下一单
  ↓
【guard】设计师机 sidecar：
  g. 校验（格式/迁移白名单/幂等/hash）→ 合法自动放行 / 非法 FLAG 停车
  h. **seq 由状态提交器（guard 独占）分配**（见 §三）
  ↓
【回流】验收 → 审验 → 设计师（合 main）→ 下一批
```

### 1.2 自动执行边界（红线）

- 默认自动、异常停车（FLAG/分叉/仲裁单 → 停车等人）
- 机器出 flag 不出决策（裁决留人）
- worker 物理隔离（角色配置+只写目录）
- **熔断器（§四）**：连续异常 → ENGINE_STOPPED

## 二、自动化等级（L2/L3 权限域分界 · 大神修订）

```text
L0（阶段1）：手动 + guard 人工跑
L1（阶段2）：guard 自动校验
L2（阶段3）：调度器自动派单 + worker 自动执行 ←【允许自动执行】
L3（阶段4+）：自动合 main ←【默认 OFF！独立权限域，额外条件才开】
```

**L3 合批门（保守）**：
```text
P0/P1/涉及安全·架构·数据 的单 → ❸ 禁自动合并（永远人合）
普通低风险单 → guard 全绿 + reviewer 全绿 + auditor 全绿 → 才允许 ff-only
```
> 理由（大神）：**L2 可以激进，L3 必须保守——越自动越容易把错误快速送进 main**。

## 三、seq 分配权（P0 小口子 · 大神①）

**seq 不是「写状态的人生成」，是「状态提交器（guard）生成」。**

```text
worker 提交状态 = 意图（event_id/ticket/phase/actor/occurred_at/hash——seq 留空）
    ↓（guard 独占）
状态提交器：读 ticket/<ticket_id>/sequence 当前值 → 分配 seq = cur+1 → 写回
    ↓
guard 落盘 event（含 seq）→ status/<角色>.md append + 幂等校验
```

- 解决：两 worker 同时产 seq=18（分配权集中在 guard——单机单线程，无锁）
- 轻量：ticket/<ticket_id>/sequence 文件（单调计数），guard 独占写——**不引入全局锁/数据库**

## 四、自动化熔断器 Circuit Breaker（P0 · 大神②）

**Guard 能防「不合法」，不能保证「合法但错误」——错误规则被机器规模化执行 100 次是最高风险。**

```yaml
# engine.yaml（设计师机 guard 配置）
max_consecutive_rejects: 3      # 连续 N 单同类 REJECTED
max_worker_failures: 3          # 同一 worker 连续异常
max_same_guard_flag: 3          # 同一 guard FLAG 重复出现
max_reentry_per_ticket: 5       # 单号重入上限（REJECTED→CODING 循环上限）
max_hash_baseline_anomaly: 3    # 同类 hash/基线异常重复
max_state_growth: 10            # 10s 内状态增长异常（突发写）
```

**触发语义**：任一超限 → `ENGINE_STOPPED` → 通知人（托盘/relay）→ **全部 worker 暂停** → 人排查后手动 resume。

**熔断器=「合法但错误」的规模化护栏**——100 单真闭环的最后一块。
