## 一、背景：为什么需要看板

**问题**：交付流水线（设计→施工→验收→审验→合 main）的每单状态**散落多处**（工单表/工单库卡/派单文件/git 分支/挂账表），**没有任何一处能「一眼看全」**。真实受害案例（2026-09-01/02）：

| 案例 | 现象 | 根因 |
|---|---|---|
| **UPG-49** | 交付后 **3 天未合 main** 无人发现（用户装 main 包体感=「没做」） | 交付/验收/合并三态无全局视图——没人知道「卡在哪」 |
| **UPG-68** | 工单库卡=「挂单」，但 **worktree 已开工**（认领人与卡状态互相不知） | 认领信息无单点登记→双方信息不对称 |
| **日常** | 「68 认领了吗」这类问题 **靠问 agent/翻文档**才回答 | 无只读的面板 |

**本质**：多 agent 协作（3-5 个并行 agent）靠**人肉记忆**协调，缺少**共同的、实时的全局状态面**——状态漂移=协作事故温床。

**用户判断**（2026-09-02 拍板）：这是**体验级**问题（「这个体验蛮重要」）——不是工具小事，值得独立评审。

## 二、目标（一句话 + 四条判据级目标）

> **一条命令，看到「谁在干、到哪了、该催谁」——三态（交付/验收/合 main）+ 超期醒标。**

| # | 目标 | 判定 |
|---|---|---|
| G1 | **三态一屏**：每单 交付→验收→合 main 三列状态一目了然 | 面板含三态列+每单每态标记 |
| G2 | **超期醒标**：交付>1d 未验收 / 验收通过>1d 未合 → ⚠️ | 面板自动计算+醒目标记 |
| G3 | **单一数据源**：读 E1 真源（工单库），不新增第二套状态 | 面板=生成物；源=工单库 |
| G4 | **零维护**：生成脚本自动产出，无人工录入 | `orders-overview.sh/mjs` 一条命令 |

## 三、设计

### 3.1 形态（首版=纯文本 Markdown——够用且可贴群/可入档）

```text
╔═ MOV 工单全局看板 · 2026-09-02 ═══════════════════════════════╗
║ 单                状态        线    关键点                   ║
║ UPG-50 阶段1     🔨 1C 施工   A   1A/1B✅已合(0bc37f7)       ║
║ UPG-50 阶段2     ⏳ 排队       —   等 1C 验收                ║
║ UPG-68           🔨 施工      B   判据 V68-7 剩余           ║
║ SYS-02 阶段一    ✅ 验收通过   C   ⚠️ 超期>1d 未合 main     ║
║ SYS-02 阶段二    ✅ 验过       C   ⚠️ 超期>1d 未合 main     ║
║ SYS-02 阶段三    📌 已派       C   待开工                   ║
╚══════════════════════════════════════════════════════════════╝
```

**列定义**：
1. **单**：卡标题（UPG-xx / SYS-xx）
2. **状态**：从 E1 真源状态行提取语义（✅已合 / 🔨施工 / 📌待认领 / ⏳排队 / ⚠️超期——超期=自动派生覆盖）
3. **线**：A/B/C（施工角色——从派单/认领信息提取；缺失=「—」诚实）
4. **关键点**：最近状态摘要（hash/判据剩余/依赖）；缺失=「—」

### 3.2 状态语义映射（关键契约）

| E1 状态行标记 | 看板显示 | 超期判定 |
|---|---|---|
| ✅ 已合 main / 已完成 | ✅ 终态 | 不适用 |
| ✅ 验收通过 | 🟡 待合 main | **>1d 未合 → ⚠️** |
| 🔨 施工中 | 🔨 | 施工>3d 未交付 → ⚠️ 提示（阈值可配） |
| 📌 已派/待认领 | 📌 | 派发>2d 未认领 → ⚠️ |
| ⏳ 排队/挂单 | ⏳ | 无超期（主动等待——不算卡） |
| 未知标记 | ⚠️ 状态无法解析（不猜） | 手动复核提示 |

### 3.3 产出与入口

- **产物**：`工单系统\处理中心\验证产物\orders-overview.md`（每次生成覆盖）
- **入口**：`工单系统\审验员\orders-overview.mjs`（一条命令；--out 可指定）
- **可扩展**（后置、不承诺）：HTML 面板 / 周报打包——v1 不做（防过度设计）
