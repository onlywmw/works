## 〇、一句话

**每台电脑 = 一个角色（设计师/程序员/验收员/审验员）+ 本地知识库；靠「文件即消息、git 即总线、状态即追加流」在局域网（WiFi 主干 / 云备胎 / 蓝牙信令）协作——消灭我们反复踩的撞车/信息失真/hash 漂移。**

## 一、背景与痛点（为什么现在做）

现状：所有角色挤在一台电脑（我=设计师兼一切），靠人工+纪律协作——**已实证的病灶**：

| # | 痛点 | 实例 |
|---|---|---|
| P1 | 同机并行撞车 | xlsx 覆盖事故≥3 次；工单表 emoji 截断/行丢失/!ref 损坏 |
| P2 | 状态双写失真 | 表「待认领」/卡「✅交付」/报告 hash 漂移（9fd39b6 不存在）/功能 3 天未合 main（UPG-49 现场） |
| P3 | 指针/基线漂移 | 目录迁移引用断链；分支被换基线覆盖（feat/upg49-r2 事件） |
| P4 | 角色上下文污染 | 设计师脑内同时装全部角色知识——边界模糊 |
| P5 | 无全局视图 | 68 单状态靠查表，无「今天该推什么」一眼盘 |

**已做**：SYS-01（防伪审计线：验收总表/条款层级/盲区/审验区——审计链完整 ✅9.4）。
**本方案**：协作执行层 + 分布式（物理隔离从根上消灭 P1/P4；机制消灭 P2/P3/P5）。

        │ 机A 设计师      │ │ 机B 程序员 │ │ 机C 验收员       │
        │ 知识库:方案/契约 │ │ 知识库:交付 │ │ 知识库:验收判据    │

### 通信降级链（自动路由）

```text
常态        WiFi 局域网（SMB 共享/git）——毫秒级，同屋不断
 ↓ 降级     云服务器（mow.kim git bare + relay）——慢但通（备胎）
 ↓ 应急     蓝牙 PAN（2-7 台近场；1-3Mbps）——只传「信令+小纸条」（派单/状态行 <1MB）
```

**各层职责**：WiFi=代码/大文件主干；云=降级同步；蓝牙=门铃（状态变化蜂鸣+小件）——**谁也不当唯一命门**。

## 五、工单流转机制（核心 · 完整生命周期）

### 5.1 状态机

```text
DRAFT ──设计定稿+判据──▶ ASSIGNED ──认领──▶ CLAIMED ──施工──▶ CODING
CODING ──交付──▶ DELIVERED ──验收──▶ ACCEPTING ──通过──▶ REVIEWING（审验）
REVIEWING ──通过──▶ MERGED（合 main+登记）──▶ ARCHIVED（归档）
          │                     ▲
          └──打回 REJECTED──────┘（带编号清单；修复 R1/R2…重入）

**v3 重入语义（二轮评审钉死）**：REJECTED → **CODING → DELIVERED（新 hash）→ ACCEPTING 全流程重走**——不跳过任何环；ACCEPTANCE_LOG 按交付 hash 分段（旧 hash 结论标 `SUPERSEDED` 保留不删——审计链完整）；**判据版本化**：派单修订号递增（v1→v2…），验收对照最新版（防判据漂移=hash 漂移同构风险）。
```

### 5.2 各阶段（谁·写什么·如何验收）

| 阶段 | 角色 | 动作（文件=证据） |
|---|---|---|
| DRAFT | 设计师 | 方案定稿（挂**判据编号** V-*/U-*——验收对照的锚）；写 `designer\派单\UPG-NN_派单.md` |
| ASSIGNED | 设计师 | 工单库卡置「待认领」+ status/*.md 追加行 |
| CLAIMED | 程序员 | 追加 CLAIM 行（含**分支名** feat/upgNN + 本地 worktree） |
| CODING | 程序员 | 施工（分支隔离）；每步变异亲杀；**commit 前验证 git 头** |
| DELIVERED | 程序员 | `coder\交付报告\DELIVERY_UPGNN.md` = **单号/分支/hash/全量结果/证据声明**；hash 必附 `git rev-parse` 实读输出（防漂移） |
| ACCEPTING | 验收员 | `reviewer\ACCEPTANCE_LOG` 追加：判据逐条（截图/journal/变异计数/真机）+ **结论**；打回=带 P1/P2 编号清单 |
| REVIEWING | 审验员 | 独立复验：申报失实/越界/漏洞模式；问题=带编号 |
| MERGED | 设计师 | ff-only 合 main（rebase 先行）；**登记两表**（hash 以 git 为准）；status/*.md 终行 |
| ARCHIVED | 设计师 | 归档（交付报告/证据链入案；单销） |

### 5.3 关键锚定（防我们踩过的坑）

1. **hash 锚**：交付/验收/合入三处 hash 以 `git rev-parse` 实读为准；rebase 重写=hash 变更必须同步三处（UPG-49 教训）
2. **判据锚**：工单卡必须挂判据编号（验收按判据逐条，不凭感觉）
3. **证据锚**：每判据一条证据（截图=文件路径+时间；真机=设备序列+logcat 段；变异=命令+red）
4. **基线锚**：交付报「基点 hash」+ `merge-base` 输出（防基线红/旧基线）
5. **单写主**：xlsx 单一机写；status/*.md 追加不覆盖；**工单库.md 单写主=设计师**（卡置待认领是编辑操作——除设计师外只读，防第二双写点）
6. **判据版本锚**：验收对照**派单最新修订版**判据；修订号+1 时验收重对（与 hash 漂移同构风险）
6. **红线**（继承 SYS-01）：机器只出 flag、人最终裁决；不进 UPG 主线零 App 影响

### 5.4 流转示例（一张单的全过程文件痕迹）

```text
designer\派单\UPG-50_派单.md            ← DRAFT→ASSIGNED
coder\CLAIM_upg50.md                    ← CLAIMED（分支名）
coder\交付报告\DELIVERY_UPG50.md        ← DELIVERED（hash+全量+证据）
reviewer\ACCEPTANCE_LOG（追加段）        ← ACCEPTING（判据逐条+截图）
auditor\审验_UPG50.md                    ← REVIEWING
status/*.md 五行追加                       ← 全链状态（一眼盘）
```

### 5.5 状态事件契约（P0-3 · v4 新增）

**每个状态事件必须携带唯一 ID + 序号（追加流升级为可恢复状态机）：**

```yaml
event_id:   EVT-20260901-000123      # 唯一（机器生成）
ticket_id:  UPG-50
phase:      DELIVERED
actor:      coder
seq:        17                       # 单号内单调递增（同一 ticket_id 内）
occurred_at: 2026-09-01T18:30:21+08:00
delivery_hash: abc123...            # 关联交付 hash（DELIVERED 必填）
```

**guard 幂等规则**：
- event_id 已处理 → 幂等忽略（重复消息：SMB/轮询/云恢复可能重复送达）
- seq <= 已处理 seq → 拒绝
- seq > expected_seq → FLAG: OUT_OF_ORDER（人工核对）


### 5.6 状态迁移白名单（v4 正式 · 之外一律 FLAG: ILLEGAL_TRANSITION）

```text
DRAFT      → ASSIGNED
ASSIGNED   → CLAIMED
CLAIMED    → CODING
CODING     → DELIVERED
DELIVERED  → ACCEPTING
ACCEPTING  → REVIEWING
ACCEPTING  → REJECTED
REVIEWING  → MERGED
REVIEWING  → REJECTED
MERGED     → ARCHIVED
REJECTED   → CODING          （重入：全流程重走+新 hash）
（其余任何迁移 → FLAG: ILLEGAL_TRANSITION）
```

## 八、安全与防伪（衔接 SYS-01）

- 审计链完整保留（SYS-01 验收总表机制）——SYS-01 的「验收总表/条款层级/证据链」**继续作为审计证据格式**，本系统只换「传输介质」
- 密钥/口令**绝不入仓库/共享**（只传存在+位置——现有红线）
- 目录权限：角色机只写自己目录（SMB 权限/文件夹 ACL）；**验收/审验配只读 SSH key**——权限在 **SSH/Git 服务端**完成（hook 仅二道保险，防 hook 被改后理论只读失效）：

```text
reviewer/auditor（只读 key）：
    git fetch ✅   git clone ✅   git cat-file ✅   git rev-parse ✅
    git push ❌    git receive-pack ❌
```

「不信自报」=他们第一步自己 rev-parse，独立核对 hash（二轮评审第 2 点）
- 蓝牙仅近场小件（不开通用文件传输——防不良设备）
