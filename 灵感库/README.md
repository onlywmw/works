# 灵感库（取精华 · 去糟粕）

> **定位**：给项目**提供灵感和升级方案**的素材库 + 评估机制。
> **核心信条**：**取其精华，去其糟粕**——吸收思想/机制/可复用工程，不复制形态/商业模式/臃肿规模。
> **管理**：灵感库管理员按本文档规则管理。
> **数据总览**：`灵感库数据总览.md`（AI 快速定位：素材评估分级 / A 级可借鉴点 / 立项状态 / 位置速查）。

---

## 一、灵感库是什么

- **收纳**：作者感兴趣的开源项目 / 论文 / 脚本 / 工具，一个项目一个子文件夹 + 收纳说明
- **产出**：持续为各项目提供「升级方向」→ 拆成 UPG / TASKS 工单落地，不是只看不动的收藏夹

## 二、取精华 · 去糟粕（铁律）

1. **机制进、形态不进**——吸收机制/架构/算法/工程实践，不复制 UI、客户端形态、商业模式、平台绑定
2. **对照项目初衷校准**——每样吸收必须能说清「服务项目哪个核心特质」（对照本项目核心特质，如「更懂你 / 更持续 / 更能干」），**说不清不进**
3. **评估后再立项**——先**精读源码**（非 README 转述）出评估文档，分级：
   - **A 直接可借鉴**（项目真缺口、工程量可控）
   - **B 方向借鉴**（已有雏形、对齐补强）
   - **C 观察**（方向成立、等产品线空出）
   - **明确不借鉴**（写清原因）
4. **防重复施工**——立项前对账 TASKBOARD / 工单表（出工单前查派单权威）
5. **防臃肿护栏**——分批进不一次性堆；大工程只吸收机制不整体搬；license 合规（引用机制不抄代码，标来源）

## 三、标准流程

1. **收纳**：项目 → `工单流转中心/灵感库/<项目名>/收纳说明.md`（来源链接 / 一句话亮点 / 可能的融合或 MCP 化想法 / license 情况）
2. **评估**：出评估文档（各是什么 / 核心机制**代码实证** / 可借鉴分级 A-B-C / 明确不借鉴 / 落地节奏 / 产物索引）
3. **立项**：对账防重复 → 拆 UPG/TASKS 工单（含施工 + 测试方案 + 红线 + 交接信息）→ 落工单表 → 按项目协作纪律走
4. **融合 / MCP 化**：进项目本体（新工具 / 小脑 / 管线 / 算法）**或** 独立 MCP server 经注册中心接入

## 四、去向二选一

1. **融合进项目本体**——成为项目能力（如：新工具 / 管线 / 算法）
2. **做成 MCP 工具**——独立 MCP server，经注册中心接入（如 Yuanzi 生态）

> 动手融合/工具化前按项目协作纪律走（TASKBOARD 登记 + 派单）。

## 五、收纳约定

- 每个项目一个子文件夹，用项目原名命名
- 每个子文件夹配**收纳说明**（`收纳说明.md`，或并入评估文档）：**来源链接 / 一句话亮点 / 可能的融合或 MCP 化想法 / license 情况**
- 保留原项目的 README.md / LICENSE，不擅自改
