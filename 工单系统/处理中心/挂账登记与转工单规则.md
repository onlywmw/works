# 挂账登记与转工单规则（2026-08-17 定）

> **谁都能登记挂账 → 设计师验证 → 转工单。** 全角色共用，防缺陷口头化丢失。
> **挂账登记表 = 唯一登记落点**（本中心 `挂账登记表.md`）；`工单表.xlsx` 只放**已转正式工单**。

---

## 一、谁能登记

**任何人**——验收员 / 程序员 / 设计师 / 用户。在工作、验收、施工、真机测试中发现**缺陷 / 观察项 / 挂账**（P2 以上或需跟进），**当场登记**，不等口头汇报。

## 二、怎么登记（挂账登记表加一行）

在 `挂账登记表.md` 表格加一行：

| 列 | 填法 |
|---|---|
| 挂账号 | `挂账-<简短描述>`（如 `挂账-approval-always-gate`）|
| 标题 | 缺陷/挂账名（一句话）|
| 优先级 | P0-P3（拿不准往高定）|
| 现象→证据→建议 | `现象 → 证据（代码位置/截图/计数）→ 建议` |
| 登记人 / 日期 | 谁发现的 / 当天 |
| 设计师验证 | **`⏳挂账待审`** |
| 施工/转工单 | — |

> **登记挂账不备份任何表**——挂账表是追加式文本，不动权威表（告别每次登记产生 .bak）。
> 复杂缺陷可附工单文档到 `程序员\`。

## 三、设计师验证

设计师审核「⏳挂账待审」挂账（**查代码/证据/复现，不信自报信实物**）：
- **通过** → 挂账登记表「设计师验证」列改 `✅已落实` → **转正式工单**：在 `工单表.xlsx` 登记新工单（**此时改表前备份一次**，`工单表.bak_<日期>_<动作>前.xlsx`），进派单队列
- **疑义** → 打回登记人补证（写清缺什么）或标「不落实」销项

## 四、转工单后

进派单队列 → 程序员施工 → 验收员验收 → 设计师合 main（按既有流转）。

**沉淀进已知坑库（2026-09-01 定 · SYS-01 P1-2，半自动）**：挂账验证解决并**转工单完成后**，追加一步——
1. 设计师/程序员把该条挂账的「现象→根因→药方」提取进 `设计师\知识库\已知坑.md` 新增一行
2. 挂账登记表原条目「施工/转工单」列追加：`→ 已解决，转入已知坑库（坑名: <坑名>）`
3. `已知坑.md` 条目「关联工单」列填：`挂账-<id> → 转工单 <UPG-xx>` —— **双向可追溯**

> 挂账表流程（红线 10）不动，只在「转工单完成」节点加一步沉淀；已解决不重收进挂账待审池。

## 五、红线

1. 登记即挂账，**不删除他人登记**（疑义走打回/销项，不直接删）
2. 真机补验类挂账走工单库「真机补验挂账」区，**不转工单**（归真机检验员）
3. 不主动收集挂账——仅**工作中被动发现**的缺陷/挂账登记
4. **备份只发生在转工单写工单表时**（登记挂账不备份，避免 bak 堆积）
5. **主文件夹不乱建登记表**：工单流转中心根目录只放核心流转文件；登记表/临时表放各角色报告处，**不堆主文件夹**；确需主文件夹新增表 → 交设计师评估

## 六、规则落点

| 文档 | 内容 |
|---|---|
| 本规则 | 全角色登记→验证→转工单 |
| `挂账登记表.md` | **挂账唯一落点**（待审池） |
| `工单表.xlsx` | 转正式工单后（派单权威） |
| 验收员工作流 §四之 | 验收员侧执行 |
| 程序员 README | 程序员侧执行 |
| 设计师 README | 设计师验证职责 |
| 工单流转中心 README 红线 10 | 全角色红线 |

## 七、派单必含（2026-08-17 更新 · 每次派工单都要）

派单文本**交接段必须包含**（缺一不可）：

1. **完成后登记两个表**（README 红线 7）：
   - `工单流转中心\工单表.xlsx`——程序员列填 `✅<代号> 完成`，备注列填 `分支名 + hash + 交付报告文件名`
   - `工单流转中心\工单库.md`——状态快照同步（**先改工单表再改工单库**）
2. **交付报告/汇报时说明登记入表**：交付报告末尾明确写「已登记工单表.xlsx + 工单库.md（分支/hash/报告名）」
3. **交付报告落点**：`工单流转中心\程序员\交付报告\`

## 八、测试匹配原则（2026-08-17 定 · 派单测试强度 = 工单性质）

**派单测试要求必须与工单性质匹配，避免过度/不足拖累程序员效率**：

| 工单性质 | 测试要求 |
|---|---|
| **代码改动**（动项目源码）| 单测 + 变异亲杀 + 全量测试（命令见 `项目配置.md`）（必要）|
| **环境/集成验证**（装环境跑通）| **真机证据**（截图/journal），不要求 gradle 全量 |
| **纯配置/接线** | 验证生效 + 定向测试 |
| **评估/报告** | 报告 + 实证，无施工测试 |

**判断**：动项目代码 → 才要单测/变异/全量；不动代码（装环境/验证外部）→ 真机证据，不堆 gradle。
**验收员核查**：验收时核对测试强度与工单性质匹配——**不验收「过度测试」（浪费）也不放行「测试不足」（该测未测）**。
