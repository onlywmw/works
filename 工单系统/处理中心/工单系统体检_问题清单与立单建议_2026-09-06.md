# 工单系统体检：问题清单与立单建议（2026-09-06 · 设计师）

> **缘起**：用户指示以吹毛求疵的使用者视角审查工单系统本身（非 MOV App）。发现全部来自 2026-09-05/06 实际操作实录 + 当日复查，每条附**验证方法**——等用户验证后按 §三 建议立单。
> **状态**：⏳待用户验证（未立单、未动任何库文件）

## 一、发现清单（按 疼痛×频率 排序）

### A. 结构性（每天都在付的税）

**1. 工单库单体巨文件 + 千字状态行 + 状态双写**
- 现象：单文件 5539 行 / 107 卡；UPG-108「**状态**：」叙事行 1508 字符、UPG-01 数千字（含批 1~4 全史）；status 块与叙事行各存一份状态、updated_at 手敲。
- 验证：`awk 'length>800 {print NR": "length"字符"}' 工单库.md | head`（多处命中）
- 疼：并发编辑必撞「File has been modified since read」（今日实录×N）；想知道阶段要人眼扫描巨行；改一处卡要写两处。

**2. 并发写零防护，铁律靠自觉**
- 现象：多 agent 同编辑库文件只靠人肉重试；共享 worktree 并发 gradle 互删 build 目录（今日 119 ClassNotFoundException 实录）；§P61 他人暂存区残渣入提交事故（催生"路径限定 commit"铁律，无机器闸）。
- 验证：问题区 §P61 段 + 2026-09-05/06 git log + 审验状态当日记录。
- 疼：事故已发生三次同族，每次都是事后铁律，没有闸。

**3. 一套系统两个运行时**
- 现象：审验.py（Python）+ sync-orders.mjs（Node）；当日 `python sync-orders.mjs` 误跑实录；websocket-client 需 `--break-system-packages`（PEP 668）。
- 验证：`ls 审验员/审验.py 审验员/sync-orders.mjs`
- 疼：新 agent/新人上手必踩。

**4. Windows 环境税**
- 现象：GBK 摩乱（Git Bash 下 tail/grep 中文路径乱码）、MSYS 路径转换（/sdcard→C:/Program Files/Git/sdcard 实录）、中文深层路径工具哑火。系统脚本层无缓冲、无环境须知文档。
- 疼：每个新 agent 重新踩一遍。

### B. 机器闸失效模式（闸了，但闸不对）

**5. STD 冻结哈希口径未进 SOP（今日实锤，同族再犯）**
- 现象：STD-UPG-108-v1 头部自报 content_sha256=7c3ac2dd（含「## 冻结区」标记口径）≠ 审验.py 机器闸算法 d12222eb（标记后口径）。UPG-93 曾因张冠李戴建交叉闸，但冻结 SOP 至今未定义算法——防了"校验不严"没防"口径不一"。
- 验证：`python -c` 重算两种口径（见问题区 2026-09-06 条目）；对比 `审验.py --manifest` 通过值。
- 疼：同族错误第三次出现。

**6. manifest 占位符「（待填）」反复过关（同族四次）**
- 现象：UPG-69（绑 75369492≠实际 be6a06a0）、UPG-100、UPG-104、UPG-108 交付时均带占位/错绑，全部到审验阶段才被挑出。红线 22 机检存在但时点后置。
- 验证：问题区各单附记条目 + 各 DELIVERY 报告。
- 疼：审验员被迫当清洁工，成本总在后置环节。

**7. verify-hash 措辞语义过载**
- 现象：「分支未合 main」= 合并前正常态，输出却叫 `HASH_REJECT <not-ancestor>`+「疑似冒充」措辞；另 output 中 repo 名未插值（`祖先链（）`空括号，小 bug）。
- 疼：天天红狼来了，真红失去信号价值。

**8. sync 校验对外部仓状态敏感，误报指控性强**
- 现象：UPG-104/108 合并当日 sync 报「**合入记录不实，人工核**」——真因仅是 app 仓本地 main 落后 origin。校验本地引用而不 fetch origin。
- 疼：「不实」级措辞配环境性误报，训练使用者无视输出。

**9. check 输出永不干净**
- 现象：UPG-62/67/86「存量豁免/DEL校验跳过」为永久性输出；健康状态无"全绿"表示法。
- 疼：噪音淹没信号。

### C. 引用易腐

**10. 行号引用裸奔**
- 现象：UPG-01 卡面「挂账登记表:211」——表每加一行即失准；manifest_UPG108.md 引用 Temp 路径的未填模板在证据目录滞留。
- 验证：`grep -n "挂账登记表:" 工单库.md`

**11. 落点/生命周期惯例靠 P3 备忘维持**
- 现象：manifest 落点（UPG-69/100/111 三次"落点"P3）、worktree 堆积（当前 16 个，无回收机制）、证据目录结构无 schema。

### D. 真实使用者体验

**12. 用户是决策瓶颈，系统无"待决策"视图**
- 现象：UPG-106"等用户拍板"数日、真机判据裁决等散落各卡叙事行，无汇总视图，发现靠汇报。

**13. 命名不达意**
- 现象：「工单库」（源）vs「工单表」（投影）——新 agent 直接过率改 xlsx，"写入五步铁律"的存在即 pain 证据。

**14. 信息密度与可读性倒挂**
- 现象：单卡合规汇报数千字；无"全库 X 卡各等什么"的一屏视图。

## 二、不是问题的（防误修）

- 恒时比较/只存哈希/一次性 ref/5 分钟窗等核心安全判断——与业界实现（Hermes Studio）逐条对得上，**不需要动**；
- xlsx 投影机制本身不是错，错在"必须存在"——按需生成的可能性归入单C设计稿评估；
- 问题区/挂账表的追加式设计正确，问题只在结构化程度。

## 三、建议的工单拆分（5 张，等验证后立卡）

| 拟编号 | 标题 | 优先级 | 范围要点 | 验收思路 | 预估 |
|---|---|---|---|---|---|
| 拟单1 | STD 冻结哈希口径统一 + STD 生成器脚本 | P2 | 出 STD 必经脚本（审验.py 同款算法）生成头部哈希；SOP 写入口径；UPG-108 头部不改、注记口径已在校验注记 | 新 STD 全部过 --manifest 交叉闸；脚本自带 self-test | 0.5 天 |
| 拟单2 | 交付闸前移：manifest 占位拒收 + 落点 schema | P2 | deliver-gen 层拒收（待填）占位；manifest/证据落点表 schema 化并入 sync 检查 | 构造占位 manifest 交付必被拒；落点错位 sync 红 | 1 天 |
| 拟单3 | 工单库结构演进设计稿（状态块唯一真源） | P2 | 设计稿先行（叙事历史折叠为 append 区/status 块唯一真源/双写消除/updated_at 自动化/xlsx 按需生成评估）——**不动库**，设计过评审后另立实施单 | 设计稿过用户+审验员评审 | 1 天 |

**不做**（本期明确排除）：工单库物理拆分的直接实施（先出设计稿）、Socket 类实时协作、引入数据库/服务化、更换运行时统一（Python/Node 双工具保持现状只加对照说明）。
