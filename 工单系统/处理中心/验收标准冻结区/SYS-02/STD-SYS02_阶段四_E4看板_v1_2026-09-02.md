## 五、实现级契约（大神三审定案 · 必须遵守）

### 5.1 核心工程原则（写入文档引言）

> **E1 负责真相，E4 负责投影；E4 只计算允许的派生告警，不重新创造状态。**

### 5.2 超期计算公式（契约定死）

```text
overdue(state) = (now - state.ts) > THRESHOLD[state.stage]
  · state.ts = 当前状态行对应的 entered_at / 状态变更时间戳（**禁止用工单创建时间 created_at**）
  · state.stage ∈ {claim, deliver, merge}（对应已派/施工/待合）
  · ts 缺失 → overdue=false（诚实降级，不算超期）
```

### 5.3 状态枚举契约（不可静默降级）

```text
状态行 → 解析：
  · 已知枚举（✅已合/🔨施工/📌已派/⏳排队/🟡验收通过/⚠️超期派生）→ 正常映射
  · 📌 语义注记：若 E1 将「已派/待认领」定义为单一状态，E4 统一展示 📌（不拆分——边界声明）
  · 未知/非法值 → ⚠️ 无法解析 + 关键点提示 + 手动复核
  · 🔴 红线：未知状态【不得】静默降级为 ⏳ 或 📌——违反=变异必红
```

### 5.4 稳定排序键

```text
ORDER = severity_rank ASC → card_id ASC
severity_rank: ⚠️超期=0 → 🔨施工=1 → 🟡待合=2 → 📌已派=3 → ⏳排队=4 → ✅终态=5
（输出稳定——git diff/审验/幂等验证友好）
```

### 5.5 投影层（实现模型 · 推荐采用）

```text
E1 状态行 → Projection Model（内部对象）→ Markdown 渲染
Projection = {
  card, delivery, acceptance, merge,   // 三态枚举
  assignee, summary, ts, severity_rank, // 展示+排序字段
}
（不直接 E1→MD 拼接——为未来 HTML/CLI/JSON 导出预留统一投影层）
```
