# 验收标准冻结区（P0-1 · SYS-01 引入）

> **验收「什么是合格」的唯一正式冻结落点。** 派单时把判定标准定死成不可变版本，防「验收通过后再改标准」的事后合理化。
> 出处：`SYS\改造计划_工单流转中心防伪抗倒退_2026-09-01.md` §P0-1（v3.1 实施定稿）。
> 配套：`SYS\交付绑定规范.md`（P0-2，交付绑定）+ 根 `README.md` 红线 22/23。

---

## 〇、一句话

**每个工单在验收前，设计师必须把验收标准冻结为一个带版本号、不可原地修改的 `STD-<工单号>-v<n>` 文件；验收 / 审验 / 合 main 抽查三方对账，都引用这个冻结版，而不是引用「散写标准」。**

## 一、目录结构

```
处理中心\验收标准冻结区\
├── README.md                      ← 本规则（你在这）
├── _模板\                         ← 冻结模板（复制后填）
│   └── STD_<工单号>-v<n>_模板.md
└── <工单号>\                      ← 每个工单一个子目录
    ├── STD-<工单号>-v1.md         ← 首次冻结版
    └── STD-<工单号>-v2.md         ← 修订派生版（禁止覆盖 v1）
```

## 二、冻结流程（谁 / 何时 / 怎么冻）

| 项 | 值 |
|---|---|
| **谁冻结** | 设计师（`frozen_by`）；`approved_by` 审验员确认 |
| **何时冻结** | 派单前或验收启动前，先冻结后验收 |
| **每单几个冻结版** | 同一时刻只允许**一个正式冻结版**（最新版本）；历史版本永久保留供溯源 |
| **落点** | `验收标准冻结区\<工单号>\STD-<工单号>-v<n>.md` |
| **引用纪律** | 派单文本 / 验收报告 / 审验报告必须写 `STD-<工单号>-v<n>`，不得引用未冻结的散写标准 |

**冻结版头部（身份 + 完整性，不可改）**：

```text
standard_id:   STD-<工单号>-v<n>       ← 业务身份（版本号）
content_sha256: xxxxxxxxxxxxxxxx       ← 冻结区内容哈希（见 §五）
frozen_at:     2026-09-01T01:20:33
frozen_by:     设计师
approved_by:   审验员
```

---

## 三、内容两区分工（冻结区 / 追加说明区）

一个 STD 文件内分两区，职责不同：

| 区 | 内容 | 可否改 |
|---|---|---|
| **冻结区** | 验收定级（L1/L2/L3）、变异锚、测试匹配档 | **不可改**（只读，本文件的哈希锚定它） |
| **追加说明区** | 任何人可追加（注时间/作者/触发原因）的备注 | 可追加，但**默认不作为合格判定正向证据** |

- **追加说明区是「事后合理化」的单独存放地**：验收通过后才想起来的理由，只能追加在这里，不能改进冻结区当合格依据。
- 判断「这条标准算不算数」= 看它是否在**冻结区**；追加说明区内容只供参考，不作为判合格的正向证据。

---

## 四、修订 = 派生新版本（红线 R2：不可变对象）

1. **修订必派生**：标准内容需要变 → 产出 **`STD-<工单号>-v<n+1>`**，**禁止覆盖 v<n>**。
2. **共批**：修订需**设计师 + 审验员共批**（与冻结批准同权责）。
3. **不影响旧判定**：修订版**不计入首次验收合格判定**；旧版若已被验收即永久保留（可追溯「当初依据什么过的」）。
4. **每个版本曾被验收即永久保留**：不得删除、覆盖、复用。

---

## 五、content_sha256 校验（机器算，人裁决）

- **定义**：`content_sha256` = 「冻结区」正文（从 `## 冻结区` 到 `## 追加说明区` 之间，UTF-8 原文含换行）的 SHA-256。
- **为什么只哈希冻结区**：追加说明区会持续增长，若哈希整文件则每次追加都「变味」；哈希冻结区才能判定「合格标准本身是否被改过」。
- **三处对账**（验收✅ / 审验 / 合 main 抽查）：
  1. 打开工单引用的 `STD-<工单号>-v<n>.md`；
  2. 用 §六 命令重算冻结区 `content_sha256`；
  3. 与文件头部声明的 `content_sha256` 比对：**不一致 → 阻断**，提示「标准已变更，需重新冻结或走修订」。
- 判定是人工的：机器只报「一致 / 不一致」flag，是否放行由验收员 / 审验员 / 设计师裁决。

---

## 六、重算 content_sha256 命令（复制进模板文末）

```bash
python -c "import hashlib,sys; t=open(sys.argv[1],encoding='utf-8').read(); s=t.split('## 冻结区',1)[1].split('## 追加说明区',1)[0]; print(hashlib.sha256(s.encode()).hexdigest())" "STD-<工单号>-v<n>.md"
```

> 阶段说明：自动化比对（验收/审验/抽查三处自动算+阻断）属 P2 自动化范围，本阶段先落「规则 + 可手动重跑的命令」，保证对账动作可执行。

## 七、与既有制度的关系

- 不推翻既有验收定级（L1/L2/L3，见 `验收员\文档\真机验收标准与方式方法.md`）——冻结区就是把「验收员手册里的分级标准」**针对本单实例化并锁死**。
- 不新增角色/审批节点：冻结/批准沿用设计师 + 审验员既有职责。
- 审计链：`STD-<工单号>-v<n>` 是因果链的**根对象**，`delivery_id` 挂在它之下（见 `SYS\交付绑定规范.md`）。
