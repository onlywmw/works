# 处理中心

> **各角色「建议 / 汇报 / 挂账 / 问题」的汇聚入口 + 设计师处理站。**
> 验收员和程序员的挂账/问题/汇报，统一放这里，设计师集中处理。

---

## 一、定位（收四类输入，设计师统一处理）

| 输入 | 内容 | 落点 | 设计师处理 |
|---|---|---|---|
| **挂账** | 验收员/程序员发现的缺陷（被动发现，P2+）| `挂账登记表.md`（⏳挂账待审）| 验证（查代码/证据/复现）→ ✅已落实 转工单（`工单表.xlsx`）→ 派单 |
| **建议** | 立项建议（灵感库/验收员评估建议）| 建议区（本中心）| 评审（服务哪个特质：更懂你/更持续/更能干）→ 立项拆单 or 不立项 |
| **汇报** | 验收员验收汇报 · 程序员交付汇报 | 汇报区（本中心）| 确认 → 流转（真机复验/验收/合 main）|
| **问题** | 各角色遇到的阻塞/疑问 + **审验员审验发现的证据链问题**（红线16：必须登记本区） | 问题区（本中心）| 解决 / 升级 |

## 二、各角色投放

| 角色 | 投放 | 位置 |
|---|---|---|
| **验收员** | 验收汇报 / 复验结果 / 建议（工具/立项）| 处理中心（汇报区 + 建议区 + 挂账登记表）|
| **验收员** | 挂账（验收发现缺陷）/ 验收汇报 / 问题 | 处理中心（挂账登记表 + 汇报区）|
| **程序员** | 挂账（施工发现缺陷）/ 交付汇报 / 问题 | 处理中心（挂账登记表 + 汇报区）|
| **设计师** | 处理全部：验证挂账→转工单 / 评审建议→立项 / 确认汇报 / 解决问题 | 处理中心 |

## 三、流转

```
各角色登记（挂账→挂账登记表 ⏳待审；建议→建议区；汇报→汇报区）
  → 设计师处理
      挂账 → 验证 → ✅已落实 → 转工单（工单表.xlsx）→ 派单
      建议 → 评审（服务哪个特质）→ 立项拆单 or 不立项
      汇报 → 确认 → 流转（真机复验 / 验收 / 合 main）
      问题 → 解决 / 升级
  → 落实后走既有工单流转（程序员施工 → 验收 → 真机 → 设计师合 main）
```

## 四、红线（沿用 `挂账登记与转工单规则.md`）

**并发协作认领（2026-08-17 定）**：多 agent 领单开工前先登记 `认领: <agent> worktree=<主仓库名>-<工单号> branch=<feat/x> @时间` 到工单表备注；worktree 命名强绑定工单号；分支被占用 = 单已被认领，直接改领其他单（详见 `工单流转中心\README.md` 红线 9 + 程序员 README「领单认领规范」）

1. **不主动收集**——仅工作中被动发现
2. **登记即挂账，不删除他人登记**（疑义走打回/销项）
3. 真机补验类挂账走工单库「真机补验挂账」区（不转工单）
4. **改表前备份**（登记挂账不备份；转工单写工单表时才备份）
5. 建议/汇报不堆主文件夹（各角色区放本中心，工单流转中心根保持清爽）

## 五、文件夹结构（2026-08-17 规划）

```
处理中心\
├── README.md（规则/入口）
├── 挂账登记表.md（挂账待审池——进行中）
├── 挂账登记与转工单规则.md
├── 验收标准冻结区\（【新·SYS-01 P0-1】验收「什么是合格」的冻结落点，STD-<工单号>-v<n>.md）
├── 建议区\（待评审建议）
├── 汇报区\（汇报）
├── 问题区\（问题）
└── 归档\（已处理完）
    ├── 建议_已评审\（建议→拆单后归档）
    └── 汇报_已确认\（汇报→确认后归档）
```

> **验收标准冻结区**（2026-09-01 引入）：每单一个 `<工单号>\` 子目录，放 `STD-<工单号>-v<n>.md` 冻结版（含冻结区+追加说明区，修订派生不覆盖）。规则见本区 `README.md`。

**归档机制**：设计师处理完的（建议评审拆单 / 汇报确认 / 挂账落实转工单）→ 对应归档子目录；待处理的保留在建议区 / 汇报区 / 挂账登记表（⏳待审）。**根目录只放规则 + 待审池**，保持清爽。

**处理完判定**：
- 建议 → 已拆单（工单表有对应工单）→ 归档 `建议_已评审\`
- 汇报 → 已确认（设计师已回复/流转）→ 归档 `汇报_已确认\`
- 挂账 → 已转工单 → 挂账登记表标 `✅已落实`（保留在表内，不删）
