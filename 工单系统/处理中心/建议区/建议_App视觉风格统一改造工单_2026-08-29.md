## 改造工单（草案，待设计师定编号与决策点）

# UPG-XX App 视觉风格统一（黑白主调 · logo 同源）

**优先级**：P1（上架物料前置）｜ **出单人**：设计师（转单后）

## 背景

logo 黑白线稿 vs 市场系绿（#0E7C5B）vs 原生无主题裸奔——风格三张脸。上架展示图制作因此返工（绿色海报被否）。目标：App 内全端视觉收敛为「黑白灰 + 可控强调色」体系，与 logo 气质一致；token 单源驱动；深浅双色跟随系统（现有 isDark 机制）。

## 施工范围（三刀）

1. **Token 换主色（Vue 7 页）**：`tokens.css` 单点——`--primary/--primary-strong/--primary-tint` 绿系 → 黑系；语义色（ok/warn/danger）**保留不动**（功能色非品牌色）；dark 变体补齐/校验。Vant 映射现成零改动。
2. **聊天页对齐**：改 `tools/ms-md-server/page/src/RoomApp.vue` 尾部 `<style>` 段——实盘点：全页色值仅 2 个（用户气泡底 `#EAF0FD` → 中性灰阶；文字 `#1F2329` → 与主色 token 对齐）；改后 vite build + 拷贝同步 `app/src/main/assets/markstream/`。**只动 `<style>` 段，不碰模板/逻辑与 markstream 渲染架构（冻结项）**。工作量实估：源 176 行、样式 57 行、色值 2 个，半天内闭环。
3. **原生壳补主题**：新增 `colors.xml`/`themes.xml`（黑白主色+状态栏/导航栏色），登录/隐私门/MainActivity 显式挂主题；`0xFF0000FF` 硬编码链接色归位。

## 验收标准

- **L1**：全仓 grep 绿系品牌色（`0E7C5B|0A6649|0B7A5C` 大小写全角）= 0（git 历史除外）；全量绿；写死品牌色 grep=0（沿用 UPG-23 硬规口径）；变异：tokens.css 主色改回绿 → 校验脚本必红。
- **L2（真机）**：五屏截图（聊天/市场本地/市场/设置/记忆）× 深浅双色落 ACCEPTANCE_LOG；**截图集须含 Vant 开关 ON/OFF、tab 选中、按钮 disabled 态**（纯黑白方案的可点态区分度实证——评审意见②）；观感与 logo 黑白气质一致——**设计师与用户双重拍板**。
- **L3**：sync-pages 产物与源一致（--check 幂等）；room 页 dist 与资产逐字节一致；原生装机走查状态栏/弹窗/审批 dialog 无系统蓝/绿残留。

## 红线

- 不动 room.html markstream 架构（冻结项：RoomApp.vue 只许动 `<style>` 段）；不动任何功能逻辑与文本内容（纯视觉单）。
- 语义色（ok/warn/danger）与审批/安全语义点（🟢🟡🔴）不动——那是功能语义不是品牌色。
- token 单源：禁页面级写死品牌色（发现即打回）；UPG-23 本地 tab 风格硬规（Vant token/禁写死色值/van-cell-group inset）全量继承。
- 官网/工作台**不在本期**（防一锅烩失控；是否同批走决策点③）。

## 决策点（出单前用户拍板）

1. 主色口径：纯黑 #000 / 暖调近黑 / 冷调近黑 #191B21——**以设计师 3 张同屏 mock（聊天+市场+设置）拍板，不做文字投票**（评审意见①；#191B21 系 room 页历史巧合色，不再作默推项）。
2. 深色模式反转口径：黑底白强调 or 维持中性灰？（建议黑底白字，气泡灰阶分层）。
3. 官网/工作台是否同批（建议否，另立单；**若否，上架物料红线 = 只截 App 内页面、禁出现任何官网预览**——评审意见④；若同批，官网只做极简对齐：只换主色不改布局）。
4. 是否保留一丝品牌点缀（如 tab 下划线/开关 ON 态用极深绿近黑？建议否，纯黑白干净）。
5. 强调色是否需要一个（如链接/可点态）：建议「黑=可点」单规则，零彩色——**但若 ④⑤ 均拍板纯黑白，工单必须随单补「可点态区分度规则」**（下划线/字重/透明度分层，或一个极低饱和功能灰蓝专供链接/可点态），并过 Vant 开关/tab/disabled 态深浅双模式可用性检查（评审意见②）。

## 备注

- 与 UPG-23 无代码冲突（同 token 体系内演进）；施工时按规则 19 从最新 main 切分支；mov-vue 构建链同 UPG-23（bun install → vite build → sync-pages.mjs，仅入改动页目录）。
- 上架展示图（mov_store_assets/ 六张黑白版）搁置待本单落地后按新风格重渲截图页。

## 评审回应（2026-08-29 评审四条处置）

1. **主色决策方式** → 采纳：决策点①由「色值文字投票」改为「设计师出 3 张同屏 mock（聊天+市场+设置）后拍板」；选色逻辑从 logo 线稿墨感出发，候选含纯黑/暖调近黑，#191B21 不再默推。程序员侧支持现成：tokens.css 换值 → vite build → Edge 无头截图链路已在 UPG-23 走通，三候选各出一套 mock 成本极低，随叫随出。
2. **纯黑白的可点态区分度** → 采纳为出单必补条款：已写入决策点⑤与验收 L2（截图含开关/tab/disabled 态）；若拍板纯黑白，区分职责须明规给下划线/字重/透明度分层或一个极低饱和功能灰蓝。
3. **room 页源工程定位** → ✅ **已闭环**（程序员，2026-08-29）：源在 `tools/ms-md-server/page/`（本仓库内，非外部仓库、非无源码）；`src/RoomApp.vue` 176 行，样式集中尾部 57 行 `<style>`，全页色值仅 2 个；构建链现成（node_modules 在位）；产物与资产 diff 逐字节一致，同步 = build 后拷贝。第二刀工作量实估**小**（改 2 个色值 + build + 拷贝 + 截图，半天内）——「工作量翻倍」风险排除，现状溯源表与施工范围第 2 刀已按实证改写。
4. **官网与上架物料两张脸** → 转设计师决策：已写入决策点③——不同批则物料只截 App 内页面，同批则官网只做极简对齐（只换主色不改布局）。
