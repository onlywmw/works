## 一、页面骨架（就一页）

```
┌──────────────────────────────────────────────────────┐
│ ◈ MOW 工作台    数据 5 分钟前同步 · admin ⏷          │  ← 细顶栏 56px（可省，并进侧栏头）
├────────────┬─────────────────────────────────────────┤
│            │                                         │
│   文件树    │            选中板块的内容区              │
│  （侧栏）   │   （流水线步进器 + 工单列表 + 挂账 + 动态） │
│  260px     │                                         │
│            │                                         │
└────────────┴─────────────────────────────────────────┘
```

- 打开默认选中「📊 总览」；
- 点树节点 → 右侧原地切换内容，**无页面跳转、无多级路由**（前端按单页应用做，hash 路由即可，如 `#/app/tickets`）；
- 手机端（<768px）：侧栏收成左上角 ☰ 抽屉，内容区全宽。

## 二、侧栏文件树样式规格

- 宽 260px，行高 34px，缩进 16px/级，节点圆角 8px；
- 节点构成：`折叠箭头 ▾` + `图标` + `名称` + 右置 `计数徽标`（灰底 pill，显示在制数）；
- **状态灯上卷（关键设计）**：任何子孙板块有「阻塞/待审」→ 沿树一路冒泡，父节点名称左侧显示 6px 红点；一眼从树根定位到问题板块；
- 选中态：品牌蓝 8% 透明度底 + 左侧 3px 蓝条；hover：暖灰底；
- 一级节点可折叠，默认全展开（树不深，展开才一目了然）；
- 字体：节点名 label-sm（13px/500），一级节点加 600。

## 三、文件树脉络（本设计的核心，照此实现）

```
◈ MOW 工作台
│
├── 📊 总览                          ← 默认页：五维状态卡 + 本周焦点（见 §四）
│
├── 📱 App 建设                       数据源：工单流转中心（自动同步）
│   ├── 🔄 工单流转                   流水线：设计师→程序员→验收员→审验员→合main
│   ├── 🧾 挂账与问题                 流水线：登记→设计师验证→转工单/销项
│   └── ✅ 验收记录                   无流水线，纯时间线列表（ACCEPTANCE_LOG）
│
├── 🏪 能力市场
│   ├── 🧩 MCP 工具审核               流水线：提交→审核→上架/打回
│   ├── 🤝 商家入驻                   流水线：申请→资料审→签约→开通
│   └── 🌐 站点建设                   流水线：需求→开发→验收→上线（含中文化收口、迁 mov-ai.cn）
│
├── ®️ 品牌
│   ├── ™️ 商标                       无流水线，状态档案卡（已注册✅ + 续展提醒日期）
│   ├── 🎨 视觉识别（VI/Logo）        流水线：策划→设计→定稿→落地
│   └── 📖 品牌内容                   流水线：策划→创作→定稿（品牌故事/命名体系/口径）
│
├── 📣 营销推广
│   ├── 💬 公众号                     流水线：注册/设置→内容→发布→复盘
│   ├── 🗓️ 内容日历                   无流水线，月历视图 + 条目状态点
│   └── 📈 渠道与投放                 流水线：调研→试投→评估→加码/停投
│
├── 🖥️ 服务器基建
│   ├── 🖧 服务器与域名               状态档案卡（服务器/域名/证书到期日 + 费用）
│   ├── 🏗️ 官网建设                  流水线：需求→开发→验收→上线
│   └── 💾 备份与运维                 流水线：计划→实施→验证（备份策略/监控/告警）
│
└── 🗄️ 归档                          完成/销项工单沉底，只读，按维度分组，可搜索
```

### 脉络设计规则（前端 & 后续维护都遵守）

1. **层级最多两级**（维度 → 板块），禁止三级——两级是「一目了然」的物理上限；想加三级时，先问能不能拆成平级板块；
2. **一级节点固定七个**：总览 + 五维度 + 归档，不增不减；维度口径已和用户定死（公众号归营销、官网归基建、工单流转是数据源不是维度）；
3. **每个二级板块必须回答三件事**：阶段流是什么（流水线）、在制什么（工单列表）、什么卡着（挂账/阻塞）。答不出这三件的板块不该存在；
4. **两种板块形态**：有流水线的（多数）+ 无流水线的档案/时间线（商标、验收记录、内容日历、服务器信息）——前端做两套模板即可覆盖全部；
5. **新增板块 = 加叶子**，加完检查父维度状态灯是否正常上卷。

## 四、总览页（默认选中页）

不做复杂架构图，一张「全维度状态墙」：

- 顶部一行聚合：`5 维度 · 在制 9 · 阻塞 2`（阻塞 >0 时红色）；
- 五张维度卡（2+2+1 网格，手机单列）：维度名 + 状态灯 + `在制 X · 阻塞 Y` + 一行最近动态；点击 = 跳到该维度第一个板块；
- 下方「本周焦点」横卡：各维度 P0/P1 在制 Top 3-5 条（优先级色点 + 维度 + 工单名 + 状态），点击跳到对应板块并高亮该工单行。

## 五、板块内容区模板（两套）

### 模板 A：流水线板块（多数板块用）

从上到下三带：

1. **流水线步进器**：阶段一字排开（阶段名 + 积压计数），活跃阶段品牌蓝描边高亮，段间 `→`；手机端横向可滑动；
2. **工单列表**：每行白条 = 左缘 4px 优先级色条（P0 红/P1 琥珀/P2 灰）+ 工单号 + 标题 + 状态 chip + 更新时间；排序：阻塞 → P0 → P1 → 其余；
3. **挂账/阻塞区**：琥珀左边条卡片（标题 + 登记日期 + 状态）；无挂账显示「无阻塞 ✅」。

### 模板 B：档案/时间线板块（商标、验收记录、服务器、内容日历）

- 档案型：若干信息卡（字段名 + 值 + 状态灯），如商标卡 = 注册号/类别/注册日/下次续展；
- 时间线型：一行一条 `日期 · 事件`，最新在上，最多 20 条分页。

## 六、数据契约（网站只读，v1 原则不变）

真相源 = 桌面工单流转中心（App 维直接读现有 `工单库.md`/`工单表.xlsx`/`挂账登记表.md`/`ACCEPTANCE_LOG.md`；其余维度各一份同款轻量 md 表）。同步脚本解析 → `workbench.json` 随部署上服务器；**前端只 fetch 一个 JSON，不做写操作**。

```json
{
  "generatedAt": "2026-08-26T12:00:00+08:00",
  "tree": [
    { "key": "overview", "name": "总览", "icon": "📊" },
    { "key": "app", "name": "App 建设", "icon": "📱", "children": [
      { "key": "app-tickets", "name": "工单流转", "type": "pipeline",
        "pipeline": [ {"stage":"设计师","count":4}, {"stage":"程序员","count":1,"hot":true} ],
        "tickets": [ {"id":"UPG-07-b1","title":"预算口径加权","prio":"P0","status":"待专家审","updated":"08-26","blocked":false} ],
        "backlog": [ {"title":"模拟器AI未回复","date":"08-26","status":"待审"} ] }
    ]}
  ],
  "focus": [ {"section":"app-tickets","ticket":"UPG-07-b1","title":"预算口径加权","prio":"P0"} ],
  "archive": [ {"dim":"app","id":"UPG-02","title":"设备工具包","doneDate":"08-24"} ]
}
```

- 状态灯/计数由前端按 `tickets/backlog` 现算（blocked 或待审 >0 → 红点上卷）；
- 字段缺省必须容错（空数组/缺字段渲染空态，不报错白屏）。

## 七、状态色与组件（沿用品牌 token）

- 状态色（低饱和，禁荧光）：正常/完成 `#16A34A`、进行中 `#3B6EEB`、待审/警告 `#D97706`、阻塞 `#DC2626`、未启动 `#9CA3AF`；状态不只靠颜色——配文字或 6px 圆点+文字；
- 组件清单：树节点、计数徽标 pill、状态灯、流水线步进器、工单行、状态 chip、档案卡、时间线行、空态插画位（先留灰块）；
- 动效只允许：150ms hover 浮起、内容区淡入；禁止闪烁红点（用静态红竖条/红点）。

## 八、不做清单（YAGNI，前端不要擅自加）

- ❌ 三级树、拖拽排序、在线编辑状态（状态只从桌面同步）；
- ❌ 图表报表/燃尽图/统计页、通知铃铛、评论协作；
- ❌ 多标签页/面包屑深层导航（只有两级）；
- ❌ 暗色模式（一期不做）。

## 九、交付物与走查标准

1. 单页静态站：`index.html` + css/js，hash 路由，fetch `workbench.json` 渲染；附 `workbench.sample.json`（五维度全填满的假数据）；
2. 登录门禁接现有 `account-service.js`（账号体系，用户已拍板），接口细节施工时与后端对；
3. 走查标准：
   - 侧栏树两级全展开时一屏可见全部节点（不滚动）；
   - 任意板块制造一条阻塞假数据 → 红点能从叶子冒泡到一级维度；
   - 375px 宽手机：抽屉可用、内容区无横向滚动、步进器可横滑；
   - 断 JSON（字段缺失）不白屏。
