微信二级商户（特约商户）开发计划
================================
版本：2026-08-23 v1
目标：让商户能方便注册、签约、上线提供服务（暂不涉及收款/支付）

一、总体链路
------------
商户（app 内填写资料）
  → 进件提交（app → partner-server → 微信支付「特约商户进件」API）
  → 微信审核（机器+人工，约 1-3 个工作日）
  → 联系人微信签约（微信侧完成，app 展示签约入口/状态）
  → 二级商户号开通（sub_mchid）
  → 商户资料同步到商业后端（a2a，role=pro + professions）
  → 上线可接单（任务大厅/预约可见）

二、现状盘点（已具备）
--------------------
服务端 partner-server（mow.kim/partner，FastAPI）：
- POST /v1/applyment        提交进件申请单（敏感字段服务端公钥加密转发微信，私钥不出服务端）
- GET  /v1/applyment/{code} 查询申请单状态（审核中/待签约/已完成/已驳回）
- POST /v1/media            图片上传（身份证/营业执照/店铺照 → media_id）
- 密钥体系：商户 API 证书、APIv3、微信支付公钥（已部署，健康检查 ok）

商业后端 a2a（mow.kim，8080）：
- POST /register 设备注册（role=buyer|pro + professions）
- 任务/预约全套 API 已通（app 已接入工作台/我的订单）

app 侧：
- 桥接协议（PagesBridge）+ biz.* 工具族
- 商家工作台/我的订单页面（已接真实后端）

三、待建（本次范围）
------------------
1. app「商家入驻」页（Vue，侧边栏"我的能力"内入口）
   - 分步表单：主体信息（个体户/企业）→ 法人/联系人 → 结算银行卡 → 经营信息 → 照片上传
   - 照片：调相机/相册 → /partner/v1/media 拿 media_id
   - 提交 → /partner/v1/applyment，本地存 business_code
2. 进件状态跟踪
   - 入驻页显示状态卡：审核中 / 待签约（展示签约指引）/ 已完成 / 已驳回（原因+重新编辑）
   - 定时/手动刷新（/partner/v1/applyment/{business_code}）
3. 签约引导
   - 待签约状态：展示微信返回的签约链接（app 内网页弹层打开）或引导联系人在微信完成
4. 上线联动
   - 状态=已完成 → 引导商户完善 a2a 资料（role=pro + professions 技能/半径）→ 工作台可接单
5. partner-server 补强（如需）
   - 进件资料草稿暂存（app 端 SharedPreferences 即可，服务端可不存）
   - AUTH_TOKEN 下发方式（试点期 app 内置；正式期改为设备级 token——见风险节）

四、进件资料字段（微信 API 必填）
--------------------------------
- business_code（业务申请编号，app 生成，幂等键）
- 主体：subject_type（个体户/企业）、营业执照号、商户简称
- 法人：姓名、证件号、证件有效期、证件正反面照片
- 联系人：姓名、手机号（短信验证可选）、邮箱
- 结算：开户银行、开户行城市、支行、卡号（个人卡/对公户）
- 经营：经营类目、商户名称、客服电话、经营地址、店铺门头/内景照片

五、安全与红线
--------------
- 支付商户私钥/证书永不进 app，全部签名在 partner-server（现有架构已满足）
- 敏感字段（身份证/银行卡）只在服务端用微信支付公钥加密，app→服务端走 https
- AUTH_TOKEN 试点期内置 app（风险：可被提取刷进件垃圾单，无资金风险）；
  正式期改为设备级鉴权（复用 a2a 设备注册体系）
- 本阶段不做收款/分账/退款（支付另立项）

六、验收标准
------------
1. 测试商户在 app 内完成资料填写并提交进件，拿到 applyment_id
2. 状态页可见审核进度流转（审核中→待签约）
3. 联系人完成微信签约后，状态=已完成，拿到 sub_mchid
4. 商户在工作台出现并可接单（role=pro 生效）

七、排期（建议）
--------------
P1：入驻页表单 + 提交 + 状态卡（本次）
P2：签约引导 + 上线联动（role=pro + professions 编辑）
P3：正式鉴权 + 驳回重提优化 + 多商户管理

八、核心交互决策（2026-08-23 修订）
----------------------------------
入驻主路径 = 对话式（MCP 工具编排），不是表单页。

商户在对话中说"我要入驻"→ AI 逐项询问收集 → 工具落草稿 → 引导拍照 → 确认提交。
工具族（agent 工具面，状态化草稿持久化，跨消息/跨房间可续）：
- biz.onboardStart   开始/续入驻，返回已填/缺失清单
- biz.onboardSet     写入单个字段（按字段校验）
- biz.onboardPhoto   登记照片（身份证正反面/营业执照/门店），经相机拍照→/partner/v1/media→media_id
- biz.onboardSubmit  校验完整性 → 提交进件 → 保存 business_code
- biz.onboardStatus  查询审核/签约状态

对话流程示例：
用户：我要入驻
AI：好的，先做主体信息——您是个体户还是企业？……（逐项收集）
AI：请点左下角相机，拍一下身份证正面。（用户拍）已收到，media 上传完成。
AI：资料齐了，我念一遍您确认：……确认提交吗？（提交）申请单已提交，编号 xxx，审核约 1-3 天。

表单页降级为备胎（大批量修改/驳回重提时用）。
