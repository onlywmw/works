# 全角色通告：验收错误内化机制启用（2026-08-17）

> **即时生效**。本机制将验收系统性误标从「靠 md 文档记忆」升级为「结构化记录 + 可追踪 + 根因收敛」——光靠文档会遗忘，必须有台账、有专项工单、有抽查。

---

## 一、背景

验收员（真机测验员）近期出现**系统性验收误标**：

- r45：截图 FAILED 却标 ✅（机制触发 ≠ 功能达成）
- r47/r50：AI 口头列计划未执行，标 ✅（口头计划 ≠ 执行）
- r82：AI 回复空 payload（超时），标 ✅（任务未完成就算过）
- r41：拿其他项目自带进程当本项目验收证据（证据归属未核对）
- A 类多单：代码+JVM 转述标真机 ✅（代码验证 ≠ 真机通过）

**影响**：验收是工单流转最后一道质量闸，误标 = 闸门失效 → 不合格工单可能合 main。这是**信任根基问题**（项目最核心关切），必须内化防复发。

**为什么不能只靠 md**：手册写了「不信自报信实物」，但仍反复误标——**文档会遗忘，机制才持久**。

---

## 二、机制：五步闭环

```
验收员误标 → 登记表.xlsx → 根因 → 手册纪律 → 专项工单追踪 → 设计师抽查 → 根因收敛 = 内化成功
```

| 步 | 内容 | 落点 |
|---|---|---|
| 1 记录 | 每次误标（含用户指出/自查发现）登记台账 | `验收错误登记表.xlsx` |
| 2 根因 | 每条误标分析根因类型（判据混淆/证据归属/环境误判/偷懒） | 台账「根因」列 |
| 3 纪律 | 根因沉淀为手册铁律（新增判据禁止项） | `验收员\文档\验收员操作手册.md` |
| 4 追踪 | 专项工单持续追踪，直到根因类型收敛 | 「验收错误学习」专项工单（工单表） |
| 5 抽查 | 设计师定期抽查 ✅ 证据，发现误标提醒登记 | 设计师职责 |

---

## 三、判据铁律（强制）

### ✅ 的唯一标准 = 用户视角的最终结果

> 标 ✅ 前自问：**「用户真的获得了这个功能吗？截图/journal/产物能证明吗？」**——写不出达成描述就不标 ✅。

### 5 条禁止项（任一命中 → 不标 ✅，标 ⚠️未达成/❌）

1. **禁止**：机制被触发就算过（fallback 执行 ≠ 搜到结果）
2. **禁止**：AI 口头列计划/口头说要做就算过（≠ 执行）
3. **禁止**：AI 没回话/回复空就算过（任务未完成 ≠ 通过）
4. **禁止**：代码+JVM 转述当真机 ✅（代码验证 ≠ 真机通过）
5. **禁止**：拿未核对归属的证据（进程/端口/数据属于谁要先查清）

### 附达成描述（强制）

每条 ✅ 备注必须附一句「用户视角的达成描述」，例如：
- ✅「买牛奶 → AI 回应并记录（journal 有笔记写入 + 会议.md 落盘）」
- ❌「AI 超时无回应——端到端未达成」

## 四、可追踪实体

| 实体 | 位置 | 用途 |
|---|---|---|
| **验收错误登记表.xlsx** | `工单流转中心\`（台账 + 根因统计） | 每条误标一行：日期/工单/现象/根因类型/整改 |
| **「验收错误学习」专项工单** | `工单表.xlsx` | 持续追踪，根因收敛后销项 |
| **手册铁律** | `验收员\文档\验收员操作手册.md` | 5 条禁止项 + 达成描述要求 |

## 五、各角色职责

| 角色 | 职责 |
|---|---|
| **验收员** | 每标 ✅ 先自问「用户获得了吗」；误标（含被指出）当天登记台账；按新判据重验 |
| **设计师** | 审阅台账、根因类型收敛分析；定期抽查 ✅ 证据（红线 15 强化）；对反复根因转工单 |
| **全员** | 发现误标 → 提醒验收员登记（不默认忽略） |
