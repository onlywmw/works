# 合 main 抽查标准（设计师 · 防 AI 幻觉，2026-08-17 定）

> **设计师合 main 前抽查验收证据，必须有明确标准，防止设计师自身 AI 幻觉**——验收员误标的教训同样适用于设计师：看到信号就当达成、拿不相关证据、想当然认为「应该没问题」。**设计师不能是第二个误标源。**

## 一、抽查核心（防幻觉第一原则）

**合 main 前，对每个待合工单的验收证据「抽查」，不只信工单表 ✅。** 判定唯一标准 = 证据可见「**用户视角的最终结果**」。

## 二、判定标准（✅ 可合）

| 证据类型 | 必须看到「结果达成」 |
|---|---|
| 截图 | 界面显示**最终效果**（文件生成/状态 DONE/拦截反馈/卡片渲染），非「界面变了」 |
| journal | 真实 `tool_call → ok=true → 结果 payload` 链（append-only） |
| 命令输出 | 可重跑，输出含**真实结果**（结果集/产物/状态码） |
| 产物 | 文件存在 + md5 匹配 / 状态机到终态 |

## 三、禁止（一票否决 · 防幻觉清单）

| 禁止 | 说明 |
|---|---|
| 只信工单表 ✅ | 必须打开证据核实，不能假设 |
| 只看文件名/OCR 首行 | 打开截图看**内容逻辑** |
| 机制触发=达成 | fallback 执行 ≠ 搜索成功；AI 口头计划 ≠ 已执行 |
| 拿不相关证据 | 核对证据归属（进程/数据/截图来自哪个工单） |
| 代码+JVM 转述当真机 ✅ | 代码验证 ≠ 真机端到端 |
| 「应该没问题」想当然 | 无把握/证据不足 → 标待核实，不合 |

## 四、抽查流程（合批前必做）

1. **抽关键单**：优先抽端到端/后端/安全类（易幻觉），前端 UI 类抽界面结果
2. **打开证据**：按 `工单↔真机证据_双向映射` 找到证据，打开截图/journal/命令
3. **对「用户视角最终结果」**：截图/journal 是否显示结果达成（非过程）
4. **核对证据归属**：证据确实属于该工单（非不相干进程/数据）
5. **判三类**：✅可合（证据可见结果达成）/ ⚠️端到端未验（标待核验，不合）/ ❌失败（回炉）
6. **记录抽查结论**：合批前在工单库/抽查记录落抽查结果（每单标注核实依据）

## 五、防幻觉自问（每单合前问）

- 「用户真的获得了这个工单承诺的功能吗？」
- 「截图/journal 里**能直接看到**那个结果吗（不是我推断的）？」
- 「这个证据确实属于这个工单吗？」
- 「我标可合的依据是什么（一条可查证的）？」

**写不出可查证依据 → 不标可合，标待核实。**

## 六、与红线 15 / 错误内化联动
- 红线 15：设计师合批前核实证据真实性——本标准是落地细则
- 验收错误登记表：设计师抽查发现的新问题 → 登记（设计师侧同样适用防幻觉）

## 七、生效
**即时生效**。设计师合 main 前按本标准抽查；不符合标准的工单不合（标待核实/回炉）。
