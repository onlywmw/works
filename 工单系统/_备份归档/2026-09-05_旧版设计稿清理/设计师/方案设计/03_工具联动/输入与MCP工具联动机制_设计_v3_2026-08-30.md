## 〇、验收原则（大神定,一句话）

> **AI 是否在正确的时候、调用正确的工具、以正确参数、在正确的安全等级下执行。**

---

## 一、最终工程图（大神版,采纳）

```
用户输入 → Context Assembly(系统提示/会话历史/记忆/工具Schema/胶囊提示)
   → Tool Candidate / RAG(threshold=配置项)
   → Tool Decision( NO_CALL | CALL | MULTI_CALL )
   → Argument Generation → Argument Validation(缺参/歧义/非法/超权限→阻断)
   → Safety Policy(Tool Risk → Execution Policy → 需确认/无需确认)
       需确认 → User Confirm
   → Handler → Tool Result
   → Conversation Context + Memory Candidate
   → Metrics
```

---

## 二、P0-1 执行安全门 = 风险分级（不只 readOnlyHint/destructiveHint）

| 风险级 | 示例 | 默认行为 |
|---|---|---|
| **L0 查询** | 查天气/车次 | 直接执行 |
| L1 低副作用 | 写个人备忘 | 可直接/轻确认 |
| L2 外部状态修改 | 发消息/创建订单 | 执行前确认 |
| L3 高风险不可逆 | 付款/取消订单/删数据 | 强确认 |

```
MCP annotations(readOnlyHint/destructiveHint) → 风险分类器 → Execution Policy → 需确认?
```
- **不依赖 annotations 填得标准**(第三方 MCP 可能不填/填错)——**自有风险策略兜底**;L2/L3 执行前确认门。

---

## 三、P0-2 工具选择 与 参数生成 分开（加 Argument Validation）

```
Tool Selection(选哪个)  →  Argument Generation(填什么)  →  Argument Validation
```
**工具选对 ≠ 参数填对**;`Argument Validation` 四类**直接阻断**：
- 缺参数 / 参数歧义(如"老板"无法唯一解析联系人)/ 参数非法 / 参数超权限。

---

## 四、P0-3 NO_CALL 正式化（合法决策,非失败）

```
Tool Decision = CALL | MULTI_CALL | NO_CALL
```
- **NO_CALL = 合法决策**(用户聊铁路历史 → 不调工具);评测集据此建(查天气→CALL/查天气+备忘→MULTI_CALL/讲历史→NO_CALL);**防统计把"正确不调用"当"没找到工具"**。

---

## 五、P0-4 多工具编排模型

```
Parallel      A ‖ B → result          (独立并发)
Sequential    A → B → C               (A结果→B)
Conditional   A → condition → B / C   (按A结果分叉,如"明天下雨→带伞提醒")
```
- 支持这三类,为未来 Agent 编排留好层(不推翻);现代 LLM 多 tool_calls 按此编排。

---

## 六、胶囊 = 工具偏好提示（v3 用词统一,防 mis-implement 成 lock）

- **胶囊 ≠ Tool Lock;胶囊 = Tool Preference Hint**(大神定词);
- 点名 → **轮次级偏好提示** + 工具提权置顶;LLM 仍可调第二工具(组合);绑定生命周期=**轮次级**(拍板);预设回填文本=最强自然引导;"是否硬锁"由度量数据决策。

---

## 七、第三方 MCP = Overlay(不覆盖原文)

- 永不覆盖作者 desc;登记层存**增强元数据**(stableId key:中文显示名/触发示例/反例),喂 LLM 原文+增强拼接;server 更新自动兼容;与胶囊 pin=stableId 同模式;

---

## 八、记忆回流 = Memory Candidate(非直接工具结果→记忆)

```
Tool Result → Conversation Context → Memory Candidate → Memory Policy → Memory Draft → 用户/系统确认 → Memory Store
```
- 工具结果**只是记忆候选来源,不是记忆本身**;("订明天去上海票"≠ 永久偏好上海)→ 防记忆污染;接 UPG-05 记忆草稿机制。

---

## 九、度量 = 六个指标（v3 扩）+ Tool RAG threshold=配置项

- **指标**:Tool Selection Accuracy / Argument Accuracy / No-Call Precision / No-Call Recall / Multi-Tool Accuracy / **Safety Gate Accuracy**;
- **Tool RAG threshold = 配置项**(不同模型 context/tool schema/server 数影响,不拍死数字);当前全量,超阈值 → candidate retrieval → top-K。

## 十一、验收测点
- 评测集回归:六指标(选工具/参数/No-Call/多工具/安全门);desc 改动后不降;

## 补 · Tool Call Trace / 决策可观测性契约（大神终审补 · 唯一补丁）

每次工具调用记录(JSON,落 trace / 可观测库):
```
traceId / conversationId / turnId
input(用户输入摘要)
candidateTools(候选工具清单)
selectedDecision( CALL / MULTI_CALL / NO_CALL )
selectedTool / arguments(生成参数)
validationResult( 缺参 / 歧义 / 非法 / 超权限 )
riskLevel( L0-L3 ) / confirmationResult(需确认→用户确认结果)
executionResult(执行结果)
memoryCandidate(记忆候选)
decisionReason(结构化决策原因,非 CoT)
```
- **`decisionReason` 示例**:`"用户明确要求查询北京到上海的高铁票"` / `"当前输入为铁路历史知识问答,无需实时工具"`;
- **用途**:Debug / Dev Console / 自动 Bug 定位——回答"为什么这次 AI 调了这个工具",可追溯 输入→候选→决策→参数→风险→确认→执行;
- **约束**:只存**结构化决策原因**,不保存模型 CoT(避免隐私/成本)。
