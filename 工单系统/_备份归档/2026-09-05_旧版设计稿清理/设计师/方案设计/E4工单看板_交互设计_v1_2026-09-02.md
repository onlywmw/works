# E4 工单看板 · 交互设计 v1（HTML 版）

> **设计师** @2026-09-02 ｜ **定位**：SYS-02 阶段四 E4 全景看板的**交互升级**（md 投影 → 静态 HTML 可交互视图）
> **送审**：大神 ｜ **对象**：工单系统（Desktop\MOV\工单系统）——多 Agent 协作工单流转的可视化仪表盘

---

## 一、背景与问题（为什么做）

E4 第一版（2026-09-02 早）输出 **Markdown 表格**（57 卡 × 7 列 + 挂账 19 条），在编辑器/渲染器里：列多易横向跑屏、状态挤在文字里、无重点分层、**看一次要翻半天**。作者（用户）实测反馈三个痛点：

1. **表格花**——5-6 列信息挤在一行，状态/卡点混在文字堆里
2. **找不到重点**——得自己数「谁在施工/谁卡了/谁待认领」
3. **多一步**——先跑命令→再打开文件→再翻——每看一次都要做一遍

## 二、设计目标（一句话）

> **30 秒内：知道总量、谁在流、谁卡了、下一步干什么。点一下就能看子集。**

## 三、信息架构（自上而下）

```
① 标题 + 数据源声明（日期/sha 绑定——E1 真相来源）
② 摘要卡 ×5（总卡数 / 在流 / ✅终态 / ⚠️超期 / 挂账）——可点击
③ ⚡ 当前重点块（前 5 在流 + 告警计数）
④ 主看板表（# 单 名称 状态 卡点/下一步 线）——状态徽章+行筛选
⑤ 挂账待审池（独立表——不参与流水线判定）
⑥ 完整性对账（卡数/无法解析/表缺行）
```

**设计取舍**：旧的「交付/验收/合 main 三态子列」**折叠进状态徽章**（✅终态=三子列全绿；🟡待合=验收过未合）——把低频细节让位给高频问题（**他现在的状态+卡点**）。

## 四、视觉设计

| 元素 | 规则 |
|---|---|
| 状态徽章 | 色底圆角 pill：✅终态 绿 · 🔨施工 橙 · ❌回炉 红 · 🟡待合 棕黄 · 📌已派 蓝 · ⏳排队 灰 |
| 名称 | 截断 20 字 + 悬停 title 全名（行高稳定） |
| 卡片 | 大数字（24px）+ 小标签；悬停浮起；当前筛选=蓝框 |
| 行 | 斑马纹 + 悬停高亮（f8fafc） |
| 布局 | max-width 1100 居中；卡片 grid auto-fit（窄屏自动换行） |

## 五、交互设计（纯静态 JS——无后端）

| 交互 | 实现 |
|---|---|
| **卡片点击=筛选主表** | 总卡数=全部 / 在流=非终态 / 终态=merged / 超期=overdue 标记行；`tr data-stage + data-over` 驱动 display；当前筛选卡=蓝框标识 |
| 状态徽章 | 显示层（下一步可加「点击徽章同筛选」） |
| 零依赖 | 内联 `<script>`（~20 行）；单击生成文件——**无框架/无 CDN/无网络** |

**当前版本边界**：行点击详情 / 挂账池滚动定位 / 移动端适配未做（见评审点）。

## 六、技术实现与数据流

```text
工单库.md（E1 唯一真相·卡状态区+优先级+卡点字段[规划]）
   ↓ readLib(parse) 只读投影（sha 跑前=跑后 实证）
   ↓ analyzeCard → projections（stage/overdue/keypoint 派生）
   ↓ renderBoard(md 存档) + renderHtml(HTML 视图)  —— 一次生成双出
   ↓ orders-overview.md / .html（验证产物）
   ↓ 看板.bat（chcp 65001 + cd %~dp0 + node + start）——双击=刷新+打开
```

- **写约束**：E4 只算允许的派生告警（S2-10~20），不写库/表——html 仍未破坏此边界
- **中文路径坑（已修）**：cmd 读 bat 默认 GBK → UTF-8 中文路径乱码 → `chcp 65001` + CRLF + `%~dp0` 变量（已实跑验证）

## 七、评审点（请大神定夺）

1. **筛选维度**：现在按「状态大类」筛——是否需加「优先级/线（A/B/C）/日期」筛选条？
2. **卡点字段化**（规划）：卡点列目前=自动从状态生成（施工中/打回）；真正「等谁/等什么」需每卡 `**卡点**：xxx` 字段（agent 更新）——**方案是否可行/谁来维护**
3. **行点击详情**：要不要点行=看卡全文（侧栏抽屉/新页）？——与工单库 md 的关系
4. **挂账池**：20 条挂账现在平铺——建议折叠/默认只显示前 5 + 「展开全部」？
5. **移动端**：手机上（作者平板）看板的适配优先级——（作者日常在电脑看）
6. **与 E4 STD 的关系**：本升级=展示层（S2-10~20 判据不变）——是否需补 S2-21（交互/可读性判据：如「30 秒可见在流/卡点」）？
