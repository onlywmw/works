## 二、AI 抽查用法

```bash
python 审验.py --ticket <工单号> --json    # 抽查某工单证据链 + integrity_flags/integrity_review（机器 flag + 人工裁决）
python 审验.py --ticket <工单号>           # 文本输出
python 审验.py --list                      # 列出有证据的工单
python 审验.py --dir <证据目录> [--json]   # 对指定证据目录直接审验（边界用例验证）
python 审验.py --manifest <manifest.json>  # 独立验证 evidence_manifest（P0-2 绑定 hash + 层B逐条）
```

输出协议（P0-3 已落地）：`integrity_flags` = 层A 行为欺骗四分类（original_rerun / benchmark_overfit / semantic_vagueness / time_inconsistency），机器只出 flag + signal，**不自动判不通过**；`evidence_integrity` = 层B 证据对象真实性六项（file_exists / hash_matches / timestamp_plausible / producer_known / source_path_valid / chain_intact）；`integrity_review` = 人工最终裁决（status: confirmed/cleared/unresolved，reviewer/reviewed_at 必填）。工具已落地：`审验员\审验.py`（2026-09-01 SYS-01 P0-3）。

## 三、抽查内容（AI 查什么）

### 证据链（journal 工具调用链 + 截图 + 命令）
- journal：工具调用链（时间/动作/结果）——是否真实 tool_call
- 截图：是否有关键界面证据（时间戳）
- 命令：是否有结果/产物输出

### 相关性 / 合理性（输出 problems）
| 检查 | 异常 |
|---|---|
| 证据链断裂 | journal 无工具调用（AI 口头说没真调） |
| 缺证据 | 无截图 / 无命令 |
| 时间不合理 | 截图早于工具调用（疑似伪造） |
| 失败标记 | 命令含 失败/不存在/FAILED |

### 结论（P0-3：机器只出 flag，人判结论）
- 机器输出 `integrity_flags`（层A 四分类 flag + signal）+ `evidence_integrity`（层B 六项），**不自动判通过/不通过**
- 人工填 `integrity_review`：confirmed（证据链可信） / cleared（flag 澄清非问题） / unresolved（保留疑点，3 工作日超时→转挂账待设计师定夺）

## 四、注意
- 部分工单 journal 可能为 0——需结合命令输出判断（AI 不能只看 journal，要查命令/结果文件）
- 证据目录有多个时，审验员应合并查所有
- 抽查结论 → 参考 `工单表.xlsx` 该工单验收状态对照
