# 证据链规范（2026-08-18 定 · 所有工单必须建证据链 + 经审验）

> **红线 17**：每个工单（工具）都要建立完整证据链 + 过审验员审验，未审验不视为可信、不得合 main。

## 一、证据链定义（每个工单的证据链应包含什么）

证据链 = 能「可见目标达成」的完整证据序列，缺一环即断裂：

| 环节 | 内容 | 缺失即 |
|---|---|---|
| **① journal（运行事件/操作日志）工具调用链** | 真实 `tool_call → tool_result(ok) → 结果`（append-only 不可伪造） | AI 口头说没真调 |
| **② 关键截图（含时间戳）** | 用户视角的最终结果（界面状态/产物/拦截反馈），文件名带时间 | 无界面证据 |
| **③ 命令/产物输出** | 可重跑的命令/脚本输出、产物文件（md5）、状态机到终态 | 结果不可验证 |
| **④ 时间一致性** | journal 调用时间 ↔ 截图时间 ↔ 命令时间 对得上（截图早于调用=伪造） | 疑似造假 |

## 二、各类工单的证据链（按类别）

| 类别 | 证据链核心 |
|---|---|
| **前端 UI** | 截图（界面最终状态含时间戳）+ journal 工具调用 |
| **后端服务** | 命令/curl 输出（结果集/状态/DONE）+ journal |
| **纯逻辑工具** | executeTool 直调输出 + journal 工具调用 |
| **安全加固** | 注入/拦截 payload 实证 + 截图反馈 + journal |
| **评估/报告** | 报告落档（无代码，标记「评估闭环」） |

## 三、审验要求（红线 17）

1. **所有工单必须过审验**：审验员用 `审验.py` 逐一核验证据链
2. **审验通过** → 标 ✅（证据链完整、无异常）
3. **审验不过** → 打回补证（证据链断裂/缺证据/疑似造假）或降级 ⚠️
4. **未审验** → 不视为可信，不得标「✅验收通过」/不得合 main

## 四、审验状态追踪

`审验员\工单审验状态.md`：记录每个工单的审验状态（✅通过 / ⚠️待补证 / ❌有问题 / ⏳未审验），全工单覆盖。

## 五、工具

- `审验员\审验.py`：逐一审验单工单证据链（--ticket <工单号> / --json）
- `审验员\审验.py --list`：列出有证据的工单
- `审验员\工单证据链映射.md`：工单 → 证据链位置
- `审验员\工单审验状态.md`：全工单审验状态追踪（本规范配套）
