## 一、验收标准

### 1.1 分级（先定级再动手，拿不准往高定）

| 级 | 范围 | 验收深度 |
|---|---|---|
| **L1 低** | docs/注释/机械重命名/纯测试 | git show 扫读 + 构建绿 |
| **L2 中** | 业务逻辑/JS 行为/规则表/文案 | 单测计数核对 + 针对性真机（一项） |
| **L3 高** | 状态机/支付/桥签名/权限/持久化/网络协议 | diff 精读 + 变异测试 + 真机多场景 + logcat |

### 1.2 通过 / 打回标准

| 结论 | 条件 |
|---|---|
| ✅ **通过** | 定级验收全过 + **无 P0/P1** + 证据链完整（一断言一证据） |
| ✅ **带缺陷通过** | 仅 P2/P3，缺陷清单登记（回工单修） |
| ❌ **打回** | 任一 P0/P1，或 L3 失败，或证据链断裂 |
| ⚠️ **阻塞** | 环境缺条件（写明缺什么 + 就绪条件），不混入通过结论 |

### 1.3 缺陷分级

| 级 | 定义 | 处理 |
|---|---|---|
| **P0 致命** | 崩溃/数据丢失/安全绕过/任务无法完成 | 打回（必修） |
| **P1 严重** | 关键功能不满足/关键路径错误/断言数字错 | 打回（必修） |
| **P2 一般** | 体验缺陷/非关键路径功能瑕疵 | 带缺陷通过，登记 |
| **P3 轻微** | 文案/样式/非关键 | 记录，不阻塞 |

### 1.4 五招（每条照做）

1. **不信自报信实物**——程序员表格只是线索，每条标准必须有亲手产出的实物
2. **变异测试杀 mutant**——改坏核心逻辑 → 目标测试必须红（带真实计数）→ 还原
3. **假覆盖四形态对照**——mock 喂答案 / 虚构数据路径 / 字面量比较 / 测试重写逻辑
4. **真机证据链**——L2 起必做，截图里看得到断言那件事
5. **打回可施工**——现象→根因→修法→复验，不写「体验不好」这种没法做的

### 1.5 能力护栏（共享面变更 · coverage_status 三档，2026-09-01 · SYS-01 P1-1）

改动涉及**共享面**（MainActivity 注册表 / 工具面 / 协议·接口定义 / 全局数据结构任一）的工单，验收时**先查交付报告「能力护栏」固定节**（红线 24）。三档判定：

| coverage_status | 含义 | 验收判定 |
|---|---|---|
| **FULL** | 全维度覆盖 | ✅ 直接过能力护栏 |
| **PARTIAL** | 部分维度未覆盖 | 必须含设计师显式裁决记录 `coverage_decision`（uncovered / risk / merge_decision / reason / decided_by=设计师 / decided_at 六字段齐）；**缺裁决记录 → 打回**（程序员/验收员不得单独放行） |
| **NONE** | 无覆盖（共享面变更） | 🔴 **禁止合 main**——不是「建议谨慎」，是明确不可合 |

**判定铁律**：
- 共享面变更 + `coverage_status=NONE` → 打回（禁合 main），不因全量回归 0 新增失败而放行
- 共享面变更 + `PARTIAL` 无 `coverage_decision`（或 `decided_by ≠ 设计师` / 缺字段）→ 打回，退回补裁决
- 共享面变更 + `PARTIAL` + 完整裁决记录（含四关键字段 decision/reason/decided_by/decided_at）→ 通过
- **全量回归 0 新增失败 ≠ 能力没倒退**——未测维度可能已坏；NONE 强制禁合 / PARTIAL 显式裁决是硬门槛
- 与红线 11 衔接：出待合 main 清单前，除核对验收员列（✅ 或 —）外，还要核对能力护栏——NONE 单不进待合批，PARTIAL 单须有裁决记录才可进

> **🔴 真实 UI 操作红线（2026-08-16）**：真机验收的用户操作（点击输入框 / 输入文字 / 点发送 / 返回等）**必须走真实 UI 路径**——用 `ui_ops.py` 的 tap/text/send 模拟真实用户。**禁止命令行直达**（CDP eval 直调 `B` 桥 / `sendMsg` / 底层函数触发操作）——那验证的是函数调用，不是真实用户体验。CDP 只用于**观测**（截图后查 DOM/状态/断言），不用于**驱动操作**。

### 2.2 连接与前置（每次必做）

App 每次重启，WebView devtools remote 会变，**必须重新 forward**：

```bash
ADB="/c/Users/Administrator/platform-tools/platform-tools/adb.exe"
REMOTE=$("$ADB" -s emulator-5556 shell "cat /proc/net/unix | grep webview_devtools | awk '{print \$NF}' | tail -1" | tr -d '\r' | sed 's/@//')
"$ADB" -s emulator-5556 forward tcp:9222 localabstract:$REMOTE
curl -s http://127.0.0.1:9222/json   # 应能看到 hermes-shell 页面
```

截图前唤醒（防黑屏）：`"$ADB" -s emulator-5556 shell input keyevent KEYCODE_WAKEUP`

### 2.3 验收流程（固定四步）

1. **装包先行**：`install -r app-debug.apk` → `dumpsys package com.mov.android | grep lastUpdateTime` 核对（防旧包白忙）
2. **唤醒 + 启动**：`KEYCODE_WAKEUP` → `monkey -p com.mov.android -c android.intent.category.LAUNCHER 1`
3. **测**：按验收项执行，逐步采证据
4. **收尾**：logcat 关键段 + 证据落档

### 2.4 证据链方法（核心）

- **一断言一证据**：每条判据 ↔ 截图 + OCR 文本成对；无图不验收
- **采集命令**：`bash _tools/evidence_shot.sh A1-cloudrelay A1-01-set-relay`
  - 产出：`2026-08-16/A1-cloudrelay/A1-01-set-relay.png` + `.ocr.txt`
- **批量 OCR（推荐，省时）**：`python _tools/ocr_batch.py <图1> <图2> ...`——**一次进程、OCR 引擎只初始化一次**，处理多图（每张落 `.ocr.txt`）。证据全采完一次批量识别，比逐张（每张新起 PowerShell 3-5s）快 3-4 倍（实测 3 张 ~3.9s）
- **命名**：`<场景>-<序号>-<动作>.png`（动作用英文连字符：set-relay / card-render / lan-delegate）
- **OCR 精度说明**：Windows OCR 中文有字间空格/个别偏差，**以截图为准**；英文/数字/结构可靠。OCR 文本是辅助判读 + 证据索引，不替代截图
- **总览表**：`python _tools/make_overview.py 2026-08-16` → xlsx（证据清单 + OCR 全文 sheet）+ md
- **总报告**：复制模板填写，逐项（步骤/证据/OCR 摘录/结论）

### 2.5 各类验收方法

| 验收类型 | 方法 | 工具 |
|---|---|---|
| UI/文案/渲染 | 截图 + OCR 文本对照断言（卡片标题/文案/状态） | evidence_shot.sh + ocr_shot.py |
| 状态/桥/前端 | CDP 执行 JS 断言（`B.query({q:'...'})` / DOM 查询） | cdp-eval.js |
| 网络/委派/进度 | logcat（`-s MOV:D AgentLoop BridgeKernel`）+ journal 事件 + 结果卡截图 | adb logcat + CDP |
| 安全边界 | 探针（外站/无 token/伪装域）+ 请求日志零泄漏断言 | 本地记录头服务 + CDP |
| 变异测试 | 生产代码改坏核心行 → 目标测试必红（真实计数）→ `git checkout` 还原 | gradlew testDebugUnitTest |
| 数字正确性 | 已知输入手算答案 → 结果逐项对照（错一项=打回） | 手动 |

## 三、常见坑（环境药方）

| 事故 | 药方 |
|---|---|
| CDP socket hang up | 进程被杀：重新 pidof + forward；targets 导航杀旧 ws，重新发现 target |
| 截图全黑 | 设备息屏：`input keyevent KEYCODE_WAKEUP` |
| logcat grep 自匹配 | 命令本身进 logcat：`grep -v ShellService` |
| 「无变化」报告 | 旧包还活着：固定四步的 force-stop 没做 |
| Windows 文件锁（output.bin） | `gradle --stop` → 删 test-results；顽固则确认无 AS 后 `taskkill //F //IM java.exe` |
| 中文路径传参乱码 | PowerShell/WinRT 用反斜杠绝对路径；Git Bash → 中文路径走 Python 中转 |
| **CDP page not found: hermes-shell.html** | **多 WebView 陷阱（2026-08-17）**：App 内 HermesActivity 页 + 内嵌 DeepSeek Harness 页 = 两个 `webview_devtools_remote_*`，`tail -1` 会选错（连到 Harness）→ `input_chain.py` 已改**遍历探测 MOV 页面**（见 §五） |
| **CDP 连到 Chrome/Harness（localhost 走 IPv6）** | **端口劫持（2026-08-17）**：Windows `localhost` 解析 `==1`，Chrome 可能占用 `==1:9222` → node/python 连到错误进程（page not found 或返回非 MOV 页）。**工具统一用 `127.0.0.1`**（`input_chain.py`/`cdp-eval.js` 已改） |
| **重启后 CDP 探测失败** | **webview 未就绪（2026-08-17）**：force-stop 重启后立即 forward 探测可能失败 → sleep 3 重跑 `input_chain.py` |
| **App 重启后仍有旧 remote 残留** | 多 WebView 进程并存，`adb forward` 的 9222 需先 `--remove` 再 forward 到新 remote |

## 五、真机工具激活实战经验（2026-08-17 沉淀）

> 适用：工具面逐工具激活验证（按项目工具面）（TASKS_TOOL_VERIFY_ALL）。**务实 + 求真是全部要义**——只认实物，区分三类，不误归因。

### 5.1 判定「工具激活」的硬标准（不信自报信实物）

- **唯一可信 = journal/渲染出现「执行工具卡片 + 完成 + 输出」= `tool_call` 实锤**。
- **AI 聊天回复「已成功××」一律不算**——无 tool_call 即幻读。铁证：`model.list` 同一工具，batch14 走 plan 真实返回 deepseek 列表，复测却编造 GPT-4o/Claude 列表。
- **工具被调用 ≠ 工具可用**：被调但实现是占位（返回提示文本）= C 类未接线，须查代码确认实现真接线再标可用。

### 5.2 三类工具分类（务实区分，别一刀切「没对接」）

| 类 | 含义 | 判定 | 示例 |
|---|---|---|---|
| **A 真对接** | 代码真调 Android API | 走 plan 真实执行 + 有输出 | wifi.status（WifiManager）/ settings.get（Settings API）/ app.info / timer |
| **B AI 幻读** | 注册了但 AI 不调用，chat_reply 声称 | AI 回复「已××」但无 tool_call，**非 API 问题** | model.add / notification.post / settings.get（AI 不调） |
| **C 占位/半成品** | 实现返回提示/建议/结果拿不到 | 代码确认 `return new Result(true,"请用…")` | file.info / process.list / qr.generate / speech.recognize |

- B 类是工具激活主体障碍（**AI 路由问题**，ai-fabricate P0），修完才能高效激活；A 类继续真实激活；C 类登记挂账转工单。

### 5.3 触发 AI 走 plan 的方法（组合任务优于单工具）

- **单工具轻量类 AI 易幻读**（AI 直接聊天声称，输出 JSON 参数不执行）。
- **组合 3-4 个「同类 + 有真实副作用」系统/设备工具 → AI 走 plan 概率高**（批18 实证：timer.set/timer.list 组合任务真实调用；单测 settings.get/model.add 均幻读）。
- 任务文本点名工具名 + 「请执行以下真实操作」。
- **批失败（AI 卡死/轮次超限/某工具反复）→ 重启新房间重试，不硬耗**（wifi.status 曾反复调用 4 次轮次超限）。
- 批内某工具卡住不阻塞判断——其余工具调用成功即各记各的状态。

### 5.4 求真：代码审计佐证真机观察

- 真机「挂起/幻读」先用代码确认实现**是否真接线**再归因——避免把 AI 不调用误报成「API 没对接」。
- **UI 缺陷用窗口级诊断**：`dumpsys window windows | grep -B2 -A8 <Activity>` 看 `mAttrs`/`frame`。实证：ConnectWeb 半屏遮挡 = `frame=[25,1159][2007,3048]` + `TRANSPARENT` + `adjust=resize`（窗口只占下半 62%，透出下层）。
- **用户质疑先复现确证再回答**：干净复现（force-stop → 启动 → 分时截屏 + dumpsys），证据落盘，再下结论。
- 环境疑难（CDP 连错进程/端口劫持）用 `netstat`/`adb forward --list`/`tasklist` 定位进程归属。

### 5.5 环境陷阱（已修工具，新会话免重踩）

1. **多 WebView**：App 内 MOV 页 + 内嵌 Harness 页两个 remote → `input_chain.py` 已改为**遍历探测 hermes-shell.html**（tail -1 会选错）。
2. **localhost IPv6 劫持**：Windows `localhost`→`==1`，Chrome 可能占用 `==1:9222` → 工具统一 `127.0.0.1`（`input_chain.py` + `cdp-eval.js` 已改）。
3. **重启后 webview 未就绪**：force-stop 重启后立即探测失败 → sleep 3 重跑。
4. **App 偶发 CDP 连到 Harness 页**：重启 App 解决。

## 三、真机证据规范（2026-08-17 倒查补强 · 强制）

> 背景：2026-08-17 倒查发现 8 项误标（「✅」实为端到端未验/失败）——根源是没核对证据内容逻辑。**本规范强制，违者误标即废。**

### 3.1 ✅「通过」必须满足（缺一不可）
1. **可查证**：截图/journal/命令输出**可复跑**，且
2. **可见目标达成**：截图里能直接看到「断言那件事的结果」——如工具真实返回数据、产物文件存在、状态机到达终态（DONE），**不是**「AI 口头说要做」/「机制被触发」
3. **证据核对内容逻辑**：打开截图看**内容**（OCR/像素/状态），**禁止只看文件名或 OCR 首行**就标 ✅

### 3.2 禁止项（误标根源，一票否决）
| 禁止 | 示例（本次真实教训） |
|---|---|
| 机制触发 ≠ 功能达成 | fallback 被触发 ≠ 搜索拿到结果（r45 误标） |
| 口头计划 ≠ 已执行 | AI 说「请批准后我将执行」≠ devicecmd 已执行（r47/r50） |
| 代码+JVM ≠ 真机 ✅ | 变异亲杀过 ≠ 真机端到端过（r3 XSS 标成真机） |
| 无端到端截图 ≠ ✅ | 只有代码/单测无真机端到端 → 标 ⚠️ 或「代码层」 |
| 服务面未施工 ≠ ✅ | dual 服务面没起来 → 端到端未验（r42/67） |

### 3.3 状态标注规范
| 情况 | 标 |
|---|---|
| 截图可见目标达成 + 可复跑 | ✅ |
| 端到端未验（AI 不走 plan/服务面未施工） | ⚠️ 端到端未验 |
| 仅代码/JVM 验证 | 「代码层」 |
| 端到端失败（如搜索全源不可达） | ❌ |
| 环境缺条件 | ⚠️ 阻塞（写明就绪条件） |

### 3.4 与设计师合批联动（红线 15）
- 标 ✅ 须附可查证截图/journal 落盘；设计师合批前抽查证据真实性
- 端到端未验/失败单，设计师不得仅凭 ✅ 合入——先登记补验挂账

## 四、无 UI / 纯后端工单如何验证（2026-08-17 补 · 方法论）

> 很多工单无可视 UI（搜索/服务面/进程清理/记忆注入）——**截图不是唯一证据**。核心标准不变：**「可见目标达成」+ 可重跑**，「可见」≠「截图」，可以是命令输出/journal/产物/状态。

### 4.1 四种证据形态（后端工单优先用）
| 形态 | 证明什么 | 示例 |
|---|---|---|
| **命令可重跑实证** | 功能真跑出结果 | curl websearch → **返回结果集**（非「fallback 触发但无结果」）；脚本输出 PASS + 数字 |
| **journal 工具调用链** | 真实 tool_call + 结果 | 工具调用 event 链：`tool_call → ok=true → 结果 payload`（append-only 不可伪造） |
| **产物/状态检查** | 后端产出真实存在 | 生成的文件（md5 校验）、服务 LISTEN、进程 pidof 无残留、返回码 |
| **状态机到达** | 流程到终态 | 委派 `RUNNING→DONE`、订单恢复后 `create 409`、搜索返回 `results:[...]` |

### 4.2 关键：区分「目标达成」vs「机制触发」
| 场景 | ❌ 机制触发（不够） | ✅ 目标达成（够） |
|---|---|---|
| websearch | fallback 源被调用但「所有源不可达/拦截」 | 命令输出含**真实结果条目** |
| dual 委派 | 服务面类存在 / LISTEN | 委派 `DONE` + **结果 payload 回传** |
| rootshell | 超时逻辑跑了 | 命令输出 `pidof 无残留` |
| devicecmd | AI 说「将执行」 | 命令输出显示**真实执行 + 返回结果** |
| approval | AI 说「请批准」 | journal 有 `alwaysPreview` 闸事件 + 用户确认后放行 |
| filecopy | file.copy 代码存在 | 目标文件生成 + md5 匹配 + 防逃逸拦截（越界路径被拒） |
| XSS | 源码有 esc | 真实页面注入 payload **不执行**（无弹窗/无异常）+ 抢单正常 |

### 4.3 后端工单验证步骤
1. **构造真实触发**：用命令/journal 直调工具（executeTool 通道可辅助）触发真实执行
2. **采证据**：命令输出（重跑可复现）/ journal 工具链 / 产物 md5 / 状态
3. **判断目标达成**：输出/产物显示「结果到达」（结果集/文件/状态/DONE），非「过程发生」
4. **落盘**：命令脚本 + 输出 + journal 段存 `2026-08-17/<工单>/`

### 4.4 与截图工单等价标准
- 后端工单证据 = **命令输出/journal/产物/状态**，与截图**等价**（都是「可见目标达成」）
- 复核标准一致：**可重跑 + 内容显示结果达成**（红线 15 + 真机证据规范 3.x）

## 六、代码层验收（2026-08-17 合并查验员职责 · 验收员必做）

> **合并背景**：原查验员（代码层验收）与真机测验员（真机层验收）方法论重叠（同一套 L1-L3/变异亲杀/不信自报），2026-08-17 用户拍板合并为单一「验收员」。本节 = 原查验员手册 §1.2 代码层五招并入。

### 6.1 验收流程（代码层，逐条照做）

1. **先定级**：L1（纯 docs/测试）/ L2（业务/前端行为）/ L3（状态机/支付/权限/网络/持久化）——拿不准往高定
2. **不信自报信实物**：程序员的「全过」表是线索，不是证据；每条标准对应你亲手产出的实物（测试计数/diff/截图）
3. **变异亲杀**：无变异先确认真绿 → 种最小变异 → 目标测试**必红** → 还原复绿
4. **假覆盖四形态排查**：mock 喂答案 / 虚构路径 / 字面量比较 / 测试重写被测逻辑
5. **真机验证**（L2 起）：`install -r` → `am force-stop` → 启动 → 测；断言与截图一一对应
6. **证据脱敏**：证据落盘前 `git grep sk-[a-f0-9]{32}` 零命中
7. **打回要能直接修**：现象（实证）→ 根因（文件:行号）→ 修法 → 复验方式

### 6.2 代码层证据（无 UI / 纯后端工单）

- 变异亲杀计数（哪行变异→哪个测试红）+ 全量绿计数 + 契约测试结果
- **判据 = 目标达成可见**：变异亲杀「目标测试必红」= 该断言真的锚定实现；全量绿 = 无回归
- 代码层结论 ≠ 真机结论：代码层过 → 标「代码层通过，真机项见验收列」；**缺真机证据不算 ✅**

### 6.3 验收记录

- **唯一落点**：`0027-mov\docs\ACCEPTANCE_LOG.md`（main 直提交）
- 每次验收补录：日期 + 交付项 + commit + 定级 + 证据表（项/结果/亲手产出）+ 挂账
- 验收员全权：代码层 + 真机层统一结论，不再拆两道关口
