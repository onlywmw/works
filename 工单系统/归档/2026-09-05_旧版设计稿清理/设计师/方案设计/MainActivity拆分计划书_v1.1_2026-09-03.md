## 一、最终要达成什么效果

### 产品终态

MOV = **AI Native 办事终端**：说/打一句话 → AI 动手办事（审批兜底）→ 结果卡片浮现于底座 → 能力可从市场装卸。两模式（经典/极简）共享同一能力面，能力零阉割。

### 工程终态

```
MainActivity.kt = 薄装配壳（生命周期委托 + 各模块装配点；目标 < 800 行且壳内只有装配与委托）
   ├── tools/ToolsRegistry.kt        工具注册面（单一入口 registerAll + 分域子注册器）
   ├── approval/                     审批面（已拆 ✅ UPG-79）
   ├── market/MarketFeature.kt       市场面
   ├── pages/                        页面桥面
   ├── ui/chips/ + ui/capsule/       chips 气泡 + 主页胶囊
   ├── ui/markdown/                  Markwon 原生视图构建
   ├── model/ModelFeature.kt         模型管理面（:2352）
   ├── memory/                       Memory OS 面（:2671）
   ├── agent/AgentFeature.kt         AgentLoop/runChat/预审单编排装配
   └── boot/BootSequence.kt          启动序列（⑥a 审计 → ⑥b 另立语义单）
```

- 加功能=加模块；bug 隔离在面内；**diff 面=责任面**（验收一眼看穿）；
- 每模块 < 1000 行；生命周期回调委托留壳（Android 的税不是债）；
- 与呈现引擎（UPG-89）衔接：拆出的 UI 模块=引擎宿主挂点（执行串行、接口并行）。

## 三、拆分原则（红线）

1. **纯搬移零逻辑改动**——每批只做移动+必要接线；禁顺手优化（优化另单）；
2. **一批一单**——独立工单/STD/验收/合 main（小 diff 小验收面单点回滚）；
3. **零行为变化锚**：全量 0 失败 + 面专属契约锚 + 真机冒烟；
4. **拆分不碰语义**（UPG-68/76/77/79/84 冻结语义全部继承）；
5. Token/KV 申报（预期全程 0/0）；
6. MainActivity 纯 CRLF 保持；新文件行尾约定入蓝图；
7. **「MainActivity 只出不进」棘轮军规（2026-09-03 大神建议今天就立）**：自批①合入起，任何工单的新代码一律进模块，不往壳里加行——拆分是单向棘轮，不许拆一半长回来；
8. **每批 rebase 前置检查**：合 main 前核对被搬移段自基线以来的外部 diff，有外部改动先消化再搬；
9. **冷启动耗时锚**（批①/⑥）：拆前后各测 3 次取中位，波动 >10% 视为行为变化（lazy→eager 类副作用功能测试看不见）；
10. **生命周期回调归属策略先定再动手**（批④起）：onRequestPermissionsResult/onActivityResult 类——默认留壳委托，进模块需单独立项理由；
11. **每批附债务清单**：搬移中看到的坏味道（如 handler 闭包捕获 Activity 的泄漏隐患）只记录不修——后续优化单弹药库。

## 五、验收与里程碑

- 每批验收=「全量 0 失败 + 面专属契约锚 + 真机冒烟 + diff 精读只见搬移」四件套；
- **行数是代理指标，真判据=装配点一眼可读 + 每面 diff 干净**（评审点 2 吸收）；逐批报「搬移行数/壳行数」两列锚点；
- 终态：壳 < 800 行且壳内只有装配与生命周期委托、每模块 < 1000 行；
- 蓝图 `设计师\方案设计\MainActivity拆分蓝图_v1.md`（UPG-93 交付物）每批合 main 后更新。
