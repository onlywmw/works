## 一、一句话定位

**mow.kim = MOV 宇宙的总指挥台**：打开第一眼看到「五个维度全在哪里、哪件事卡着」，点一下就能钻进任一维度看工单级进度。

- 用户：站长本人（私人工作台，登录后可见）。
- 痛点对治：事情多、跨维度、进度追踪不到位 → 所以**全局一览 + 阻塞高亮**是第一优先级，美观服务于此。
- 能力市场迁往 mov-ai.cn（另线处理），mow.kim 整站释放为工作台。

## 二、信息架构（两页结构，不做多页导航迷宫）

```
mow.kim（登录门禁）
└── 首页 = 架构图即工作台（唯一主屏，一屏看完）
    ├── 点击维度节点 → 维度钻取页（/dim/<brand|marketing|app|market|infra>）
    └── 点击「本周焦点」条目 → 跳到对应钻取页并高亮该工单
```

五个维度（已和用户确认）：**品牌、营销推广、App 建设、能力市场、服务器基建**。
口径：公众号归入营销、官网归入基建、工单流转中心作为数据源接入（不单列维度）。

## 三、数据契约（网站只读，这是「简约」的根）

- 真相源 = 桌面工单流转中心：App 维直接读现有 `工单库.md`/`工单表.xlsx`；其余四维各一份同款轻量工单表（md）。
- 同步脚本解析 → 生成 `workbench.json` 随部署上服务器；**前端只 fetch 这一个 JSON，不做任何写操作**（改状态仍在桌面工单系统里做）。

## 四、视觉语言（沿用品牌设计系统，浅色）

直接引用 `market-web/DESIGN.md` 的 token，不新造：

- **底色**：暖白 `#FAFAF9`；卡片纯白 `#FFFFFF` + 1px `#E5E5E5` 边 + 大模糊低透明阴影（30-40px blur / 3-5%）。
- **字体**：Inter 全家桶；标题紧凑字距、正文 1.6 行高；微标签用 `label-caps`。
- **圆角**：卡片/pod 24px，嵌套元素按比例缩小；按钮/标签 pill。
- **主色**：品牌蓝 `#3B6EEB` 只用于交互暗示（hover/选中/当前阶段），不大面积铺。
- **状态色**（唯一新增，用低饱和版本，禁止荧光色）：
  - 正常/完成 `#16A34A`（绿）、进行中 `#3B6EEB`（蓝）、警告/待审 `#D97706`（琥珀）、阻塞 `#DC2626`（红）、未启动 `#9CA3AF`（灰）。
  - 状态灯 = 8px 圆点，配 `label-sm` 文字说明，**不只靠颜色传达**（色盲友好）。
- **整体气质**：「独立画廊」的安静感搬进工作台——大留白、无横幅、无花哨动效；动效只允许 150ms 的 hover 浮起和页面淡入。

## 五、首页设计（一屏，信息量从大到小）

桌面端从上到下四带，容器 max 1280px 居中：

1. **顶栏（细，64px）**：左 `◈ mow.kim 工作台`；右 日期 + 数据同步时间（「5 分钟前同步」，这是信任来源，必须显眼）+ 账号菜单。
2. **架构图主视觉（首屏核心，约占 55% 屏高）**——中心辐射式：
   - 中心一个主 pod：「MOV 宇宙」+ 一行聚合数字（`5 维度 · 在制 9 · 阻塞 2`），阻塞数 >0 时数字用红色；
   - 五个维度 pod 环绕（品牌/App/市场/营销/基建），每 pod 含：状态灯、维度名、`在制 X · 阻塞 Y` 一行；边线 1px 灰色连接中心，**阻塞维度的连线变红色虚线**（一眼定位问题源）；
   - 交互：hover pod 浮起 + 阴影加深；点击进钻取页；阻塞维度 pod 左侧多一条 4px 红色竖条（不用闪动动画，违反气质）。
3. **本周焦点带**：一张横贯白卡，标题 `本周焦点`，列 3-5 条各维度 P0/P1 在制工单（每条：优先级色点 + 维度名 + 工单名 + 当前状态）；为空时显示「无在制焦点，去工单库出单 →」。
4. **维度摘要带（可选，空间够才放）**：五张窄卡一排，每卡 = 维度名 + 状态灯 + 迷你流水线（5 段小色块表示各阶段积压数）——首页信息兜底。

**克制红线**：首屏不允许出现图表报表（柱状/折线都不要）、不允许通知铃铛、不允许 todo 输入框。看，不操作。

## 六、钻取页设计（所有维度同一版式，只换流水线定义）

1. **顶栏**：`◀ 返回首页` + 维度名（大标题 headline-md）+ 数据源标注（App 维显示「数据源：工单流转中心 · 5 分钟前同步」）。
2. **流水线步进器（页面上部 1/3）**：该维度阶段一字排开，每段 = 阶段名 + 积压计数；当前活跃段用品牌蓝描边高亮；段间用 `→` 连接。各维度阶段：
   - App：设计师 → 程序员 → 验收员 → 审验员 → 合 main（与工单流转中心一致）；
   - 品牌：策划 → 设计 → 定稿 → 注册/落地；
   - 营销：选题 → 创作 → 发布 → 复盘；
   - 市场：需求 → 开发 → 验收 → 上线；
   - 基建：计划 → 实施 → 验证。
3. **工单列表（主体）**：每行一张白条，左缘 4px 优先级色条（P0 红 / P1 琥珀 / P2 灰），行内 = 工单号 + 标题 + 当前状态 chip + 更新时间；按「阻塞 → P0 → P1 → 其余」排序。
4. **挂账/阻塞区**：琥珀色左边条的卡片区，列该维度挂账（标题 + 登记日期 + 状态）。
5. **最近动态**：一行一条（`日期 · 事件`，如 `08-24 · AB模式真机验收✅`），最多 5 条，证明「这个维度在动」。

## 七、响应式（手机是高频场景：随时掏出来看进度）

- 手机端首页：架构图中心辐射式 → 改为**纵向堆叠**：顶部聚合数字卡，下面五张维度卡顺序排（保持状态灯 + 计数 + 红竖条），点击照样钻取；本周焦点带收进一张卡。
- 钻取页流水线手机端改为横向可滑动步进器。
- 断点：<768px 走移动布局；侧距移动 20px / 桌面 64px（沿用设计系统）。

## 八、不做清单（YAGNI，前端不要擅自加）

- ❌ 在线编辑/拖拽改状态（状态只从桌面同步）；
- ❌ 图表报表、燃尽图、统计页；
- ❌ 通知/提醒/推送、评论、协作功能；
- ❌ 多页导航栏（只有首页 + 钻取页两级）；
- ❌ 暗色模式（一期不做）。

## 九、交付物

1. 静态站：`index.html`（首页）+ `dim.html`（钻取页模板，按 `?dim=` 渲染）+ 共用 css/js，fetch `workbench.json` 渲染；
2. 一份 `workbench.sample.json` 假数据（按 §三 结构填满五维度），供无同步数据时开发；
3. 登录门禁接现有 `account-service.js`（账号体系，用户已拍板），接口对接细节施工时与后端对；
4. 设计走查标准：首屏不滚动能看到「五维度状态 + 本周焦点」；手机 375px 宽无横向滚动。
