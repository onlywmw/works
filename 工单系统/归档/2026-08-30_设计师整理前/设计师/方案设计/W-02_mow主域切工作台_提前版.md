## 一、目标

打开 `https://mow.kim/` = 我的后台管理工作台（带现有账号门禁，未登录见登录页，登录后见工作台）。市场现站与各 API **原样继续跑**，App 端零感知。

## 二、方案（最小改动面：只让出根路径）

1. **Caddy 只改根路径映射**：`mow.kim/`（精确根路径）→ 工作台静态目录 `/var/www/workbench-web/`；`/wb/*` 301 → `/`（旧入口收编）。
2. **其余一切照旧**：`/market/`（含 registry.json，App 在用）、`/market-admin`、`/market-submit`、account/review 各 service 反代、市场各页（guide/upload/merchant 等）——**一行不动**。
3. **市场首页入口迁移**：根路径让出后，市场首页入口改为 `mow.kim/market/`（核查该前缀下 index 是否直达；不直达则 Caddy 加一条 `/market/` → 市场 index 的精确映射）。市场站内部链接若由此产生断链，按"改链接不改功能"修，改动留痕到交付报告。
4. 门禁逻辑不变（account-service 现有校验），工作台代码不改，纯部署层施工。

## 三、验收标准

- **L1**：Caddy 配置改前备份（快照入交付报告）；`caddy validate` 通过；变更 diff 仅根路径与 /wb/ 301 两条。
- **L2**（真实浏览器，截图入 ACCEPTANCE_LOG）：未登录访问 `mow.kim/` → 登录页；登录后 → 工作台五维总览；`mow.kim/wb/` → 301 到主域且功能正常；市场回归 `mow.kim/market/` 首页 + 详情页 + 上传页可开。
- **L3**（真机/模拟器实证）：已装 App 的市场功能实测（拉 `registry.json` 成功、市场页可浏览）——证明旧 App 零影响；API 冒烟：account `/me` 无 token=401、review health 正常。

## 四、红线

- API 路径与市场文件**一个不改**；动任何一个 = 打回；
- 只做部署层（Caddy）+ 至多市场站内部链接修补，不碰工作台代码、不碰 account-service；
- 配置改动先备份、可一键回滚（报告附回滚命令）；
- 本单不涉 LLM 链路，Token/KV 申报「无影响」。
