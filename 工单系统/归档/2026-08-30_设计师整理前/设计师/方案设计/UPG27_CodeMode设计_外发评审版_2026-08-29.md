# UPG-27 设计评审稿：Code Mode SDK 生成 + 工具描述按需加载（tool.help）

> **v1.2.1 终态** ｜ 2026-08-29 ｜ MOV 设计师
> 版本线：v1 初稿（分层溯源过）→ v1.1 灵感库增补 → v1.2 评审一轮定案 → **v1.2.1 二轮评审 + 源码实证定案**（shell.exec schema / 权限双门 / tool.help 直呼地位）。
> 工单卡同版本号在 MOV 工单库 UPG-27 v1.2.1，本稿与卡一致。

---

## 1. TL;DR

MOV（Android 平板 AI 工作台）已有一个「Code Mode 半成品」：code 呈现模式下模型只看到 `shell.exec` 一个工具，但没有任何文档告诉它**有哪些工具、怎么调**。本设计补上另一半——

1. **件 1**：从工具登记层**纯函数生成** SDK 提示节（**两级分层**：全量短描述目录常驻 + 常用集签名层 + 全路径调用判例 + 塌缩契约 + 版本化冻结）；
2. **件 2**：新增读类元工具 `tool.help`（**直呼面成员**），长尾工具签名与长文档**按需加载**（≤1.5K tokens/次，支持批量精确名查询）；
3. 两面**同源生成**（同一数据源 + 同一生成器，紧凑/完整双渲染无语义漂移），配三重变异验收。

不新造执行器：`shell.exec → 本机 MCP 面 (127.0.0.1:8389) → 权限门 → 任意工具` 的通路已存在并经真机实证，本设计只补「告诉 AI 怎么调」。

---

## 2. 背景与问题

MOV 有 ~145 个工具（`file.*` / `browser.*` / `obsidian.*` / 场景工具等），正常 BOTH 模式下全量 schema 常驻模型面前，约 **13–18K tokens/轮**（ASCII schema ≈4 字符/token）——token 贵、注意力稀释。

已有基础：

- **呈现模式体系在案**：BOTH / NATIVE / code 等模式可切换（入口 uiOnly，用户手控）；
- **code 模式半成品**：`codeTools = setOf("shell.exec")`，模型只见执行器；
- **执行通路天然存在**：`shell.exec → 127.0.0.1:8389（本机 MCP 面，JSON-RPC executeTool）→ 权限门 → 工具执行`，此链路已真机实证可调任意工具。

**缺口**：code 模式下 systemPrompt 的工具提示节只有一列**工具名**，没有签名、没有调用方式。模型面对一个空执行器——既不知道能调什么，也不知道 JSON-RPC 长什么样。**「有枪没弹药说明书」。**

参照系：deepseek-harness（dsh）的 Code Mode = `run_code` 执行器 + **自动生成的 SDK 提示节** + 其余直呼一律塌缩拒绝。MOV 已有执行器和塌缩（过滤），缺的正是「SDK 提示节生成」这一半。

---

## 3. 目标与非目标

**目标**

- code 模式下模型仅凭提示节 + `shell.exec` 即可完成真实任务（读笔记、查票）；
- 常驻 token 从 ~145 schema（13–18K tokens）降到 2 schema + SDK 节（**目录层 ≤3K + 签名层，目标合计 ≤7K tokens**）；
- 默认 BOTH 模式**零变化**（本设计只动 code 分支）。

**非目标**

- 不改任何工具的行为与调用签名（**含 shell.exec**——其结构化改造挂账另立小单，见 §4.2-3）；
- 不新造执行器、不改权限模型；
- 不做「BOTH 模式降级为短描述」的切换（开关形态预留，默认不启用）；
- `tool.help` 的 fuzzy 搜索模式**首发不做**（后置可选增强，见 §4.3）。

## 4. 方案

### 4.1 总览

```
ToolDefinition 登记层（单源：name / description / summary / inputSchema / output / longDescription）
        │
        │  纯函数生成器（同源，唯一渲染出口；紧凑/完整两种渲染；声明文本也从 codeTools 集合生成）
        ├─→ 目录层：全量工具「name + summary 短描述」────────┐
        ├─→ 签名层：常用集（频次 Top N）附加参数签名 ────────┼─→ 常驻 SDK 节（systemPrompt，code 模式，版本化冻结）
        └─→ 完整三件套文档 ────────────────────────────────→ tool.help（直呼，读类 free，≤1.5K tokens/次，支持批量）

模型（code 模式）──直呼 tool.help 查文档 / ──shell.exec──→ 本机 MCP 面 127.0.0.1:8389 ──权限门──→ 工具执行
                                    （外层 shell.exec 恒 ASK + 内层写类再过 guard：双门）
```

### 4.2 件 1：SDK 提示节生成

1. **两级分层（v1.2 定案；v1.2.1 补短描述来源）**：
   - **目录层**：全量在面工具「name + 一句话短描述」**常驻**（目标 ≤3K tokens）——消灭「长尾不可见 → 模型不知道工具名 → 无从 tool.help」的**可发现性死锁**（评审定案：发现税值得交）；**短描述来源 = 登记层新增 `summary` 专用字段**（可控长度）+ 生成器强制 per-entry token 上限（**超限 fail-loud，不静默截断**——截断会切关键语义）；过渡口径 = 截断 description + 逐条标注待补；
   - **签名层**：常用集（频次 Top N，输入 = journal 频次榜产物；N 以 Token 实测定）附加参数签名；
   - **长尾**的签名与长文档按需走件 2 `tool.help`（book-to-skill #12 分层范式：常驻核心 + 按需章节，实测省 24–51x token）。
2. **SDK 版本化冻结（v1.2 定案）**：会话开始绑定当前 SDK 版本，**会话内不重排、不漂移**；后台按天/周、或 Top N 成员变化 **>20% 阈值**时重新生成；**版本元数据（版本号 + 成员名单）入配置态**，SDK/长文档文本仍**零落盘**、运行时由登记层派生；冷启动初始常用集 = 频次榜现状产物。
3. **shell.exec schema 定案（v1.2.1，源码实证）**：现状 = **单字符串 `command` 入参**（`MainActivity.kt:386` paramSchema `"command" to "string"`；`:3598` handler `args["command"] as? String`）——即「真 shell 命令内嵌 JSON」形态，**嵌套转义（引号/换行/中文）是经典翻车点，单判例救不了**。处置：①判例**必须含「参数值含引号」的转义样例**；②JSON 解析失败返回**结构化错误（带位置 + 指引）**；③结构化 `{tool, args}` 对象入参改造**违反本卡红线 1（不改调用签名）——挂账另立小单**，本卡按现状 schema 定案。另：**工具本体输出经 shell.exec 回流暂无大小策略**（长尾文档防住了、长尾结果没防住）——本卡接口预留，接 spill 线（A1 超长结果溢出）。
4. **权限双门（v1.2.1，源码实证）**：外层 shell.exec **恒 ASK**（`isHighRisk`「任意代码执行」，open 模式不豁免，`McpToolScheduler.kt:185-191`）+ 内层 8389 executeTool **独立过 guard**（`McpServer.kt:109-111`）——SDK 节**如实写双门**（外层每次弹确认 + 内层写类再弹），不粉饰；文档中的权限标注一律经 `permissionTier` 单源访问器取 tier 字符串（UPG-23 纪律），名单本体不进 AI 面。
5. **调用判例**：SDK 节含「如何经 shell.exec 调本机 MCP 面」范式说明 + **一个完整可复制的调用判例**——**必须展示 `shell.exec → executeTool` 全路径**（含外层包装，不能只给裸工具名 JSON，防模型把目录当直呼面）；判例选**读类无害工具**（`file.read` / `obsidian.search`——双门下外层仍会弹确认，选读类是保证示例无副作用可复现），显式标注**双门权限现实**；含转义样例；token 写「运行时注入变量」占位；**顺带教 `tool.help` 用法一行**（别让模型需要 `tool.help(tool.help)` 才会查文档）。
6. **塌缩契约（dsh 源码三实证 + v1.2.1 补全）**：
   - **直呼面 = `codeTools = {shell.exec, tool.help}`（v1.2.1 定案）**——tool.help 读类无害直呼，查文档不该再包一层 JSON-RPC 转义；
   - **声明前置**：「code 模式仅 {直呼面} 可直呼」规则声明放在工具目录**之前**（dsh `COLLAPSE_SECTION_ORDER` 教训：规则后置会让模型直呼刚读到的工具名、判定「部署不一致」）；**声明文本由 codeTools 集合生成、禁模板手写**（未来加第三个直呼工具时自动同步，防自漂移）；声明内钉死目录层语义：**目录列表 = 可经 shell.exec 间接调用的工具，非可直呼面**；
   - **同谓词**：prompt 声明的可见面与执行层拦截面**同一谓词/同一数据源**（dsh `index.ts:859-861`「the SAME predicate the executor denies by」）；
   - **错误语义三分（v1.2.1 补全）**：直呼非在面工具 / 查询不存在 / 参数校验失败，三种失败各有结构化 code + 指引：**「已塌缩」**（工具存在、仅 code 面不直呼 → 指引走 shell.exec）、**「真未知」**（TOOL_NOT_FOUND + `nearSuggestions[]` 近邻候选）、**「参数校验失败」**（schema 不符 → `INVALID_ARGS` + 指出具体字段 + 指引「tool.help 查该工具字段」，对齐 E4 失败结构化口径）——**长尾工具凭目录名字猜参数，参数校验失败恰恰最高发**；防模型循环瞎试。
7. **容错**：登记层 output 声明目前大量缺失（清偿批次在途），生成器对缺失字段可选渲染，不阻断生成。

### 4.3 件 2：tool.help（按需加载元工具）

- 新增 `tool.help` 查询工具，**读类无害（权限 free），进 codeTools 直呼面**（v1.2.1 定案）；
- 入参工具名 → 返回该工具完整三件套文档（长描述 / 字段说明 / output / 近邻差异点）；
- **批量精确名查询（v1.2.1）**：一次传多个确定工具名，返回多个紧凑签名（省「目录见名 → 查签名 → 再调用」的轮次；与后置 fuzzy 不同，不诱导探索；总量上限同单次）；
- 查不存在工具 → **结构化错误**：`code=TOOL_NOT_FOUND` + `nearSuggestions[]`（**命名空间感知匹配**：先匹配 `file.` / `browser.` / `obsidian.` 等段，段内再编辑距离——比全名编辑距离更符合工具命名结构）+ 指引措辞——**未命中报最接近候选，不臆造**；
- **返回大小上限**：单次 **≤1.5K tokens**（统一 token 口径）；`longDescription` 超长 → 摘要先行（可二级取详情 / 字段级查询）；journal 监控调用后上下文增长；
- **同源生成**：tool.help 与 SDK 节出自**同一纯函数生成器**（同数据源，紧凑/完整双渲染），登记层改一处两面同步变，严禁两处手写两套口径；
- 长文档位随登记层内存态扩展（`longDescription` 可选字段），**不落盘**；
- **fuzzy 搜索模式后置为可选增强（首发不做）**：目录层已给全量名字，搜索诱导「先搜再调」；后做必须带护栏——返回 ≤8 条 + 提示语「仅在不确定工具名时使用」+ 监控未命中率/搜索频率。

## 6. 验收与度量

- **L1 单元**：SDK 生成纯函数测试（给定登记层 → 文本含**目录层短描述** / 常用集签名 / 调用范式 / 全路径判例（含转义样例 + 双门权限标注）、未登记工具不出现）；tool.help 契约（已登记→三件套、不存在→TOOL_NOT_FOUND+近邻、**返回 ≤1.5K tokens**）；**同源断言**（改登记层描述 → 两面同步变 + 紧凑/完整双渲染签名与描述语义一致）；**塌缩语义断言**（已塌缩 / 真未知 / 参数校验失败三种错误可区分且都带指引）；**声明生成化断言**（改 codeTools 集合 → 声明文本自动同步）。变异亲杀：①删 SDK 装配必红；②tool.help 改空返回必红；③同源断言改单面必红。
- **L2 真机**：code 模式下 AI 仅凭 SDK 节 + shell.exec 经本机 MCP 面完成一个真实任务（journal 可见 `shell.exec→MCP→工具` 调用链 + **双门权限实测**：外层 shell.exec 恒 ASK + 内层写类再 ASK）；tool.help **直呼**返回真文档；塌缩实测——直呼非在面工具收到结构化错误且 AI 能据指引自纠。
- **L3 对比观察**：code vs BOTH 同任务选参正确率；**任务集必须显式含长尾工具主导任务**（否则对比只验证了常用集）；**A/B 观察项（非硬门）**：混合形态 vs 全英文比成功率/轮次/实际 token（注意 Top N 来自 BOTH 模式 journal，code 分布未必一致，勿把分布差当语言形态差）；**增测 prefix cache 命中率 / 实际计费 token**——版本冻结红利押在缓存上，不验证则「前缀恒定」只是纸面性质。
- **Token 申报**：经 `check-token-effect` 实测 + `estimateTokens` 加权估算（ASCII×0.3 / CJK×1÷1.5 / 其他×1.2）；**一律 tokens 口径，禁 KB**。

## 7. 评审定案对照（两轮回收）★

### 一轮（v1.2）

| # | 原开放问题 | 定案 |
|---|---|---|
| 一 | 长尾在 AI 面保留什么 | **(a) 全量短描述常驻必做**（杀可发现性死锁）；(b) fuzzy 后置带护栏；(c) 否决 |
| 二 | Top N 冻结策略 | **会话绑定版本 + 版本化发布**（按天/周或成员变化 >20% 重生成；冷启动手动初始集） |
| 三 | SDK 节语言形态 | **混合起步**（结构英文 + 描述中文）+ A/B 数据说话 |

附加四条：目录列表语义钉死 / 全路径读类判例 / tool.help 上限 / 双渲染同源断言——全部落卡。

### 二轮（v1.2.1，动工前缺口五条）

| # | 缺口 | 定案 |
|---|---|---|
| 1 | shell.exec 自身 schema 未定案（最大未决变量） | **源码实证定案**：单字符串 `command`；判例含转义样例 + 解析失败结构化错误；结构化改造挂账另立小单；输出回流大小策略预留 spill 接口 |
| 2 | tool.help 直呼地位与「同谓词」自相矛盾 | **tool.help 进 codeTools 直呼**；声明文本由 codeTools 集合生成，禁模板手写 |
| 3 | 错误面漏参数校验失败 | **错误语义三分**：已塌缩 / 真未知 / INVALID_ARGS（带字段 + 指引） |
| 4 | Token 预算 KB 违反「禁按字节估」 | **全卡 tokens 口径**（目标 ≤7K tokens；实算收益约 2–3x 而非 KB 暗示的 4–5x，仍成立但口径诚实） |
| 5 | 短描述来源未定义 | **登记层 `summary` 专用字段** + per-entry token 上限 fail-loud |

次要建议（批量查询 / 教 tool.help 用法 / 上限单位 / 命名空间近邻 / 分布差注记 / cache 命中率实测）——全部落卡。

**评审结论**：设计可进入原型实现；重点验证 SDK 节实际 token ≤7K + 模型真机仅凭判例正确构造调用（含转义）。

## 8. 约束与红线

1. 不改工具行为/调用签名（含 shell.exec）；不新造执行器；
2. SDK 文档与 tool.help **不得含敏感名单内容**（权限标注只取 `permissionTier` 单源访问器的 tier 字符串，名单本体不进 AI 面）；
3. 权限口径不变且**双门如实**：外层 shell.exec 恒 ASK + 内层 8389 executeTool 独立过 guard；SDK 不得教 AI 远程切模式；
4. 呈现模式切换入口与默认模式（BOTH）不动；
5. 请求前缀恒定：SDK 节 = 版本化冻结，会话内稳定；token/token 路径绝不写进文档明文；版本元数据入配置态，文本零落盘；
6. SDK 节与 tool.help 纯函数同源生成（紧凑/完整双渲染），**禁止手写/硬编码任何工具文档**；「可直呼面」声明文本由 codeTools 集合生成；
7. **Token 预算与上限一律 tokens 口径，禁 KB/字节**；`summary` 长度超限 fail-loud 不静默截断。
