# 标签关联体系 · 设计 v1

> 设计师 @2026-08-27 ｜ 上游：`工单系统_文件映射_v1.md`（多维表格模型）
> 目标：事件/工单/挂账/验收 四类实体跨表可关联、可跳转、可溯源。

---

## 一、问题

实体间关联目前全是自由文本（挂账写"已转工单 UPG-13#9"、E-02 备注写"W-03 页脚依赖"），系统不识别：事件页看不到它产出了哪张工单，工单页看不到它从哪个事件/挂账来。用户场景："要办什么证 → 事件分析 → 形成工单 → 事件上能看到对应工单"——本设计即为此。

## 二、统一 ID 命名空间（既有事实，固化为规则）

| 前缀 | 实体 | 例 |
|---|---|---|
| UPG-NN | App 工程工单 | UPG-13 |
| W-NN | 基建/官网工单 | W-05 |
| S-NN | 市场工单 | S-05 |
| T-/V-/B-/G-/C-/I-/Y-NN | 维度条目 | T-01、Y-02 |
| E-NN | 事件 | E-02 |
| 挂账-xxx | 挂账 | 挂账-w05-事件白名单fail-loud虚标 |

规则：ID 全库唯一、不复用、销项不改号；新实体类型上线先登记前缀。

## 三、关联字段（源文件改动，最小侵入）

每张源表加一个 `关联` 列，值为逗号分隔的 ID 列表：

- **事件登记表**：`关联` = 该事件衍生/依赖的工单（E-02 → `W-03`）
- **工单卡/dims 行**：`关联` = 来源事件/挂账（W-03 → `E-02`；UPG-13 → `挂账-upg13-tab往返发码按钮消失`）
- **挂账表**：现有「施工」列升级为 `关联`（"未施工/UPG-13/无需施工"本就是半成品关联）
- **命名即关联**（自动，无需填写）：挂账 ID 含工单号前缀（挂账-upg13-*）→ sync 自动建立关联

方向语义不另设类型：渲染层按表类型推导显示文案（事件卡显示"产出工单"，工单卡显示"来源"，挂账卡显示"转工单"），双向自动成图。

## 四、解析（sync 增量）

1. 各表解析时提取 `关联` 列 + 挂账 ID 前缀 → 生成全局 `links` 图（A→[B,C]）；
2. 每条记录注入 `related: [{id, type, exists}]`（双向补全：A 声明关联 B，B 的记录也自动出现 A）；
3. **弱引用**：目标 ID 不存在 → 标记 `exists:false` 灰色显示 + verify 警告（不 fail，防止改历史 ID 阻塞同步；但 verify 有警告清单输出）。

## 五、展示（前端增量）

1. **关联徽章**：卡片标题行右侧显示关联 chip（`⇄ W-03`），点击跳到对应卡片（树同步定位）；
2. **详情抽屉**（依赖 W-06）：加「关联」区，分两组——上游（来源事件/挂账）、下游（产出工单/销项挂账）；
3. **事件节点特色视图**（本设计的初心场景）：事件卡直接显示其衍生工单及其当前状态（E-02 卡上看到 `⇄ W-03 待派单`）——事件推进情况一眼穿透到工程线；
4. 不做关系图谱可视化（超需求，后续再说）。
