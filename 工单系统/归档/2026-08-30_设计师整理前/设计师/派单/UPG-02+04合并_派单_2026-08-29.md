## 二、施工要点（两子方案共享）

1. 两个 Provider 文件：`DeviceProvider.kt` + `ObsidianProvider.kt`——**均为 class 持 Context**（照 HardwareProvider 范式；禁 object 单例/禁照 SceneTools 骨架）；
2. **接线四点一次做完**（同一注册段相邻落笔）：mcpHandlers 注册段实例化 + **schema 随 Provider 走**（各自携带 schemas 表，注册段一次 merge）+ 权限名单（写类进 writeTools / 查询类进 harmless；obsidian.file.write 例外维持 ASK 理由见上）+ isHardwareTool 白名单（设备类需要）+ ToolRegistry 并行声明（查询类 true）；
3. **权限门陷阱**：漏登记 writeTools = else 静默 ALLOW（McpToolScheduler.kt:187-188）——验收变异钉死。**溯源复核 @2026-08-29 补两条**（当前 main 实证）：①判定顺序=敏感 DENY → **harmless 优先** → writeTools ASK → else ALLOW（:180-196），且名单匹配全是 `contains` **子串匹配**——新工具命名必须避让 harmless 名单子串（否则写类工具被自动放行，反方向陷阱）；②黑名单四处镜像仍在但 McpExtDiscovery 已挪包：`mcp/McpExtDiscovery.kt:31`（勿按 tools/ 旧路径找）；
4. **黑名单先对齐再同步**：四处镜像内容不一致（McpToolProvider.kt:31 / McpMarket.kt:563 / mcp/McpExtDiscovery.kt:31 / McpToolScheduler.kt:94 子串 vs 精确匹配）——对齐后补等价变体（sms.recent/contacts.search/location.get）；
5. 产物红线：截图/照片只落 filesDir；obsidian 沙盒根=已授权 vault 非 Download/MOV；
6. **串行约束**：本单占用 MainActivity 装配区——UPG-07 若开工须等本单合 main（或显式协调），交付报告声明占用窗口。
