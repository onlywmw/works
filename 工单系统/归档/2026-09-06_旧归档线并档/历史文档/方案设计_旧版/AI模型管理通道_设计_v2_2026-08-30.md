## 〇、一句话

**把「AI 模型」做成一条统一通道：设置页三级(入口→列表→设置) ↔ ModelStore(数据唯一源) ↔ ModelRegistry(运行时) ↔ 聊天页模型 chip(显示/切换) ↔ 请求(用当前模型自己的 key/baseUrl)。模型(含 key、本地自部署)全在设置页管理，换模型/加本地模型 = 设置页配置，零代码改动。**

**"各搞各的"四个断点**：
1. **key 与模型分离**：设置页 key 走 `credential.setKey`(DeepSeek 专属单 key)，模型走 `model.add`(ModelStore)——两条通道，key 不归属模型；
2. **设置页无模型管理 UI**：`model.add/setDefault` 底层在，但 UI 没开放 → 用户加不了别的模型（云 or 本地）；
3. **显示无缩写**：`chipLabel` 用完整 label；
4. **请求不一定用当前模型 key/baseUrl**：可能残留 DeepSeek 特判。

## 二、通道架构（一条链）

```
设置页「AI 模型」── 三级 UI（唯一管理入口）
  ① 一级入口(AI 模型 ›)  ② 二级列表(模型名+⚡测试+启用开关)  ③ 三级设置(完整配置)
        │ 全走 model.* CRUD
        ▼
ModelStore (model_store.json)   ← 数据唯一源（每模型含 provider/model/baseUrl/keyName/label）
        │ syncModelRegistry
        ▼
ModelRegistry (current/list/use) ← 运行时注册表
        │ current() → label/缩写 + modeName
        ▼
聊天页模型 chip（显示 + 切换）
        │ 请求读 current().baseUrl/keyName
        ▼
Adapter（DeepSeekAdapter / OpenAI兼容(本地Ollama/LM Studio/vLLM)…） → 真发请求
```

## 三、三级设计（定稿）

### ① 一级 · 设置页入口
```
[⚙️] AI 模型          ›        ← 简约（无副题/无当前模型名）
```

### ② 二级 · 模型列表
```
[DeepSeek V4 Flash  ✓当前]   [⚡测试]  [开关·on]
[另加模型 A                ]  [⚡测试]  [开关·off]
[LLaMA 3.2（本地部署）      ]  [⚡测试]  [开关·on]
──────────────────────────
◇ ＋ 添加模型（含本地自部署）        ← 唯一添加入口（底部）
```
- 行 = 模型名 + 当前✓ + **⚡快速测试**(发起一次简单对话/health验证连通) + **启用开关**(停用不可被选为当前)；
- 点行 → 三级编辑；底部「＋添加模型」→ 三级添加态(空白表单)；**二级不留供应商/接口小字**(用户拍板，简约)。

### ③ 三级 · 真正设置（编辑/添加两态）
```
模型名     DeepSeek V4 Flash
模型 ID    deepseek-v4-flash
供应商     DeepSeek ▾ (OpenAI / 本地自部署 / …)
接口地址   https://api.deepseek.com   (本地= http://127.0.0.1:11434/v1 )
API Key   sk-****5f77 [编辑]         (本地自部署可空)
设为当前  [开关]
[保存]  [⚡快速测试]
删除该模型
```
- 添加态：标题"添加模型"，表单空白可填；编辑态：回填该模型，标题"模型设置 · 模型名"；
- **本地自部署**：供应商选「本地自部署」，接口地址填本地服务(Ollama `127.0.0.1:11434` / LM Studio `1234` / vLLM)，key 可空；与云端同一条 `model.add`(ModelStore)，只是 `baseUrl=本地` + `provider=local/Ollama`。

## 四、关键机制

### A. API Key 归属模型 + 安全存储
- 每个模型的 `keyName` 指向**安全存储**(EncryptedSharedPreferences / credential.vault)，**禁明文**；
- `model.add/update` 的 key 走安全层；**取代 `credential.setKey`(DeepSeek 专属)**——key 是"当前模型的 key"，跟模型走。

### B. 模型 chip 缩写（元数据驱动，换模型不改代码）
- `ChatChips.chipLabel(provider, modelId, modeName)` → **`provider + 主版本(modelId)`** + ` · modeName`；
  - `DeepSeek + deepseek-v4-flash` → `DeepSeek V4 · 快速`；`GPT + gpt-4o` → `GPT-4o`；`Qwen + qwen2.5-72b` → `Qwen2.5`；
- 无版本→provider；完整名(label)悬浮/详情可查；**缩写由元数据生成，非硬编码**(换模型自动缩对)。

### C. 请求路由（当前模型的 key/baseUrl）
- 请求侧读 `ModelRegistry.current()`：`baseUrl/provider/keyName` → 分发到对应 Adapter；
- `DeepSeek` → DeepSeekAdapter；`本地自部署`(baseUrl 本地/OpenAI 兼容) → OpenAI 兼容 Adapter(可用 Ollama/LM Studio/vLLM)；**去 DeepSeek 特判残留**。

### D. 本地自部署（不绑死供应商）
- = 一种 provider=local/Ollama/vLLM + baseUrl=本地 + key 可空；走 OpenAI 兼容适配器；
- 与云端同等待遇(同一 ModelStore/model.add/切换/chip)。

## 六、验收测点

- **L1**：①设置页三级可导航(入口→列表→设置) ②`model.list` = ModelStore 全量(当前✓/启用态) ③添加任意模型(云/本地自部署) → ModelStore 新增 + Registry 同步 + 请求可用 ④切换 setDefault → Registry.current 变 + chip 变 ⑤key 归属模型(不同模型不同 key) ⑥chip 缩写随 provider+版本生成(DeepSeek V4 / GPT-4o / Qwen2.5 / 本地 LLaMA 3.2 自动缩对，非硬编码)。
- **L2 真机**：设置页加本地自部署(Ollama 127.0.0.1:11434) → 聊天页 chip 显示"LLaMA 3.2" → 切换 → 用该模型(本地)发起对话成功；key 脱敏存储(shared_prefs 无明文)；切换回 DeepSeek 正常。
- **L3**：适配层按 current().provider/baseUrl 分发(去 DeepSeek 特判)；旧 credential.setKey 迁移到 per-model key 不冲突。
