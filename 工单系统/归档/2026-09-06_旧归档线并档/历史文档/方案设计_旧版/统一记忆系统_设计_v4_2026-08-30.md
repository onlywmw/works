# 统一记忆系统（Unified Memory）设计 v4 · 架构冻结版

> 设计师 @2026-08-30 ｜ 状态：**架构冻结**（基于 v3 冻结基线 + 用户拍板纳入 **Memory Timeline 底座**——"当前记忆可变、记忆历史不可变"）
> **架构铁律（两条）**：
> ① `Event = observed fact / Episodic = contextualized / Semantic = confirmed`（Event ≠ Memory）
> ② **`Current Memory is mutable. Memory History is immutable.`**
> 层级：v4 = 架构基线；池子 v2 = Semantic 层详设；碎片层(契约v4+记忆页v5) = Episodic 层。接续，不推倒。
> **冻结纪律**：不再加自动总结 / 知识图谱 / Embedding / Obsidian / 智能整理；先把记忆生命链跑通。

---

## 〇、核心主张（五条）
1. **生命周期**：记忆有新鲜度/可信度；「最常见的歌 ≠ 最喜欢的歌」。
2. **增量合流**：`Event → Extract → Merge → Update`，绝不用 LLM 重写整库；Merge 只在事件/情景层，语义库只读。
3. **双向·人拍板**：候选→语义（采纳）与语义→待确认（Re-evaluation）都 **AI 只发 Proposal、人确认才动库**；"退化"= 事实→待确认假设，**保历史非删除**。
4. **Event ≠ Memory**：播 17 次《晴天》≠ "喜欢"；观察≠偏好（防污染第一边界）。
5. **当前可变 · 历史不可变**：Semantic（当前有效认知）可变；Memory Timeline（记忆历史）**append-only 不可改**——历史事实不被今天认知篡改。

## 一、五层架构（Event / Timeline / Working / Episodic / Semantic）
```
                        Unified Memory
                             │
        ┌────────────────────┴────────────────────┐
        ↓                                         ↓
   [Event Store]                            [Memory Timeline]      ← 横向底座·不可变
    原始行为账本                                 记忆历史账本
    "世界发生了什么"                            "系统何时知道什么·怎么变"
        │                                         │
        └───────────→ Memory Processor ───────────┘
                          │
        ┌─────────────────┼─────────────────┐
        ↓                 ↓                 ↓
   [Episodic(=现有碎片)]  [Candidate]     [Pattern]
        │                 │  用户「采纳」
        │                 ↓
        └──────────→ [Semantic(主记忆库=池子v2)]
                          │ 时间/新证据/冲突
                          ↓
                     [Re-evaluation]
                          │ 用户确认
                          ↓
                    [Active / Archive(保历史)]
```
- **Event Store**：原始事实（媒体/Agent/外部），append-only；
- **Memory Timeline**：记忆系统**状态变化账本**（OBSERVED/PROPOSED/ACCEPTED/REEVALUATED/REJECTED/ARCHIVED/CORRECTION），**不可变**；
- **Episodic / Semantic**：当前可使用的情景记忆 / 当前认可的长期理解（可变层）；
- **Working**：运行时 context（**不入库**，横向，`…→Retrieval→Working→AI`）；
- **关键**：①`Event` 可直接 → Pattern → Candidate（不必都先转 Episodic，防海量碎片）②Semantic 是"当前有效态快照"，Timeline 是"如何变成这样"——**分工不混**（当前态读 Semantic，历史读 Timeline）。

## 二、Memory Timeline 底座（新增 · 不可变铁律）

**定义**：用户记忆系统的**不可变历史账本**；回答"过去什么时候认为你怎样、为什么变"。

### 2.1 契约
```json
MemoryTimelineEntry {
  id, timestamp,
  eventType,        // OBSERVED / PROPOSED / ACCEPTED / REEVALUATED / REJECTED / ARCHIVED / CORRECTION
  subject,          // 记忆对象（如"音乐偏好"）
  payload,          // 结论内容
  actor,            // user / ai-proposal / system-decay   ← 审计锁
  sourceIds,        // 来源（碎片/Event id）
  reason,           // 触发原因（freshness decay / 用户确认 / 冲突…）
  previousMemoryId, // 状态链前驱（或 correction 指向原条）
  correlationId     // 与 Event Store 关联
}
```

### 2.2 不可变规则（仅允许）
```
CREATE / APPEND / READ   ✓
UPDATE / DELETE / REWRITE ✗   （连 dev 环境也不提供 timeline.delete()/update()，防调试工具破坏原则）
```

### 2.3 actor 审计（AI 只读 → 数据结构锁定）
- **AI 产出的 actor = `ai-proposal`**，只能 `PROPOSED`；
- `ACCEPTED / REJECTED / ARCHIVED` 的 actor **必须 = user**；
- `system-decay`：系统按策略触发 Re-evaluation（仅生提案，不直接改语义）。

### 2.4 Correction（错误不改，只追加）
- 判错 → 追加 `CORRECTION` + `previousMemoryId` 指向原条；读历史见"原记录+更正"，旧条永远原样。

### 2.5 与 Event Store 边界
- Event Store = "**世界发生了什么**"（20:31 播《晴天》）；
- Memory Timeline = "**系统何时知道、怎么判断、用户怎么确认、后来又怎么变**"；
- 不合并；`correlationId` 关联。语义不同，以后各有价值。

## 三、记忆生命链 + 总图（含 Timeline）
```
Event → Episodic → Candidate → Semantic → Re-evaluate → Archive
  事实     情景       候选      确认理解     待重新确认     保历史
                                                    │
       所有上述状态变化，同时 append 到：            ↓
                              Memory Timeline（immutable·append-only）
```
- **"自动退化"改叫 `Re-evaluation`**：旧记忆→系统发现可能过时→RE-EVALUATE→**用户确认**→才 ARCHIVED；
- **每次活动执行 `Memory Update Pipeline`，但不保证产生持久记忆变更**（"你好"→无沉淀→结束）；
- **产品原则**：记录"用户经历过什么"，不替用户决定"用户是谁"——系统同时拥有**过去的你 + 现在的你**（当前层可变、历史层不可变）。例如：
```
2026-08-30 OBSERVED   重复播放《晴天》
2026-09-15 PROPOSED   可能喜欢《晴天》      (actor: ai-proposal)
2026-09-15 ACCEPTED   用户喜欢《晴天》      (actor: user)
2027-03-01 REEVALUATED 长期未观察          (actor: system-decay)
2027-09-20 REJECTED   用户表示已不喜欢      (actor: user)
2027-09-20 ARCHIVED   保留历史·退出注入
```

## 四、语义状态机 + 极简 UI
| 状态 | 语义 | AI 注入 | 用户可见 |
|---|---|---|---|
| `ACTIVE` | 主记忆（可信） | 允许 | ✓ |
| `RE-EVALUATE` | 待重新确认 | **禁止** | ◌ |
| `ARCHIVED` | 历史保留（正文保留） | 禁止 | 折叠/历史 |

- Re-evaluate 触发=事件驱动（decayPolicy 到期 / 冲突），确认低频·非阻塞（`◌` 点进才确认）；
- "不是"→ ARCHIVED 保历史（不删除、退出注入、生成候选）；
- UI：`我的记忆·记忆库 → 关于我 ✓ / 音乐 ◌`；`confidence/decay_score/天数` 全内部不暴露。

## 七、Conflict Matrix（表3）
| 判据 | 例 | 判定 → 处理 |
|---|---|---|
| 同一类型且互斥 | 「最喜欢A」vs「现在最喜欢B」 | **冲突**→RE-EVALUATE |
| 不同值同类型不互斥 | 「偏好爵士」vs「最近听摇滚」 | 不算冲突（可并存） |
| Observed≠Inferred | 播《晴天》17 次 | 不算"喜欢"→只可候选/Proposal |
| 新证据覆盖 | 2026 晴天→2028 听 A | 旧条 RE-EVALUATE（保历史） |
| 身份 vs 偶发行为 | 「游戏设计师」vs 偶尔玩一局 | 不算冲突（身份极稳） |

> 核心：跨类型不冲突、同类型互斥才冲突；冲突不自动改库，只标 RE-EVALUATE 待用户裁决。

## 八、原子写入管道（关键一致性）
任何记忆状态变更，必须走 **Memory Processor 单一入口，同事务完成**：
```
Processor 处理 → 写 Semantic 快照（当前态）+ append MemoryTimeline（历史）  ——同锁/同事务
```
- 防"Semantic 变了但 Timeline 没记 / 记了但没变"（与 `poolState` 不能双写同坑）；
- `poolState` 派生自池子存储；Timeline 是 Semantic 变化的**审计侧写**，二者经 `previousMemoryId/correlationId` 关联。

## 九、工程原语（冻结清单）

## 十、验收测点
- **L1**：①Event≠Memory（变异：Event→直接"喜欢"→必红）②**Timeline 不可变**：任何人尝试 update/delete/rewrite → 拒绝（变异：提供 delete API→必红）③**actor 审计**：AI 只 `PROPOSED`、user 才 `ACCEPTED/REJECTED`（变异：ai-proposal 直接 ACCEPTED→必红）；④**原子一致性**：Semantic 变 ⇒ Timeline 必有对应条目（变异：只写 Semantic 忘 append→必红）⑤Correction 追加不改旧条 ⑥Semantic=当前态、Timeline=历史（分工不混）⑦类型系统：同类型互斥→冲突、Observed≠preference 不冲突（表3 逐断）⑧`memoryType` 生命周期差异 ⑨freshness 派生、不暴露 UI ⑩Re-evaluate 事件驱动非全扫 ⑪空库→行为零影响。
- **L2 真机**：看剧→Observed→Episodic；重复行为→PROPOSED→用户 ACCEPTED→`关于我.md`；旧偏好→RE-EVALUATE→[是/不是]→UPDATE/ARCHIVED；**用户可看"记忆时间线"**：一个人怎么从喜欢晴天 → 听 A → 变 B（时间线 UI，只读）；UI 只见 ✓/◇。
- **L3**：三层隔离（`memory-api` 零改）；Semantic 对 AI 只读约束测试；EventStore append-only；Timeline 仅 append；原子写入一致性契约测试；类型/冲突矩阵逐格契约测试。

## 十一·结 / 结论
- v4 = **架构冻结版**：五层（Event/Timeline/Working/Episodic/Semantic） + 双向生命周期 + 三张表 + 增量合流 + **Memory Timeline 不可变底座**；
- **铁律**：`Current Memory is mutable. Memory History is immutable.`；`Event ≠ Memory`；`record experience, don't decide who user is`；
- **Timeline 让"过去的你 + 现在的你"真正工程化**——不可改的历史 + 可变的当前认知；
- **不再堆功能**：先把 `Event→Episodic→Candidate→Semantic→Re-evaluate→Archive` 生命链 + Timeline 账本跑通。
