## 〇、评审收口（v5.1 · 响应大神 P0×3 / P1 / P2 + 承接旧账）

### P0-1 删除复活（最重 · 结构保证"删掉的不回来"）
> 铁律②(Timeline 不可变)+铁律③(Event 无限留痕)+落地序(Event→Pattern 聚合候选)→ 用户移除的偏好会被**不可变原始事件重新推导**——v4 留白的"语义拦截"现在是结构问题。
- **定案**：
  ```
  移除某记忆 ⇒ 记录 blockedSourceHashes(该记忆 sourceHash 集合)
  ⇒ 候选生成 / Pattern Detection：sourceHash ∈ blockedSourceHashes 的派生候选 → 丢弃
  ⇒ 同机制用于"移除 IN_POOL 碎片→池内副本"：被挡派生 ⇒ 池内条目标 ARCHIVED / RE-EVALUATE
  ```
- **purge 逃生口**（append-only vs 彻底抹掉）：`purge`(仅人类触发) 记 `purgedSubject` + 结果数据打标，或 Correction 收尾——历史不可改但可标注；
- 置于 `MemoryProcessor` 候选生成**之前**过滤（写入契约，L1 变异锚：删 blockedSourceHashes 判定→候选复活→必红）。

### P0-2 Timeline 管辖 / 写者（诚实声明，不假单一）
- 定案：**两个写者 + 分工**——`MemoryProcessor`(管 Semantic + Timeline，语义层单一入口)；碎片层保留现有 `Lifecycle writer`(管 Episodic)；
- **Timeline 现阶段 = Semantic 历史账本**（PROPOSED/ACCEPTED/REEVALUATED/REJECTED/ARCHIVED）；碎片 **promote/remove/pin 不 append Semantic Timeline**，其历史走 Event Store / 碎片 journal + 后续 hook；
- 修正"铁律②全系统" vs "碎片保留不动"矛盾：铁律②对 **Semantic 层**成立（历史不可变），碎片层历史由 Event/journal 记（后续加 hook）。

### P0-3 冻结真义（不冻结没跑过的内核）
- 定案：**冻结接缝**（API 形状 / 事件类型 / 状态机）；**参数版本化**（decay 阈值 / Router 规则 / importance 权重 / 稳定模式 N → 配置，不冻结，防第一个月"解冻"）；
- **承接旧账**（这些在 契约 v4 / 记忆页 v5 层**已定**，统一记忆 v5 引用、不重冻）：`memorySetPinned`/`memoryRestore` API 入口、tombstone 时序(即时+restore)、标签人工覆盖(`tagsTouchedByUser`)、删除传播(blockedSourceHashes 接 sourceIds/sourceHashes)。

### P1
- **Core = 确定性规则选条目拼接**（type×importance×预算，非"造短语"）；L1②判定：Core 由规则稳定从 Semantic 选出，AI 造短语→必红；
- **Conflict 锚定人工确认检查点**（AI 提议·人裁决，延续"提示不改"）；补**跨层冲突行**（新事件/新碎片 vs 池内条目，不只 Semantic 内部）；
- **Index 范围**：Timeline 按时间/actor 查询、**不进 Index**；重建=同事务，允许异步+陈旧度上限；
- **Event Store = 监控级隐私**（本地/加密/可导出/可删/purge，铁律级承诺）；
- **RE-EVALUATE"长期未验证"= Android WorkManager/Doze 现实约束**（矩阵一行字=工程一整块，标注）；
- **生命链补死亡路径**：`TOMBSTONE/移除` + `Archive≠删除`，两出口都画、每转移=Timeline 记账；
- **L2 可见面**（◌ 确认 / 时间线只读页 / C 端词表）：**落地第1步前先定**，不裸奔进开发。

### P2
RELATION 断联降级（"遗忘"一个人）=情感敏感，**必须人拍板**；Router 误分类有默认信道兜底（Core+Semantic）；Timeline 检索接口（按时间区间 / 按记忆 id）定义。

## 〇、三条架构铁律
1. **`Event ≠ Memory`**：`Event=observed fact / Episodic=contextualized / Semantic=confirmed`；播 17 次《晴天》≠"喜欢"。
2. **`Current Memory is mutable. Memory History is immutable.`**：当前认知可变，Timeline 历史不可变。
3. **`记忆无限存储，知识有限暴露`**：Event/Timeline/Episodic/Semantic 可无限增长；AI 每次只拿**最相关、最可信、最新、最少量的那一小撮**。

> **收敛声明**：本版为 Memory OS **最终架构形态**。存储 + 检索两大域划分完毕，**不再增加新层**（不做知识图谱/自动总结/embedding 作为 P0）；下一步只有一件事——**把 `Event→Episodic→Candidate→Semantic→Re-evaluate→Archive` 生命链 + Timeline 记账 + Retrieval 消费跑通**。

## 一、总收敛架构图（存储 + 检索消费）
```
                        Unified Memory
                             │
 ┌───────────────────────────┴───────────────────────────┐
 ↓                       ↓                              ↓
[Event Store]      [Memory Timeline]              [Memory Layers]
 原始事实账本        不可变记忆历史账本                  │
 "世界发生什么"       "系统何时知道/怎么变"            ┌──┴──────┐
  append-only         append-only·不可改               ↓        ↓
                                                [Episodic][Semantic]
 └──────────────────────┬───────────────────────────────┘
                        ↓
              Memory Processor（单一入口：Extract→Merge→Update；同事务写 Semantic 快照 + Timeline append）
                        ↓
              [ Memory Index ]        ← 由存储派生（非双写）
                        ↓
              [ Memory Router ]       ← intent→层映射
                        ↓
              [ Memory Retrieval ]    ← 只读·Top-K
                        ↓
              [ Context Composer ]    ← 带来源·预算裁剪
                        ↓
                       AI
```
- **存储域**（无限）：Event / Timeline / Episodic / Semantic；
- **消费域**（暴露极少）：Index → Router → Retrieval → Composer → Context(几KB~几十KB) → AI；
- **Working Memory** = 运行时 context（不入库，横向，`Current → Working` 临时叠加）。

## 二、存储层（五层 · 承接 v4，不推倒）
| 层 | 载 | 说 |
|---|---|---|
| Event Store | 原始事实账本 | 媒体/Agent/外部，append-only；"世界发生了什么" |
| Memory Timeline | 不可变历史 | 记忆状态变化账本（append-only，actor 审计，Correction 追加） |
| Working | 运行时 context | 不入持久化，仅当前叠加 |
| Episodic | = 现有碎片层(契约v4+记忆页v5) | 情景记忆，保留不动 |
| Semantic | = 现有池子 v2 | 主记忆库，人工确认后"我懂你" |

**生命链**（核心）：`Event → Episodic → Candidate → Semantic → Re-evaluate → Archive`；所有状态变化**同事务写 Semantic 快照 + Timeline append**（原子写入管道，防"变了没记"）。

## 三、检索消费层（新增 · 只读·挑极少）
| 模块 | 职责 | 约束 |
|---|---|---|
| **Memory Index** | 为每个记忆建**检索画像**；**派生于存储**（非双写、可重建） | 同 `poolState`/`_index.json`——派生非事实源 |
| **Memory Router** | 判断 intent → 映射到层；**默认 Core+Semantic**，特定 intent 降级 | 保守；intent → Memory Type Matrix |
| **Memory Retrieval** | 挑**Top-K**（importance/confidence/freshness 排序） | **只读**，绝不写存储 |
| **Context Composer** | 组合上下文，**带来源标注 + 预算裁剪** | 每段标 CORE/SEMANTIC/EPISODIC/EVENT + 溯源 id |
| **Memory Core** | Semantic 的**极小投影**（1-4KB"瞬时用户模型"） | **派生视图，非 LLM 重写、非新事实源** |

## 四、分层检索优先级 + intent 映射
```
普通对话:   Core → Semantic → Episodic → Event(必要时)
历史问题:   Timeline → Event → Episodic
当前任务:   Working → Core → Semantic → Episodic
```
**Router intent → 层（Memory Type Matrix 映射）**：
| intent | 例 | 取层 |
|---|---|---|
| progress | "看到哪了" | Event / Episodic |
| preference | "推荐我喜欢的剧" | Semantic + Episodic 支撑 |
| historical | "去年最喜欢什么歌" | Timeline → Event |
| personalization | "按我习惯拆项目" | Core → Semantic → 当前项目 Episodic |
> 默认包 Core+Semantic；**不固定全读，动态 Top-K**。

## 六、Memory Core（瞬时用户模型 · 派生）
```
Semantic →(投影)→ Index →(投影)→ Core(1-4KB)
```
- **非** `LLM 重跑总结所有记忆 → Core`（否则又是"重写整库"）；
- Core = Semantic 的**派生摘要**（如「关于用户】游戏设计师·偏好简洁UI·重工程契约」「当前】正在做 Unified Memory」「工作方式】先P0·直接方案」）；
- 可重建：Core 变 ⇒ 由 Semantic 投影重算，**不与 Semantic 双写**。

---

## 七、上下文预算（Runtime 硬裁剪）
- **MVP**：Semantic 总量小 → Core 全量注入；超阈值（`POOL_FULL_INJECT_THRESHOLD=8KB` 泛化）→ Index + Top-K 精配；
- **Top-K**：Semantic 5~20、Episodic 5~20、Event 必要时几条；**总额由 Runtime 控制（几KB~几十KB）**，单层不超——"AI 每次看到极少"的工程保证；
- **可解释**：Composer 每段标来源（层 + 溯源 id），供 AI 引用、用户看"为什么基于这个"；
- **MVP 不用 embedding/RAG**：先索引精配 + importance/freshness 排序；embedding 后置（P2）。

**D. 生命周期 + 类型/冲突（表1/2/3 + 生命链）**
| # | 测点 | 变异锚 |
|---|---|---|

| # | 测点 | 变异锚 |
|---|---|---|

| E2 | Semantic 对 AI 只读 | AI 写库 |

### L2 真机取证（8 条用户路径 · 截图/回放印证）
1 看剧/听歌→Event 记痕→Episodic「正在看黑镜」；2 重复偏好→候选→建议→用户采纳→`关于我.md`；3 旧偏好→**◌ 待确认→[是][不是]→更新/保历史(ARCHIVED)**；4 **记忆时间线只读页**（喜欢晴天→听A→变B，无编辑入口）；5 对话「按我习惯拆项目」→上下文**很相关、很少、可解释来源**；6 「去年我最喜欢什么」→**历史信道**(Timeline)，常规对话不带 Timeline；7 用户分清「我的记忆↔记忆库」从属；UI 无 `confidence/decay 天数`；8 **空库**零影响。

## 十三、待定 / 边界
稳定模式阈值 N / C 端命名（记忆库·记忆时间线）/ Router intent 启发式（规则先于 LLM）/ `importance` 排序权重 / 云同步 / Obsidian（后置）/ embedding 与 Vector DB（后置 P2）/ Timeline 长期膨胀（索引 + 归档后置）/ `last_verified` 复核周期。

## 十四、落地序（自本版起收敛）
| 步 | 层 | 说 |
|---|---|---|
| **先行** | Semantic(池子 v2) + 生命周期管道（Type/Conflict/Re-evaluate/◌ UI/双向 Proposal）+ Timeline 记账 + **Retrieval(Core+Top-K)** | 用生命链串起碎片+池子，检索消费落地 |
| 其次 | Event Store + Pattern Detection → Candidate | 一切活动留痕、聚合候选 |
| 渐进 | Router intent 细化 / 自动升级频次 / 时间线 UI / 云同步 / embedding | 不再新增架构层 |

---

## 十五、结论
- v5 = **Memory OS 层结构冻结**：存储五层 + 检索消费层（Index/Router/Retrieval/Core/Composer）；
- **铁律**：`Event≠Memory` / `Current mutable·History immutable` / `记忆无限存储·知识有限暴露`;
- **收敛**：架构划分完毕，**停止加层**；下一步唯一要做 = **跑通生命链 + Timeline 记账 + Retrieval 消费**；
- **记录经历，不替用户定义是谁**——系统同时拥有**过去的你 + 现在的你**，且 AI 每次只取**极少、极准、可解释**的一小撮。
