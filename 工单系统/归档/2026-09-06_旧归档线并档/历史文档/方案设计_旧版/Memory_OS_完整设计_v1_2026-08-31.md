## 〇、定位与愿景
- **记忆不是"有/没有"，而是有生命周期、新鲜度、可信度**；「最常见的歌 ≠ 最喜欢的歌」。
- **记录"用户经历过什么"，不替用户决定"用户是谁"**——系统同时拥有**过去的你 + 现在的你**。
- **三条铁律**：
  1. `Event = observed fact / Episodic = contextualized / Semantic = confirmed`（Event ≠ Memory）；
  2. `Current Memory is mutable. Memory History is immutable.`；
  3. **`记忆无限存储，知识有限暴露`**——AI 每次只拿最相关、最可信、最新、最少量的那一小撮。

## 一、架构总览（五层存储 + 检索消费层）
```
                    Unified Memory
                         │
 ┌───────────────────────┴────────────────────┐
 ↓                       ↓                     ↓
[Event Store]      [Memory Timeline]      [Memory Layers]
 原始事实账本         不可变历史账本            │
 世界发生了什么        系统何时知道/怎么变      ┌──┴──────┐
 append-only          append-only·不可改     ↓        ↓
                                        [Episodic][Semantic]
 └───────────────────────┬────────────────────┘
                         ↓
            Memory Processor（单一入口：Extract→Merge→Update；同事务写 Semantic 快照 + Timeline append）
                         ↓
              [ Index → Router → Retrieval → Composer ]（只读·挑极少）
                         ↓
                       Context(几KB~几十KB) → AI
```
- **存储域**（无限）：Event / Timeline / Episodic / Semantic；
- **消费域**（极少）：Index → Router → Retrieval → Composer → AI；
- **Working Memory** = 运行时 context（不入库，横向临时叠加）。

## 二、底层契约（Memory API v4 · Episodic 门面）

### 2.1 状态机（幂等/冲突）
| 操作 \ 当前态 | DRAFT | ACTIVE | TOMBSTONE |
|---|---|---|---|
| promote(设为重要) | ok→ACTIVE | ok(幂等) | NOT_FOUND |
| remove(移除) | ok→tomb | ok→tomb | ok(幂等) |
| restore(撤销) | BAD_STATE | ok(幂等) | ok→回原态 / RESTORE_EXPIRED |
| setPinned(置顶) | ok | ok | NOT_FOUND |
- **restore 恢复完整状态**：tombstone 存 `previousStatus + previousPinned`，restore 回「原 ACTIVE+pinned 则仍 ACTIVE+pinned」；
- **错误码三分类**：失败回滚(TIMEOUT/UNKNOWN/RESTORE_EXPIRED/BAD_STATE)｜冲突 diff(NOT_FOUND)｜业务拒绝(PINNED_LIMIT/SYNC_TOKEN_INVALID)。

### 2.2 统一 Envelope
`{ok, code, data, syncToken, seq}`；UI 只判 `ok/code`。

### 2.3 API 表
`memoryList(filter,cursor,page=30)`(分页+facets 精确计数) / `memoryGetDetail(id)` / `memoryPromote(id)` / `memoryRemove(id)` / `memoryRestore(id)` / `memorySetPinned(id,pinned)` / `memoryChanges(syncToken)`(对账) / 标签：`memorySetTags(id,tags)` / `memoryListTags()`(M2 预留) / `memoryList`+`memoryGetDetail` 返回 `tags`。

### 2.4 规则
- **pinned 归属**：持久化在门面层**独立 PinnedStore(pinned.json)**，core 零感知、不进 MemoryEntity/记忆 DB；置顶≤3（**API 拒 PINNED_LIMIT + UI 禁第4** 双保险）；置顶移除释额 / 晋升保持置顶；
- **tombstone**：`remove` 立即生效(即时落库)，5s 撤销只是 UI(Snackbar→restore)，**不做**"5s 后才 tombstone"；只承诺"不再使用此条"（语义拦截留待定）；
- **标签(v4.1)**：`MemoryEntity + tags`(默认空) + 内部 `tagsTouchedByUser`(不入 API)；`memorySetTags` 规范化(trim/去重/≤8字/≤5)后置 true；AI 只对 `!touched && tags 空 && 晋升点` 打标、落库前重查；**人工改不被 AI 重覆盖**。

## 三、Episodic 层（记忆页 · 分层管理 v5）

### 3.1 C 端语言 ↔ API 语言
`DRAFT→待确认 / ACTIVE→已记住 / promote→设为重要 / pinned→置顶 / remove→移除(承诺"不再使用此条")`；API=ACTIVE/DRAFT/promote/pinned/tombstone。禁黑话。

### 3.2 两级极简 UI
- **一级（半屏 Sheet 列表）**：`我的记忆` 标题 + `共N条` + 搜索框(圆角8) + `已记住 / 待确认` 分层并列；行=content+副题+`›`；无卡片/状态点/标签（搜索态显示命中 tag pill）；行高≥44；
- **二级（点行进详情）**：内容大字 + 状态/来源/首次/最近/引用 + 标签区(灰 pill 增删改) + `[设为重要][置顶][移除]`——**操作下沉二级**（极简）；
- **半屏 Sheet 形态**：BottomSheetDialog、EXPANDED、70% 屏高、顶部圆角16、S0 底、暗色跟随 uiMode；撤销条深色圆角8 贴 safe-bottom；**撤销不跨旋转**（短生命周期=旋转视为确认移除——行为取舍）。

### 3.3 标签（AI 打标 + 二级手动改）
- AI 晋升点**异步**打 1-2 个短 tag(≤6字)，**禁凭空加**(UPG-06)、LLM 不可用→空(零编造)；人工 `memorySetTags` 后 AI 不覆盖(`tagsTouchedByUser`)；搜索命中标签显示 pill；打标跟随主对话同一 LLM 管道。

## 四、Semantic 层（统一记忆池 v2）

### 4.1 两级实体
- **`PoolDocument`**(篇=MD 文件：关于我/生活习惯/工作与项目/关系与社交) + **`PoolEntry`**(条目=篇内可溯源知识条目)；
- MD 分篇(非一份大 MD)；frontmatter=权威元数据，`_index.json`=**派生缓存**(可重建)；原子写盘覆盖 MD 本体；

### 4.2 溯源 + 版本证明
- `sourceIds`(来自哪些碎片) + **`sourceHashes`**(sha256,来源内容版本)——人工编辑后仍能判"当前句子等价于某源"；

### 4.3 晋升路径（先手动）
`碎片(ACTIVE)→「移入记忆库」→PENDING_POOL(AI 草案)→「采纳」→IN_POOL`；AI 只重组 content、禁凭空加；进池负向清单+时变标记；采纳时 `sourceHashes` 校验来源未变。

### 4.4 删除传播（P0-1 · 不自动删池）
`移除 IN_POOL 碎片 → 弹确认「一并移出记忆库？」`；一并移出=只删该条目 `sourceIds/sourceHashes` 引用(无他源→RE-EVALUATE)；保留=仅 tombstone 碎片；**池子文本不自动传播删除**(人工整理成果不因源碎片消失被拆)；撤销时回滚引用。

## 五、生命周期（三张表）

### 5.1 Memory Type Matrix
| 类型 | 含义 | 例 | decay |
|---|---|---|---|
| STATE | 当前状态 | 正在看黑镜S3E1 | 快 |
| PROGRESS | 进度 | 项目到P2 | 中快 |
| PREFERENCE | 偏好 | 喜欢简洁UI | 慢 |
| HABIT | 习惯 | 常用Obsidian | 中 |
| FACT | 事实 | 是游戏设计师 | 极慢 |
| IDENTITY | 长期身份 | 职业/原则 | 极慢 |
| RELATION | 关系 | 重要的人 | 慢 |

### 5.2 Lifecycle Policy Matrix
| 类型 | 何时观察 | 何时候选 | 何时 RE-EVALUATE | decay |
|---|---|---|---|---|
| STATE | 每次行为 | 状态变化即替换 | 不再观察即降级 | 快 |
| PROGRESS | 每次行为 | 连续推进 | 停滞超期 | 中 |
| PREFERENCE | 行为频次 | 稳定模式(≥N) | 长期未验证/diff | 慢 |
| HABIT | 行为模式 | 重复出现 | 模式消失 | 中 |
| FACT | 声明/确认 | — | 长期未验证 | 极慢 |
| IDENTITY | 声明/沉淀 | 稳定模式 | 明确冲突 | 极慢 |
| RELATION | 交互频次 | 高频交互 | 长期断联 | 慢 |

### 5.3 Conflict Matrix
| 判据 | 例 | 判定→处理 |
|---|---|---|
| 同类型互斥 | 「最喜欢A」vs「现在最喜欢B」 | 冲突→RE-EVALUATE |
| 同类型不互斥 | 「偏好爵士」vs「最近听摇滚」 | 不算冲突(并存) |
| Observed≠Inferred | 播《晴天》17次 | 不算"喜欢"→只候选 |
| 新证据覆盖 | 2026晴天→2028听A | 旧条 RE-EVALUATE(保历史) |
| 身份 vs 偶发 | 「游戏设计师」vs 偶尔玩局 | 不算冲突 |

### 5.4 语义状态机 + 极简 UI
`ACTIVE(注入 ✓) / RE-EVALUATE(禁注入 ◌) / ARCHIVED(禁注入·历史)`；Re-evaluate=事件驱动(decay 到期/冲突)、低频非阻塞(◌ 点进才确认)；"不是"→ARCHIVED 保历史不删。UI 只看 ✓/◇，无 confidence/decay 天数。

## 六、Timeline 底座（不可变）
- **契约**：`MemoryTimelineEntry{id,timestamp,eventType(OBSERVED/PROPOSED/ACCEPTED/REEVALUATED/REJECTED/ARCHIVED/CORRECTION),subject,payload,actor(user/ai-proposal/system-decay),sourceIds,reason,previousMemoryId,correlationId}`；
- **不可变**：只允许 CREATE/APPEND/READ；`UPDATE/DELETE/REWRITE` 无入口(连 dev 无 `delete/update`)；
- **actor 审计**：AI 只 `ai-proposal`·`PROPOSED`；`ACCEPTED/REJECTED/ARCHIVED` actor=user——数据结构锁死"AI 不改用户长期认知"；
- **Correction**：判错→追加 CORRECTION，旧条原样；**purge**：人类触发彻底抹除(记录+数据打标，历史可标注不可改)；
- **管辖声明**：Timeline **现阶段 = Semantic 历史账本**（碎片 promote/remove/pin 不 append Semantic Timeline，其历史走 Event Store/碎片 journal + 后续 hook）；原子写入（Semantic 变 ⇒ 同事务 Timeline append）。

## 七、检索消费层（知识有限暴露）
- **分层检索**：普通对话 `Core→Semantic→Episodic→Event(必要时)`；历史 `Timeline→Event→Episodic`；当前任务 `Working→Core→Semantic→Episodic`；
- **Router(保守默认)**：默认 Core+Semantic；intent→层（progress→Event/Episodic、historical→Timeline、personalization→Core+Semantic+Episodic）；
- **Index/Core 为派生**（由 Semantic 元数据投影、规则选条目拼接，**非 LLM 重写**、非双写、可重建）；
- **预算裁剪**：Core < 阈值(`POOL_FULL_INJECT_THRESHOLD=8KB` 泛化)全量；超→Index+Top-K；总额 Runtime 控(几KB~几十KB)；**MVP 不用 embedding/RAG**(P2)；
- **可解释**：Compose 每段带来源(层+溯源 id)；Timeline/Event 不走 Index(按时间/actor 直查)。

## 八、评审收口（P0×3 + 承接旧账）
- **P0-1 删除复活**：`移除→blockedSourceHashes→候选生成/Pattern Detection 过滤其派生→(移除IN_POOL碎片→副本标RE-EVALUATE)`；purge 逃生口——**结构保证"删掉的不回来"**；
- **P0-2 Timeline 管辖**：两个写者(Processor 管 Semantic+Timeline；碎片 Lifecycle writer 管 Episodic)，Timeline 现=Semantic 账本；
- **P0-3 冻结真义**：冻结接缝(API 形状/事件类型/状态机)；**参数版本化**(decay 阈值/Router/importance/稳定N→配置不冻结)；承接旧账(契约 v4/记忆页 v5 已定：setPinned/restore/tombstone/tagsTouchedByUser 不重冻)。

## 九、验收方案（L1/L2/L3 · 不信自报信实物）

### 测点 A~E（证据 + 变异锚·改回旧实现必红）
- **A 删除复活屏蔽**：A1 记 blockedSourceHashes；A2 候选过滤(删后重复同源不复活)；A3 移除 IN_POOL→副本 RE-EVALUATE；A4 purge 接口。
- **B Timeline**：B1 原子(Semantic 变⇒Timeline append)；B2 无 update/delete；B3 actor(AI 只 PROPOSED)；B4 Correction 追加；B5 碎片不 append Semantic Timeline。
- **C 检索消费**：C1 Retrieval 只读；C2 Router intent 映射；C3 预算裁剪；C4 每段带来源；C5 Index/Core 派生(非 LLM)；C6 Timeline/Event 不进 Index。
- **D 生命周期**：D1 生命链含死亡路径(TOMBSTONE/Archive≠删除)+每转移 Timeline 记账；D2 冲突逐格；D3 跨层冲突；D4 人工确认锚；D5 memoryType 差异；D6 freshness 派生/不暴露。
- **E 隔离**：E1 三层隔离(memory-api 零改)；E2 Semantic 只读；E3 Event append-only；E4 Index/Core 派生一致。

### L2 真机取证（8 路径 · 截图/回放）

## 十二、结论
- Memory OS = **记录经历过什么，不替用户定义是谁**；三条铁律 + 五层存储 + 检索消费层；
- **层结构冻结**（非"最终形态"）：层到头，接缝(P0×3)已收口，参数版本化；
- 下一步唯一要做：跑通 `Event→Episodic→Candidate→Semantic→Re-evaluate→Archive` 生命链 + Timeline 记账 + Retrieval 消费 + blockedSourceHashes；
- **同时拥有过去的你 + 现在的你**，且 AI 每次只取**极少、极准、可解释**的一小撮。
