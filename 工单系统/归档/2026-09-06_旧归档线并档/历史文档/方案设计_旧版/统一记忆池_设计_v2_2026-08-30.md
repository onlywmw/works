## 一、背景 / 为什么
碎片天然散（同事多条/冲突/过时）。AI"懂你"靠碎片只是记住字面；聚成 MD 篇 AI 能整段引用、连续一致，人也能翻开看。MD 开放可迁移、可接 Obsidian（后置）。人工把关 = 质量。

## 二、分层架构
```
[碎片层 · v5]  Memory API 契约 v4 + 记忆页 v5（定稿收口）
  DRAFT/ACTIVE/TOMBSTONE · 标签 · 置顶(≤3) · 5s撤销 · 两级UI
```

## 四、记忆池形态（PoolDocument / PoolEntry 两级）

### 4.1 两级工程实体（钉死③）
```
PoolDocument  = 一篇 MD 文件（"关于我.md"）        → pool.get(篇)/pool.update(篇,md)
PoolEntry     = 篇内一条可溯源的知识条目            → 承载 sourceIds/sourceHashes/审查状态
```
- **篇 = Document**（归档单元：按主题分篇，不一份大 MD）；
- **条目 = Entry**（知识单元：篇内一行/一区块，含溯源与状态）。

```
关于我.md                          ← PoolDocument
# 关于我
- 喜欢简洁、低干扰的 UI                 ← PoolEntry
  sourceIds: [mem_001, mem_002]
  sourceHashes: {mem_001: sha256:ab…, mem_002: sha256:cd…}
  status: ACTIVE
- 做产品时倾向先定义工程契约            ← PoolEntry
  sourceIds: [mem_003]
  sourceHashes: {mem_003: sha256:ef…}
  status: ACTIVE
```

### 4.2 溯源 + 来源版本（钉死①）
- **`sourceIds`**：这条池内内容**来自哪些碎片**（溯源）；
- **`sourceHashes`**：来源碎片**内容哈希**（sha256）——解决"人工编辑后当前句子是否仍等价于某源"。评审动作（§五.4）据此判断来源是否未变；删除传播（§九.2）据此定位要移除的来源；
- **frontmatter / 索引**：`frontmatter` = 权威元数据；`_index.json` = **可重建派生缓存**；**原子写盘覆盖 MD 本体**（不只 index），迁移幂等；
- Obsidian 打通**后置**（frontmatter+索引即桥梁）。

## 五、晋升路径 + 状态机（MVP 先手动）
```
碎片(ACTIVE) ──「移入记忆库」──▶ PENDING_POOL(AI 草案)
                                    │ 用户「采纳」
                         ┌──────────┴──────────┐
                     source 未变            source 已变/删除
                         │                      │
                         ▼                      ▼
                       IN_POOL              拒绝采纳(提示重核)
                         │
              ┌──────────┴──────────┐
              │                     │
            无冲突                 有冲突
              │                     │
              ▼                     ▼
        Entry.ACTIVE          Entry.REVIEW_REQUIRED
        (AI 可注入)             (AI 禁止注入)
```
1. 入口：碎片二级详情「移入记忆库」（**MVP 先手动**；自动聚类挂 flag 后置——省 LLM / 避竞态 / 与 v4 标签"增强非依赖"同思路）；
2. AI 草案：聚类相关碎片 → MD 草案（归篇），标注「建议整理 · 主题 XX」——**只重组碎片内容，禁凭空加**（UPG-06）；
3. 进池判据：**负向清单 + 时变标记**（短时效状态类"最近在学X"打时变标记；凑不成篇的单条不硬塞）；不设正向硬规则（人拍板=规则）；`PENDING_POOL` 防重复晋升；
4. 采纳竞态：`sourceHashes` 校验**来源仍存在且未变**；变 → 拒绝采纳提示重核。
> **`poolState` = 派生自池子存储**（非双写），契约测试锁一致（PENDING_POOL 由 draft 存在、IN_POOL 由 Entry.sourceIds 含该碎片、NONE=都不满足）。

## 六、编辑权 / 防过时（条目状态机，钉死②）
- 池子内容**人工可编辑**；**AI 端只读**（检索用不写入）；
- **池内条目状态机（唯一）**：
  | 状态 | 语义 | AI 注入 |
  |---|---|---|
  | `ACTIVE` | 正常 | **允许** |
  | `REVIEW_REQUIRED` | 可见，禁注入 | **禁止**（硬约束） |
  | `ARCHIVED` | 不参与检索 | 禁止 |
- **冲突检测（在入池时）**：新碎片入池与同主题 diff → 命中冲突的旧条目置 `REVIEW_REQUIRED` 并从注入剔除，直到用户裁决——**陈旧/冲突内容不静默进 AI 上下文**；"最近确认为准"已删除；
- **沉积层**：冲突提示长期被忽略 → `last_verified`（v4 留口兑现）扫描，超期未验 → `REVIEW_REQUIRED` 或降级。

---

## 七、AI 调取优先级（检索策略）
- **注入预算（钉死④）**：**MVP 默认 `POOL_FULL_INJECT_THRESHOLD = 8KB`**——低于它全量注入；高于走 `poolSearch`（索引精配 + FTS，embedding 后置）。**8KB 是阈值，不是绝对 token 安全线**（中文/英文密度不同）；**实际上下文预算由 Runtime 最终裁剪**，换模型不被此数绑死；
- **优先级**：池子 > 碎片；**同一事实**：池子命中 → 不叠加碎片版本；**不同信息需求** → 两层并行取（非"命中就不读碎片"）；
- **来源标注**：调取池子 → 侧标「来源=记忆库」（渲染位置见 §十一 待定）；碎片 → 标原文；呼应 v5 溯源；
- 池子未命中 → 回退近期碎片；空池 = 零行为变化（安全）。

## 八、与现有体系关系
- `memory-api` / Lifecycle：零改动；**承认对 v5 小改**：
  - 碎片详情页**露「已入记忆库」状态**（IN_POOL）；
  - 「移入记忆库」按钮对已入池条目**变文案**（「已入记忆库」/只读）；
- **`MemoryEntity` + `poolState`**（内部，迁移兼容）：`NONE / PENDING_POOL / IN_POOL`；旧实体缺字段 → `NONE`（不丢数据）；**派生自池子存储非双写**；与碎片层 `DRAFT` 撞名已避。

## 九、工程契约
### 9.1 池子 API + 数据
- API：`pool.list(主题)` / `pool.get(篇)` / `pool.search(query)` / `pool.confirm(draftId)`(=「采纳」) / `pool.update(篇,md)` / `pool.discard(draftId)` / `pool.promote(碎片id→draft)`(=「移入记忆库」)；
- 存储：PoolDocument 分篇 + frontmatter（权威）+ `PoolEntry`（含 sourceIds/sourceHashes/status）+ `_index.json`（派生缓存）；**原子写盘覆盖 MD 本体**；
- 检索：索引精配 + FTS（MVP 全量注入优先）；**只在池内容里引用**（防编造 UPG-06）。

### 9.2 删除传播（P0-1 · 定死）+ 图
```
IN_POOL 碎片删除 (v5 remove)
        │
        ▼
「此条已整理进记忆库，是否一并移出？」
        │
   ┌────┴────┐
   是         否
   │          │
   ▼          ▼
删 targetEntry.sourceIds 中  池子不动
该碎片 + 对应 sourceHashes   碎片 tombstone
   │
   ▼
该 Entry 无其它来源？
   ├─ 否 → 正常
   └─ 是 → 置 REVIEW_REQUIRED（人工裁决是否删 Entry 文本）
```
- **源碎片删除 ≠ 自动传播删除人工整理的记忆库文本**（防"你为什么把我确认过的东西删了"）；
- "一并移出" = 只删 **Entry 里该碎的 `sourceIds`/`sourceHashes` 引用**；若 Entry 因此无其它来源 → `REVIEW_REQUIRED`（用户可再决定删整条目）；
- "保留" = 仅 tombstone 碎片，池子不动；
- 撤销（restore）时若已一并移出 → **回滚池子 sourceIds 引用**（与 restore 恢复完整状态一致）。

## 十、验收测点
- **L1**：①聚类草案去重/归篇 ②「采纳」→ `PENDING_POOL→IN_POOL`（防重复）③**人工采纳后 AI 不自动改写池**（变异：AI 写入→必红）④`poolSearch` 只在池内容命中 ⑤**同一事实**池子命中不叠加碎片 ⑥池子未命中→回退碎片 ⑦`poolState` 迁移兼容（旧→NONE）⑧冲突→旧条目 `REVIEW_REQUIRED`、**AI 禁止注入**（变异：冲突条目仍注入→必红）⑨**删除传播**：删 IN_POOL 碎片→确认两态（一并移出→删 sourceIds/来源源→无他源→REVIEW_REQUIRED；保留→池不动）⑩采纳竞态：`sourceHashes` 不符→拒绝入库 ⑪frontmatter 权威>index（重建一致）⑫条目三态语义（ACTIVE 注入/REVIEW 禁/ARCHIVED 不检索）⑬`last_verified` 存疑→REVIEW。
- **L2 真机**：「移入记忆库」→草案→「采纳」→入库；AI 引用库→溯源「来源=记忆库」；删 IN_POOL 碎片→确认弹窗两态即时生效；详情页「已入记忆库」；用户能分清「我的记忆ᵃ记忆库」。
- **L3**：碎片层/池层隔离（仅动 `memoryPool`，`memory-api` 零改）；`poolState` 派生自池存储（契约测试锁一致）；池子对 AI 只读约束测试；MD 本体原子写盘迁移幂等。
