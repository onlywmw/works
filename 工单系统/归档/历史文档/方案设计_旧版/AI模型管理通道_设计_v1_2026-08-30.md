# AI 模型管理通道 · 设计 v1（打通「设置页 ↔ 模型库 ↔ 运行时 ↔ 显示」一条链）

> 设计师 @2026-08-30 ｜ 状态：设计定稿（待评审后可实施）
> 起因：用户「**不能只有各搞各的**」——现在的模型链路是散的：设置页只显示模型 + 绑死「DeepSeek API Key」一个口、ModelStore 有 CRUD 但 UI 没开放、ModelRegistry 另有同步、chipLabel 显示又一套。要打通成**一条统一通道**：设置页加/切模型 → ModelStore → Registry → 聊天页模型 chip 显示/切换 → 请求用该模型自己的 key/baseUrl。

**诊断（用户点破的"各搞各的"）**：
1. **设置页绑死 DeepSeek**：key 走 `credential.setKey`(DeepSeek 专属单 key)，模型走 `model.add`(ModelStore)——**两条通道**，key 不归属模型；
2. **设置页无模型管理 UI**：`model.add/setDefault` 底层在，但 UI 没开放 → 用户加不了别的模型；
3. **显示层无缩写**：`chipLabel` 用完整 label(无缩写规则)；
4. 四处各管各的(设置页/ModelStore/Registry/chipLabel)，**未连成一条链**。

## 二、目标：一条统一通道（消除各搞各的）

```
设置页「AI 模型管理」       ← 管理入口(唯一)
  列表(现有模型·当前✓) / 添加 / 切换 / 删除
        │ 全走 model.* CRUD
        ▼
ModelStore (model_store.json)   ← 数据唯一源(每模型含 provider/model/baseUrl/keyName/label)
        │ syncModelRegistry
        ▼
ModelRegistry (current/list/use)  ← 运行时注册表
        │ current() → label/缩写 + modeName
        ▼
聊天页模型 chip (显示 + 切换)        ← 展示层
        │ 请求走该模型 key/baseUrl
        ▼
DeepSeekAdapter / 其它模型 Adapter  ← 真正发起请求
```

**核心**：模型(含 key/baseUrl)全在 **ModelStore** 一处，由**设置页模型管理**统一增删改；聊天页 chip/请求都读 Registry(由 ModelStore 同步)；**key 归属模型**(每模型自己的 key)，不再是"DeepSeek 专属单 key"。**换模型 = 设置页加/切，零代码改动。**

## 三、分层设计

### L1 数据层：ModelStore（单一来源，已有）
- 保持 `ModelStore.Entry(id, provider, model, baseUrl, keyName, label, enabled)`；**keyName 指每个模型自己的 key(归属模型)**；
- **key 存储**：keyName 指向安全存储(SharedPreferences 加密 / EncryptedSharedPreferences / credential.vault)——**不建议明文**；`model.add/update` 时 key 走同一安全层；取代 `credential.setKey`(DeepSeek 专属)。

### L2 管理层：model.* CRUD（已有，补契约）
- `model.list`(含 isDefault/enabled) / `model.add` / `model.update` / `model.delete` / `model.setDefault` —— 已实现，接设置页；
- 设置页**每次改动**后 `syncModelRegistry`(已有)，保证 Registry 与 ModelStore 一致。

### L3 设置页「AI 模型管理」UI（**新增·核心缺口**）
- `AI 模型` 行点进 → **模型管理页**：
  - **列表**：每模型一行(label + provider + 当前✓/启用开关)，点击切换 `model.setDefault`，右滑删除 `model.delete`；
  - **＋添加**：表单 = 模型名(label)/供应商(provider)/接口地址(baseUrl)/模型 id(model)/API Key(keyName)/是否默认；
  - 编辑：改 key/baseUrl/label = `model.update`；
- 替换现在「AI 模型(显示) + DeepSeek API Key(credential.setKey)」两行 → 成一个「**AI 模型管理**」入口。

### L4 运行时：ModelStore → Registry（已有 sync）
- `syncModelRegistry`(MainActivity:2057) 从 `modelStore.list()` 同步到 `ModelRegistry`；`current()/use()` 供 chip/请求读。

### L5 显示层：模型 chip（改缩写 + 读元数据）
- `ChatChips.chipLabel(provider, modelId, modeName)` → 缩写 `provider + 主版本(modelId)`(如 DeepSeek V4) + ` · modeName`；无版本→provider；
- **缩写规则** = 供应商(provider) + 主版本(从 model id 提取)——**元数据驱动，换模型自动缩对，不硬编码**；
- 完整名(label)悬浮/详情可查。

## 四、打通点（消除"各搞各的"，逐一对应）

| # | "各搞各的"现状 | 打通到 |
|---|---|---|
| 1 | 设置页 key 走 `credential.setKey`(DeepSeek 专属单 key)，与模型分离 | key 归**每个模型**(keyName)，模型管理里配，走安全存储 |
| 2 | 设置页只有显示模型行，无管理 UI，加不了模型 | 设置页=**AI 模型管理**(列表/添加/切换/删)，接 model.* |
| 3 | 模型数据 ModelStore / Registry 双份可能不同步 | 设置页改完**立即 syncModelRegistry**，Regist 单向从 Store 同步 |
| 4 | 显示用完整 label(无缩写) | `chipLabel` 用元数据 provider+版本**生成缩写** |
| 5 | 请求不一定是"当前模型的 key/baseUrl" | 请求侧读 `Registry.current()(baseUrl/keyName)` → 用对应 adapter+key |

## 五、验收测点
- **L1**：①模型管理页 list=ModelStore 全量(含当前✓) ②添加任意模型(填 provider/model/baseUrl/key) → ModelStore 新增 + Registry 同步 + 请求可用 ③切换 setDefault → Registry.current 变 + chip 变 ④key 归属模型(不同模型不同 key 生效，非 DeepSeek 共享) ⑤chip 缩写随 provider+版本生成(GPT-4o/Qwen2.5/Kimi V2 都自动缩对，非硬编码)。
- **L2 真机**：设置页加一个非 DeepSeek 模型 → 聊天页模型 chip 显示其缩写 → 切换到该模型 → 发起对话用该模型 key/baseUrl 成功(ModelRegistry.current().label/use 验证)；key 脱敏存储(shared_prefs 无明文)。
- **L3**：请求侧 adapter 按 current().baseUrl/keyName 路由(DeepSeek 特判移除/或留作 provider 分发)；旧 `credential.setKey` 与新的 per-model key 不冲突(迁移/废弃)。

## 六、实施切分（单）
- **单 1 · 设置页 AI 模型管理 UI**（核心缺口）:列表/添加/切换/删界面，接 model.* CRUD + 表单(模型名/供应商/接口/模型id/API key/默认)。
- **单 2 · API key 归属模型 + 安全存储**：model.add/update 的 key 走安全层(EncryptedSharedPrefs/credential.vault)，替代 credential.setKey(DeepSeek 专属)；请求侧读 current().keyName。
- **单 3 · 显示层 model chip 缩写**：`ChatChips.chipLabel(provider, modelId, modeName)` 用元数据生成缩写 + 完整名悬浮；同步原生/Vue 两处 label 链路。
- **单 4 · 请求路由**：adapter 按 current().provider/baseUrl 分发(去 DeepSeek 特判残留)，确保"当前模型的 key/baseUrl"。

> 依赖：单 1/2 是通道主干(管理+key 归属)；单 3/4 是显示/请求接线。ModelStore/model.*/syncModelRegistry **底层已备，无需新建**——只补 UI + key 归属 + 缩写 + 路由。

## 七、风险与备注
- **key 安全**：模型 key 必走安全存储(明文=风险，红线)；`credential.setKey` 迁移需兼容(旧的 DeepSeek key 迁到 per-model)。
- **兼容**：现有 `model.list/setDefault` 契约不变；设置页加管理不破坏现有"AI 模型"行(升级为管理入口)。
- **不绑死**：模型全元数据驱动(provider/model/baseUrl/keyName/label)——换模型 = 设置页添加，零代码改动；chip 缩写、请求路由都读元数据。
