## 一、C 端语言定案（v4 · 大神开工前 4 件事）

| 内部模型(API 不动) | C 端文案(定案) | 说明 |
|---|---|---|
| DRAFT | **待确认** | C 端不用"草稿"——用户会说"草稿=我写一半没保存的",真实语义是"AI 认为有价值、待你确认长期保留" |
| ACTIVE(晋升) | **已记住** | "草稿/已固化"是系统语言;用户懂"已记住/待确认" |
| promote → | **设为重要** | C 端不出现"晋升"(黑话);底层 `memoryPromote` 不变(产品语言≠API 语言) |
| pinned → | **置顶** | "固定"与"设为重要"语义冲突;改"置顶"(=排序),与"重要(=生命周期)"区分 |
| toggle(移除非本条) | 承诺**"移除后不再使用此条"** | **不承诺拦截语义相似的新记忆**(tombstone 只挡本条;语义拦截底层待定,别被文案绑架) |

> 四个定案:①C 端用「设为重要」非"晋升" ②「固定」→「置顶」 ③「草稿」→「待确认」(经评审,定为"待确认";"已记住"为 ACTIVE) ④删除只承诺"不再使用此条"。

## 二、界面(简单)

```
我的记忆
共 12 条 · 已记住 4 · 待确认 8
🔍 搜索记忆…
[ 已记住 | 待确认 ](筛选;默认=已记住前置+待确认在后)

已记住
📌 我喜欢简洁的界面
   MOV 会优先参考
   置顶    移除
   （内容→点它进详情）
待确认
   我最近在学习……
   设为重要    移除
```

## 三、操作(语义清晰)
- **设为重要**(待确认 → 已记住):底层 `memoryPromote`(失败回滚/竞态 diff/loading 防抖);
- **置顶**(已记住):UI 排序偏好,稳定 ID(非 hash),**≤3 条(与 API 契约一致)**,移除/降级时清理;
- **移除**(两层):tombstone 软删("不再使用此条")+ 5s 撤销(回原位,旋转不失效)。

## 五、工程契约（v4 · 大神点重点 · 下一步最该做的）

大神:UI 做得再漂亮,若「按钮看起来工作了但真实状态没变」就白搭。**下一步把整条链路定成工程契约**:
```
Memory API 门面(memoryPromote/memoryRemove/memoryList)
        ↓
MemoryLifecycle(memoryPromote 落库 / memoryRemove tombstone)
        ↓
judge(自动晋升,幂等)
        ↓
UI diff(以底层返回为准,不乐观写死)
        ↓
持久化(原子写盘/迁移版本/幂等)
```
- **契约**：呈现层只 import 记忆 API 门面(不触 MemoryLifecycle 内部);所有状态变更以**底层返回为准**做 diff;UI 乐观态必须能被底层权威覆盖;
- 落点：L3"解耦"固化为**依赖检查/契约测试**(非口号)——防"按钮看起来工作、状态没变"。

## 十、记忆标签（2026-08-30 拍板：AI 自动打标 + 二级手动改）

> **现状**：底层契约 v4 **无 tag 字段/API**（`ListItem/MemoryEntity` 仅 id/content/status/createdAt/lastUsedAt/refCount/pinned/kind，`kind`=记忆源非用户标签）→ 标签为**新功能**，需动 Entity + API + 存储迁移，非改 Sheet 即可。
> **定位**：与生命周期（已记住/待确认）、排序优先级（置顶/重要）**正交的第三维度 = 发现**。标签来自内容、不占名额（区别于置顶 ≤3）；AI 默认 1-2 个、克制。

### 10.1 数据模型（MemoryApi 契约扩展为 v4.1）
- `MemoryEntity` + `tags: List<String>`（可空，默认空）；
- **迁移兼容**：旧实体缺 tags 字段 → 渲染为空标签，**不丢已有记忆**（向后兼容约束）；
- MemoryApi 新增：
  - `memoryGetDetail` 返回 `tags`；`memoryList` 的 `ListItem` 加 `tags`；
  - `memorySetTags(id, tags: List<String>)`：手动改（覆盖，含清空）；
  - `memoryListTags(): List<String>`：全量标签集合（供筛选）；
  - `memoryList(filter, tag?, …)`：加按 tag 过滤参数。

### 10.2 AI 打标（自动 · 增强非依赖）
- **时机**：记忆**晋升 ACTIVE** 时**异步**打标（DRAFT 产生亦可，推荐晋升点）；打标不阻塞记忆主链。
- **生成**：LLM 依 **content 提炼** 1-2 个短标签（≤6 字）——**禁凭空加**（UPG-06：只提炼，不猜语义）；置信低/LLM 不可用 → **tags 为空**（零编造）。
- **来源冲突规则**：人工 `memorySetTags` 后，AI **不覆盖人工**（人工改=生效；AI 只填补未打标项）；MVP 不区分 ai/manual 来源字段，`tags` = 当前生效标签。

### 10.3 UI（极简约束）
- **一级列表**：**不加标签**（保持 §九 极简，防破坏清净）；
- **二级详情**（§九.2 点行进入）加「标签」区：当前标签=轻量灰底 pill（11px TEXT2），可点删；「＋」输入新 tag；一个输入框、逗号/回车分隔多 tag；
- **搜索顺带命中标签**（`content + tags` 匹配，低成本，正是"发现"价值）；
- 可选 M2：一级顶部"按标签筛"入口（灰小字下拉）——**MVP 不做**，先搜索 + 二级编辑。

### 10.4 验收测点
- **L1**：①晋升记忆自动打标（断言 tags 非空且 ≤2、词来自 content）②详情 tags 可增/删/改/清空 ③**人工改不被 AI 重覆盖** ④旧实体无 tags → 渲染空（迁移兼容）⑤搜索命中标签 ⑥LLM 不可用 → 空标签零编造。
- **L2 真机**：晋升记忆 → 详情见 AI 标签；手动加/删即时生效；无 LLM 场景 → 空标签、记忆仍可用。
- **L3**：`Entity.tags` 单源；AI 打标与记忆主链**解耦**（fail 不影响记忆可用/调出）；标签无上限但 AI 默认 1-2。
