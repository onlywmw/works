## 一、L1 代码/契约层（自动化 + 静态核实）

### 1. 状态机契约（核心,逐格断言）
- `promote/remove/restore/setPinned` × `DRAFT/ACTIVE/TOMBSTONE` 状态机表**逐格断言**(记忆 API 契约测试);
- **幂等重放**:同操作重复调用 → 返回当前成功状态(ok:true, 当前 status/hidden),不再报错;
- **删除死错误码**:`ALREADY_PROMOTED/ALREADY_REMOVED` 在代码中**零出现**(变死码=不可测分支);
- **变异锚**:①restore 未恢复 previousPinned → 必红 ②remove 做成"5s 后才 tombstone" → 必红 ③change 里带 lastUsedAt → 必红。

### 2. Result Envelope 统一
- 各 API(memoryList/detail/promote/remove/restore/setPinned/changes)**统一 `{ok, code, data, syncToken, seq}`**——断言 UI 层只检查 ok/code,不按各 API 兼容不同返回类型。

### 3. memoryChanges / 对账
- 首 token=list 首页附 syncToken(同读快照);`SYNC_TOKEN_INVALID` → 全量回退 + **新 token 成基线**;变更结构 `{id,op,status,seq}`;lastUsedAt 不进变更流;在途操作竞态按 id 去重、seq 高者为准。

### 4. pinned 归属
- pinned 持久化在 **memory-api 门面层**,`memory-core/MemoryLifecycle` **零感知**(grep 证实);
- 置顶移除→释额;草稿晋升→保持置顶;上限 3 = 原子 check-and-set(连点不破)。

### 5. keyset 分页 / facets
- 游标 keyset(排序元组+id,非 offset);`facets.activeCount/draftCount` **精确分状态计数**(与 syncToken 快照一致,非"约");置顶/取消置顶 → UI 重拉第一页。

### 6. 依赖检查（L3 硬门槛落地）
- `memory-api`(门面,UI 只依赖)/`memory-core`(Lifecycle+Persist)模块化;Gradle 依赖配置 或 ArchUnit 包依赖测试 **CI 必跑**;呈现层只 import 门面,不触 core 内部(依赖检查通过)。

## 三、L3 异常/恢复层（工程契约验收）

1. **契约/竞态/失败注入/迁移幂等/UI diff 测试全绿**(进 CI,关键测试为硬门槛);
2. **进程/配置恢复**:添加模型→强杀→重开:Store/Registry/会话/KeyVault 正常;测试中强杀→重开:`TESTING→UNTESTED`(不留永久态);
3. **SYNC_TOKEN_INVALID 自愈**:旧 token 失效→全量刷新 + 新 token 成基线;
4. **并发/竞态**:promote×judge 幂等无副作用;restore×remove 竞态正确;置顶连点上限不破;
5. **原子写盘 + 迁移幂等**:model_store / memory 存储文件中断/并发后完整;version 升迁二次启动不重复建;
6. **tombstone 语义**:移除只承诺"不再使用此条"(不承诺拦截同内容再写入——边界明确)。
