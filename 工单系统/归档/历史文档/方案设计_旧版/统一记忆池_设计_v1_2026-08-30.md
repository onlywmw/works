# 统一记忆池（MOV 记忆 v2）设计 v1 · 评审稿

> 设计师 @2026-08-30 ｜ 状态：**待大神评审**（非定稿；用户提议"统一记忆"，我据此成稿）
> 底层：Memory API 契约 v4 + 记忆页分层管理 v5（**保留不动**，本设计在其上增量叠加）
> 核心：碎片 = 事件记忆（"你说过"）；**统一记忆池 = 知识记忆（"我懂你"）**——一份经人工/确认、按主题组织的 Markdown 知识库，AI 调取记忆时**优先读它**，未命中再读近期碎片。

---

## 〇、一句话
MOV 现在的记忆是**碎片**（AI 自动抓的事件碎末，如「喜欢简洁的界面」「最近学健康」）——能"记住"却不成体系、"懂"不了人。本设计新增一层**统一记忆池**：用户/AI 把优质碎片**整理成按主题组织的 MD 文档**（人工确认入库），AI 调取记忆时**优先读这份池子**。碎片层保留（近期上下文），不推翻契约 v4 / 记忆页 v5。

---

## 一、背景 / 为什么
- **碎片天然散**：同一件事被记成多条、可能冲突（"刚搬家" vs 旧住址）、会过时（"每周三健身"）。靠一堆零散片段，"AI 懂你"只是记住字面，不是理解。
- **知识记忆才有"懂"**：把碎片聚成一篇「关于我」「生活习惯」的 MD，AI 能**整段引用**、连续一致，用户自己也能翻开看——这是质变。
- **MD 开放可迁移**：人类可读、机器可注入、不锁定，还能和 MOV 的 Obsidian / md 生态打通。
- **人工把关 = 质量**：AI 自动记的会误/乱/时变；人确认一次，来源可控（呼应记忆页 v5「删除只承诺不再用」的克制）。

---

## 二、分层架构（不推翻，增量叠加）
```
[碎片层 · 现有，零改动]  Memory API 契约 v4 + 记忆页 v5
   DRAFT / ACTIVE / TOMBSTONE · 标签 · 置顶(≤3) · 5s 撤销 · 两级 UI
              │  晋升/整理路径（碎片 → 池子）
              ▼
[记忆池层 · 新增]  统一记忆池 = MD 多篇 + 索引 + frontmatter
   只读给 AI（AI 检索用，不写入）· 人工/确认后编辑
              ▲
[AI 调取优先级]   ① 池子（权威·优先）→ ② 近期碎片（兜底·上下文）
```
- 碎片层 = "当下"（会话、临时）；池子层 = "长期懂你"；两层分工，非互相替代。
- 迁移/改造**只动 `memoryPool` 新域**，`memory-api`/Lifecycle 零改动（隔离，防回归）。

## 三、C 端语言 vs API 语言（词表唯一）

| 内部(API) | C 端文案 | 说明 |
|---|---|---|
| pool / 池子 | **「记忆库」** | C 端不说"池子"（黑话） |
| promote 碎片→池 | **「移入记忆库」** | 不说"晋升"；底层 `pool.promote` |
| pool.confirm(草案→入库) | **「确认」** | 人工确认整理草案 |
| pool.update(篇, md) | **「编辑记忆库」** | 人工改库 |
| pool.draft(AI 整理建议) | **「建议整理」** | AI 只给草案，人确认才入库 |

> 术语唯一：C 端 = 记忆库 / 移入记忆库 / 确认 / 编辑记忆库；API = `memoryPool` 域。零黑话。

## 四、记忆池形态（MD 多篇 + 索引，非一份大 MD）

```
记忆库/
├── _index.json           索引/元数据（主题 → 篇；frontmatter：tag/更新时间/来源）
├── 关于我.md             长期偏好/身份/原则（"喜欢简洁的界面"→归此篇）
├── 生活习惯.md           健康/作息/饮食/运动
├── 工作与项目.md         进行中/偏好/待办
└── 关系与社交.md         重要的人 / 关注点
```
- **按主题分篇**（不堆一份大 MD——文件会越来越大、检索/维护难）；`_index.json` 聚合索引，AI 检索主入口；
- **md 正文**人类可读；**frontmatter** = 结构化元数据（供精确精配检索）；
- 池子内容 = **片段进池条目**（每条保留来源/时间），AI 调取按"篇/条目"粒度整段引用，比散碎片精准。

> 迁移/扩容：篇可增删；未来需与 Obsidian / md 查看器打通时，索引 + frontmatter 即桥梁（可后置）。

## 五、碎片 → 池子 · 晋升路径
```
碎片(优质/ACTIVE) → [AI 聚类·去重] → [MD 草案(按主题归篇)] → [人工确认/改] → 入库(池子)
       ↑ 非所有碎片都进池（去重/筛选，防池子被碎末污染）
```
- **触发**：碎片晋升 ACTIVE 时 或 手动「移入记忆库」+ 后台聚类建议；
- **AI 草案**：聚类 n 条相关碎片 → 一段 MD，标注「建议移入记忆库 · 主题 XX」——AI 只**重组**碎片内容，**禁凭空加**（UPG-06 防编造）；
- **人工确认**：确认 / 修改 / 驳回；确认 → 写入池子 + 碎片标记"已入池"（防重复晋升）；
- **哪类进池**：**由用户拍板质**（人决定什么值得长期记），AI 负责把确认的碎片组织成文；
- **防污染**：AI **不自动改写已入库内容**；AI 只对"未入池碎片"给草案。

---

## 六、编辑权 / 防过时
- 池子内容**人工可编辑**（借笔记/内容编辑）；**AI 端 = 只读**（检索用，不写入）；
- **过时**：池子中"每周三健身"这类会过时；AI 检测到新碎片与池内逻辑**冲突/过时** → **提示用户**（不自动改），确认后更新；
- 若池内条目与碎片矛盾 → 以"最近确认"为准，提示用户复核（不让 AI 私自覆盖历史确认）。

---

## 七、AI 调取优先级（检索策略）
- **调取链路**：先 `poolSearch`（`_index.json` + FTS/embedding）命中 → **整段引用**；未命中 → 再读近期碎片（现 memory API）兜底上下文；
- 优先级：**池子 > 碎片**；低频/长稳知识从池子取，高频/近期从碎片取；
- **防"只读池子"脱节**：碎片仍实时（刚聊的），池子周期整理——两层并存而非只保留一个；
- **Trace 溯源**：调取来源标注（**记忆库 / 碎片**）——呼应记忆页 v5「我为什么这么答」溯源，防"AI 用了库却说不清来源"。

---

## 八、与现有体系的关系
- `memory-api`（契约 v4）/ Lifecycle / 记忆页 v5：**零改动**，仅加"已入池"标记；
- **MemoryEntity + `poolState`**（内部，迁移兼容）：`NONE / DRAFT(待确认) / IN_POOL`；旧实体缺字段 → `NONE`（不丢数据）；
- 池子**独立于 memory-store** 存储（MD 目录 + `_index.json`），不强耦合实体库；
- 碎片"已入池"标记 = 防同一碎片重复晋升。

---

## 九、工程契约方向
- **池子 API（`memoryPool` 域）**：`pool.list(主题)` / `pool.get(篇)` / `pool.search(query)` / `pool.confirm(draftId)` / `pool.update(篇,md)` / `pool.discard(draftId)`；
- **池子存储**：MD 目录 + `_index.json`；**原子写盘**（临时+rename）+ 版本迁移幂等；
- **检索**：`poolSearch` 高频——索引精配（frontmatter/tag）+ 低频 embedding（或 FTS 先行）；**只在池内容里检索引用**（防编造，UPG-06）；
- **变更通知**：池子变更走类似 `changes` 的增量（防 UI/检索脱节，与契约 v4 同思路）；
- **依赖**：LLM 通道（聚类/草案）、FTS/embedding（MVP 可 FTS 先行、embedding 后置）。

## 十、验收测点
- **L1**：①碎片→AI 草案聚类正确（去重/归篇）②人工确认→入库 + 碎片标记 `IN_POOL`（防重复）③**人工确认后 AI 不自动改写池子**（变异：AI 写入池 → 必红）④`poolSearch` **只在池内容命中**（变异：命中库外 → 必红）⑤AI 调取**优先池子**（池子命中即不与碎片拼凑）⑥池子未命中 → **回退碎片** ⑦`Entity.poolState` 迁移兼容（旧实体→NONE）⑧过时冲突 → **提示不改**（确认后更）。
- **L2 真机**：「移入记忆库」→ 池子出现"待确认"草案 → 确认 → 入池；AI 对话引用库内容 → 溯源标注"来源=记忆库"；池子内容人工可编辑；冲突提示可达。
- **L3 转可执行**：碎片层与池子层**隔离**（改造仅动 `memoryPool`，`memory-api` 零改——依赖检查/契约测试）；池子对 AI **只读**约束（单测/契约测试锁定）；`_index.json` 原子写盘迁移幂等。

## 十二、需求切分（建议）
大单可拆四步，①先行：
1. **池子底座**：MD 目录 + `_index.json` + `pool.*` API + 迁移（实体 `poolState`）；
2. **晋升路径**：AI 聚类草案 + 人工确认 + 碎片标记入库；
3. **调取优先级 + 溯源**：`poolSearch` 优先、碎片兜底、来源标注；
4. **编辑 + 过时提示**：人工编辑库、AI 提示（不改）、确认后更新。
依赖：碎片层（契约 v4，保留）、LLM 通道（聚类/草案）、FTS/embedding。
