## 〇、一句话
**联动 = 上下文组装(工具定义 desc/inputSchema + 记忆 + 会话历史 + 点名偏好 四输入源) → LLM 语义匹配选工具 → 执行安全门(副作用确认) → 度量(选工具准确率)。胶囊=本回合显式点名(轮次级强提示,不硬锁);记忆=持久上下文通道;工具 desc=能力自述。**

## 一、联动 = 上下文组装层（v2 补,原图少两个输入源）

```
[系统提示 + 会话历史 + 记忆(UPG-05) + 工具注册表(desc/inputSchema) + 点名偏好(胶囊·本回合)]
                        │ 组装(顺序/优先级/token 预算)
                        ▼
                        LLM 语义匹配 → tool_calls → 执行安全门 → handler
```
- **四个输入源**:①工具定义(desc/inputSchema)②记忆(持久上下文,过敏记忆→影响点餐工具调用)③会话历史 ④**点名偏好**(胶囊=本回合显式意图);
- **工具 RAG(规模化)**:当前 `agentToolSchemas` **全量**进每请求(token 随工具数线性涨,MCP 一个 server 可带十几个);**阈值态**——工具少全量,超阈值按输入语义检索 top-K 再喂(当前态声明,非默认架构);使用偏好(历史高频工具预排序)=未来项;
- **反向接缝**:工具调用结果进对话后 → 是否算**记忆草稿来源**(记忆文档来源="来自「XX」对话")——两文档对接。

## 二、五问题定案（大神标准答案）

### 1. 联动模型 —— 对,扩成上文四输入源;记忆=另一条联动通道
### 2. 触发示例硬要求 —— **内置硬 / 第三方可降级默认**
- 内置工具(我方写)→ 硬要求;第三方 → 登记层**自动补全 + 可编辑**(自家 LLM 对 desc/inputSchema 生成中文触发示例);
- 标准 = 「一句话用途 + 2~3 正例 + **1 反例**」——反例(如"用户在聊火车历史时勿调用我")对消歧作用被低估;
- 硬门槛致命:**无法拒绝第三方入库**,硬要求会大量工具不可用。

### 3. 胶囊优先级 —— **轮次级强提示,不硬锁**(否掉会话级绑定)
- **否掉"会话级绑定"**:用户点 12306 查完票,5 回合后问健康,会话绑定是事故;绑定最长到**任务/轮次级**;
- **否掉硬锁**:点"查北京到上海高铁 + 记到行程"需 12306+备忘两工具,硬锁废掉组合调用;
- **推荐**:点名 → 注入轮次级偏好提示 + 该工具在本次请求工具列表**提权置顶**,LLM 仍可调第二工具;预设回填文本本身是最强自然引导;——**"是否硬锁"从拍板变数据决策**(度量发现 LLM 无视显式点名比例高才升级硬锁)。
- **拍板点(唯一)**:胶囊绑定生命周期 = **轮次级**(大神建议,其余有标准答案)。

### 4. 第三方 desc 不可控 —— **登记层 overlay,不覆盖原文**
- **永不覆盖作者原始 desc**(server 更新会与润色互踩);登记层存**增强元数据**(stableId 为 key:中文显示名/触发示例/反例),喂 LLM 原文+增强拼接,server 更新自动兼容;
- 与胶囊系统"pin 只存 stableId,渲染读注册表"**同一模式**(两文档对齐)。

### 5. 与胶囊/记忆冲突 —— **不冲突,同上下文三来源,只有组装问题**
- 胶囊=本回合显式意图(信号最强)/记忆=持久上下文/工具 desc=能力自述——进同一 LLM 上下文;**无冲突,只有组装**(顺序/优先级/token 预算);
- 反向接缝:工具调用结果是否进记忆(见上)。

## 三、v2 补缺口（大神:v1 缺的）

### 1. 执行侧安全门（最大缺口）
- 文档原来画到 tool_calls → handler 停;但"**AI 语义匹配 + 自动执行**"对**副作用工具**(订票/下单/发消息)是危险组合;
- **引用 MCP annotations `readOnlyHint / destructiveHint`**:副作用工具执行前**插确认门**;
- 胶囊"回填优先"管入口,这里管**执行**,中间这段两边都要覆盖。

### 2. "不选任何工具"显式允许
- 过度触发(用户聊火车轶事、AI 调 12306)是真实失败;反例防它,机制上**声明 LLM 可零调用**。

### 3. 误匹配用户出路
- AI 选错工具,用户看到什么:至少**透明展示「正在调用 X」+ 可中断**——否则一次错误执行耗尽信任。

### 4. 多工具组合
- 现代 LLM 发多个 tool_calls;声明**支持多工具组合**(与胶囊轮次级/提权联动)。

### 5. 质量度量（验收形态）
- 联动验收**不是 UI 断言,是选工具准确率**:建评测集(典型输入→期望工具,含模糊输入/多工具候选/不该触发边界),desc 改动前后回归——"desc 语义化"的改进才能证明。

---

## 四、验收测点（v2 补）
- 评测集回归:desc 改动后选工具**准确率不降**(含"不该触发"零调用用例);
- 胶囊点名后,组合任务仍可调第二工具(不硬锁验证);第 N 回合后点名偏好已失效(**绑定不跨任务**);
- 副作用工具确认门(readOnlyHint/destructiveHint 驱动);
- 记忆影响工具调用的正向用例(过敏记忆+点餐工具);
- 工具数量过阈值行为声明(当前全量/阈值多少/超了走 RAG)。
