## 〇、核心主张（四条 · 含 P0-1 铁律）

1. **生命周期**：记忆有新鲜度/可信度，不是非有即无；「最常见的歌 ≠ 最喜欢的歌」。
2. **增量合流**：`Event → Extract → Merge → Update`，**绝不用 LLM 重写整本语义库**；Merge 只在事件/情景层，语义库只读。
3. **双向·人拍板**：候选→语义（采纳）与语义→待确认（Re-evaluation）都 **AI 只发 Proposal、人确认才动库**；"退化"= 事实→待确认假设，**非删除**（保历史）。
4. **P0-1 铁律（Event ≠ Memory）**：
   ```
   Event     = observed fact（事实记录，≠ 记忆）
   Episodic  = contextualized experience（情景化经历）
   Semantic  = confirmed understanding（用户确认的理解）
   ```
   播 17 次《晴天》只能得到"最近频繁播放"，**不能**直接得到"喜欢""最喜欢"——观察≠偏好，防污染第一边界。

## 一、分层（Event / Episodic / Semantic / Working）
```
              USER ACTIVITY（AI 对话 / Agent 行为 / 外部·媒体行为）
                         │
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
   Event Store(append-only)──→ Episodic(=现有碎片层)
   Everything Log 原始痕迹      └─→ Pattern Detection
         │                             ↓
         │                        Candidate(候选)
         │                             │ 用户「采纳」
         └─────────────────────────────┴─────→ Semantic(主记忆库=池子v2)
                                                     │
                                         时间/新证据/冲突
                                                     ↓
                                             Re-evaluation
                                                     │ Proposal → 用户确认
                                              ┌──────┴──────┐
                                              ↓             ↓
                                           保留(ACTIVE)   变化(ARCHIVED·保历史)
```
**Event 可直接 → Pattern Detection → Candidate**（不必都先转 Episodic——媒体连续 30 天播某类音乐可直接产候选，避免海量无价值碎片）。
**Working Memory = 运行时 context（横向）**：`Event/Episodic/Semantic → Retrieval → Working → AI`；**不是第四个数据库层**（不入持久化）。

## 二、记忆生命链（核心，先跑通这条）
```
Event → Episodic → Candidate → Semantic → Re-evaluate → Archive
  事实     情景        候选       确认理解     待重新确认      保历史
```
- **"自动退化"改叫 `Re-evaluation`（P0-2）**：旧记忆 → 系统发现可能过时 → 生成 RE-EVALUATE → **用户确认** → 才 ARCHIVED；不是"自动退化"（避免与"AI 只发 Proposal"冲突）。
- **每次活动结束执行 `Memory Update Pipeline`，但不保证产生持久记忆变更**（P0-2 相关）："你好"→无沉淀→结束；"我以后 UI 保持轻量"→才进候选→采纳。
- **产品原则**：**记录"用户经历过什么"，不替用户决定"用户是谁"**——系统同时拥有**过去的你 + 现在的你**；不用现在覆盖过去、也不让过去绑架现在。

## 三、语义层状态机 + 极简 UI
| 状态 | 语义 | AI 注入 | 用户可见 |
|---|---|---|---|
| `ACTIVE` | 主记忆（可信） | 允许 | ✓ |
| `RE-EVALUATE` | 待重新确认 | **禁止** | ◌ |
| `ARCHIVED` | 历史保留（被否定，正文保留） | 禁止 | 折叠/历史 |

- **Re-evaluate 触发（事件驱动，非全扫）**：①`decayPolicy`/类型策略到期 ②冲突（见表3）；确认低频、非阻塞（`◌` 标记，点进才确认）；
- **"不是"→ ARCHIVED 保历史**：正文保留、退出注入、生成候选待新证据——不物理删除（呼应删除传播 P0-1：别让用户觉得"你把我确认过的删了"）；
- **UI**：`我的记忆·记忆库 → 关于我 ✓ / 音乐 ◌ / 影视 ✓`，点 `◌` →「《晴天》现在还是吗？[是][不是]」；`confidence/decay_score/天数` 全内部，永不暴露。

## 四、Memory Type Matrix（P0-3 · 表1）

| 类型 | 含义 | 例 | decay |
|---|---|---|---|
| `STATE` | 当前状态（高频变） | 正在看《黑镜》S3E1 | 快 |
| `PROGRESS` | 进度 | 项目到 P2 / 减肥进行中 | 中快 |
| `PREFERENCE` | 偏好（中稳） | 喜欢简洁 UI | 慢 |
| `HABIT` | 习惯（模式） | 常用 Obsidian | 中 |
| `FACT` | 事实（稳） | 是游戏设计师 | 极慢 |
| `IDENTITY` | 长期身份 | 职业 / 性格原则 | 极慢 |
| `RELATION` | 关系 | 重要的人 | 慢 |

> 比单纯 `decayPolicy` 更稳——不同类型走不同生命周期。`confidence`（内部）：沉淀次数/一惯性，仅供"稳定模式"判定与建议强度。

## 五、Lifecycle Policy Matrix（表2）

| 类型 | 何时观察 | 何时成候选 | 何时 RE-EVALUATE | decay |
|---|---|---|---|---|
| STATE | 每次相关行为 | 状态变化即替换 | 不再观察即降级 | 快 |
| PROGRESS | 每次相关行为 | 连续推进 | 停滞超期 | 中 |
| PREFERENCE | 行为频次 | 稳定模式(≥N 例, N 待定) | 长期未验证/新行为 diff | 慢 |
| HABIT | 行为模式 | 重复出现 | 模式消失 | 中 |
| FACT | 用户声明/确认 | — | 长期未验证 | 极慢 |
| IDENTITY | 用户声明/沉淀 | 稳定模式 | 明确冲突 | 极慢 |
| RELATION | 交互频次 | 高频交互 | 长期断联 | 慢 |

## 六、Conflict Matrix（表3 · 什么叫"真正冲突"）

| 判据 | 例 | 判定 → 处理 |
|---|---|---|
| **同一类型且互斥** | 「最喜欢 A」vs「现在最喜欢 B」 | **冲突** → RE-EVALUATE |
| **不同值但同类型不互斥** | 「偏好爵士」vs「最近听摇滚」 | **不算冲突**（可并存，各自候选） |
| **Observed ≠ Inferred** | 播《晴天》17 次 | 不算"喜欢"→ 只可生成候选/Proposal |
| **新证据覆盖** | 2026 晴天 → 2028 大量听 A | 旧条目 RE-EVALUATE（保历史），新事实入候选 |
| **身份 vs 偶发行为** | 「游戏设计师」vs 偶尔玩一局 | 不算冲突（身份极稳） |

> 判定核心：**Observed behavior ≠ inferred preference**；跨类型不冲突、同类型互斥才冲突；冲突不自动改库，只标 RE-EVALUATE 待用户裁决。

## 八、验收测点
- **L1**：①Event 结构化（媒体/Agent/外部）+ **Event≠Memory**（变异：Event→直接"喜欢"→必红）②增量合流 Merge 幂等/冲突标 RE-EVALUATE ③Semantic 只读（变异：AI 写库→必红）④候选→采纳 / 语义→Re-evaluation 都人确认（变异：自动改→必红）⑤否定→ARCHIVED 保历史 ⑥**类型系统**：同类型互斥→冲突、Observed≠preference 不冲突（表3 逐断断言）⑦`memoryType` 生命周期差异（STATE 快 / IDENTITY 极慢）⑧freshness 运行时派生、不暴露 UI ⑨Re-evaluate 事件驱动非全扫 ⑩空库→行为零影响。
- **L2 真机**：看剧→Event→Episodic「正在看黑镜」；连播 30 天某类→候选→建议→采纳→`关于我.md`；旧偏好→◌→[是/不是]→更新/ARCHIVED；UI 只见 ✓/◇，无数字。
- **L3**：三层隔离（Event/Episodic/Semantic 独立演进，`memory-api` 零改）；Semantic 对 AI 只读约束测试；EventStore append-only；新鲜度派生一致性；类型/冲突矩阵逐格契约测试。
