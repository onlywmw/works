# 【安全相关】审批弹窗呈现通道断链 —— 问题陈述（2026-09-02 真机实测）

## 一、现象（真机实测，main @014c10f = UPG-75 合入后）

1. **vault.get（only-once 必弹工具）被 LLM 调用时无任何审批弹窗，直接执行并返回明文凭据**（测试凭据 acc03/pw03——注意：凭据在 App 内处于**锁定态**，用户本人通过 UI 都无法查看，但 LLM 通过 vault.get 读到了）。
2. 同时「审批待办」chip/面板**从未出现**。
3. 此前多轮，LLM 反复报告「工具调用返回 APPROVAL_REQUIRED（requestId=req-1/req-8/req-9，全部未批准）」——**用户从未见过对应审批弹窗**（既无 App 内弹窗，也无通知栏通知）。

## 二、复现

- 环境：Android 平板（真机）+ debug APK（main 014c10f）+ DeepSeek V4
- 路径：App 对话（WebView/markstream 会话）→ LLM 直接调用 `vault.get` → **应弹审批（允许/拒绝两键，only-once 无勾选行）→ 实况：什么都不弹，直接返回明文**
- 频率：多次复现（先前 LLM 侧提示 APPROVAL_REQUIRED + 用户侧无弹窗；本次 LLM 直接拿到明文）

## 三、代码链路（静态核对：全部按设计正确）

- `McpToolScheduler.dispatch`（McpToolScheduler.kt:315-319）：only-once 工具强制 ASK **先于模式判定**（open 模式也拦）；:350-360：only-once 只接受 `OUTCOME_ALLOWED_ONCE`（turn/goal/remembered 豁免一律拒绝）——**防御语义正确**
- `PermissionRegistryData.kt:198`：`vault.get` = ask / high / harmless=false ✓
- `ApprovalService.request`（ApprovalService.kt:355+）：入 FIFO → `driveUntilDecided` → `present`（:298-320）→ `answerer?.invoke()`，60s fail-closed
- `MainActivity.kt:4378-4400`（D4 回答者）：`if (isAppVisible && !forceNotification) → AlertDialog` **else → 后台通知（NotificationAnswerer.show）**
- `MainActivity.kt:4417-4422`：`onQueueChanged → refreshApprovalChip`（chip 角标）

**静态看：链路各环节齐全，语义正确**——问题必然在**运行时呈现通道**。

## 五、待判的 3 个确定性线索（拿到即定位）

1. **answerer 是否被调用**：日志 tag `ApprovalService`（回答者异常/审批请求异常/决策: xxx）与 `ApprovalVis`（`answerer: visible=? forceNotification=? tool=?`）——真机 logcat 目前拿不到（无线调试关闭时序问题），**首要取证就是这两行**。
2. **`isAppVisible` / `forceNotification` 实值**：
   - `isAppVisible=false` → 应走通知分支——但**通知也没出现** → NotificationAnswerer.show 是否被调/失败？
   - `isAppVisible=true` 但无弹窗 → runOnUiThread 弹窗是否被后续逻辑关闭（`presentationCanceller`/`finally dismiss` 竞态）？
3. **弹窗生命周期竞态**：`approvalDialogDeferred` / `approvalDialog` 全局单例 + answerer 的 `finally { dismiss }`——**并发表面是否覆盖/提前 dismiss**（此前用户点弹窗时另一弹窗叠加盖过已有实证倾向）。
