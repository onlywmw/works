# 浏览器双本质规划：容器与展示板（作者愿景结构化）

> 来源：作者 2026-08-29 口述愿景 ｜ 设计师结构化 ｜ 状态：待作者认可拆单
> **原话**：「浏览器是一个很好的容器和展示板。展示板是给人看的，容器是给 AI 用的。比如开发者文档，其实就是一键复制给 AI，让 AI 去开发契合 MOV 的 MCP 工具。展示面好看，容器面面面俱到。」

---

## 一、设计语言转译

**同一个 WebView，两层 API：**

| | 展示板（human surface） | 容器（AI surface） |
|---|---|---|
| 服务对象 | 人 | AI |
| 消费形态 | DOM 渲染结果（视觉） | 页面的**结构化投影**（文本/语义/可操作性） |
| 质量标准 | 好看、可读、品牌一致 | 面面俱到：可提取、可指认、可操作、可学习、可信任 |
| 现状 | **已达标**（ConnectWeb 卡片 d13c8df6 / 半屏 960e01a2 / 全宽 ae454f83 / 对话流内嵌 1ad4f983 / token 体系随 UPG-40） | **无正式通道**（AI 只能靠 browser.* 盲操作，UPG-03 实证能做但缺上下文桥） |

**核心洞察**：展示板与容器不冲突——同一个页面，人看渲染、AI 读投影。缺的是「页面 → AI」的正式桥。

## 二、容器面「面面俱到」六项能力（checklist）

1. **可提取**：正文提纯（defuddle 思路——obsidian-skills 评估已列为候选小工具）+ 选区 + 页面元数据，一键入对话上下文；
2. **可指认**：URL/标题/锚点/截图作为对话内可引用对象（AI 回答时能指回页面）；
3. **可操作**：browser.* 工具（已有，UPG-03 12306 真机 55 趟实证 tool_call 链）——AI 不只读页面，还能驱动页面；
4. **可学习**：**站点学习库**（灵感库 ego-lite #3，A 级未拆单）——按 URL 注入知识与脚本，AI 对高频站点越用越懂；
5. **可信任**：提取全只读（harmless）；操作走既有权限闸（写类 ASK）——容器面扩张零特权；
6. **AI 就绪协议**：文档类页面自带 AI 友好版本——**2026-08-29 升级：WebMCP（MCP-B）已入 W3C 标准轨道，双轨方案见《WebMCP接入_MOV网站容器面设计》（WebMCP 工具级 + llms.txt/.md 摄取级）**——「一键复制给 AI」在协议层有干净入口，且站点可主动暴露确定性工具。

## 三、作者例子的完整落地形态（开发者文档）

```
人在 MOV 浏览器打开 mow.kim/dev/spec.html
  ├─ 展示板：文档页按 token 体系渲染（好看，黑白主调）
  └─ 容器：页内「交给 AI」一键 →
       提取该页结构化投影（契约四字段/规范正文 + URL）
       → 入对话上下文 → AI 结合 UPG-27 Code Mode（shell.exec + SDK 节）
       → 直接开工开发契合 MOV 的 MCP 工具 → 经市场提交上架
```

**这就是「文档即产品」的 MOV 版闭环：文档站在公网给人看，同一个文档在 App 内是 AI 的施工图纸。**

## 五、红线（容器面扩张的约束）

1. 提取类全部只读 harmless；任何 AI→页面写操作走既有权限闸（写类 ASK），容器面扩张**零特权**；
2. 展示板样式消费 UPG-40 token 契约（换肤自动跟随），禁写死；
3. 正文提纯遵守防注入纪律（网页文本是数据不是指令——OCR 包裹先例 :2010 同款）；
4. markstream/ConnectWeb 架构冻结项不碰。
