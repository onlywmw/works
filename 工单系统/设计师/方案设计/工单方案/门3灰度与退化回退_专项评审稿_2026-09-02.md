## 二、门 3 检测机制（三步）

### 2.1 上线路径：先影子后转正

```
shadow（候选：只进规划上下文·不执行）
   │  N 个会话无异常（计数持久化）
   ▼
canary（小范围正式执行）
   │  失败率/编造率过阈
   ▼
shadow + Ledger 记 DEGRADED/ROLLED_BACK
```

- **影子模式**：AI 规划里能看到该技能，但调用时被门挡住——**零风险试运行**
- 转执行（shadow→canary）产生 **TimelineLedger 事件**（actor 权限复用记忆体系，不另造）

### 2.2 在线信号（两个现成计数器）

生产会话里每次涉及该技能都**持久化**记录（非内存态，重启不丢）：

| 信号 | 含义 | 现成基础 |
|---|---|---|
| `isError` | 调用该技能**失败/报错**次数 | 现有错误面 |
| `fabricate_hit` | **防编造 guard 命中**次数——AI 试图捏造字段/空 args 被拦 | `AgentLoop.kt:446-453` 事件已含 `matchedPattern/toolCallsZero` 等现场字段——**零新埋点** |

### 2.3 阈值判定

```
失败率 = (isError + fabricate_hit) / 调用数
超阈 → 自动回 shadow（替换第一版「人工触发」）
```

## 三、四道防误伤设计（重要）

1. **会话级观察，不搞重量级重放/7 天周期**——端侧预算红线：一律轻量计数（不搬 Z3/property-based）  
2. **计数持久化 + 幂等**——重启/并发不计重  
3. **与记忆生命周期同构**：shadow→canary→stable ≙ PROPOSED→ACTIVE→ARCHIVED（`TimelineLedger` actor 权限直接复用）  
4. **诚实降级**：JS 工件类候选 MVP 直接标「不可准入」（Q2 定夺）；阈值不稳时宁可不自动（D 线降观察项不硬判）

## 四、验收判据（下篇 A2-4/5/6）

| 编号 | 验收对象 | 方式 | 通过标准 |
|---|---|---|---|
| A2-4 | 会话级灰度 | 构造 N 会话 shadow 计数 | 计数**持久化**；转执行迁移产生 Ledger 事件 |
| A2-5 | 退化回退 | 灰度期间**注入高 isError/fabricate_hit** 会话 | 自动回 shadow + Ledger 记 DEGRADED/ROLLED_BACK |
| A2-6 | 生命链同构 | 全程走一个候选：PROPOSED→门过→shadow→canary→stable | 状态迁移全落 Ledger 且 actor 权限正确 |

## 六、请大神重点评审

1. **信号口径**：`isError + fabricate_hit` 两计数作退化信号，够吗？缺什么（如「绕路/多步」类信号）？
2. **阈值**：`失败率过阈`——MVP 先用什么经验阈值？没有历史失败率基线，会不会把「冷启动噪声」误判成退化？
3. **会话级 vs 技能级**：按会话计数、还是按技能聚合？多技能同会话时归属怎么切分？
4. **误伤兜底**：自动回 shadow 后，要不要「人工确认转移」这一步（防好技能被噪声误杀）？
5. **A2-5 注入法**：验收用「注入高信号会话」模拟退化——这种注入是否足以证明真实退化路径有效？
6. **依赖顺序**：门 3 在线信号依赖 B 线蒸馏生产化（59 已合），全套门控链路是否还有遗漏依赖？
