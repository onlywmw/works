## 〇、来源与背景（为什么重设计）

**用户本意**：本地页**一级做列表（简约）、二级做详情（复杂操作）**。用户原话：「一级弄得简约一点，二级做复杂操作」「让人一目了然知道怎么用、有什么用」。

**现状（main 上 UPG-23 的本地 tab）**：一个**总览面板**——概览卡（工具/来源/钉选占用）+ 钉选槽 + 三层分组（内置/市场/系统）+ 工具级下钻 + 每行右端一排控件（星标钉选+状态点+开关+折叠箭头）。**信息密度极高，与「简约列表」本意相悖**，用户评价「一塌糊涂」。

**UPG-41（分支 feat/upg41，未合 main）**：把本地 tab 收缩为「入口卡 + 全屏二级弹层」。方向对（收缩一级/下沉二级），但一级仍是**摘要卡而非列表**，二级是把 UPG-23 面板原样搬进弹层，未真正做「列表→详情」。

**迭代决策链（用户三连反馈 → 定稿）**：
1. 一级做列表 → 2. 一级太花哨（去卡片/控件）→ 3. 一级不要图标 → 4. 一级做好分类管理（补分组）→ 5. 标题/工具不顶格（内缩分层）→ 6. 去「N 项」计数 → 7. **市场包要独立模板（以"装后主页示意"为核心）** → 8. 浅色视觉。

---

## 一、设计目标

1. **一级 = 简约的分类列表**：分组管理（内置/市场/系统），每行仅 名称+一句副题+箭头；无图标、无 badge、无健康点、无计数、无控件。
2. **二级 = 详情页**：承载「用途 / 用法 / 工具明细 / 权限 / 启停授权卸载」等复杂操作。
3. **市场包 = 商店式独立模板**：以「普通模式主页示意 / 极简模式主页示意」为核心，让人一眼看懂「装了这个工具有什么用、怎么用」。
4. **视觉**：沿用 MOV 浅色 token（候选C近黑为 deep 皮肤值，本方案采用浅色主视觉）。

## 三、设计定稿

### A. 一级 · 分类列表（本地 tab）

```
内置能力                    ← 分组标题（左靠、灰色、小号）
    设备控制                ← 工具行（比标题右缩一档）
    生活场景 · 12306
    笔记 · Obsidian
市场已安装
    效率增强包
系统基础能力
    系统基础能力
```

- **分类**：内置能力 / 市场已安装 / 系统基础能力（沿用 LocalOverview 的 Group 结构）。
- **行内容**：仅 名称（16px 600）+ 一句副题（12.5px 灰）+ 右侧箭头 `›`。**无图标、无 badge、无健康点、无「N 项」计数、无任何按钮/开关**（控件全部下沉到二级）。
- **排版**：标题靠左（margin-left 12px）、工具行右缩（padding-left 20px），形成「分组头 → 内容」两级层次；均不贴左边框（不顶格）。
- **健康提示**（绿/黄/红）：**一级不显示**，全部移到二级详情。

### B. 二级 · 内置工具详情

```
头卡：图标 + 名称 + badge + 一句 tagline + 健康状态   【右上角=启停开关】
② 这能干嘛      —— 一句人话讲透用途（重点加粗）
③ 怎么用        —— 例子：💬"你一句" → 它回什么   [用它=点回填输入框]
④ 工具一览      —— 每个工具 名称/作用/权限(自由·询问·拦截)
⑤ 权限分布      —— 自由/询问/拦截 各几个
⑥ SAF 授权      （Obsidian 需要）/ 卸载（仅市场包）
```

- **启停开关在头卡右上角**（点击切换；系统基础能力灰显「常驻」不可关）。
- 复杂操作（启停/授权/卸载）集中置于 **下方操作区**；头卡右上角只保留启停开关，不放冗余裸控件。
- **用途/用法前置**（②③）：这是「一目了然怎么用/有什么用」的核心；工具清单/权限分布（④⑤）为补充，顺序靠后。

### C. 市场包 · 商店式独立模板（与内置工具区分）

```
头卡：图标 + 包名 + v版本·作者 + 「已安装」标签
① 核心：安装后你的主页长这样
      [普通模式主页 | 极简模式主页]  （segment 切换）
      ┌ 手机主页缩略示意 ┐
      │ 顶栏 ☰ 房名 🌙        │
      │ hero: 你好，我是MOV…    │
      │ 功能栏: ⚡标准 📷照片OCR  │
      │        📦效率增强 ←新增  │
      │ 输入框 [📷] … [🎤]     │
      └────────────────────┘
      「↑ 装了它，主页功能栏多出 📦效率增强，点它直接用」
② 怎么用（例子，1-2 条）
③ 卸载（/安装/更新）
```

- **与内置工具的差异**：
  - 内置=本机能力，关键是「能不能用/怎么启用」→ 有**启停开关、SAF 授权**（本机权限）；
  - 市场=第三方安装，关键是「**可信不可信、装了会对主页有什么影响**」→ 以**装后主页示意**为核心，操作是**安装/更新/卸载**（无启停开关，是「装不装」问题）。
- **主页示意建议真机截图替换**（见 §五 待办）——「信实物」。
- **信任区（权限请求/来源核验）—— 保留但低调（v2 定稿）**：不作为首屏大卡，而是**详情页底部一个致密、低调的折叠区**（默认收起，一行灰字提示「关于此包 · 作者/来源/权限」，点击展开）。例如：
  - 收敛为单行：`关于 · mcp.example — 来自某开发者 · 已核验 ▸`
  - 展开后：作者、来源（mow.kim）、权限请求（读写文件/网络… 逐条+是否高危），用灰色小字、低对比，**不抢「装后主页示意」的核心地位**；
  - 视觉克制规则：灰字 `--text3`、无彩色 tag、无大标题，折叠默认收起。

## 五、验收测点（随单测试方案）

**代码层（变异/契约）**：
1. 分组标题缺失 → 必红（变异1：删「内置能力」标题）
2. 一键入口缺失 → 必红（变异2：删「怎么用」区/删除"用它"回填按钮）
3. 一级行无图标/无计数/无健康点 → 断言视图层净输出（对应「简约」约束）
4. 二级「用途/用法」位于「工具清单/权限」之前 → DOM 顺序断言

**真机层（用户视角最终结果）**：
1. 进本地 tab → 一级仅显示分组标题+名称+副题+箭头（截图可见，无控件堆叠）
2. 点进某工具 → 二级详情：能看懂「这能干嘛」+「怎么用」例子
3. 点市场包 → 看到「普通/极简主页示意」能切换，直观明白装了会怎样
4. 启停开关、SAF 授权、卸载可操作
