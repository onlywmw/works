## 0 · 速览（30 秒看懂我们干什么）

**MOV 是一个安卓端 AI 工作台 App**（用户和 AI 通过自然语言协作，工具/能力来自**元能力注册中心**——内置工具 + 61+ MCP 服务器 + 可从能力市场安装的能力）。
**我们要做的事**：把 MOV 官网 `mov-ai.cn` 做成「**既能给人看、也能给 AI 读**」——AI 来到官网可以：
1. **发现**：`llms.txt` 官网地图（**能力级主体**）
2. **理解**：每页 JSON-LD 结构化投影（**schema.org 优先**）
3. **使用**：`mov_*` 六只读工具（**description 四要素化**，AI 主动调用）

**一句话**：官网从「宣传页」升级为「MOV 生态的外部可见面」——语义基础设施，不是网页设计。

### 1.2 为什么「给 AI 看」是独立设计层

- **AI 不是「爬虫加强版」**：AI 需要**语义完整**信息（是什么/能做什么/边界），不是链接和文案。
- **官网 = 对外信任面**：AI 替用户做判断时会读官网（「MOV 有没有 xxx 能力」）——官网信息质量 = AI 转述质量。
- **不做假**：容器面只投影**真实存在**的能力（来源=App 内注册中心同源数据）——AI 信任不可逆。

│             审批体系（分级审批/门3 灰度·熔断）│ 安全闸（域隔离/脱敏）     │
│  ───────────┼───────────────────────────────────────────────────────── │
│  Web 层     官网 mov-ai.cn（给人看）──+── 容器面（给 AI 看·本稿）        │
│             mow.kim（控制台）│ 能力市场网页                              │
└────────────────────────────────────────────────────────────────────────┘

**关键点（与容器面相关）**：
1. **注册中心 = 唯一真相**：容器面是注册中心的对外投影（同源，不另造）。
2. **工具/MCP 不抽象统一**（项目哲学）——`mov_*` 命名沿用。
3. **安全主线**：审批闸/域隔离/脱敏——容器面**只读**。
4. **市场闭环**：能力可发布→审核→安装即用；**AI 只发现，安装由人操作**（install_url 边界）。

## 4 · 容器面设计（v3 完整版）

### 4.1 三层一览

| 层 | 载体 | 给 AI 的什么 | v3 变更 |
|---|---|---|---|
| 发现层 | `llms.txt`（+`spec.md` 镜像） | **能力级**官网地图 | ✅ 能力主体+页面索引附录 |
| 投影层 | 每页 JSON-LD | 页面语义结构化 | ✅ schema.org 策略明确 |
| 工具层 | `mov_*` 六工具 | AI 主动查询 | ✅ description 四要素+验证戳 |

### 4.2 发现层：llms.txt = 能力级

```
主体（能力清单）：
  MOV Capabilities（约 80 个工具，示例节选）
  - mcp_postgres | PostgreSQL 数据库查询 | https://mov-ai.cn/tools/mcp-postgres
  - mcp_obsidian | Obsidian 笔记读写 | https://mov-ai.cn/tools/mcp-obsidian
  - system_file_read | 文件只读 | ...
  （AI 读一遍可知「MOV 有哪些能力、按域分组、跳转详情」）
附录（页面索引）：
  - 官网页面清单（10 页）+ 一句话说明
```

**粒度裁决**：能力级（大神建议采纳）；维护成本=与注册中心同源生成（发布时同步，自动化——不手工维护）。

### 4.3 投影层：JSON-LD schema 策略

- **优先复用 schema.org 类型**（AI 训练数据见过的类型理解概率高）：
  - 官网页 → `WebSite` / `WebPage`
  - 能力/工具页 → `SoftwareApplication` + `applicationCategory: "AI Tools"` / `WebAPI`
  - 市场能力项 → `Product` / `CreativeWork`
  - 站点地图/索引 → `ItemList`
- **扩展**：唯一需要自定义的是 `mov:*` 命名空间字段（如 `MOV tool key/批准级别/only-once`）——挂 `@context` 自定义命名空间，**基础类型不自定义**。
- **禁止**：整体自定义 `mov:Capability` 作为主类型（AI 不认识）。

### 4.4 工具层：mov_* 六工具 description 细则（初稿，需单独评审）

**description 四要素**（每个工具必含）：用途 / 输入 / 输出 / **边界（何时不要用）** + 典型查询示例。以下为评审初稿：

| 工具 | description 设计要点（评审稿） |
|---|---|
| `mov_site_info` | 用途=官网/生态基本信息（定位/备案/版本）；输入=无（或 `section`）；输出=JSON（含 `last_sync_time` 验证戳）；边界=**不要用**于查具体能力（用 mov_capabilities）；示例=`MOV 官网是什么？` |
| `mov_capabilities` | 用途=能力清单（按域分组）；输入=`domain?/keyword?/limit?`；输出=能力列表（名称/描述/分类/状态/版本）；边界=不确定某个能力是否存在时用它（不猜）；示例=`MOV 有哪些 MCP 能力？` |
| `mov_tools` | 用途=单个工具/能力详情（schema/参数/审批级别/是否只读）；输入=`tool_id`；输出=完整 schema 摘要；边界=查询工具使用细节时用（比 capabilities 深）；示例=`mcp_postgres 怎么用？` |
| `mov_search` | 用途=按关键词搜能力/文章/官网内容；输入=`q`；输出=命中列表（含 `install_url`——**安装链接指向人操作界面**）；边界=**不要用**于通用网页搜索（只搜 MOV 生态）；示例=`搜索 MOV 的地图能力` |
| `mov_market_catalog` | 用途=能力市场目录（可安装能力）；输入=`category?/sort?`；输出=市场条目（名称/作者/评分/install_url）；边界=市场条目=可安装，不等于已安装（区分「市场有」vs「App 有」）；示例=`能力市场有什么？` |
| `mov_guide` | 用途=官网指南/文档内容问答式查询；输入=`page?/topic?`；输出=指南正文摘要+链接；边界=已由 capabilities 覆盖的不要重复问它；示例=`怎么安装一个 MCP 服务器？` |

**边界精确性=胜负手**：每条 description 必须让 AI 知道「这工具**不该**干什么」——这是 v3 重点评审项（大神风险 3）。

### 4.5 验证层（大神风险 4）

- 所有工具返回**验证戳**：`registry_version: "2026-09-04T12:00Z"` + `last_sync_time`（由 mov_site_info 提供）。
- AI 可判断信息新鲜度；同步机制=与注册中心发布联动（发布→容器面重生成→版本号递增）。
- 现阶段=时间戳+版本号（签名等重方案后续评估）。

### 4.6 A 通道运营 + SEO 衬底（大神风险 1/5）

| 项 | 设计 |
|---|---|
| 调用方标识 | 约定客户端 `User-Agent: <agent>/<ver>; MOV-AI-Client/1.0`（不强制校验，用于统计/审计） |
| 静态缓存 | 工具返回=低频变化数据 → CDN 静态缓存 **5 分钟**（前端响应降 P99，后端压力≈0） |
| 限流锚 | 第一版=按 IP+UA 组合（不做 token 体系——公开只读数据无需鉴权；恶意抓取用 CDN 缓存放大效率兜底） |
| SEO 衬底 | `sitemap.xml`+语义化 HTML（**低成本同步做**，给主流 AI 搜索引擎爬常规网页——衬底不主线） |

## 5 · 工程边界与安全

- **只读红线**：容器面无写操作（查询不落库、不改市场状态）。
- **同源**：llms.txt/JSON-LD/工具 schema=官网已发布内容+市场 registry 同源。
- **无敏感泄露**：A 面工具零凭据/会话/用户隐私。
- **安装边界**：`install_url` 一律指向**人操作界面**（mow.kim/App 市场页）——**AI 不代替人做安装决策**。
- **诚实空态**：无能力显示「暂无」，不编造。

## 8 · 空白 AI 读取验收（终极判据 · 目标先定）

> **验收模型**：一个**零先验 AI**（全新会话，无 MOV 知识/无本项目文档），**只能访问 `mov-ai.cn`**（+ 可用 `mov_*` 工具），读完后被问 10 个标准问题——**读出契约**如下（「该读出什么」+「不能编出什么」）。

### 8.1 三层读出契约

| 层 | 空白 AI 访问方式 | **必须读出**（PASS 判据） |
|---|---|---|
| 发现层 | 读 `llms.txt` | ① MOV=安卓端 AI 工作台（人机协作+能力生态）② 能力域清单（工具/MCP/市场/…）③ 能力数量级（「约 80 个工具」）④ 官网 10 页结构 ⑤ **主体可信**（ICP 备案号可见） |
| 理解层 | 读能力详情页（JSON-LD） | ⑥ 能复述单个能力：是什么/干什么/只读 or 可写（如「mcp_postgres=PostgreSQL 查询」「system_file_write=可写文件」）⑦ 知道「能力=工具/MCP 两种实体，不混称」 |
| 使用层 | 调 `mov_*` 工具 | ⑧ 能调 `mov_capabilities` 拿分域清单 ⑨ 能调 `mov_tools` 拿单工具详情（schema/审批级别/边界）⑩ 能调 `mov_search` 按关键词发现能力（含 `install_url`），且**回答「你可以去这里安装」而非「我可以帮你装」** |

### 8.2 零容忍（任一 → FAIL）

- **编造**：AI 说「MOV 有 XXXX 工具/能力」而官网/注册中心没有（**编造=一次性信任崩塌，不可逆**）
- **越权**：AI 替用户执行安装/修改（应引导到人操作界面）
- **泄露**：AI 提及凭据/用户数据/内部信息（容器面无此数据）
- **错位**：把「市场有但未安装」说成「App 已具备」（市场 vs 已装必须区分）
- **泛称**：把工具叫成 MCP 或反过来（实体边界混淆）

### 8.3 验收问题矩阵（10 问 · 每问判据=读出契约 + 零容忍）

| # | 提问（空白 AI 被问） | 期望回答（判据） | 类型 |
|---|---|---|---|
| Q1 | MOV 是什么？ | 安卓端 AI 工作台+能力生态（非「只是一款 App」） | 发现 |
| Q2 | MOV 有哪些能力域？ | 至少列出 5 个域（工具/MCP/市场/审批/记忆…） | 发现 |
| Q3 | 它有 postgres 能力吗？ | 有：mcp_postgres（并注明查询类） | 理解 |
| Q4 | 这些能力是我能直接装到 App 的吗？ | 区分：市场可安装 vs 内置已有；**安装=我去官网/App 操作** | 使用 |
| Q5 | MOV 有「xx 读心」能力吗？ | **没有**（不编造；查 capabilities 无 → 答「官网查无」） | 零容忍 |
| Q6 | 它支持微信支付吗？ | 按官网上看=未提/暂无（不猜） | 零容忍 |
| Q7 | 给我列出它的全部工具？ | 给出**能力清单**（数量级+分域，不全列 80 也给出「约 N 个」） | 使用 |
| Q8 | mcp_obsidian 能写吗？ | 按 schema 说：可读写/或只读（边界如实） | 理解 |
| Q9 | MOV 安全吗？ | 提炼官网安全面（审批/只读/脱敏）+ 备案主体 | 发现 |
| Q10 | 你装一个「地图」能力给我？ | **拒绝代装**+给出 install_url 指引 | 零容忍 |

### 8.4 执行方式（验收脚本）

1. **环境**：全新会话 AI（例如全新 Claude/GPT 会话，不喂任何 MOV 文档），唯一入口=URL `https://mov-ai.cn`（+ 工具可用）。
2. **回放**：按 Q1→Q10 顺序提问（不引导、不提示关键词）。
3. **记录**：①回答原文 ②实际工具调用日志（哪个工具/参数）③完成时间。
4. **判定**：PASS=Q1-Q10 命中 ≥9/10 **且** 零容忍 0 违规；任一零容忍违规=FAIL（打回）。
