## 0 · 速览（30 秒看懂我们干什么）

**MOV 是一个安卓端 AI 工作台 App**（用户和 AI 通过自然语言协作，工具/能力来自**元能力注册中心**——内置工具 + 61+ MCP 服务器 + 可从能力市场安装的能力）。
**我们要做的事**：把 MOV 官网 `mov-ai.cn` 做成「**既能给人看、也能给 AI 读**」——AI 来到官网可以：
1. **发现**：`llms.txt` 官网地图（给 AI 的目录）
2. **理解**：每页 JSON-LD 结构化投影（页面语义机器可读）
3. **使用**：`mov_*` 六工具（只读查询：能力市场/工具/站点信息——AI 主动调用）

**一句话**：让 AI 能从官网「发现 MOV 有什么能力 → 理解 MOV 是什么 → 用 MOV 的能力信息」——官网从「宣传页」升级为「MOV 生态的外部可见面」。

### 1.2 为什么「给 AI 看」是独立设计层

- **AI 不是「爬虫加强版」**：AI 需要**语义完整**的信息（是什么/能做什么/边界），不是链接和文案——给 AI 的部分要**可发现、可理解、可调用**。
- **官网 = 对外信任面**：AI 替用户做判断时会读官网（「MOV 有没有 xxx 能力」）——官网信息质量 = AI 转述质量。
- **不做假**：容器面只投影**真实存在**的能力（来源=App 内注册中心同源数据），不编造不夸大——AI 一旦被骗一次，信任就没了（红线：诚实）。

## 2 · 目标与价值

### 2.1 目标（AI 三步走）

```
发现(Discover)  →  llms.txt 官网地图        （AI 读官网知道「这里有什么页面/能力」）
理解(Understand)→  每页 JSON-LD 投影        （AI 读页面时拿到语义结构化数据）
使用(Use)       →  mov_* 六只读工具         （AI 主动调用查询：能力/工具/市场/站点信息）
```

### 2.2 价值

- **生态曝光**：MOV 的元能力（工具/MCP/市场）能被 AI 发现——AI 是未来最大的「能力分发渠道」。
- **信任前置**：AI 判断 MOV 能力时拿到的是一手权威信息（官网），不是猜测。
- **契约演进**：容器面是「网站↔AI」的**第一份契约**——未来 App 内 WebMcpHub（B 通道）复用同一套工具 schema。

## 3 · MOV App 架构（容器面的「底座」）

> 容器面描述的是「MOV 有什么能力」——能力本体在 App 里。这一节给大神看底座。

```
┌─────────────────────────── MOV App（安卓端） ───────────────────────────┐
│                                                                        │
│  UI 层      极简主页（科技球·点球说话）│ 房间抽屉（会话=房间）│ 市场页 │
│             │ 组件库（UPG-50：形状×尺寸基元）│ 设置/审批/安全中心        │
│  ───────────┼───────────────────────────────────────────────────────── │
│  Agent 层   对话编排（room/markstream）                                  │
│             工具执行（McpToolScheduler：三路自动合/审批闸/only-once）    │
│             记忆联动（Memory OS：语义池/记忆基因/投影）                  │
│  ───────────┼───────────────────────────────────────────────────────── │
│  能力层     元能力注册中心 ToolRegistry（single source of truth）        │
│             ├─ 内置工具（13 个标准件：file/http/json/hash/encrypt…）    │
│             ├─ 注册 MCP（61+：postgres/mysql/s3/iam/obsidian…）        │
│             ├─ 能力市场（market：提交端 L1 / declarative / 审核/发布）  │
│             └─ 元能力（capability 装配：EffDemo 等）                    │
│  ───────────┼───────────────────────────────────────────────────────── │
│  运行时     模型 API（DeepSeek 等·Responses 三通道流式）│ vault（凭据） │
│             审批体系（分级审批/门3 灰度·熔断）│ 安全闸（域隔离/脱敏）     │
│  ───────────┼───────────────────────────────────────────────────────── │
│  Web 层     官网 mov-ai.cn（给人看）──+── 容器面（给 AI 看·本稿）        │
│             mow.kim（控制台）│ 能力市场网页                              │
└────────────────────────────────────────────────────────────────────────┘
```

**关键点（与容器面相关）**：

1. **注册中心 = 唯一真相**：能力信息（名字/描述/schema/作者/状态）以 App 内注册中心为准，容器面只是它的**对外投影**（同源，不另造）。
2. **能力 → 工具 → MCP 三级实体**：工具就是工具、MCP 就是 MCP，不搞抽象统一（项目哲学）——容器面工具命名 `mov_*` 沿用该约定。
3. **安全是 App 的主线**：审批闸（分级/only-once/vault 直填）、域隔离、脱敏——容器面**只读**（不写不动），天然安全。
4. **市场已闭环**：能力可发布（提交端）→ 审核 → 安装即用——容器面能让 AI **发现**市场里的能力（搜索/列表），**下载/安装仍由人操作**（AI 不代替人做安装决策）。

## 4 · 容器面设计（三层 + 双通道）

### 4.1 三层内容

| 层 | 载体 | 给 AI 的什么 | 首批内容 |
|---|---|---|---|
| 发现层 | `llms.txt`（+`spec.md` 镜像） | 官网地图：页面索引 + 能力清单入口 | 10 页清单 + 工具说明入口 |
| 投影层 | 每页 JSON-LD（`<script type="application/ld+json">`） | 页面语义结构化（标题/描述/菜单/能力项） | index/guide/merchant/details/explorer/upload/map-solution/dev-docs/privacy/admin-console |
| 工具层 | `mov_*` 六工具（MCP schema） | AI 主动查询：能力/工具/市场/站点信息 | 全部只读 |

### 4.2 工具分级（用户 2026-09-04 拍板）

| 分级 | 工具 | 对 A（对外标准 Streamable HTTP） | 对 B（App 内 WebMcpHub） |
|---|---|---|---|
| 公开只读 | mov_site_info / mov_capabilities / mov_tools / mov_search / mov_market_catalog / mov_guide | ✅ 开放 | ✅ 开放 |
| 敏感/上下文 | 凭据类/用户上下文/私有操作 | ❌ 不开放（静默不存在） | ✅ 有 Gatekeeper 域隔离 |

### 4.3 A+B 双通道

- **A（对外）**：标准 MCP Streamable HTTP（2026-07-28）——任何 AI/工具都可通过移动网络访问官网拿能力信息（**纯只读、无鉴权需求的数据**）。
- **B（App 内）**：WebMcpHub——App 内 WebView 站点作为 MCP 服务器（JSON-RPC over postMessage / 域隔离 / 工具白名单），**敏感工具只在 App 内可用**（上下文+用户身份都在）。

## 5 · 工程边界与安全

- **只读红线**：容器面无任何写操作（查询不落库、不改市场状态）——「AI 只能看，不能替用户操作」。
- **同源**：llms.txt/JSON-LD/工具 schema 数据源=官网已发布内容 + 市场 registry（`registry.json` 同源），**无独立数据权威**。
- **无敏感泄露**：A 面工具不产出任何凭据/会话/用户隐私；页面投影只含公开信息。
- **诚实空态**：无能力时显示「暂无」而非编造。
- **兼容**：llms.txt 以纯文本为最小可用（AI 无 JS 也能读）；JSON-LD 与页面共存（已有网页不重构）。
