# 第三方站 WebMCP 接入性扫描器（UPG-109）设计稿 v1

> 版本：v1 ｜ 2026-09-05 ｜ 关联：UPG-109（P2）｜ 前置：UPG-43a（App 内 WebMCP Hub，已在 main）

---

## 一、前因与问题

43a（App 内浏览器 WebMCP Hub）已合——MOV agent 已能消费「已改造站点」。
但**「哪些站可改造/怎么改」目前靠人工挑**（低效、不可规模化）。

用户愿景（原话）：「WebMCP 是我们对外的名片，也是探索外面网站的尝试」——
需要一个**浏览器前置扫描器**：访问任意站点 → **自动评估 WebMCP 接入性** → 三档判定 → 可接入的经 Hub 就地桥接。

## 二、目标

1. 用户在浏览器打开站点 → 自动探测该站 **WebMCP 接入性**（无需用户懂技术）
2. 三档判定输出（A/B/C），AI 侧可用（结果可进 agent 上下文）
3. **探测只读零副作用**；判定报告落 journal + 卡片投影（U-40 视觉纪律：AI 动作用户可见）

## 三、探测面（判定依据）

| 探测项 | 内容 |
|---|---|
| 原生 WebMCP | 站点自带 `window.mov_webApi` 类登记 / W3C webmcp 标准物 / `llms.txt` / `.well-known/ai.txt` / AI 容器面 |
| 可注入性 | CSP 强度（`default-src`/`connect-src` 是否放行）/ 页面框架（Vue/React/原生）/ 关键操作 DOM 可定位性 |
| 只读判定 | 站点公开 API/数据面（只探公开读面——**不绕反爬/验证码/登录墙**）|

## 四、三档判定模型

| 档 | 含义 | 处理 |
|---|---|---|
| **A 原生支持** | 自带 WebMCP/容器面 | 直接接入 Hub |
| **B 可注入改造** | 无原生但 CSP/框架可桥接（附改造建议清单）| 经 43a Hub 桥接（需用户确认+域名级授权）|
| **C 不可改造** | CSP 锁死/登录墙/反爬 | 只读展示「不可接入」+ 原因（诚实）|

**判定报告**：{档位, 依据项, 建议动作}——AI 可见；**不确定=C 档**（诚实降级）。

## 五、安全红线

1. **探测只读零副作用**（不向站点发写操作/不绕验证码反爬）
2. **注入改造必须用户显式授权**（域名级；过审批门；与 MOV 审批体系对接）
3. 判定报告**诚实**（不确定不装确定；C 档如实）
4. 扫描范围可限（用户关闭探测功能即全局禁用）

## 六、范围

**做**：探测面三项 + 三档判定 + 判定报告（journal + 卡片投影）+ 自建三档测试站（L1 用例集）
**不做**：不自动改造第三方站（判定≠动手）；不爬取受保护内容；不存储站点内容副本

## 七、验收思想（STD 雏形）

- U109-1 三档判定用例集（自建 A/B/C 三类站 → 判定正确）
- U109-2 真机：mov-ai.cn（A 档实证）+ 一个开源站（B/C 档实证）
- U109-3 变异：探测逻辑删除→红（判定函数亲杀）
- U109-4 只读证据：探测过程零写请求（请求日志检查）

## 八、技术要点（参照存量）

- 探测器：App 浏览器（43a WebView）注入探测脚本（页面 JS 对象检查 + CSP 头读取——**CSP 需服务端/请求层读取**（WebView 可读 response headers）
- 判定=纯函数（输入探测结果 → A/B/C）——**可 L1 单测**（与门 3 灰度/OrchRules 同类范式）
- 卡片投影：复用 UPG-40 卡片体系（AI 动作用户可见）

## 九、风险

| 风险 | 应对 |
|---|---|
| CSP 探测不准（框架差异） | 三档测试站兜底；C 档兜底诚实 |
| 扫描资源损耗 | 探测超时（3s）+ 手动触发为主 |
| 反爬敏感 | 只读+不违用户意愿（探测=用户打开站点时触发）|

## 十、待评审点

1. 探测触发时机：用户打开站点自动探测 vs 手动「扫描」按钮（建议：自动+可关闭）
2. 判定报告放哪：journal + 卡片 vs 单独扫描页（建议：卡片先行）
3. B 档「改造建议清单」的深度（建议：只列 3-5 条建议，不自动改）
