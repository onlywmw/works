## 一、前因与问题（同 v1）

官网 mov-ai.cn 定位=AI 与人共用的站：层 1（AI 面）已合（UPG-105）；**层 2（用户面）= 本设计**：用户扫码登录后，网站内容由**手机 MOV App 实时供给**（手机=个人服务器，官网=窗口）。核心矛盾：用户数据在**手机本地**（隐私红线）——服务端中转违反「数据不出设备」；需要**用户显式建立的、端到端的本人通道**。

## 二、目标（同 v1）

1. 用户**官网出码 → 手机 App 扫码确认** → 配对建立
2. 官网展示用户自己的内容（只读投影第一版：记忆/资产/衣柜/会话摘要）
3. 断开→离线态；重连→恢复
4. **服务器零存储**（只握手/信令/兜底转发密文）

## 三、架构与通道选型（修订：用户面独立端）

```
官网页面（浏览器 Web）
   │ ① 官网出码（二维码含 sessionId 一次性引用）→ 手机 MOV App 扫码 → 手机确认
   ▼
【配对会话】sessionId + 会话密钥（手机生成）——官网仅持一次性引用
   │
   ├─ 阶段 1：LAN 直连（演示）── App 内【用户面代理端】（0.0.0.0:8841 NEW；**非 8389**）
   ├─ 阶段 2 主推：WebRTC P2P（STUN；TURN 兜底）
   └─ 阶段 2 兜底：E2E 加密中继（零知识）
   ▼
手机 MOV App（数据源）
```

**关键安全决策（溯源实证）**：
- **8389 不直接复用**：`MainActivity.kt:1652-1680` 实证——8389 仅绑定 `127.0.0.1` 回环 + 每次启动随机 `mcp_token`（应用私有目录 `mcp_token.txt`，仅本机进程可读）——**它是「本机 MCP 面」，不是「对外服务面」**。
- 阶段 1 的 LAN 直连走**新用户面代理端**：仅配对会话存活期间绑定 `0.0.0.0:8841`；鉴权 = **配对会话 token**（256-bit，配对时手机生成，经扫码 chan 交给官网侧）；`mcp_token` 永不外发；8389 保持不变（回环）。

## 四、数据流契约（修订）

| 项 | 定义 |
|---|---|
| 配对 | **官网出码**（二维码载荷=一次性 sessionRef）→ 手机 App 扫码 → 手机确认 → 双方会话密钥协商 → 建立 |
| 请求 | `GET /user/<section>`（浏览器 → 用户面代理端；Bearer = 会话 token）|
| 响应 | 手机本地组装（JSON；脱敏=InfoVault 白名单；明文仅本通道）|
| 鉴权 | **会话 token 校验层**（用户面代理端强制：无 token/错 token → 401；token 泄漏=单会话吊销即断）|
| 审计 | 配对建立/断开/内容类型 → 手机 journal（用户可见）|

## 五、安全红线（修订：加鉴权条）

1. **用户内容零服务端存储**（含缓存/日志）
2. **配对=显式用户动作**（官网出码+手机扫码+手机确认）；单方解除=立即断开
3. 断开=离线态（不做默认缓存/不显示旧数据）
4. 只读投影第一版（写操作另评）
5. 投影数据遵循 InfoVault 白名单（凭证 NEVER/照片需确认）
6. **用户面鉴权**：用户面代理端只认「会话 token」；`mcp_token`（8389 本机）永不外发；**同 WiFi 下无 token 一律 401**（防同网他人拉取手机内容）

## 六、分阶段范围（同 v1，加用户面端）

- 阶段 1：官网出码 + 手机扫码配对 + **用户面代理端（0.0.0.0:8841 + 会话 token）** + 只读投影四类
- 阶段 2：WebRTC P2P + STUN/TURN + E2E + 断线重连
- 阶段 3：官网登录态=配对关系；写操作另评

## 七、验收思想（修订：加鉴权判据）

- U108-1 配对建立（官网出码→手机扫→确认→sessionId）
- U108-2 投影正确+脱敏正确（凭证类不出现）
- U108-3 断开→离线态；重连→恢复
- U108-4 服务器零存储扫描
- **U108-5 鉴权：同 WiFi 无 token 请求 → 401；错 token → 401；8389 仍仅回环（curl 127.0.0.1 可达 ≠ LAN 可达）**
