## 二、字段 Schema：全面强类型化（治 G5 弱类型病）

飞书多维表格的命门是**字段有类型、单选取值域封闭、公式派生**。我们的字段纪律对齐：

| 字段类型 | 应用于 | 取值域/规则 |
|---|---|---|
| 自动编号 | 各表 ID 列 | 前缀+递增，唯一不复用（UPG-/W-/S-/E-/挂账-/A-） |
| 单选（带色） | 状态列 | **封闭取值域**：工单=未启动/设计师处理中/程序员处理中/验收中/打回修复中/待合main/审验中/已完成；事件=待办/进行中/待外部/完成；非法值 sync fail-loud |
| 单选 | 优先级 | P0/P1/P2/P3（**废止**「批1P0/批2P1」复合写法——复合优先级拆两行或注备注） |
| 人员（角色） | 负责方/发现者 | 用户/设计师/程序员/验收员/审验员/外部机构 |
| 日期 | 截止/更新/完成日 | ISO 或 MM-DD，临期 3 天变红 |
| 关联（Link） | 关联列 | 指向其他表记录的 ID 列表（W-08 设计），双向渲染 |
| 公式 | status/blocked | deriveStatus 等派生列，**禁止手填**（手填与公式冲突时以公式为准并告警） |
| 多行文本 | 备注/详情 | 自由文本，敏感词双保险（源头禁写+sync 打码） |

**录入纪律（先表后库的 Bitable 表述）**：登记 = 向表中新增/更新记录；先 xlsx 后 md 即"先录结构化字段，后补长文本详情"。

## 三、视图注册表：workbench 树 = 视图目录

飞书里视图是"表的镜头"（同一张表，多种看法）。把我们的树节点重述为**命名视图**（视图配置=筛选+分组+排序，不含数据）：

| 视图名（=树节点） | 基于表 | 视图类型 | 配置 |
|---|---|---|---|
| 总览 | T1+T2+T3 | 仪表盘 | focus 混排 Top5 + 各表状态计数卡 + 红点汇总 |
| 工单流转 | T1 | 看板 | 按 status 分组（步进泳道），按 prio 排序 |
| 挂账与问题 | T4 | 看板 | 按 status 分组（⏳待审红点） |
| 验收记录 | T5 | 表格（时间倒序） | 按 date 倒序，可按 ticket 筛选 |
| 事件 | T3 | 看板 | 按 status 分组（待外部不红点；临期红） |
| 事件日历 | T3 | 日历 | 按 截止 字段落格（**新增**，事务线的杀手锏视图） |
| 维度板块×12 | T2 子表 | 看板/画册 | 档案型子表用画册（卡片大图） |
| 归档 | T1+T2+T3 | 表格 | 筛选 status=已完成，按完成日倒序 |
| 关联视图 | 全表 | 关联 | 任意记录展开其 Link 链（W-08） |

**新增的两个飞书式视图**（本重塑的增量）：
1. **事件日历视图**——事件按截止日落格，月底看排期一目了然（备案审核周期、证件到期）；
2. **画册视图**——资产档案表（商标图样、证书扫描件）以卡片图展示，品牌维天然适配。

## 四、仪表盘（总览升级版）

飞书仪表盘 = 图表组件自由组合。总览重排为四个组件：
- **focus 混排 Top5**（现有，跨线权重已定夺）
- **状态漏斗**：工单八态计数（在哪一环淤积一眼可见）
- **红点清单**：全库红点记录平铺（比冒泡更直接的行动列表）
- **本周动态**：验收/合并/销项事件近 7 日计数（T5 聚合）

## 五、关联（W-08 已设计，纳入本框架）

关联列即飞书 Link 字段；本框架补充一条：**关联 + 视图联动**——事件看板卡片直接内联显示其 Link 工单的状态色点（穿透），点开跳转。

## 七、不做清单（防止重塑变失控）

- 不引入外部多维表格产品/数据库（smart_table 仅作思维参照，不部署）；
- 不做双向编辑（工作台永远只读，录入=改文件）；
- 不做自动化工作流（飞书的"到期自动提醒"这类，本期靠红点+日历视图人肉覆盖）；
- 不做表单视图录入页（网页端不出单，出单纪律仍在流转中心）。
