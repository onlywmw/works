# UPG-76 审批预审单 · 方案 v2 增补（设计师B · 2026-09-03）

> 定位：UPG-76 v1 概览（`审批预审单模式_设计_v1概览_2026-09-02.md`）的**增补**，不替代 v1。
> 缘起：用户问「预审单方案怎么样」——设计师B 答：方向支持、时机对（UPG-73/75/77 底座已齐），但有四个钉子必须钉进方案与 STD，否则会把「判定双写」的病第三次犯回来。用户认可（2026-09-03）。
> 与总纲关系：本增补 = 总纲 R2 的施工口径修正案；UPG-76 同时是执行引擎 **S4（ApprovalGroup 状态机 + EXPIRED）的 UI 面**。

## 钉子 1：审批单 = ApprovalGroup 的呈现形态，不开第三套状态机

- 预审单的状态流转**必须**走执行引擎 v0.4 §8.3 双状态机：Group（pending → partially_decided → completed | expired | stale）× Node（approved | rejected | blocked | expired | stale），逐条独立授权、一次提交。
- v1 卡面的「plan→approved→executing」只是 Group 状态机的投影别名，**禁止**在 UI 层另立状态字段。
- 部分同意/依赖阻断语义照 §8.1 EdgePolicy：C 拒 → D（depends C）blocked；E 独立 → 放行。UI 只呈现不解释。
- 落地含义：UPG-76 与 S4 合并为一单两阶段（JVM 状态机先行、UI 面随后），或 S4 先派、UPG-76 紧跟——二选一由派单时定，**不允许**UPG-76 甩开 S4 单跑。

## 钉子 2：执行绑定——计划外调用 = 硬拦截转新审批（核心安全属性）

- 用户批准的是 LLM 自述的计划，执行是 LLM 临场行为。**清单指纹五元同验只覆盖参数层漂移；「执行时出现计划外工具/步骤」必须独立成闸**：
  - 执行期每一步 dispatch 前比对批准清单（capabilityId + 五元）——命中且在授权次数内 → 放行；**未命中 → 当场转新 ASK（现行弹窗通道），禁止顺着批过的单子滑过去**。
- 验收锚（STD 必收）：
  - A3-2 执行时注入计划外工具调用 → 硬拦截 + 新审批弹窗，原计划项不受影响（变异亲杀：删掉计划外比对 → 红）；
  - A3-3 批准后篡改参数（五元之一漂移）→ APPROVAL_STALE 不执行（复用 UPG-73 语义亲杀）。

## 钉子 3：扫描阶段机制性只读 + 出单门槛（防过度设计）

- 「预演零副作用」不靠 LLM 自觉：扫描阶段挂 **READ-only 工具面**（写类/支付类工具在扫描期对 LLM 不可见，机制保证不是提示词保证）。
- 出单门槛：计划含 **≥2 个审批级（WRITE/MONEY）步骤**才出预审单；单步直接走现行弹窗（UPG-75 通道）——防「事事一张单」比碎片弹窗更难用。
- READ/无害类**免单**：不上审批单、只推进度（元能力稿 §7.1「感知而不打扰」）——审批单只聚合 WRITE；MONEY 永远独立实时逐笔（红线不动）。
- Token/KV 申报：扫描=多一轮模型请求，方案须申报量级与触发条件（仅多步骤请求触发，简单请求零增量）。

## 钉子 4：时效 + 单次执行 + 失败措辞

- **时效**：审批单批后有时效——EXPIRED ≠ 拒绝（§6.3）：过期不可执行，要跑 = 重新发起新单，不复活旧 token。MONEY 不适用任何预批时效（永远实时逐笔）。
- **单次执行**：每条授权 = 该步骤**恰好一次**执行权；重试/循环消耗新授权（转新 ASK 或明确失败）——防批量批准后被循环重放。
- **A5 措辞修正**：「拒绝 = 撤销后续」→「拒绝 = **阻断下游**」（§8.1）。已执行的外部副作用不可撤回，方案与 UI 文案不得承诺「撤销」；已执行项在单上如实标「已执行」。

## 建议验收锚汇总（STD-UPG-76-v1 起草输入）

| 锚 | 内容 | 亲杀变异 |
|---|---|---|
| A1-1 | 扫描阶段写类工具不可见（机制面断言） | 扫描期放开写工具 → 红 |
| A1-2 | 单审批级步骤不出单（走现行弹窗）；≥2 才出单 | 门槛删除 → 红 |
| A2-1 | 审批单含步骤清单+支付行明示；部分同意可勾选；READ 仅进度 | — |
| A3-1 | Group 双状态机与 §8.3 对齐（无第三套状态字段） | UI 层私设状态 → 红 |
| A3-2 | 计划外调用硬拦截转新 ASK | 删比对 → 红 |
| A3-3 | 参数漂移 → APPROVAL_STALE 不执行 | 跳过五元同验 → 红 |
| A4-1 | MONEY 无论单子批否，执行到该步实时逐笔确认 | 预批豁免 → 红 |
| A5-1 | 拒绝/过期 → 下游 blocked；已执行项标「已执行」不承诺撤销 | 过期复活 → 红 |

S4（ApprovalGroup 状态机，纯 JVM）与 UPG-76 合并一单两阶段，或 S4 先派；R1（ApprovalSurface 组件化 + 3 个 P2 挂账）并行不冲突——预审单 UI 落成时正好接上 ApprovalSurface。
