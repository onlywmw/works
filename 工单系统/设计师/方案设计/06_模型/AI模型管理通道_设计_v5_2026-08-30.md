## 〇、一语

**「AI 模型」一条统一通道：设置页三级 ↔ ModelStore(唯一配置源) ↔ ModelRegistry + KeyVault ↔ AdapterFactory ↔ 请求;会话绑定 `modelEntryId`(实例) + `modelSnapshot`(历史)。换模型/加本地 = 配置,零代码改动。**

---

## 一、模型身份(定死:modelId ≠ entryId)

**两个不同概念**:
- **modelId** = 模型本身(`deepseek-chat`/`llama3.2`),可能多个配置复用;
- **entryId** = 用户配置实例(UUID),是**会话/切换/启停绑定的对象**。

同 `modelId=deepseek-chat` 可有三个不同实例:「DeepSeek 官方(provider=deepseek)」「DeepSeek 中转(provider=openai-compatible, baseUrl=中转)」「本地 DeepSeek(provider=local, baseUrl=局域网)」——**三个 entryId,三个不同配置**。

**⇒ 会话绑定 `Conversation.modelEntryId`(不是 modelId)。**

## 三、会话级绑定(定死)

```
Conversation
├── modelEntryId       ← 绑定实例(继续请求用;删/停→提示替代)
└── modelSnapshot      ← 历史显示"当时哪个模型"(provider/model/label 快照,防 id 复用/改名语义污染)
```
- 新消息默认沿用该会话 `modelEntryId`;模型已删/停 → 进入会话提示选择替代;
- 历史消息显示 `modelSnapshot`(不追 modelEntryId 当前值)。

## 四、Key 安全(定死:JCA 标准,不自写)

- **Android Keystore 生成 AES 密钥 + JCA 标准 `Cipher("AES/GCM/NoPadding")`**(常见库通过叫标准实现;**不自实现 AES/GCM 算法**);
- 密文存 SharedPreferences/DataStore,明文只在内存;`keyName → KeyVault` 契约不变;
- **备份策略(重要)**:Keystore 密钥不可随备份迁移 → 恢复后密文解不开。**`model_store.json`/模型配置可备份;API Key vault 不备份** → 换机提示「已恢复 N 个模型,API Key 需重新输入」(UX 更合理)。

---

## 五、网络安全边界(大神硬问题:不清全 HTTP)

**分类型,不清全 cleartext**(Android 9+ 默认禁明文,官方建议避免全局 cleartextTrafficPermitted=true):
- **云端模型**:HTTPS only,不放行明文;
- **本地自部署**:HTTP 允许,但限 `localhost / 127.0.0.1 / 局域网 IP`(network_security_config 精确放行,非全局)。

**保存时 URL 安全校验**(防用户把任意 baseUrl 变成明文出口):
```
https://xxx.com        ✅ 云端
http://localhost       ✅ local
http://127.0.0.1       ✅ local
http://192.168.x.x     ✅ local
http://10.x.x.x        ✅ local
http://8.8.8.8         ⚠️ 非 local 明文,拒绝(作为本地)
http://公网IP          ⚠️ 拒绝为 local
```
**L2 真机语义修正(大神)**:真机连电脑 Ollama 用 **局域网 IP `192.168.x.x:11434`**(非 127.0.0.1=手机自己);模拟器用 **`10.0.2.2:11434`**;仅 Ollama 跑在设备本机才用 `127.0.0.1`。服务端需 `OLLAMA_HOST=0.0.0.0`。

## 六、适配层(大神:provider 是身份,≠ Adapter 类型)

**AdapterFactory 收敛**——不要过早建一堆 DeepSeek/Ollama/LMStudio/vLLM/LocalAI Adapter:
```
provider=deepseek / openai / local / openai-compatible / …  → OpenAICompatibleAdapter
provider=gemini(真协议不同)  → GeminiAdapter(仅这种才 Native)
```
> provider = 品牌身份;协议相同(多 /v1/chat/completions)→ 统一 OpenAI 兼容;只有真不同协议才加 Native Adapter。未来加模型极轻。

## 八、⚡测试状态机 + connectionStatus

```
UNTESTED → TESTING → READY
                     └→ ERROR(分型:网络不可达/服务未启动/模型不存在/API Key 无效/模型加载中)
```
分型错误消息(用户自解):
- 网络不可达:`无法连接服务 {ip}:无响应,请确认手机与电脑同一 Wi-Fi`
- 服务未启动:`请启动 Ollama 后重试`
- 模型不存在:`服务已连,但模型 llama3.2 不存在`
- API Key 无效 / 模型加载中(首载 30-60s 用长超时)
- 测试用 `max_tokens=1` 最小 chat 请求(非只 ping /models);列表页持久化「上次测试时间/结果」。

```

   │ model.* API
   ▼
ModelStore(唯一配置源) ──sync──> ModelRegistry(当前/启用)

   ▼

Conversation: modelEntryId + modelSnapshot
聊天页: 当前会话 → modelEntryId → ModelStore → chipLabel() → 「LLaMA 3.2」
```

## 十、验收测点

- **L1**：①三级可导航(含连接方式分流) ②model.list=ModelStore 全量(当前✓/启用态/connectionStatus 分列) ③加云/本地模型→Store+Registry+请求可用 ④切换 setDefault→Registry+chip 变 ⑤key 归属模型 ⑥chip 缩写随 provider+版本(自动缩对) ⑦本地 provider=local 识别 + URL 校验(108.8.8.8 拒绝 local)。
- **L2 真机**：本地自部署用**局域网 IP 192.168.x.x:11434**(模拟器 10.0.2.2)连接成功;明文 HTTP 精确放行(非全局 cleartext);key 密文存储(shared_prefs 无明文 Keystore 加密库);旧 DeepSeek key 自动迁移默认模型;换机备份→模型恢复/API Key 提示重录。
- **L3**：AdapterFactory 按协议分发(deepseek/local→OpenAICompatible)；删除当前→自动设启用模型当前;无启用模型→禁输入+引导;**会话 modelEntryId 绑定**(换 modelId 同名实例不污染历史,modelSnapshot 显示当时模型)。
- **补充**：①model_store.json 原子写盘完整性(临时+rename) ②迁移 version+migration flag 幂等(二次启动不重复建默认) ③无可用模型空态路径。
