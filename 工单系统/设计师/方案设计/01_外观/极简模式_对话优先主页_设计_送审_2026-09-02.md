## 〇、一句话

**极简模式 = 对话优先主页**：进入后只剩一个 **Hero 视觉单元（HeroVisual）**——点它直接说话 / 输入框打字 → 一句话（如「我要吃辣椒炒肉」）→ logo 隐去、**全屏实时渲染结果页**（商家卡片：图片/价格/参数/付款键）→ 底部继续对话。技术路线上：**纯 HTML5 四化 + 一个核心 JS 渲染引擎 + 现有模块逐步迁入引擎**。

## 一、前因后果（为什么是现在 · 从哪来）

### 1.1 在路线中的位置

```text
语言输入（语音 ASR 设计 v1·已出）→ 极简模式（本方案）→ 外观组件化（CT-03/v4.1）→ 商业板块（CT-13/14）
```
极简模式是承上启下的核心一环：语音输入的主场、外观组件化的第一个真实模块、商业板块（付款键/商品卡）的体验层。

### 1.2 现状盘点（实读）

| 能力 | 现状 |
|---|---|
| TTS 播报 | ✅ 已有（xiaomi.speak 小爱引擎） |
| 语音输入 ASR | ❌ 零实现（ASR 设计 v1 已出，待施工） |
| 结果呈现链 | ✅ 已有（Markstream 全屏 MD 渲染 / WebPageSheet / PresentToolSupport） |
| 结构化 JSON→UI 渲染（schema2ui） | ❌ 无——**本方案唯一新件** |
| 页面技术栈 | 存量=mov-vue（Vue 页面：设置/市场/资产…）；新线=纯 HTML5 引擎 |
| 外观极简 v3.1 | ✅ 已有（皮肤/形态极简：输入框三形态/明暗/状态矩阵）——**与本方案分层** |

### 1.3 明确「极简模式」≠「外观极简」

```text
v3.1 外观极简 = 皮肤/形态层（输入框 capsule、明暗）——「界面变简洁」
本方案  极简模式 = 交互范式层（主页=一个 logo，一切靠对话）——「交互变聚焦」
两者叠加：极简模式里用 v3.1 的极简形态组件（不冲突、互补）
```

### 1.4 动机（用户原话整理）

极简模式不是「功能阉割」，是**把复杂的 App 压成「一个说话入口」**——对老人/小白/快速场景（点个餐、查个东西）是零学习成本的入口；对大 logo 的品牌感是「开口即用」的产品主张。

## 二、设计思路（技术路线 · 用户三轮对齐定稿）

### 2.1 四化一条线（用户定夺）

```text
① 纯 HTML5：UI 唯一载体=WebView（不做原生 UI 拼装）
② UI 组件 = CSS 拼装化：组件=CSS 类组合（.card + .card--offer + .img）
   不加 Vue/React 运行时——轻引擎路线
③ 内容 = LLM「重要内容提取」填充化：
   LLM 从工具结果/长内容中提取重要内容（图/名/价/参）→ 填充组件
   —— LLM 不产页面/不产 HTML，只做「提取器」
④ HTML 骨架 = API 拼接化：页面骨架不是写死 HTML，是结构描述（JSON）
   → JS 引擎拼 DOM——骨架随数据变
⑤ 核心资产 = 一个 JS 渲染引擎（骨架拼装/组件装配/LLM 提取管线/事件/状态）
```

### 2.2 引擎架构（唯一心脏）

```text
           mov-render-engine (core.js)
  ┌───────────┬───────────────┬───────────────┬──────────────┐
  │ skeleton   │ assembler     │ component     │ llm-extract  │
  │ 拼装器      │ 组件装配器      │ (CSS 组件库)    │ 提取管线      │
  │ JSON→DOM   │ 组件挂载/事件   │ 类组合/主题化   │ 内容→结构化    │
  └───────────┴───────────────┴───────────────┴──────────────┘
  数据流：API 骨架(JSON) + LLM 提取物(结构化) → 引擎 → DOM → WebView
```

### 2.3 引擎共用 · 模块化迁移（用户定夺：现在共用，不做大迁移）

```text
现在：引擎立起来——极简模式 = 第一个引擎模块
  ↓
逐步：模块逐个迁移（设置→市场→资产→… 每次模块改版时顺手迁，不大改）
  ↓
最终：一个引擎 + 数据统一（组件一套/逻辑一处/数据同源）
```

- **为什么安全**：模块化=每张迁移卡只动一个页面（小 diff/小验收面/单点回滚）；不是大迁移（一次动全站=高险）
- **为什么高效**：共用引擎后组件一套（CSS 类组合库）/逻辑一处/数据统一（骨架 JSON 同源）——不再各页各写
- **迁移规则**：①模块改版时顺手迁（不单独开迁移专项）②迁移卡=「渲染壳替换+行为回归」（原功能零变化）③新页面一律引擎上建（不加新 Vue 页——红线）

### 2.4 安全基础（与既有红线一致）

- **LLM=提取器**（结构化输出，永不产 HTML）——XSS/UI 注入红线（与外部注入锁死、CT-07 白名单、MCP 资产治理同哲）
- 骨架与组件契约化：先冻结契约（骨架 JSON/组件类组合/提取 schema）再写引擎——**契约纪律**（与 CT-03 一致）
- 商业面联动：付款键占位（「即将开放」）——商业期经 CT-14 + **UPG-68 Commercial Entry Gate** 激活

## 三、要呈现的效果

### 3.1 交互流（五态）

```text
① 进入极简模式（入口：设置切换/开机默认——待拍板）
   ↓
② 极简主页（极简单元）
   ┌──────────────────────┐
   │    [HeroVisual]          │ ← 可注入：图案/动画/特效/文字（MOV 默认=品牌 logo）
   │  「说出或输入你的需求…」 │
   │  [🎤 点 logo=说话] [输入框: 打字] │ ← 双通道输入
   └──────────────────────┘
   ↓
③ 一句话：「我要吃辣椒炒肉」（说 or 打）
   Hero 画面过渡隐去（轻动画，不黑屏）
   ↓
④ 全屏结果页（实时渲染）
   ┌──────────────────────┐
   │ [商家卡片：图片|价格|参数|付款键] │
   │ 底部输入条：「换一家」「不要辣的」… │
   └──────────────────────┘
   ↓
⑤ 返回：轻触空白/「←」→ 回到 ②（Hero 再现循环）
```

### 3.2 Hero 视觉单元（中心元素的正式抽象）

**中心元素不是「必须 logo」——是 Hero 视觉单元（HeroVisual）**：主页中央的可注入呈现槽，任何形态都可作为它的值：

```text
图案  → 静态图（品牌 logo/插画/照片——MOV 默认=竖眼 logo）
动画  → 动效（Lottie/CSS 动画/粒子流）
特效  → 渐变/模糊/3D/光效（品牌炫效）
文字  → 品牌名/标语/自定义句子（可让 LLM 生成「今天推荐」文案）
```

- **交互语义**：用户原话——「**logo→说话/打字，不是 logo 说话打字**」——Hero 只是**起点（点击即说话/打字）**，Hero 展示什么与「它是一个输入起点」无关
- **引擎装配**：HeroVisual = core.js 的一个组件（CT-03 注册），值=装配配置（皮肤值段/白标注入）——第三方可放他们自己的任何视觉（不只是换 logo 图）
- **品牌一致性**：MOV 默认=品牌竖眼（logo 定案保持）；第三方/白标=商业期注入（架构位现在留好）

### 3.3 结果页呈现（商家卡片 · 模板化）

```json
{ "type": "offerCard",
  "fields": { "image": "🍛 占位", "name": "湘味小炒 · 辣椒炒肉",
              "price": "¥32 起", "params": ["辣度·中辣","份量·1人份","配送费¥3"],
              "actions": ["order(占位)", "more", "close"] } }
```

**呈现效果**：卡片=图片区（占位图源，商业期接真实图）+ 名称/评分/月售/送达时长 + 产品参数 chips（辣度/份量/配送费）+ 价格高亮 + **付款键（占位「即将开放」）**；底部输入条继续对话（「换一家」→ 卡片切换第二家——demo 已实现）。

### 3.4 视觉（MOV token 双套）

- **默认浅色 + 深色**（`data-theme`——demo 已可切）；品牌绿 token（CT-01 换肤标准）
- **极简单元**：无菜单/胶囊/抽屉——主页只留 logo + 双通道输入
- **动效**：logo 缩放淡出 → 结果页上浮（沉浸，非新窗口）；说听状态 pulse 动画

### 3.5 Demo（配套体验）

`设计预览\极简模式_demo_v1_2026-09-02.html`（双击即开，431px 手机框）：
- 点大 logo → 模拟听写「我要吃辣椒炒肉」→ 转场结果页
- 输入框打字回车 → 同样渲染；底部「换一家」→ 卡片切换
- 付款键点按显示「即将开放（商业期）」；`data-theme=dark` 切深色

| 状态 | mic | 输入框 | 结果页 |
|---|---|---|---|
| 主页 idle | 可见 | 正常 | — |

## 四、技术选型确认

| 问题 | 结论 |
|---|---|
| Web 底层？ | ✅ **必须**——动态内容 HTML 天然；现有 WebView 通道（appassets 本地域+syc-pages 产物链）零新基建 |
| 引擎 vs Vue | **引擎共用**（用户定夺）——Vue=存量技术债模块化退场，新页面一律引擎 |
| 新件 | ①core.js 渲染引擎（骨架拼装/组件装配/提取管线）②schema2ui（JSON→模板渲染）③merchant.search mock 工具 |
| 复用 | AgentLoop（不动）/WebView 通道/PresentToolSupport 呈现链/Markstream（文本类）/CT-01 token/CT-03 组件契约 |
| 不引入 | 无新 SDK/无框架（纯 JS）/无原生 UI 层（除既有 WebView 宿主） |
| **PC 端（未来注记）** | 引擎=纯 HTML5 → **天然跨端**（浏览器直接渲染）——PC 端沿用同一引擎，不另起 Vue；「一次编写双端适配」用自有引擎实现（PC 端具体栈=立项时定；外部白皮书分级存档见 ） |
