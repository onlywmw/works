## 二、v4 扩展：组件可插拔统一契约（换芯层）

### 2.1 UIComponentRegistry（与 AssetKind Registry 同构）

```text
UIComponentRegistry
  ├─ 组件契约 {component_id, props 接口, 默认实现, 可替换级别}
  ├─ 三级替换点
  │    ├─ P 页面级  ── 整页实现可换（如资产首页换全套布局）
  │    ├─ B 区块级  ── 卡片/列表行/面板可换（核心——同 AssetKind 类目卡片）
  │    └─ A 原子级  ── 按钮/输入框/图标可换
  └─ 声明式配置 {component_id: impl_id}（换实现=改配置，不动代码）
```

- **同构参照**：67-A AssetKind Registry 已验证（注册制/注册即用/替换不破坏既有——本契约照搬其纪律）
- **与 v3.1 的关系**：v3.1 的形态映射 = 组件**内部形态**（classic/capsule/underline 是 input 的形态值）；v4 的实现映射 = 组件**本体**（impl_id 指向整套实现）——两层正交：换皮（v3.1）/换芯（v4）独立生效

### 2.2 替换来源分级

| 来源 | 允许 | 说明 |
|---|---|---|
| **内置多套** | ✅ | 默认/极简/深色/演示——与 v3.1 皮肤扩展自然衔接 |
| **外部注入（MCP/市场 UI 包）** | ❌ **本契约不开放** | 插件化=安全面风险（UI 注入/DOM 污染），**锁死不开放**——未来如需求，独立立项评估安全面（参照 MCP 资产访问治理的教训：单用户本机场景不做企业级） |
| **开发者 patch（改仓库代码换实现）** | ✅ | git 管理，走验收 |

### 2.3 覆盖范围（部署面）

- **Vue WebView 侧先行**（mov-vue 组件栈：设置/市场/资产页等——与资产类目同栈，落地最快）
- **原生侧（气泡/抽屉/设置 sheet）留机制位**：本契约定义接口形态（component_id/impl_id），原生侧实现排后（量级大，先不动）

## 三、配置与解析（v4 统一二合一）

```text
appearance = {
  globalMinimal: false,                      // v3.1 继承
  components: { input:'capsule', ... },      // v3.1 继承（形态映射）
  impl: { assetCard:'impl.eco',              // v4 新增（实现映射——换芯）
          homePage:'impl.classic' }
}
→ UIResolver（v3.1 Resolver 扩展）→ 算最终 {形态类, 实现组件} → DOM
```

- 单源：一张配置表（impl 映射并入 APPEARANCE_MAP 同源管理）
- 回滚：置换实现=改配置回默认（无破坏状态；默认实现永在 registry 兜底）

## 四、验收测点（v3.1 全继承 + v4 新增）

**v4 新增判据**：

| 编号 | 判据 | 通过标准 |
|---|---|---|
| V4-1 | 注册制不破坏既有 | 注册新组件实现（test_impl）→ 默认组件的渲染/行为零变化 |
| V4-2 | 替换即生效 | 配置 impl_id → 页面重新渲染为新实现（无刷新/无坏状态） |
| V4-3 | 回滚安全 | impl 配置回默认 → 恢复现状（registry 默认实现兜底） |
| V4-4 | 两级正交 | 换皮（components）+换芯（impl）独立生效互不干扰 |
| V4-5 | 外部注入锁死 | grep 断言无外部构件加载路径（MCP/网络注入=0 命中） |
| V4-6 | 状态矩阵 | 新实现组件过 v3.1 状态矩阵（default/focus/error/disabled×明暗） |

## 五、实施路线（v3.1 × v4 合并）

```
v3.1 第一阶段（先跑通机制） → 输入框3形态+明暗+状态+持久化
   ↓（机制已验证后）
v4 注册制扩展 → UIComponentRegistry → 区块级先行（资产首页/凭据卡·同 AssetKind）→ 页面级 → 原子级
```

**先窄后宽**：v3.1 第一阶段照旧先跑（机制/状态/可用性），v4 注册制在其上叠加；不并行铺开（组件克制纪律）。
