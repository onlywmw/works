## 〇、一句话

**极简模式 = 对话优先主页（不是换皮肤！）**：大 logo 品牌主页 → 说话/打字一句话 → 全屏实时渲染结果页（数据→模板→WebView）→ 继续对话/轻触返回。Web 底层是对的（回答用户问句）。

## 一、定位（与既有体系区分清楚）

| 概念 | 是什么 | 关系 |
|---|---|---|
| v3.1 外观极简 | **皮肤/形态**极简（输入框 capsule/明暗/状态矩阵） | 叠加层——极简对话主页上的组件形态用 v3.1 |

| 外观组件化 v4.1 | 组件可插拔（换皮+换芯） | 结果页卡片/logo 组件走 CT-03 |

**极简模式 ≠ 空屏**：极简=省全部 HUD（菜单/胶囊/抽屉），只留「说话/输入」这一个动作——但对话后的**结果页是丰富的**（这正是「极简入口 + 丰富结果」的张力点）。

## 二、交互流（五态）

```text
① 进入极简模式
   入口：设置/极简切换（待定：开机默认？手势？——决策点 1）
   ↓
② 极简主页（极简单元）
   ┌─────────────────┐
   │   [MOV 大 logo]   │ ← 可替换第三方（决策点 2：皮肤化 vs 白标）
   │                  │
   │  「说出或输入你的需求…」│
   │  [🎤 点 logo=说话] [输入框: 打字] │ ← 双通道输入
   └─────────────────┘
   ↓
③ 一句话（例：「我要吃辣椒炒肉」）
   logo 画面过渡隐去（轻动画，不黑屏）
   ↓
④ 全屏结果页（实时渲染）
   ┌─────────────────┐
   │  [商家卡片：图片 | 价格 | 参数 | 付款键] │
   │  底部输入条：「换一家」「不要辣的」…     │ ← 继续对话
   └─────────────────┘
   ↓
⑤ 返回：轻触空白/「返回」→ 回到②logo 主页（循环）
```

**关键交互**：③→④ 是**同一个页面切换**（非新窗口）——logo 隐去、结果浮出，符合「实时渲染沉浸感」；④ 内继续对话 = 回到③ 的输入态（结果页保留，输入置于底部）。

## 三、技术判断：Web 底层对不对？——**对，而且必须**

用户问「用 web 底层比较好实现吧？」——答案是**对**，三个理由：

1. **动态内容天然 HTML**：图片/价格/参数/按钮 = 结构化数据的 UI 化——Web 模板渲染最灵活（native 手排动态布局=布局爆炸）
2. **现成链已有**：MOV 已有 `MarkstreamViewActivity`（MD 全屏渲染）/`WebPageSheet`（WebView 弹层）/`PresentToolSupport`（工具结果呈现链）——极简结果页可**复用重排**，非从零
3. **外观体系就在 Web 侧**：CT-01 换肤 token / CT-03 组件契约（mov-vue）——结果页卡片直接进组件化体系

### 但有一个**关键安全限定**（不能是「LLM 直接出 HTML」）

```text
❌ LLM 产 HTML → WebView 渲染     （XSS/UI 注入——外部注入锁死同哲，禁止）
✅ LLM 产结构化数据（JSON Schema）
     → 模板渲染（MOV token + CT-03 组件卡片）
     → WebView 展示
```

**这是本项目一贯红线**（与 UI 外部注入 DENY、MCP 资产访问治理同源）：AI 只产出数据，**渲染交给受控模板**——「商家卡片」= 一个模板组件（数据字段：图片/名称/价格/参数/按钮动作），LLM 只填值。

## 四、渲染管线（现成链 + 缺口）

```text
语音/输入 → LLM 工具调用（mock/实商户）
  → 工具结果（结构化 JSON：{image,name,price,params,action}）
  → [缺口] schema2ui：JSON→模板渲染（需补！）
     ↓ 复用：PresentToolSupport 呈现链 + Markstream（文本类）/新模板卡（数据类）
  → WebView 全屏页（WebPageSheet 沉浸模式：无边框/无地址栏/输入条下沉）
  → 交互：点击付款键 →（商业期）CT-14 支付链；现占位=「即将开放」
```

**缺口**：`schema2ui`（JSON Schema → UI 模板渲染器）现无——是极简结果页的核心新件（~中量级）；其余全复用。

### 结果页「商家卡片」模板契约（CT-03 第一实例 · 雏形）

```json
{ "type": "offerCard",
  "fields": { "image": "...", "name": "辣椒炒肉·湘菜馆",
              "price": "¥32", "params": [{"辣度":"中"},{"份量":"1人份"}],
              "actions": ["order"(占位), "more", "close"] } }
```

## 九、技术路线定稿（用户拍板 @2026-09-02 · A+C）

### 9.1 用户路线（四化一条线 · 原文确认）

```text
① 纯 HTML5：UI 唯一载体=WebView（不做原生 UI 拼装）
② UI 组件 = CSS 拼装化：组件=CSS 类组合（.card + .card--offer + .img）
   —— 不加 Vue/React 运行时，轻引擎路线
③ 内容 = LLM「重要内容提取」填充化：
   LLM 从工具结果/长内容中提取重要内容（图/名/价/参数）→ 填充组件
   —— LLM 不产页面/不产 HTML，只做「提取器」（安全面更纯）
④ HTML 骨架 = API 拼接化：页面骨架不是写死 HTML，是结构描述（JSON）
   → JS 引擎拼 DOM——骨架随数据变
⑤ 核心资产 = 一个 JS 渲染引擎：
   骨架拼装器 + 组件装配器 + CSS 组件库 + LLM 提取管线 + 事件总线 + 状态
   ——「重点把核心 JS 做好、引入 LLM」
```

### 9.2 引擎架构（唯一心脏）

```text
           mov-render-engine (core.js)
  ┌───────────┬───────────────┬───────────────┬──────────────┐
  │ skeleton   │ assembler     │ component     │ llm-extract  │
  │ 拼装器      │ 组件装配器      │ (CSS 组件库)    │ 提取管线      │
  │ JSON→DOM   │ 组件挂载/事件   │ 类组合/主题化   │ 内容→结构化    │
  └───────────┴───────────────┴───────────────┴──────────────┘
  数据流：API 骨架(JSON) + LLM 提取物(结构化) → 引擎 → DOM → WebView
```

- **骨架契约**：页面 = 骨架 JSON（节点/组件类型/插槽）——API 拼接化
- **组件契约**：CSS 类组合目录（配合 CT-01 token 主题化；CT-03 组件注册制沿用）
- **提取契约**：LLM 提取物 = 结构化 JSON（如 offerCard {image,name,price,params}）——**LLM 永不产 HTML**（XSS/UI 注入红线，与外部注入锁死同哲）
- **状态**：引擎内状态统一（页面/输入/会话）——数据统一

### 9.3 引擎共用 · 模块化迁移（用户定夺 @2026-09-02 · 修正 A+C）

```text
现在：引擎立起来（core.js 渲染引擎）——极简模式 = 引擎第一个模块
      ↑
逐步：一个模块一个模块迁（设置→市场→资产→… 每次改版顺手迁，不大改）
      ↑
最终：一个引擎 + 数据统一（用户原话「共用一个引擎，更加高效且数据统一」）
```

- **为什么安全**：模块化迁移 = 每张迁移卡只动一个页面（小 diff + 小验收面 + 单点回滚）——不做「大迁移」（大迁移=一次动全站=高险）；每模块迁移=独立批次验收
- **为什么高效**：模块共用引擎后——组件一套（CSS 类组合库）/逻辑一处（事件/状态/提取管线）/数据统一（骨架 JSON 同源）——不再各页面各写
- **迁移规则**：①模块改版时顺手迁（不单独开「迁移专项」——顺势而为）②迁移卡=「渲染壳替换 + 行为回归」判据（原页面功能零变化）③新页面一律引擎上建（不加新 Vue 页——红线）
- **Vue 定位**：存量技术债——每迁一个减一个，余下直到全迁完

### 9.4 与现有体系关系

| 体系 | 关系 |
|---|---|
| AgentLoop/工具链 | 不动（引擎只管呈现——输入→LLM→工具→结果 JSON→引擎渲染） |
| WebView 通道 | 复用（appassets 本地虚拟域 + sync-pages 产物链） |
| Markstream/M-VIEW | 文本类内容仍可走引擎的 md 组件（嵌入 not 取代） |
| CT-03 组件契约 | 沿用（引擎组件=CSS 类组合+注册；与原 v4.1 契约定稿一致） |
| 安全 | LLM=提取器（结构化输出）→ 引擎契约化拼装——最干净的面 |
