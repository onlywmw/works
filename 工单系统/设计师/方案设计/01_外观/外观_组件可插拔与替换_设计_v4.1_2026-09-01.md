## 二、P0-1：ComponentContract（契约钉死第一件）

**实现可以换，但组件契约不能换。**

```text
ComponentContract {
  component_id            // 命名空间：asset.card / home.page（角色+组件名）
  props_schema            // 输入契约（JSON Schema：必填/可选/类型——换芯不换 props）
  events_schema           // 输出契约（事件名+payload——页面依赖的事件集不变）
  slots_schema            // 插槽契约（哪些槽可覆盖/供内容）
  state_schema            // 状态契约（状态字段+语义——State Ownership 落地）
  accessibility_contract  // 无障碍契约（aria/label/焦点——换芯不可降级）
  lifecycle_contract      // 生命周期契约（mount/unmount/remount 语义）
  capability              // 能力契约（见 §三）
}
```

**依赖方向（钉死）**：

```text
页面 → ComponentContract → [impl.default / impl.eco / impl.compact]
```

页面**只依赖 Contract**，永不直接依赖 impl——这是「换芯不动其他代码」的工程保证（不是产品描述）。

- **props_schema 不一致不允许注册**：impl 声明的 props 必须与 Contract props_schema 匹配（Registry 注册时校验，运行时挂载不校验=启动即校验）
- **accessibility_contract 不可降级**：换芯若破坏无障碍（aria/焦点），与「纯显示层」原则冲突——注册校验拦截

## 三、P0-2：Capability Contract + Capability Check（契约钉死第二件）

**能渲染 ≠ 满足契约**——impl 可能缺行为能力（不糊弄）。

```text
Capability Contract（属于 ComponentContract.capability）：

assetCard:
  required:  [render, click, selected, disabled]
  optional:  [drag, contextMenu, loading, permission-denied]

Registry 解析：
  impl.eco → Capability Check
    ├─ 满足 Contract（required 全覆盖）→ 使用
    └─ 否 → fallback default（Registry 默认实现兜底）
```

- required 缺失 → **拒绝使用该 impl，回退默认**（V4-8 判据）
- optional 缺失 → 允许使用，**但页面若尝试调用 optional 能力需有默认降级路径**（契约级声明「该 impl 无 drag → 拖拽入口灰显」——诚实空态纪律同源）

## 四、P0-3：State Ownership（契约钉死第三件 —— 大神：「比状态矩阵更关键」）

**状态属于 Component，不属于 Impl。**

```text
oldImpl → Component State → newImpl        （State Adapter）

Impl 只负责实现 ComponentContract；
业务状态、语义状态、持久化状态归属 Component Runtime，不得绑定具体 Impl。
```

- 换芯时：业务状态（如 asset.selected / expanded）**原样保留**；UI 瞬态（滚动/动画中间态）按组件级策略恢复或重置
- **持久化状态**（配置/草稿）永远在 Component 层——Impl 换掉不带走
- 落地：Component Runtime 持有 state，Impl 只接收 props/state + 发 events（纯渲染实现）

## 五、P0-4：Override Resolution（契约钉死第四件 —— 防配置地狱）

**不要让三级替换演变成「谁最后写入谁生效」。**

```text
优先级（同一 component_id 被多级配置时）：
  页面局部 > 区块局部 > 原子局部 > 全局 impl > Registry default
```

- 更具体的**作用域**赢（与 CSS specificity 同思想——越具体越优先）
- 同级重复配置 → **确定性拒绝**（配置校验时报错，防「谁后写谁赢」不确定性）
- 简化记忆：**Local > Global > Default**

## 六、MCP UI 门户开放（v4.2 修订 · 用户方向+大神终裁）

**UI 最高原则（四条）：**

> **任何 MCP 都可以提供 UI；任何 UI 都必须以组件身份进入 UI Registry；任何注册组件都必须遵守统一 UI Contract；Runtime 负责生命周期、主题、状态、权限、版本与兼容性。**

```text
第三方 MCP
  ├─ Tool
  ├─ UI Component
  ├─ Appearance
  └─ Interaction
        ↓
   UI Registry → Contract Validation → Appearance Resolver → UI Runtime → APP UI
```

### 6.1 两种注册（组件与外观分开）

```text
A. Existing Component Variant（扩展已有组件形态）
   core.input → vendor.xxx.input.cyber（MCP 扩展 input 的 implementation/variant）
B. New Component（新组件类型）
   vendor.xxx.codeEditor（系统没有「代码编辑器」——全新 component type）

Registry 条目：componentId / provider / type / variants / capabilities / states / appearance / interaction
```

### 6.2 第三方自己的设计语言（允许·隔离）

```text
MCP UI Token（brand.primary/surface/radius/spacing…）
    ↓ Token Namespace / Mapping（隔离！）
    ↓ 你的 Theme System → 最终渲染
**第三方可以拥有自己的风格，但不能污染你的全局 token。**
```

### 6.3 契约管什么/不管什么

- **管**：怎么接入/怎么渲染/怎么交互/怎么换主题/怎么声明能力/怎么处理状态/怎么处理版本/怎么退出
- **不管**：必须圆角 8px/必须这种阴影/必须像官方——**统一规范，不统一创意**（否则开放 MCP UI = 官方皮肤插件）

### 6.4 安全红线（不变）

- 注册制全程：Contract 校验（V4-7）+ Capability Check（fallback default）+ 命名校验（V4-11）——「UI 注入安全面=注册制高速，不是无门」
- **UPG-68 Commercial Gate 约束不变**（商业激活前置）；外部组件=可信注册源（签名/沙箱评估随商业期）
- DOM 污染/全局 token 污染=两条死区——Token Namespace 隔离即防护

## 七、热替换契约：Runtime 级 hot replace（大神第 4 条修订 V4-2）

**不要求 DOM 级 hot swap，要求 Runtime 级 hot replace：**

```text
替换生效契约：
  ① 当前页面无需重启
  ② 已挂载组件允许 remount（P/B 级可 remount，不承诺 DOM 零重建）
  ③ 业务状态不丢失（State Ownership 保证）
  ④ UI 瞬态状态按组件级策略恢复/重置（组件契约声明）
```

- A 原子级通常可热替换（低代价）；B/P 级**不强行无刷新**（避免 Runtime 复杂度爆炸）
- 验收口径由「无刷新」改为上述 4 条

## 八、V4-5 升级：CI 门禁化（大神第 8 条）

**grep 一次 ≠ 永远安全——CI 直接失败。**

```text
V4-5' External Provider Policy（四层断言，CI 执行）:
  Runtime:   externalProvider = DENY
  Registry:  仅 BuiltInProvider + DeveloperProvider
  Network:   component loading = 0（无网络加载路径）
  MCP:       component registration = 0（MCP 不可注册 UI 组件）
  CI:        出现 external provider activation path → build 失败（硬闸）
```

## 九、impl_id 命名收紧（大神第 6 条）

```text
component_id:  asset.card                    // 角色.组件名
impl_id:       asset.card.default            // 实现必须声明所属 contract
               asset.card.eco
               asset.card.compact

Registry 天然校验：
  asset.card → asset.card.eco    ✅
  asset.card → home.page.eco     ❌（实现声明属于别的 contract——拒绝）
```

**实现声明所属 component contract，Registry 校验即拦截错误换芯。**

## 十、UI Component Runtime 模型（大神第 10 条 · 最终收敛）

```text
                    UI Runtime
                        │
                UIComponentRegistry
                        │
                ComponentContract
                        │
             ┌──────────┴──────────┐
             │                     │
      Appearance Resolver     Impl Resolver
             │                     │
       classic/capsule       default/eco/compact
             │                     │
             └──────────┬──────────┘
                        ↓
                 Component Runtime
                        │
                 State / Events
                        │
                        ↓
                       DOM
```

- **换皮**：Appearance 变；Component/State/Impl 不变
- **换芯**：Impl 变；ComponentContract/State/Appearance 不变
- **页面换芯**：Page → Block → Atomic 全走同一 Registry（无第二条路径）
