## 〇、一句话总览

**MOV 的 UI 是平台级组件生态**：页面/工具只依赖「组件契约」，实现可换、外观可换、MCP UI 可进（注册制高速）——**统一规范、不统一创意**；组件库选择页=该生态的用户入口（看组件→选形态→即换即显）。

```text
                UI Component Catalog（合法清单/平台ID）
                        ↓
             Component Registry（本机已装/启用）
                        ↓
        UI Component Contract（九字段）+ Variant + UISchema
                        ↓
        Registry Gateway → Validation/Capability/Security → Activation
                        ↓
                Appearance Resolver → UI Runtime
                        ↓
              Actual UI  /  组件库选择页（UPG-50）
MCP 上架 = 绑定 Component ID（公共复用）或贡献获新 ID（验证后）
```

## 一、机制层（v3.1 · 9.0/10 工程契约 · 继承）

- **形态 ID 规范**：`input.capsule → appearance-input-capsule`（同一组件不同外貌）
- **AppearanceProfile**：`{globalMinimal: bool, components: {input: "capsule"}}`——存储契约
- **DisplayAppearanceResolver**：逻辑层最终类→DOM（无 CSS 权重战争）
- **状态矩阵**：default/hover/pressed/focus/error/disabled × 明暗
- **覆盖清除 = A 真删**（选回默认=彻底清除自定义，不留残留态）
- 第一阶段范围：输入框 3 形态 + 明暗 + 状态 + 持久化

## 二、换芯层（v4.2 · 四件钉死 + MCP 门户开放）

### 四件钉死

| # | 钉死 | 内容 |
|---|---|---|
| ① | **ComponentContract** | 九字段（见 §三）；**页面→Contract→impl**（页面永不 import impl——工程不变式） |
| ② | **Capability Check** | required 缺失→fallback default；optional 缺失→入口灰显（诚实降级链） |
| ③ | **State Ownership** | 状态属于 Component 不属于 Impl（换芯不丢业务状态） |
| ④ | **Override Resolution** | 页面局部>区块>原子>全局>Default（CSS specificity 类比） |

### MCP UI 门户开放（最高原则四条）

> **任何 MCP 都可以提供 UI；任何 UI 都必须以组件身份进入 UI Registry；任何注册组件都必须遵守统一 UI Contract；Runtime 负责生命周期、主题、状态、权限、版本与兼容性。**

- **安全边界：不是「不可注册」，而是「不可绕过注册制注册」**
- Contract 管接入/渲染/交互/换主题/声明能力/状态/版本/退出；**不管**圆角 8px/阴影/像官方
- Token Namespace 隔离：第三方有自己的风格、**不污染全局 token**

## 三、Runtime Contract（v5.0 · 单一事实源）

### 九字段 ComponentContract

```text
1 component_id  2 props_schema  3 events_schema  4 slots_schema  5 state_schema
6 accessibility_contract  7 lifecycle_contract  8 capability
9 presentation_contract（新增：name/description/provider/icon/preview_title/category/
                        variant_label/is_official/is_enabled/is_active——组件库零猜渲染）
```

### CI 门禁（v5.0 断言——与注册制开放一致）

```text
✅ 禁止绕过 Registry 直接渲染外部组件（bypass 路径=0）
✅ 注册路径必须经过 Contract Validation + Capability Check
✅ externalProvider 只能通过 Registry 激活（禁直接 DOM 注入/禁全局 token 污染）
❌ 旧断言作废：MCP registration=0
```

### 其余有效条款

- **State Adapter 三态**：业务语义（Impl 注册须声明映射——不声明 fallback）/ 持久化（Component 只读）/ UI 瞬态（remount 重置）
- **State Compatibility 五值**：migrate/preserve/reset/drop/unsupported
- **分级注册 L1/L2**：L1 轻量（无状态/minimal——展示型）；L2 完整——生态门槛
- **版本协商**：impl 声明范围/Registry 只激活兼容/不兼容 fallback+提示/多 impl 版本高优先
- **render-only（七禁）**：无事件/无监听/不改 State/无持久化/无副作用/不超需数据/无长期订阅——U50 预览卡基于此
- **CI/热替换**：Runtime 级 hot replace（页面不重启/允许 remount/状态不丢/瞬态按策略）

## 四、Registration Contract（v2.0 · Catalog+上架绑定）

### 核心原则

> **UI Component ID 是平台级 UI 身份；MCP 不创建匿名 UI。MCP 上架时必须绑定一个已注册的 UI Component ID；可复用公共组件，也可提交自定义组件经验证获得新 ID。**

- **Catalog（合法清单）vs Registry（本机已装/启用）** 两层拆开
- **ID 规则**：`UI-000001` 输入框/`UI-000002` 按钮…公共；`UI-010001+` 第三方——**ID 不表达供应商**（provider 另记）；**永不复用**；版本升级同 ID
- **上架二选一**：绑定公共 ID（`{component_id, version_range}`）/ 上传自定义→Validation→获新 ID
- **绑定 ID 不绑 impl**（impl 由 Resolver 解析——升级零 MCP 修改，与「页面只依赖 Contract」一致）
- **安装 MCP ≠ 安装 UI**（UI 本身=可安装资源——本机没有才装包）
- **四态**：Installed → Registered → Enabled → Selected（安装≠注册≠激活≠选择）
- **Selection Intent**：用户明确选择 > override > 开发者配置 > 系统默认 > BuiltIn（**用户选择后 provider 更新不可顶掉**）
- **UISchema**：声明式渲染协议（type/variant/props/children；禁内联 HTML/模板——schema 是数据不是代码）
- **Variant Contract**：REPLACE/VARIANT/EXTEND 三类机器可判（新组件 vs 变体）
- **版本四层**：Contract/Variant/Implementation/Provider Package（升级失败定位层）
- **Accessibility 生态化**：第三方强制字段级（name/role/…/aria-label/expanded/selected）

## 五、组件库选择页（UPG-50 v1.2 · 用户画面确认）

```text
外观组件库（= Component Catalog 的选择视图）
├─ 每行 = 一个组件（UI-ID·名字·提供者标记）
│   [形态卡横铺]——选中=即换即显（✓ 出现 + 100~180ms 过渡）
├─ 官方精选 + 热门/最近 + 「组件市场」入口（搜索/分类/筛选/启用）
└─ 明暗跟随全局（顶部切换）；仅选中卡可「明暗双框」增强
```

- **选中即替换**：用户手动选择=**最高优先级局部覆盖**（>MCP 默认>系统默认）
- **✓/● 语义**：✓=当前生效；●=最近使用未生效；生效卡不再显 ●
- **展示分级**：形态 ≤3=直接展示 / 4~6=横滑+页码圆点 / >6=点击展开网格——防「MCP 涌入滑不过来」；**运行时只加载已启用形态**
- 预览卡=真实组件实例（render-only）；无障碍（aria-label/焦点序/✓ 非只靠颜色）
