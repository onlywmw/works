## 2 病根（本地盘点证据）

1. **组件目录双份手写**：`UiComponentCatalog.kt`（Kotlin，20 条+52 档）与 `AppearanceApp.vue`（Vue COMPONENTS 数组）不同构、人肉同步——无单一 JSON schema 源。
2. **形态类定义分散**：tokens.css（12 族）/ SettingsPage.vue scoped（SETTINGS 族）/ VaultPage、ModelPage、ChatPage 等**完全写死**未接入编号体系。
3. **无组件运行时**：`<prefix>-<variant>` 只是 class 字符串约定，无注册/context/provider——「可插拔替换」停留在设计稿。**→ 本轮不建设**（见 §3）。
4. **10 页面入口割裂**：每页独立 html + 重复 WebViewAssetLoader/Bridge/主题注入，无统一页面宿主。
5. **规范与实现漂移**：`MOV设计规范_v2` 记 `--primary:#0E7C5B`（深绿），tokens.css 实际 `#23272F`（灰黑）；暗色 s0-s3、Motion/z/elevation/inset token 规范有、代码无。

## 3 改造范围（地基）

### 明确边界
- **本轮不建设组件运行时/注册机制**——「可插拔替换的运行时」归后续阶段（另行立卡）；本卡只统一**目录**与**形态层**。病根 3 的不处置是**有意为之**，不属遗漏。

### A1 目录单一数据源（本单核心）
- 建 `前端设计/mov-vue/src/catalog/ui-components.json`：
  - 字段：`version / id / name / kind / prefix / variants[{id,label,state}] / defaultVariant / site / order / provider / semanticType`
  - `version` + 每字段注释；`semanticType/provider` 为现有目录元数据（展示+后续运行时消费），**本轮不新增半截运行时字段**。
- 生成脚本 `scripts/gen-ui-catalog.mjs` 输出：
  1. `UiComponentCatalog.kt`（CatalogEntry/ComponentVariant/ComponentSpec + 20 编号常量 + components 列表）
  2. `AppearanceApp.vue` 的 `COMPONENTS` 数组段
  3. 断言：schema ⇄ Kotlin ⇄ Vue 全等
- **防漂移三层**：
  1. 生成物文件头 `// AUTO-GENERATED from ui-components.json. DO NOT EDIT.`（断言检查该标记）
  2. pre-commit 钩子跑生成+对账
  3. CI 步骤：`npm run gen-ui-catalog && git diff --exit-code`（无 diff=干净证据落档）
- 双写归零：Kotlin source 引用生成物；Vue import 生成物。

### A2 形态类归层 + 规范对齐（先评估后动）
- SETTINGS 族形态类从 SettingsPage.vue scoped 迁入 tokens.css 形态层（与现有 12 族同层）。
- **规范对齐前置影响面评估**：产出影响面清单（哪些页面/组件消费待对齐 token + 视觉差异说明）→ **用户裁决**：
  - 选「改代码对齐规范」：明确视觉回归风险 + 安排回归测试；
  - 选「改规范对齐实物」：该 token 标记「暂不调整」，只改规范。
- Motion/z/elevation/inset token：落库或从规范删除（按实际使用裁决）。
- 产出 `tools/ui-catalog-audit.mjs`（未接入页面清册）+ 对账表（**含处置结果+影响面**）。

### A3 统一页面宿主（B 阶段：试点先行，拆小单）
- **先试点**：SettingsSheet 做 PageHost 抽象试点（WebView+AssetLoader+Bridge+主题注入通用性）。
- **试点结论**产出（可行性/复用面/风险）→ 再拆多个小单逐步替换其余页面；**不一次重构 10 页**。
