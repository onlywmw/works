## 〇、最高原则（四条不可违反 + 一条军规）

1. **Intent before Navigation**——用户表达意图，不寻找页面。
2. **Content becomes Interface**——内容在需要时成为临时交互界面。
3. **Engine owns Presentation**——引擎拥有呈现制度，LLM 不拥有 UI 决策权。
4. **Base never disappears**——常驻的不是 logo 也不是输入框，而是**输入能力本身**：任何时刻至少一枚输入图标按钮在场（用户拍板修正 @v1.1 送审前：「logo 常驻没必要，可以替换，就是一个按钮而已——但至少要有一个输入的图标按钮」）。

> **军规（评审原话入册）：AI 可以生成内容，但不能生成交互制度。** 选什么壳、放在哪里、几个按钮、什么动画、哪个层级——全部由契约与引擎决定；LLM 只参与内容理解/摘要/亮点/非契约字段提取。

## 一、为什么必须引擎驱动（反例锚）

审批体系教训（2026-09-02 真机 P0 起）：呈现层散装 →「静态全对、运行时黑洞」→ 六张工单连续修补。本体系把呈现从散装代码提升为**引擎（机制件）+ 登记契约（静态件）**；业务代码和 LLM 不许即兴呈现。

## 二、核心抽象：Presentation Surface（呈现表面）

**架构单位不是「卡」，是 Surface**——卡片只是其中一种（评审 P1-1）：

```text
PresentationSurface
├── BaseSurface        底座=空画布 + 输入通道（唯一常驻=至少一枚输入图标按钮：idle 时=HeroVisual 形语音钮[logo=按钮皮肤，可替换/白标注入]+细线打字入口；内容在场时收成右下角一枚小圆钮；点=展开说/打）
├── ContentSurface     内容表面：Result / List / Timeline / PlainText（Transient 默认）
├── DecisionSurface    决策表面：ApprovalSurface（UPG-79 复用）
└── RecallSurface      回看表面：MiniChip（折叠小圆片）
```

**Transient vs Persistent（评审 P1-3——「没有页面」的修正）**：

- **Transient Surface**（默认）：任务结果临时呈现，完成/收叠后消失或入历史；
- **Persistent Surface**（显式允许）：系统管理面——资产/安全中心/记忆/设置/模型管理——用户主动进入、可长期停留。
- 口径：**极简模式无传统页面导航（主页无 tab/路由/返回键），但不禁止 Persistent Surface**——默认不要求用户导航，复杂管理任务允许进入稳定空间。「一切都是卡」不反向绑架系统；全屏地图/相机预览/系统级电话等未来形态=新 Surface 类型注册，不推翻本体系。

## 三、呈现栈模型（z 序自底向上）

```
L0 BaseSurface（常驻）      空画布 + 输入通道（至少一枚输入图标按钮永在场）——内容表面出现时底座 docked（HeroVisual 隐去，输入收成角落小圆钮）
L1 ContentSurface           内容大卡（Transient）
L2 内容遮罩                  压暗底座
L3 DecisionSurface           决策小卡（可叠在内容卡上）
L4 决策遮罩                  再深一档（决策优先于内容）
```

- 底座不卸：docked 时 HeroVisual 隐去、输入收成右下角小圆钮（**永不少于一个输入入口**——语音与打字双通道等价；logo=按钮皮肤，可替换不神圣）；
- 决策永远压内容：决策未完成前内容表面只读；
- 无路由/无返回键/无 tab（Transient 面）；Persistent Surface 有自己的入口与退出（见 §二）。

## 四、卡片编排——浅栈 + PresentationPolicy（评审 P1-2）

浅栈规则不变（新卡压旧卡：旧卡 scale −4%/下沉 12px/压暗露上缘；点边缘翻回；决策置顶），但**参数不冻结为 UI 常量**——抽成 `PresentationPolicy`（认知负荷策略，按设备形态分档）：

| 参数 | 手机默认 | 平板默认 |
|---|---|---|
| `maxVisibleStackDepth`（绝对上限 +1） | 2（上限 3） | 3（上限 4） |
| `maxRecallChips` | 2 | 3 |
| `recallTimeout` | 30min | 30min |
| 内容卡尺寸 | 宽−48px · 高 ≤66% 视口 | 宽 ≤520px 居中 · 高按视口比例（viewport-relative，**不是固定 66%**——防大屏变「漂浮的巨大网页卡」） |
| `backgroundScaleStep` / `backgroundOffsetStep` | −4% / 12px | 同 |

折叠与回收（不变）：✕/遮罩/下滑 → RecallSurface 小圆片（右下缘，图标+一行题）；点回展开；超时自动入历史；历史=记忆/会话区。

## 五、动效原语（只立三个，有限动效）

| 原语 | 用途 | 参数（冻结） |
|---|---|---|
| **浮现** | 任何 Surface 出现 | scale .95→1 + 淡入，280ms，cubic-bezier(.32,.72,.28,1) |
| **收叠** | Surface 回底座/小圆片 | 下滑+缩小退向眼睛方向，260ms |
| **层叠** | Surface 压 Surface | 后卡上浮压前卡 + 遮罩加深一档 |

底座 docked 转场 450ms 同曲线；听/说态=眼睛 pulse（1.4s）；无循环装饰动画；`prefers-reduced-motion`→全部退化为 150ms 淡入淡出；新增动效原语=修订本契约。

## 六、输入意图仲裁器（评审 P0-1——「输入常驻」与「决策锁定」的语义缝合）

**Visual Availability ≠ Execution Availability**：输入通道永远随手可及（语音=点眼即说；打字=点细线展开——视觉承诺=「能表达」，不是「框常驻」），但输入是否立即执行由 Runtime 裁决：

```text
用户输入（任何时刻可打）
   ↓
Intent Router
   ↓
存在 Blocking Decision（审批/付款 pending）？
 ├── 否 → 正常派发
 └── 是 → 仲裁四路：
      ├── Cancel     「算了」→ 取消当前决策（fail-closed 释放）
      ├── Modify     「换一个/不要辣的」→ 修当前任务参数（重走验证）
      ├── NewTask    语义无关的新意图 → 暂存排队（当前决策完成后呈现）
      └── Defer      模糊 → 先问一句澄清（不打断审批面）
```

- 决策面 pending 期间，新输入**不打断、不抢占、不丢失**——仲裁结果全部留足迹；
- 经典/极简同一仲裁器（经典模式的对话流同样走它）；
- 防的就是评审点的场景：付款 pending 中用户说「算了换一个」——系统必须知道这是 Cancel+NewTask 而不是新任务硬挤。

## 七、内容截取与填充——双通道 + 解析隔离（评审 P0-3）

```text
通道①（首选·确定性）：工具 out schema 直映（Registry.slots 写死映射）
通道②（兜底·丰富化）：LLM 提取——主回复双段输出 [结构化 JSON 块 + 散文]（零额外轮次）
```

**解析隔离（P0 工程规则）**：

```text
LLM Response
   ↓
Response Splitter（唯一解析点）
   ├── Structured → Schema Validation → Validated PresentationData → 引擎
   └── Prose      → 对话消息
```

- **Renderer/引擎只能消费 Validated PresentationData，禁止直接依赖 LLM 主回复**——主回复格式漂移不塌 UI；
- LLM 不产 HTML/骨架/壳选择（军规）；校验不过=fail-closed 纯文本回落卡（PlainText Surface + 诚实小字「未登记·纯文本回落」）；
- 新内容类型走登记纪律（candidate 可用、≥2 独立消费者转 registered）。

## 八、语音交互——Voice EOU 多信号判定（评审 P0-2）

- **入**：点输入按钮=直接说（pulse；按钮皮肤=HeroVisual 默认 logo，可替换）；partial 实时回填输入通道（可见可改）；手动 ↑ 永远可用（双保险）；
- **说完判定 ≠ 1.2s 沉默**（中文自然语会「想一下再说」）：

```text
VoiceEndDetector（多信号）
├── ASR endpoint 信号      → 立即发送
├── VAD 静音 > 1.2s        → tentative complete（进入观察窗）
├── 语义不完整（未完结短语） → 延迟等待
└── 静音 > 2.5s            → force complete（兜底）
```

- 参数是 policy 不是常量（随 PresentationPolicy 分档可调）；
- **出（TTS）**：播报内容=Registry `voice_hint` 确定性槽（非 LLM 散文）；结果呈现时自动播报；点任意处打断；引擎=xiaomi.speak（既有资产）；
- 三态呈现：listening（pulse）/ partial（实时转写）/ speaking（卡浮现+播报可打断）；
- 语音与文字完全等价（说的都能打，打的都能说）；ASR=SpeechRecognizer（UPG-88 在施）。

## 九、PresentationRegistry（呈现契约·含 presentation_intent）

**三分法（评审收口——最后一道线）**：

```text
JobView（执行引擎）        回答「发生了什么」——status/progress/output/effects/errors（事实投影，禁含视觉结构）
PresentationRegistry      回答「怎么被看见」——呈现契约（本表）
PresentationEngine        回答「现在怎么呈现」——layer/stack/transition/motion/state/recall（运行时编排）
```

一行 = 一种呈现契约：

| 字段 | 说明 |
|---|---|
| `content_type` | 内容类型（注册枚举：offer/checklist/plaintext…） |
| `presentation_intent` | **呈现意图**（评审 P1-4）：`RESULT / PROGRESS / DECISION / WARNING / ERROR / EMPTY / RECALL`——同一 content_type 的「搜索中」与「搜索完成」不再共用呈现逻辑，防 Registry 按业务状态爆炸 |
| `shell` | Surface 类型（ContentSurface/DecisionSurface/PlainText…） |
| `skeleton` | 骨架 JSON 模板引用（slot 布局） |
| `slots` | 工具 out 字段 → slot 映射（写死） |
| `components` | 领域组件引用（UPG-70 注册库） |
| `voice_hint` | TTS 播报槽（确定性内容） |
| `owner` / `state` | 治理（candidate→registered→deprecated→removed；无消费者清退） |

判定纪律照抄权限面：新类型必须先登记；LLM 输出的类型/意图不在表 = 引擎拒渲染、纯文本回落。

## 十、卡片样式规范（两尺寸档 + 内容纪律）

| 档 | 用途 | 尺寸（进 PresentationPolicy，按形态分档） |
|---|---|---|
| ContentSurface（大） | 结果/清单/文本 | 手机：宽−48px/高≤66% 视口；平板：宽≤520px 居中 |
| DecisionSurface（小） | 审批/确认 | 宽−84px（UPG-79 已定稿件） |

内容纪律：一卡一主动作；参数一行化；图区可省（无图=纯排版卡）；全令牌引用；纯黑白+唯一功能红；新增视觉元素=修订本规范。

## 十一、状态矩阵（引擎状态机·唯一合法态集）

| 状态 | 底座 | Surface | 输入框 | 语音 |
|---|---|---|---|---|
| idle | 空画布+HeroVisual 形语音钮 | 无 | 细线打字入口（与语音钮等价并存） | — |
| listening | 眼睛 pulse | 无 | 自动展开「正在听…」 | 收音 |
| partial | 眼睛 pulse | 无 | 自动展开实时转写 | 收音 |
| presenting | docked | 内容表面浮现 | 正常（Intent Router 裁决执行） | voice_hint 播报可选 |
| stacked | docked | 内容+决策 | 决策优先，输入走仲裁 | — |
| docked-mini | docked | 小圆片 | 正常 | — |
| persistent | 用户主动进入管理面 | Persistent Surface | 按面约定 | 按面约定 |
| error/empty | 正常 | 诚实空态 | 保持 | 停 |

非法迁移=引擎拒绝；业务代码只发事件不直接操作 DOM。

## 十二、安全与工程红线

1. **AI 可以生成内容，但不能生成交互制度**（军规；LLM 不产 HTML/骨架/壳/布局）；
2. 呈现决策只许存在于 Registry（契约）+ 引擎（机制）；业务代码禁即兴呈现；
3. **UI 只能依赖 Validated PresentationData**（解析隔离），主回复永不成 UI 直接依赖；
4. fail-closed：未登记/校验不过=纯文本回落，不硬凑；
5. 能力零缩减：两模式工具面/审批/记忆全量一致（UPG-84 红线延续）；
6. 输入常驻但执行仲裁（Intent Router 四路全留足迹）；
7. 有限动效 + prefers-reduced-motion；
8. Token/KV 申报：双段输出零额外轮次；voice_hint 确定性槽不占 LLM 轮次。

## 十三、分期与衔接

- **阶段 1（UPG-88 在施）**：BaseSurface（底座+ASR+两态开关+快速提示词）——含 Voice EOU 多信号判定（本体系 §八）；
- **阶段 2（评审冻结后派单）**：PresentationRegistry + core.js 引擎（呈现栈/动效原语/浅栈/RecallSurface/Intent Router/Response Splitter）+ offerCard/timelineList/plain 三骨架；
- **阶段 3**：schema2ui 商家卡真实数据（商业期）+ 白标 HeroVisual 注入 + Persistent Surface 面收编（设置/资产/安全中心迁移评估）。
