## 〇、一句话

**「外观组件库」= 一个列表选择页：每行一个组件类别（名字+区域标题），行下横排该组件的各种样式预览卡（可左右滑动），点选某张卡 = App 里这个组件立即换成那种外貌（即换即显）。**

**要点（用户原话转写）**：
- 每个组件**有名字+区域**（行标题即名字，行内容即区域）
- 每行列表标题下面 = 该组件**相应样式**（预览卡）
- 样式卡**横铺**（多出屏幕**左右滑动**查看）——不是垂直堆叠
- **选中一个 = 替换**（当前生效样式有标记 ✓/高亮；点击立即生效）

## 三、交互规则

| 规则 | 说明 |
|---|---|
| **选中即替换** | 点样式卡 → **✓ 出现 + 组件本体 100~180ms 轻微过渡**（边框/形态变化=确认感，不用 Toast）→ App 全界面立即换形（无刷新/无重开） |
| **用户选择优先级** | **用户在 UI 上的手动选择 = 最高优先级局部覆盖**（> MCP 提供的默认形态 > 系统默认）——不受 MCP 注册形态影响，直到用户手动改回（v5.0 §四 对齐） |
| **即换即显** | 本页自身也是被测件——**页面功能区组件（导航/返回/标题栏）始终跟随全局生效值**（用户可选区对比基线 = 上方静态预览卡恒为各自形态）；预览卡本身**永不随全局变** |
| **选中态明确** | 当前生效卡：描边高亮 + 角标 ✓（避免「哪个在生效」猜谜） |
| **横滑规则** | 形态数 ≤3→直接展示；4~6→横滑+页码圆点；>6→**点击展开网格**（浏览式弃横滑）——防「MCP 涌入滑不过来」（v5.0 §八-B） |
| **双层结构** | 默认视图=官方精选+热门/最近+「组件市场」入口（搜索/分类/筛选/启用管理）——不是展示全部 MCP 组件 |
| **默认形态** | 不选=经典（现状）——无隐性覆盖；选回经典=恢复默认 |
| **✓ 与 ● 语义** | **✓ = 当前生效**；**● = 最近使用但当前未生效**（找回上一选择）；**当前生效卡不再显示 ●**（避免双重标记困惑：经典 ○ / 胶囊 ✓ / 下划线 ○ → 经典 ● 胶囊 ✓ 下划线 ○） |

## 四、视觉约束（红线）

1. **品牌 token 贯穿**：三形态都用同一套语义 token（品牌绿/表面/文本/分割线）——只变形状/密度/线条，**不变颜色语义**（`契约固定+皮肤=纯值段`）
2. **形态不同、气质一致**：留白/圆角尺度/反馈手感同族——一看就是 MOV
3. **状态矩阵全**：每形态×明暗×默认/按下/聚焦/错误/禁用（预览卡至少展示默认+一种状态）
4. **明暗=跟随全局**：预览卡只按当前主题渲染（顶部浅/深切换承载）；仅当前选中卡可增强「明暗双框」对比
5. **品牌绿死区**：预览卡禁写死色值（走 token）
6. **覆盖=真删**：选回默认=彻底清除自定义（不留残留态）

## 五、技术机制（衔接 v3.1/CT-03）

### 5.0 唯一真相契约（P1-1 · 冻结）

> **页面不维护独立选中状态——所有选中态实时读取 AppearanceProfile/Resolver 的最终生效值。**

```text
唯一真相 = AppearanceProfile
页面：只读当前生效值 → 渲染 ✓
点击：写 AppearanceProfile → Resolver → 组件刷新 → 页面重新读取
（禁止前端本地 selected="capsule" 独立态——防双真相）
```

```text
样式卡（UI） = 该形态的预览渲染（APP内真实组件实例——不是色块）
选中（点击） → 写 AppearanceProfile.components["input"] = "capsule"
            → v3.1 Resolver 解析 → 全界面 input 组件换形
            → 预览卡高亮（当前生效读取 profile）
（明暗跟随全局 data-theme；样式数随 v4.1 换芯扩展为 impl 切换）
```

**「预览卡=真实组件实例」**：所见即所得（预览卡就是组件本身缩小版）——不是缩略图/示意图，选的看到的=真实效果。

## 九、大神 UI 评审采纳记录（v1.1 · 7 条全采纳）

| # | 评审 | 采纳 |
|---|---|---|
| ① 对比基线 | 预览卡恒静态（各自形态）+**页面功能区组件始终跟随全局生效值**——同时看到「我要选的」「全局在用的」，对比更清晰 | ✅ 交互规则显式化 |
| ② 手势冲突 | 形态 ≤3 不启用横滑直接全展示（MVP 大部分）；超屏才横滑；判定 ±30° | ✅ 交互规则补充 |
| ③ 明暗重复 | **预览卡只跟随全局主题**（顶部切换承载）；仅当前选中卡增强「明暗双框」——60 卡→30 卡 | ✅ 约束修订 |
| ④ 无撤销焦虑 | **「最近使用」小圆点**（找回上一选择）；对比模式（长按临时预览）过度设计不做 | ✅ 新增交互规则 |
| ⑤ 风格联动 | MVP 不做自动联动（混搭自由）；**预留「风格预设」扩展位**（未来一键整体切换——现代风组合） | ✅ 方案 §展望 |
| ⑥ 无障碍 | 每卡 aria-label/焦点 DOM 序/✓ 角标非只靠颜色 | ✅ 验收 V-U50-8 |
| ⑦ 性能 | **预览卡实例禁交互**（pointer-events:none）——静态渲染+点选，防动画监听/状态污染 | ✅ 交付物约束 |

**大神总评**：交互模型 ★5（路径最短）/视觉约束 ★5/工程衔接 ★4——方向完全正确，核心原则（真实实例预览/即选即换/token 贯穿）坚定执行。
