# MOV 极简模式 · 呈现交互体系设计 v1（送大神评审）

> 设计师B @2026-09-03 ｜ 状态：送审版 ｜ 配套 demo：`设计师\设计预览\极简呈现架构_demo_v3_2026-09-03.html`（可交互，卡片浮于主页实拍）
> 用户拍板前提：① 只要两种模式（经典+极简），极简只是画面极简、**能力零阉割**；② 呈现形态=「OpenAI 想造的手机」三合一（内容即界面+语音优先+生成式呈现）；③ 生成权=**引擎规则驱动**（LLM 零渲染决策）；④ 一切内容=卡片/弹窗浮于主页底座，输入框常驻。

---

## 〇、一句话

**极简模式的呈现 = 一张常驻桌面（底座）+ 一叠引擎驱动的卡片**——所有内容（办事结果/清单/文本/审批）都是按呈现契约（PresentationRegistry）由引擎拼装出来的浮卡，没有页面、没有导航、没有摊开；LLM 只办事和提取内容，永远不做渲染决策。

## 一、为什么必须引擎驱动（反例锚）

审批体系的教训（2026-09-02 真机 P0 起）：呈现层散装（弹窗/通知/chip 各写各的、零组件测试）→「静态全对、运行时黑洞」→ 连续六张工单修补。本体系把「呈现」从散装代码提升为**引擎 + 契约**：呈现逻辑只许存在于引擎（core.js 机制件）+ 登记表（静态契约件），业务代码和 LLM 都不许即兴呈现。——「不然又一堆 bug」的制度化回答。

## 二、呈现栈模型（五层 z 序，自底向上）

```
L0 底座（常驻）      眼睛（HeroVisual）+ 输入框 —— 永远在，卡来了缩小上移（docked）
L1 内容卡（fcard·大）  办事结果/清单/文本回落 —— 浮于底座，圆角大卡
L2 内容卡遮罩         压暗底座（突出当前卡）
L3 决策卡（acard·小）  审批/确认（ApprovalSurface 复用，UPG-79 已定稿）
L4 决策卡遮罩         再深一档（决策优先于内容）
```

- **底座不卸**：任何卡出现，底座 docked（眼睛缩小上移 9%、scale .82），输入框原地不动、永远可打字——「输入框必不可少」的机制化。
- **决策永远压内容**：审批卡可叠在内容卡上（双层遮罩），决策未完成前内容卡只读。
- **没有页面**：无路由、无返回键、无 tab——收回=回底座。

## 三、动效原语（只立三个，有限动效）

| 原语 | 用途 | 参数（冻结） |
|---|---|---|
| **浮现** | 任何卡出现 | scale .95→1 + 淡入，280ms，cubic-bezier(.32,.72,.28,1) |
| **收叠** | 卡回底座 | 下滑 + 缩小退向眼睛方向，260ms（视觉因果：卡从底座来回底座去） |
| **层叠** | 卡压卡 | 后卡上浮压前卡 + 遮罩加深一档（L2→L4） |

- 底座 docked 转场：450ms 同曲线；听/说态 = 眼睛 pulse（1.4s）。
- **无循环装饰动画**；`prefers-reduced-motion` → 全部退化为 150ms 淡入淡出。
- 新增动效原语=修订本契约（评审），业务代码禁自写动画曲线。

## 四、卡片排列——浅栈（非单卡、非轮播）

- 新内容卡**压**旧卡：旧卡 scale −4%、下沉 12px、压暗一档，露出上边缘（「底下还有」可感知）。
- 栈深 **≤3 层**可视；更早的自动进历史（不删）。
- 点旧卡露出边缘 = 翻回它；**审批卡永远置顶**（决策优先于内容）。
- 被否的备选：单卡制（丢「刚才那件事」上下文）；轮播（小屏横滑易误触）。

## 五、折叠与回收——「待回看」小圆片

- ✕ / 点遮罩 / 下滑手势 → 卡收叠成底座**右下缘小圆片**（缩略=图标+一行题）。
- 点小圆片 = 原样展开回浮卡；圆片 ≤2 枚，更多自动并入历史。
- **30 分钟未回看自动熄灭入历史**（不积攒）；历史=记忆/会话区，不在主页留痕。
- 被否备选：直接收回消失——「先放放」场景没有着落。

## 六、卡片样式规范（两尺寸档 + 内容纪律）

| 档 | 用途 | 尺寸 |
|---|---|---|
| 内容卡（fcard） | 结果/清单/文本 | 宽=屏宽−48px，max-height 66%，圆角 20 |
| 决策卡（acard） | 审批/确认 | 宽=屏宽−84px，圆角 16（UPG-79 已定稿件） |

内容纪律（防卡片变网页）：

1. **一卡一主动作**（最多一个主按钮；次级动作降级为输入条话术，如「换一家」不进按钮区）；
2. 参数一行化（纯文本行，禁 chips 阵列）；
3. 图区可省（无图内容=纯排版卡，不塞占位图）；
4. 全令牌引用（tokens.css/colors.xml 单源），纯黑白+唯一功能红（拍板④）；新增视觉元素=修订本规范。

## 七、内容截取与填充（双通道 · 都过校验）

呈现数据从哪来——**两条通道，契约层定结构，LLM 零决策**：

```
通道①（首选·确定性）：工具 out schema 直映
  Registry.slots 写死映射：slot ← out 字段（offer.price ← merchant.search.out.price）
通道②（兜底·丰富化）：LLM 提取管线
  仅非契约字段（摘要/亮点/描述）；
  形态=主回复双段输出 [结构化 JSON 块 + 散文]（一次请求零额外轮次，Token 友好）
  → 提取结果过 schema 校验；不过 = fail-closed 纯文本回落卡（不硬凑壳）
```

- LLM **不产 HTML、不产骨架、不选壳**（元能力稿 §6.1 + 送审稿安全红线落地为引擎机制）；
- 未登记 content_type → 引擎拒渲染壳 → 纯文本回落 + 「未登记·纯文本回落」诚实小字；
- 新内容类型走登记纪律：candidate 可用、≥2 独立消费者转 registered（同元能力治理）。

## 八、语音交互（语音优先链）

- **入**：点眼睛=直接说（pulse 态）；partial 实时回填输入框（可见可改）；**停顿 1.2s 断句自动发送**（手动 ↑ 也可——双保险）；权限拒绝/无识别=诚实空态不卡死。
- **出（TTS 播报）**：播报内容 = Registry `voice_hint` 槽（**确定性槽内容**，如「播报 名称+价格」——不是 LLM 散文）；结果卡呈现时自动播报；点任意处打断；引擎=xiaomi.speak（已有资产）。
- **三态呈现**：listening（眼睛 pulse）/ partial（输入框显实时转写）/ speaking（卡浮现+播报，可打断）。
- ASR=Android SpeechRecognizer（UPG-88 阶段 1 在施）；语音与文字完全等价（说的都能打，打的都能说）。

## 九、状态矩阵（引擎状态机·唯一合法态集）

| 状态 | 底座 | 卡 | 输入框 | 语音 |
|---|---|---|---|---|
| idle | 眼睛居中 | 无 | 正常 | — |
| listening | 眼睛 pulse | 无 | 「正在听…」 | 收音 |
| partial | 眼睛 pulse | 无 | 实时转写 | 收音 |
| presenting | docked | 内容卡浮现 | 正常 | （voice_hint 播报可选） |
| stacked | docked | 内容卡+决策卡 | 决策卡优先 | — |
| docked-mini | docked | 收叠小圆片 | 正常 | — |
| error/empty | 正常 | 诚实空态卡 | 保持 | 停 |

非法迁移=引擎拒绝（状态机引擎内置，业务代码只发事件不直接操作 DOM）。

## 十、与既有体系的关系（收编映射）

| 体系 | 关系 |
|---|---|
| PresentationRegistry（本体系唯一新契约件） | 仿 PermissionRegistryData 的呈现版；一行=一种呈现契约——`content_type`（注册枚举）/ `shell`（fcard 内容卡\|acard 决策卡\|plain 回落卡）/ `skeleton`（骨架 JSON 模板引用）/ `slots`（工具 out 字段→slot 映射）/ `components`（领域组件引用）/ `voice_hint`（TTS 播报槽）/ `owner` / `state`（candidate→registered→deprecated→removed，无消费者清退——治理纪律同元能力稿） |
| ApprovalSurface（UPG-79） | 决策卡容器复用（已定稿：环形倒计时/参数卡/单勾选/拒绝左同意右），零改动挂进 L3 层 |
| 执行引擎 JobView（v0.4 §6.3 三件套） | JobView=运行时投影 → 本体系的「呈现描述」消费它（render_hint 语义并入 Registry.skeleton/slots） |
| 元能力稿 §6.1/§7 | 「LLM 不产渲染决策」「壳由副作用定」→ 落地为 Registry + 引擎机制；副作用 WRITE/MONEY 的壳=决策卡，READ 的壳=内容卡 |
| UPG-70 组件注册库 | 卡的领域组件引用注册库（CT-03 契约），禁卡内自绘 |
| 送审稿四化 | 纯 HTML5/CSS 组件化/JSON 骨架/LLM 提取——全部保留，本体系补「呈现栈+编排纪律」 |
| 经典模式 | 同引擎同壳库——形态差异只在主页（经典=现有聊天主页，卡可浮于其上） |

## 十一、安全与工程红线

1. LLM 不产 HTML/骨架/渲染决策（XSS/注入/幻觉防线；G5 可信链同哲）；
2. 呈现决策只许存在于 Registry（静态契约）+ 引擎（机制件）；业务代码禁即兴呈现、禁自写动画曲线；
3. fail-closed：未登记类型/校验不过 = 纯文本回落，不硬凑；
4. 能力零缩减：两模式工具面/审批/记忆全量一致（UPG-84 红线延续）；
5. 有限动效 + prefers-reduced-motion；
6. Token/KV 申报纪律：LLM 提取双段输出=零额外轮次；voice_hint 为确定性槽不占 LLM 轮次。

## 十二、分期与衔接

- **阶段 1（UPG-88 在施）**：底座+ASR+两态开关+快速提示词——本体系的 L0 底座与语音入口；
- **阶段 2（本体系落地单·待评审后派）**：PresentationRegistry + core.js 引擎（呈现栈/动效原语/浅栈/小圆片）+ offerCard/timelineList/plain 三骨架 + 内容双通道；
- **阶段 3**：schema2ui 商家卡真实数据（商业期）+ 白标 HeroVisual 注入。
