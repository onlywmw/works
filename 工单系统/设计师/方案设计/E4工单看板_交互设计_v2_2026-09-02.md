# E4 工单看板 · 交互设计 v2（HTML 版）

> **设计师** @2026-09-02 ｜ 大神评审采纳（v2 修订：TL;DR/三级时间指标/色值表/R 项带建议/A1-A6 验收）
> **定位**：SYS-02 阶段四 E4 全景看板交互升级 ｜ **送审已闭环**

## TL;DR

把 E4 的 Markdown 表格升级为静态 HTML 可交互看板——点卡片筛表、状态徽章分层、30 秒内定位「谁在流/谁卡了」。零依赖内联 JS（~20 行）、一次生成 md+html 双产物、双击 bat 即刷新打开。不写库、不改判据，纯展示层升级。

## 一、背景与问题

1. 表格花（5-6 列挤一行、横向跑屏）
2. 找不到重点（自己数谁施工/谁卡）
3. 多一步（跑命令→开文件→翻）

**升级边界**：判据 S2-10~20 不变；数据源=工单库.md（E1 唯一真相）；只读投影不写库/表；展示=md 表格 + HTML 可交互视图。

## 二、设计目标（可衡量）

| 时间 | 应完成 | 界面 |
|---|---|---|
| 5 秒 | 总量/在流/超期/挂账数 | 摘要卡×5 |
| 15 秒 | 识别在流卡/卡了 | ⚡重点块+状态徽章 |
| 30 秒 | 定下一步关注哪卡 | 卡点/下一步列+点击筛选 |

## 三、信息架构

①标题栏(日期/sha) → ②摘要卡×5 → ③⚡当前重点 → ④主看板表(#/单/名称/状态/卡点/线) → ⑤挂账待审池 → ⑥完整性对账

（旧「交付/验收/合main 三态子列」折叠进状态徽章——低频细节让位高频问题）

## 五、交互规范

**核心=卡片点击筛选**：总卡数=全部 / 在流=非终态(active) / ✅终态=merged / ⚠️超期=data-over / 挂账=滚动到池+高亮。

实现：tr 行带 data-stage/data-over；JS 切换 display；当前筛选卡 .active 蓝框。**当前仅单选筛选，不叠加条件**。空状态：筛选为空显示「无匹配卡片」占位。

## 六、技术实现

数据流：工单库.md → readLib(只读,sha 实证) → analyzeCard(projections) → renderBoard(md)+renderHtml(html) → 验证产物 → 看板.bat(chcp 65001+%~dp0) → 双击刷新+打开。

零依赖：内联 <script>，无框架/CDN/网络。坑：cmd 读 bat 默认 GBK→中文路径乱→chcp 65001+CRLF+%~dp0（已实跑）。

## 七、评审定夺（大神 v2 结论）

| R | 结论 |
|---|---|
| R1 筛选维度扩展 | **V2 不加**（状态大类覆盖 80%；多条件叠加违背零依赖——V3 规划） |
| R2 卡点字段化 | **可行且必要**——每卡 `**卡点**：xxx` 字段，各 agent 自己维护；E4 只读自动反映——**从「状态展示」到「协作工具」关键一步** |
| R3 行点击详情 | **V2 不加**（看板=全局视图；详情=工单库.md 已有锚） |
| R4 挂账池 | **默认折叠：前 5 条+「展开全部(N)」**（不参与流水线判定，不抢占主权重） |
| R5 移动端 | **V2 不做专门适配**（grid auto-fit+max-width 已有基本兜底；完整响应式 V3） |
| R6 S2-21 | **建议补**——判据草案：打开 HTML 30 秒内人工可识别在流/超期/挂账卡数 |
