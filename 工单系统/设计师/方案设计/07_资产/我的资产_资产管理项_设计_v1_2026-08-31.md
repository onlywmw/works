# 我的资产 · 资产管理项注册体系 设计 v1（评审稿）

> 设计师 @2026-08-31 ｜ 状态：**⏳挂账（待全局安全体系重构前置）**——用户拍板：**安全体系要先独立成层、全局重构**，不能只在资产里实现；「我的资产」先挂账，**待安全体系定稿后基于其上立项**。本稿作为资产方向的**参考件**（其 securityPolicy 部分将并入统一安全体系设计）。挂账号：`挂账-我的资产-待安全体系前置`。
> 核心：**「我的资产」= 按类目的"资产管理项"注册体系**——每类一个独立管理项（自己的存储/元数据/UI/操作/规则），**可不断增加**（含 MCP 注册）；承载「能力 → 资产 → 商业」。

---

## 〇、一句话
把「我的信息」（原 Vault，身份证/密码）升级为**「我的资产」**：按类目**可扩展**——每个类目（图片 / 视频 / 音乐 / 文章 / 衣物·衣柜 / 凭据…）是一个**独立管理项**，规则各自为政，新增类目 = 注册一个管理项；**MCP 生态（如换装·我的衣柜）可注册新管理项并产出资产**。为商业提供承载。

---

## 一、背景 / 为什么
- **每类资产管理规则不同**：图片要 EXIF/缩略图/看大图，视频要时长/封面/播放，音乐要元数据/播放，衣物要款式/颜色/尺码/换装，凭据要加密/填充——**无法用一套通用规则**定义所有资产；
- **要可扩展**：未来能力/MCP 会不断产生新类型资产（换装衣物、虚拟人像、更多），必须能**注册新管理项**而非改通用模型；
- **承载商业**：资产库是"用户自建/用 MCP 产生资产 → 资产沉淀 → 商业交易/品类"的底座（与 MOV 交易·支付方向契合，商业对接后置）；
- **原「信息库」（Vault/InfoVault，存身份证/账号密码）降为 credential 管理项**——不再特殊，统一进管理项体系，但保留加密/填充规则。

---

## 二、架构（AssetKind Registry 注册制）
```
我的资产（入口）
  ├─ 按类目列出已注册「资产管理项」：图片 / 视频 / 音乐 / 文章 / 衣物·衣柜 / 凭据…
  └─ 点某管理项 → 该类目**自己的**管理界面（网格/列表 + 该类操作：看图/播放/换装/填充）

AssetKind Registry（管理项注册表）
  ├─ picture    ：文件+EXIF+缩略图          → 网格预览 · 看大图
  ├─ video      ：文件+时长+封面            → 播放
  ├─ music      ：文件+元数据               → 播放
  ├─ wardrobe   ：衣物图+款式/颜色/尺码      → 换装（连结虚拟人像 MCP）
  ├─ credential ：加密(AES-GCM)             → 填充/审阅（原 InfoVault）
  └─ (未来 MCP / 开发者可注册新 kind)

每个管理项 = 自己的 存储 / 元数据 schema / UI / 操作 / 规则 —— 完全独立，互不干扰
```
- **每类规则独立**（不同元数据/操作/存储策略）——满足"不能一套规则"；
- **可增加**：新类目 = 注册一个新管理项（进 Registry），不动其它类目；
- **承载 MCP**：换装 MCP（我的衣柜）注册 `wardrobe` 管理项 + 产出衣物资产；任何能力/MCP 都能注册新资产类型——这是"能力 → 资产 → 商业"的承载底座。

---

## 三、管理项契约（AssetKind）

每个管理项定义：
| 字段 | 说明 |
|---|---|
| `kind` | 唯一 key（picture / video / music / wardrobe / credential…） |
| `label` / `icon` | 入口显示名 / 图标 |
| `storage` | 文件 + 元数据落点（文件目录 + meta；credential 加密存储） |
| `metaSchema` | 该类元数据字段（图片 EXIF、衣物款式/尺码、凭据敏感级…） |
| `ui.render` | 列表/网格形态 + 预览（图/视频/音频/文本） |
| `actions` | 该类操作（看图 / 播放 / 换装 / 填充 / 删除） |
| `rules` | 该类管理规则（数量上限 / 加密 / 校验 / 排重） |
| `mcpWritable` | 是否允许 MCP 写入（wardrobe 允许；credential 谨慎） |

> 注册制：新增类目 = 实现一个 AssetKind 管理项并注册进 Registry；**不改任何已存在管理项**。

---

## 四、首批管理项（①先跑通）

| 类目 | 存储 | 元数据 | UI | 操作 |
|---|---|---|---|---|
| **credential**（原信息库） | 加密(AES-GCM) | 敏感级 | 列表 | 添加/编辑/填充/删除 |
| **picture**（图片） | 文件+元数据 | 文件名/尺寸/时间 | 网格 | 传/看大图/删 |
| **wardrobe**（衣物·衣柜） | 文件+元数据 | 款式/颜色/尺码/缩略图 | 网格 | 传/换装(连人像 MCP)/删 |

> 首批三类规则**完全不同**（加密 / 图片 / 衣物+换装），正好验证"注册制、规则独立"。

---

## 五、扩展管理项（②）
视频 / 音乐 / 文章 / 虚拟人像 —— 各自注册新管理项（播放 / 播放 / 阅读 / 换装主体），规则独立。

---

## 六、换装 MCP（我的衣柜）接入
- `wardrobe` 管理项注册；MCP 生成**等比例虚拟人像**（作为资产/换装主体）；
- 换装：用户选衣物资产 → MCP 应用到人像 → 生成换装图（assets）；**衣物/人像均为资产文件**，落入对应管理项；
- **MCP 写资产库**：MCP 产出资产（换装结果/衣物）经 `mcpWritable` 管理项入库——能力 → 资产的关键一环。

---

## 七、数据 / 存储 / 安全
- 文件 + 元数据分离；credential 加密（AES-GCM，复用 VaultKeystoreCrypto）；图片/衣物等按需加密/明文本地；
- 资产管理项**隔离**（各 kind 独立存储/命名空间，互不干扰）；元数据版本化；
- 敏感（credential）保持原 Vault 加密/填充规则；MCP 写资产走 `mcpWritable` 门控（wardrobe 开、credential 关）。

---

## 八、与现有系统关系
- **InfoVault（信息库）→ credential 管理项**：迁移兼容（旧数据不丢），加密规则保留；
- Memory OS / Semantic：资产库可作记忆的"引用/对象"（可选，后置）；本设计先做资产管理项基础。

---

## 九、验收测点（L1 / L2 / L3 + 变异锚）
- **L1**：①**注册制**——新增一类（注册新 AssetKind）不破坏已存在类（变异：改通用模型影响他类→必红）②每类规则独立（图片 EXIF / 衣物尺码 / 凭据加密 各自 schema 生效）③credential→管理项迁移兼容（旧数据在、加密仍可解）④MCP 写资产（wardrobe 可写、credential 拒写）⑤加密凭据、敏感项不出明文 ⑥AssetKind 注册即用（编译/注册后列表出现该入口，无需改他处）。
- **L2 真机**：「我的资产」入口列各管理项；点进图片→网格预览/看大图；衣物→换装(连 MCP)；凭据→加密填充；各管理项规则不同（界面/操作各异）。
- **L3**：管理项隔离（各 kind 独立存储/命名空间）；MCP 写资产门控（mcpWritable）；credential 迁移幂等；注册制契约测试（增 kind 不影响既有）。
