## 〇、一句话

**给每个记忆类型配一个可选的结构化 payload 模板：content 继续给人读/给 AI 注入，payload 给机器管理（去重/冲突/合并/画像对齐）；抽取失败安全降级为纯文本条目——渐进结构化，不一刀切。**

---

## 一、现状盘点（main @2026-09-05 实证，`memory-os/.../semantic/SemanticEntry.kt`）

**骨架已结构化**（UPG-52 已交付）：

- type 八类枚举（STATE/PROGRESS/PREFERENCE/HABIT/FACT/IDENTITY/RELATION/LESSON）+ 类型驱动 decay 表
- 四态状态机（PROPOSED→ACTIVE→RE_EVALUATE→ARCHIVED，Decay≠Truth、RE_EVALUATE 必人工裁决）
- sourceIds/sourceHashes 来源链（删除传播）、confidence/importance 检索真变量

**肉身是自由文本**：`content: String` 是唯一非结构化字段——池子管理三个痛点全出在这里：

| 痛点 | 现状 | 后果 |
|---|---|---|
| 去重/合并 | 只能靠 title 哈希+type | 「喜欢少油」和「口味清淡」识别为两条 |
| 冲突检测 | 同型互斥只到 type 层 | 「喜欢辣」vs「不吃辣」值层冲突检不出 |
| 画像对齐 | UPG-51 标签池=结构化 vs Semantic 条目=自由文本 | 两套体系口径对不上，无法互查 |

## 二、设计：类型化 payload 模板

### 2.1 数据结构（SemanticEntry 扩展，不破坏既有字段）

```text
SemanticEntry 新增：
  payload: Map<String, String>?   // 可选；null=纯文本条目（合法一等公民）
  payloadVersion: Int?            // 模板版本（演化追溯）
```

### 2.2 类型模板（v1 六类先开，LESSON/STATE 暂缓）

| type | payload 模板 | 管理收益 |
|---|---|---|
| PREFERENCE | `{场景, 取向, 强度}` | 同场景不同取向=冲突检出 |
| HABIT | `{行为, 频率, 场景}` | 频率演化追踪 |
| FACT | `{主体, 谓词, 值}` | 同主体同谓词不同值=更新/冲突 |
| IDENTITY | `{维度, 值}` | 画像维度对齐 UPG-51 标签池 |
| RELATION | `{对象, 关系, 强度}` | 关系网络可查 |
| PROGRESS | `{目标, 进度, 里程碑}` | 进度可比较 |

### 2.3 双轨纪律（设计核心）

- **content 保留**：人读 + Retrieval 注入用，永不被 payload 取代（语义完整性兜底）
- **payload 供机器**：池子管理操作（去重/冲突/合并/画像对齐）一律字段比对，不解析 content
- **降级路径**：LLM 抽取失败/字段缺项 → payload=null 纯文本条目照常入库——结构化是增量红利，不是准入门槛

### 2.4 AI 闸门（AI Runtime Pattern 复用，零信任成本增加）

```
LLM 抽取 payload 草案（只输出模板字段枚举值，超出=拒绝）
  → 字段校验闸（模板匹配/枚举合法/置信阈值）
  → PROPOSED（既有四态状态机原样：人确认才 ACTIVE）
  → Timeline 账本 append（actor=ai-proposal 只能 PROPOSED，不变）
```

**红线**：payload 抽取永不直接写 ACTIVE；payload 校验失败=降级纯文本，不是报错；模板演进只加字段不改语义（payloadVersion 追溯）。

## 三、池子管理操作升级（payload 驱动）

| 操作 | 现状 | 结构化后 |
|---|---|---|
| 去重 | title 哈希撞 | 同 type+关键字段相等 → 合并候选（人裁决） |
| 冲突 | 同型互斥（type 层） | 字段级互斥（PREFERENCE 同场景异取向必检出） |
| 画像对齐 | 无 | IDENTITY.payload.维度 ↔ UPG-51 标签池双向查 |
| 合并 | 不支持 | 字段级合并提案（保留双来源链） |

## 四、与既有体系的关系

- **UPG-52 已交付物零破坏**：SemanticEntry 加可选字段，既有测试全保留；状态机/账本/检索评分公式不动
- **UPG-51 标签池**：从「两套体系」变「画像的结构化投影面」——标签池=画像维度的商用只读面，Semantic payload=全量记忆的结构化面
- **UPG-49 记忆页 UI**：条目卡片可显示结构化字段（维度/值分行呈现），但不强制（纯文本条目照显）
- **Memory OS v2 五条 P0 全部不受影响**（事实认知分离/历史不可变/AI 无权改/检索只读/删除不复活——payload 只是条目的一个可选属性）

## 五、验收思路（立项后展开为 STD）

- L1：六类模板抽取用例集 + 降级路径（抽取失败→纯文本条目入库）+ 字段校验闸（非法枚举拒）+ 去重/冲突检出锚
- 变异锚：①payload 越级直写 ACTIVE→必红 ②抽取失败阻塞入库→必红（应降级不阻塞）③冲突字段不检出→必红
- L2 真机：同义偏好入库→合并候选出现；画像页与记忆页字段一致
- 回归：UPG-52 既有 27 用例+UPG-05/22 打点链零退化
