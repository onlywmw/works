> 设计师 @2026-08-31 ｜ 大神 9.1/10：架构成立、可进工程评审（**不建议直接大规模开发**）。本版吸收 9.1 全部关键点 + **锁死 5 个 P0** + 明示**不再扩层、跑通生命链**。
> 一份自洽文档 = Memory OS 全链路（给大神/工程评审唯一口径）。原 v1 及五份分散文档已归档。

## 〇、定位与两条思想
- **记忆不是"有/没有"，有生命周期/新鲜度/可信度**；「最常见的歌 ≠ 最喜欢的歌」。
- **① 所有东西都记，但不是所有东西都成为当前记忆。**
- **② 当前记忆可以变化，但历史不能被改写。**
- 记录"用户经历过什么"，不替用户定义"用户是谁"——同时拥有**过去的你 + 现在的你**。
- **三条铁律**：`Event=observed fact / Episodic=contextualized / Semantic=confirmed` ｜ `Current mutable · History immutable` ｜ **记忆无限存储，知识有限暴露**。

---

## 一、架构总览（冻结）
```
                          MEMORY OS
        ┌────────────────────┼────────────────────┐
        ↓                    ↓                    ↓
    EVENT STORE          EPISODIC             SEMANTIC
    Everything          经历(可变)             当前认知(人确认)
    append-only                               Documents/Entries
        │                    │                        │
        │                    └────────;──────────────┘
        │                             ↓
        │                        [PROCESSOR]
        │                         Extract→Merge→Update
        │                             ↓ (Proposal→用户确认)
        │                              ↓
        └────────────────────→ SEMANTIC
                                      │
        └────────────→ MEMORY TIMELINE ←──────────┘
                       不可变历史账本
                                      │
                                 Semantic → CORE(只读投影) → INDEX → ROUTER → RETRIEVAL → COMPOSER
                                      ↓ (派生·非新层)  Int→Topic→Tags→Importance→Freshness→Top-K
                                 WORKING(运行时·不入库) → AI
```
- **四种持久化事实/认知空间**：`Event(做过什么)` / `Episodic(经历过什么)` / `Semantic(现在确认知道什么)` / `Timeline(记忆怎么变化的)`；
- **一个运行时**：`Working Memory`（不入库）；
- **一套派生索引系统**：`Core / Index / Router / Retrieval / Composer`（完全派生，只读，非存储层）。

## 五、生命周期（三张表 + 两条边界规则）

### 5.1 Memory Type / Lifecycle Policy / Conflict（三表同 v1）
`STATE/PROGRESS/PREFERENCE/HABIT/FACT/IDENTITY/RELATION` × 各自 decay；冲突同类型互斥才冲突、Observed≠Inferred。

### 5.2 **自动记录 ≠ 自动形成记忆（Process 分流 · 铁律）**
全部活动 → Event Store；Processor 严格甄别：
| 输入 | 去向 | 说明 |
|---|---|---|
| 无价值事件 | **只留 Event** | 不产生记忆 |
| 有上下文价值 | Episodic | "你当时在干嘛" |
| 出现模式(重复≥N) | Candidate | 待确认 |
| 用户确认 | Semantic | 只在此处写入 |
> 例：第一次听 → Event；连续 20 次 → Candidate+Proposal；用户采纳 → Semantic。**防止系统爆炸。**

### 5.3 **Decay ≠ Truth Change（边界规则）**
时间衰减**只产生 RE-EVALUATE 候选**，**不直接 ARCHIVED**——"一年没看某电影"≠"不喜欢了"。Decy 只意味"不该继续当高确定性当前认知"。状态机 `ACTIVE→RE-EVALUATE(候选)→[是→ACTIVE/不是→ARCHIVED]`。

### 5.4 语义状态机 + 极简 UI
`ACTIVE(注入✓) / RE-EVALUATE(禁注入◌) / ARCHIVED(历史)`；Re-evaluate=decay 到期或冲突；◌ 低频非阻塞；"不是"→保历史不删；UI 只看 ✓/◇，无 confidence/decay 数字。

## 六、Timeline（升为 Memory History Ledger）

### 6.1 定位
> **Timeline = 记忆历史账本**——系统**曾知道什么、为什么知道、何时知道、后来怎么变**；不是简单 Semantic 历史，一条都不能消失。

### 6.2 TimLine vs Event Store（边界钉死，防污染）
| | 回答 | 例 |
|---|---|---|
| Event Store | **用户做了什么？** | 20:31 播放《晴天》 |
| Memory Timeline | **记忆系统发生了什么？** | OBSERVED/PROPOSED/ACCEPTED/REEVALUATED/REJECTED/ARCHIVED/CORRECTION |
> 用户听晴天→Event；AI 猜喜欢→Timeline PROPOSED；用户采纳→ACCEPTED；后来否定→ARCHIVED。

### 6.3 契约 + 不可变 + actor
`MemoryTimelineEntry{id,timestamp,eventType,subject,payload,actor(user/ai-proposal/system-decay),sourceIds,reason,previousMemoryId,correlationId}`；只 CREATE/APPEND/READ；actor(ai 只 PROPOSED)；Correction 追加不改旧条；purge(人类触发)；**原子写入**(Semantic 变 ⇒ Timeline append)。

---

## 七、检索消费层（知识有限暴露 + Core 实体化）

### 7.1 **Memory Core = AI 的"首页"（核心缺口补上）**
```
Semantic ──→ Documents / Entries
              └──→ Core Projection ──→ Memory Core(1-4KB,即时认知摘要)
```
- **Core 不是新记忆层，是 Semantic 的高速只读投影**（派生、可重建、非双写）；
- AI 第一眼看到 Core（"用户：游戏设计师/偏好简洁UI/当前重点 Memory OS/工作方式先架构后实现"），再按需 Semantic Retrieval。

### 7.2 importance（检索真变量）
- 与 confidence 不同：`confidence=真不真`，`importance=用不用得上`；
- 例：昨天听《晴天》confidence=1.0/importance=0.05；长期偏好简洁 UI confidence=0.95/importance=0.95；正在做 Memory OS confidence=0.95/importance=0.99/freshness=1.0；
- **Retrieval 评分** = `Relevance × Importance × Confidence × Freshness × ContextMatch`（非纯 embedding）。

### 7.3 检索路径（MVP 不急着上 embedding）
`Intent → Topic → Tags → Importance → Freshness → Top-K`；分层：普通对话 `Core→Semantic→Episodic→Event(必要时)`；历史 `Timeline→Event→Episodic`；当前任务 `Working→Core→Semantic→Episodic`。

### 7.4 约束
Retrieval **只读**；Router 默认 Core+Semantic(intent→层)；预算裁剪(`POOL_FULL_INJECT_THRESHOLD=8KB` 泛化·Runtime 控)；Compose 每段带来源；`Index/Core` 派生一致性。

## 八、评审收口 · **锁死 5 个 P0**
| P0 | 锁 | 保证 |
|---|---|---|
| **P0-1** 事实与认知分离 | `Event≠Memory`；`Observed≠Confirmed` | 播 17 次≠喜欢 |
| **P0-2** 历史不可变 | Timeline `append-only` | 历史不被改 |
| **P0-3** AI 无权改 Semantic | `AI→Proposal / User→Accept / Semantic→Update` | 人确认才动库 |
| **P0-4** 检索不能污染记忆 | `Retrieval=read-only` | 检索不写库 |
| **P0-5** 删除不能复活 | `blockedSourceHashes` + `purge` | 删掉的不回来 |
> 其余（Router 优化/importance 公式/N/embedding/云同步）**不在 P0，参数化/后续迭代**。

## 十二、结论
- Memory OS = **个人记忆操作系统**：记录经历过什么 + 拥有"过去的你 + 现在的你"；
- **5 个 P0 已锁死**（事实认知分离/历史不可变/AI 无权改/检索只读/删除不复活）；

# 附 · Commercial Projection（用户画像标签池 · UPG-51）

> **⚠️ 2026-08-31 重构（淘宝式 · 用户拍板）**：本附录原方向（标签池 + 显式输入手选 + 用户画像入口）**作废**——用户画像**不设独立入口/词表手选**（用户警惕 + 死板）。改为：**首启协议授权下记忆加工 + 个性化推荐**（挂 UPG-11 首启隐私政策）——①撤 ProfileSheet 手选/ProfileDims 词表/「用户画像」入口 ②记忆本地加工偏好标签（星座/生肖=生日推算·饮食/偏好=记忆归纳，无感）③UPG-11 协议补「信息加工用于个性化推荐」④协议授权下把**去标识标签**用于推荐/分组（**只传标签不传原文**·敏感不碰）⑤「关闭个性化」开关（算法推荐合规）。**以下 C1-C6 作为"标签池数据/合规"参考件保留，实际落地以 UPG-51 重构派单为准。**

> 定位：Memory OS **Semantic 层商业投影**（非新记忆层）——为商业（营销分组/推荐/文案）提供**结构化、授权、去标识、可删**的画像。复用锁死的 **P0-3 / P0-5 / 权限隔离**。
> **P0 先行（不依赖 Semantic）**：标签池结构 + 显式输入 + 合规闸门 + 用户画像入口；**阶段二**（Semantic 落地后）接自动抽取投影。

## C1 标签池模型（schema）
```
ProfileTag {
  dimension,        // 星座|生肖|MBTI|饮食|消费|生活场景|…
  value,            // 枚举值（维度决定：星座=双子座、饮食=辣…）
  source,           // EXPLICIT(显式输入/问卷/用户填写) | AI_CANDIDATE(AI/行为推断,候选) | SEMANTIC(阶段二,从确认认知投影)
  confidence,       // 0-1（EXPLICIT=高；AI_CANDIDATE=低,待确认才升）
  sensitivity,      // NORMAL(星座/生肖/饮食) | SENSITIVE(MBTI 类,单独同意)
  consent,          // Boolean 是否授权商用（显式同意,默认 false）
  timeVarying,      // IDENTITY(星座/生肖=不变) | PREFERENCE/STATE(饮食/消费=会变)
  staleOff,         // 时变更新时间（时变类会过期→RE-EVALUATE）
  scope,            // LOCAL(默认) | CLOUD(可上云,需另同意)
  blocked,          // 用户关闭/删除→blockedSourceHashes,不复活
}
```
- **时变**：星座/生肖=`IDENTITY`；饮食/消费=`PREFERENCE/STATE`（走生命周期）；**MBTI=显式测试/确认，不从对话硬猜**。

## C2 商用投影 API（商业侧只读 · 权限隔离）
- `profile.list(dimension?)` → 仅 `consent=true && !blocked && 命中敏感规则 && 经确认` 的标签；
- `profile.aggregate(dimension)` → **人群分组**（去标识，不针对个人全集）；
- **权限隔离（硬约束）**：商用 API **绝不**回 `content`/记忆原文/Timeline/完整语义；只吐结构化标签（维度/值/置信度聚合）——验证见变异锚。

## C3 合规五道闸（落地）
① **分级**：一般(星座/生肖/饮食·可商用) ｜ 敏感单独同意(MBTI 类) ｜ **绝不碰**(性向/宗教/政治/健康)——采集时校验，绝不碰直接拒；
② **授权**：设置页「隐私与个性化」明示+主动勾选；敏感项(MBTI)单独弹窗；**拒绝≠功能降级**(PIPL 第24条)；
③ **用户权利**：设置页「用户画像」——查(显示自己有哪些标签)/改(改某值)/关单个(→blocked)/关全部(关闭个性化→不再采集)/删号(清零)；
④ **脱敏+隔离**：商用 API 聚合去标识 + 权限隔离；
⑤ **安全**：本地加密(Keystore AES-GCM)·第三方仅合规 SDK·未成年不收集。

## C4 抽取（阶段一 vs 阶段二）
- **阶段一（P0 先做，不依赖 Semantic）**：**显式输入**——设置页「用户画像」问卷/填空（星座/生肖/饮食/消费…）→ 直接建标签（需 consent 授权）；**不做自动抽取**；
- **阶段二（依赖 Semantic 落地）**：从**确认的语义**投影（星座/生肖/饮食/消费标签由 Semantic 确认认知生成）；仍走 P0-3(确认)/P0-5(可删)——Semantic 起来后自动接入。

## C5 设置页「用户画像」入口
`设置 → 隐私与个性化 → 用户画像`：可查全部标签(带 value/来源/置信度/时变)、改、关单个、关全部(开关)、删号；敏感项(MBTI)单独展示+单独同意。
