## 二、P1 规范空白（本迭代补，按优先级）

> 判断依据：这些组件/规则**在定稿文档里已被点名使用**，但 00 规范中没有对应规格 → 施工只能自由发挥。

### P1-1 五态只覆盖了两态（最该补）

你自己定的底线是「loading / empty / error / disabled / submitting 五态」，现状：

| 态 | 00 规范 | 说明 |
|---|---|---|
| empty | 有（§五.9 空态） | 仅 1 条通用范式，缺变体 |
| disabled | 有（01 外观 §四 状态矩阵） | 仅输入框 |
| **loading** | **无** | 记忆页「300 条冷启动 <2s」、模型 TESTING 态、列表首屏 |
| **error** | **无** | 模型连接 ERROR 五型、网络错误、页面级故障 |
| **submitting** | **无** | 保存模型、设为重要（memoryPromote）、审批提交 |

- **建议补**：骨架屏规格（形状/圆角/微光动画时长）、进度规格（线性/环形/不确定，模型首载 30-60s 需要长时反馈）、按钮 submitting（loading 占位 + 禁重复点）、错误态三层（**行内校验 < 区块错误 < 整页错误**）各一套组件 + 文案范式 + 重试入口。

### P1-2 无障碍（a11y）完全缺失

全库只在 `01_外观` §四 提了一句「机器检查对比度（≥4.5:1）+ 焦点环」，无系统章节。而现有设计有**明确 a11y 风险**：

- 状态点**仅靠色相**区分（ok 绿 / warn 橙 / danger 红）→ 红绿色盲不可辨；
- 危险操作仅用红色文字按钮承载语义（§五.1）；
- 字阶最小档 10px（说明/badge/时间戳）→ 低于 WCAG 与移动端可读舒适线；
- 无触控目标最小尺寸定义（只在按钮写了高 44，图标钮/开关/chevrons/钉选 34×34 未达标）。

- **建议补 a11y 一节**：① 文本对比度阈值（正文 4.5:1 / 大字与图形 3:1）+ token 级合规标注；② 触控目标最小 44×44（含不可见热区扩展规则）；③ **状态冗余编码**——颜色之外必须配形状或图标（这条同时解决 P0-5）；④ 动态字号/系统字体缩放下的布局容忍（固定宽时间戳、chip 截断与放大字号的冲突）；⑤ 内容描述（contentDescription）约定。

### P1-3 动效（Motion）零规范，但文档里已点名需要动画

- `02_主页胶囊` §五.7：「显隐导致的 dock 位移加**过渡动画**」——无时长/曲线参数；
- 胶囊展开气泡、底部 sheet 升起、toast 出现、Snackbar 撤销倒计时、审批弹窗 30s 倒计时，全部无 motion 定义。

- **建议补 Motion tokens**：duration（`--dur-fast 120ms` / `--dur-base 200ms` / `--dur-slow 320ms`）、easing（standard / decelerate / accelerate）、位移缩放参数、以及**减弱动效（prefers-reduced-motion）降级规则**。

### P1-4 图标（Icon）体系缺失，且与审美偏好冲突

- 00 规范无图标章节：尺寸档（16/20/24）、线宽、风格（描边/填充）、栅格、命名。
- `05_审批` §三 分类表直接用 **emoji 作为语义图标**（📝📄🖼️⚙️📨📦🔐💼），且 `00` §五.2 提到"免 key 标 / 状态点"。

- **建议**：① 补 Icon 规范（尺寸/线宽/风格/命名/切图倍率）；② 审批的 emoji 图标**待拍板**——emoji 跨端渲染不一致（尤其 Android 各厂字形差异大），作安全语义图标不可控，建议换线性图标；③ 语义图标映射表（审批 9 类 + 状态点 4 态）纳入 00，别散在 05。

### P1-5 层级栈（z-index / elevation）未定义

弹层、底部 sheet、胶囊气泡、审批弹窗、toast、Snackbar（撤销）、长按菜单、遮罩 scrim —— 8 类浮层**没有层叠顺序表**。审批弹窗 vs Snackbar 撤销 vs toast 谁在上，是联调第一周必踩的坑。

- **建议补**：① `--z-*` 阶梯表（原生 elevation / web z-index 对应）；② 浮层互斥规则（同一时刻最多几层、后者是否关闭前者）；③ 阴影分级 elevation 1/2/3（现状只有一句"rgba(0,0,0,.08~.18)" 与气泡的 `0 8 28`）。

### P1-6 安全区 / 刘海 / 手势条未定义

移动端必需项，全库零提及。底部 sheet、dock（主页胶囊所在）、Snackbar 撤销都贴底 → 直接受手势条影响。

- **建议补**：安全区 inset 规则（顶部状态栏 / 底部手势条 / 横屏左右）、sheet 与 dock 的底边距处理、横屏/折叠屏下顶栏 46px 是否保留。

### P1-7 反馈组件的选型规则缺失

现状有 toast（§五.8）与记忆移除的 Snackbar（5s 撤销）两种，但**没有"何时用哪个"的决策规则**，也没有内联提示（Banner）和对话框。

- **建议补决策树**：瞬时结果 → Toast；可撤销操作 → Snackbar（带动作）；需要上下文持续提示 → 内联 Banner；需要阻断决策 → Dialog。并补 Dialog 通用规格（标题/正文/主次动作/危险动作/不可点外部关闭的场景）。

### P1-8 组件规格覆盖不足（现有 10 项，建议补 15 项）

现有：按钮、chip、卡片/分组、弹层/sheet、开关、状态点、tab、toast、空态、时间戳。

**文档中已被使用但无规格的组件**（按出现频次）：

| 组件 | 被谁点名 |
|---|---|
| 输入框 / 搜索框 | 01 外观（只有形态无规格）、04 记忆「🔍 搜索记忆…」 |
| 列表行 cell | 00 §四 行高 44+（仅尺寸，无选中/滑动/副标题规格） |
| 分段控件 Segmented | 04 记忆「[ 已记住 ｜ 待确认 ]」 |
| 徽标 Badge / 计数 | 04 记忆「共 12 条 · 已记住 4 · 待确认 8」 |
| 长按/下拉菜单 | 02 主页胶囊 §二（有行为无视觉规格） |
| 对话框 Dialog | 06 模型「删除确认」、02「取消钉选」 |
| 进度 / 骨架屏 | 06 模型 TESTING 态、04 记忆 300 条冷启动 |
| 头像 | 00 §四 icon-btn/头像 40px（仅尺寸） |
| 标签 Tag | 00 §三 圆角「标签 4」+ §四「tag 高 22px」（散落，无组件规格） |
| 复选/单选 | 02 主页胶囊管理弹层「☐」、01 外观主题三选「○」 |
| 表单（label/helper/校验时机） | 06 模型三级设置页表单 |
| 折叠/展开、滑动操作、步骤指示器、引导 | 散见各处 |

- **建议**：把上面 12 类补进 00 §五（至少给尺寸 + 默认态 + 关键状态 + 一句话用法），其余（折叠/滑动/步骤/引导）可标"暂不立规格，用到再补"。

### P1-9 布局栅格 / 断点 / 单位基准

- 只有「4 的倍数」间距档，无栅格列数、无断点（手机/平板/折叠屏/横屏）、无容器最大宽度。
- **单位混用**：§二 注明「px = web；sp = 原生」，但 §四/§五 混用 px 与 dp（「44+」「40px」「8dp」「16」），无换算表。跨端施工会各解各的。
- **建议**：补栅格与断点表 + 明确「规范内统一写 dp，web 侧 1:1 映射 px」的单一基准。
