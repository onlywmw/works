## 施工(照执行引擎稿 §6)

L0 范围 = S3,在 `mov-exec-engine` 新增 **approval 子包**(建议 `com.hermes.mov.exec.approval`),核心全纯 JVM:

1. **CanonicalCodec**:canonical 参数稳定序列化(键排序、数组保序、仅 plain/JSON 值、拒循环/非有限数)——供 hash 稳定与 summary 确定性;sha256 得 `canonicalHash`。
2. **DeterministicSummaryRenderer**(§6.5,禁 LLM):由 canonical + 能力声明(registry)确定性渲染人读摘要。MVP 形态=结构化两行:`op: <capability.name>` + `参数: <key>=<value> 逐项`(key 取 in 属性名、value 取 job input,值域就能力语义;不得引入 LLM/自证链)。
3. **policyFingerprint**(§6.1):sha256(该能力注册表安全面 = side_effect + env + 审批相关约束),随能力安全面变;文案/描述变更不变。
4. **ApprovalSnapshot**:`{capabilityId, capabilityDefinitionVersion, policyFingerprint, canonicalPayload, canonicalHash, summary(renderer 输出), summaryVersion, approvalScope}`(MVP scope 取 `capability_call`)。
5. **ApprovalRequest/Record**(§6.2 首决胜+不可变):requestId=`apr_sha256(runId+snapshot)`;Record{request, decision?};decision 只 approve/reject + reviewerId + decidedAt;**先到者生效、二次 decide → CONFLICT;已决 Record 不可变(无覆盖/撤销入口)**。本单不实现 TTL/expire(归 S4),但把「未决请求」状态留给 S4。
6. **ExecEngine 接线**(改 S2 的 blocked 占位):WRITE/MONEY job 由「直接 DISPATCH_BLOCKED」改为 → **进入审批流**:创建 snapshot + request → 注入 reviewer 裁决(本单=程序化 reviewer 供测试;真人 reviewer/UI 接 S4)→ approve → 复验 fingerprint → dispatch;reject → blocked;无 reviewer/未决 → `pending_approval`(挂起,不等于执行)。**默认无 reviewer 时绝不自行放行**(fail-closed)。
   - READ 路径**不改**(README/READ 直跑不回归)。
   - 仍禁 `if(capabilityId==…)` 决定审批——策略源 = 注册表 side_effect(G2 持续守)。
7. **STALE 复验**(§6.1/§6.6 dispatch-time):dispatch 前重读注册表现况 policyFingerprint 与 snapshot 比对;不一致(安全面已更严)→ 该批作废,状态 `stale`,**不 dispatch**;记账事件。
8. **Ledger 事件扩展**(append-only,加审批链最小集):`APPROVAL_REQUESTED → APPROVED | REJECTED | APPROVAL_STALE`;与 S2 READ 链共存,不覆盖已写行(G7 持续守)。事件词表并入模块常量。
9. **Guard 固化**:新增 `ApprovalGuardTest`/静态锚:decide 后 mutate → 红;summary 存在 LLM 注入/非确定性 → 红;决策未含 fingerprint 校验 → 红。
