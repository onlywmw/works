# 【派单 SYS-02 阶段三】E1 状态单源（工单库=唯一权威，工单表=生成物）

**角色**：C 线（基建）｜ **级别**：P2｜ 依据：`改造计划_工单流转中心防伪抗倒退_2026-09-01.md` §8.1（E1 组件设计）+ §8.2（阶段划分）
**背景**：UPG-49 四处状态不一致（表「待认领」/卡「✅C 交付」/报告 hash 不存在）；UPG-68 卡「挂单」但 worktree 已开工——**双源（表+库）人为同步=失同步反复发生**。E2（阶段一已做）只在「登记前」拦一道；E1 从根上消灭「双份」。

## 一、范围

1. **唯一权威 = `工单库.md` 每卡状态行**（人只写这一处——含状态/判据/认领/hash 全链；**状态行必须含状态变更时间戳 ts**——E4 超期判定依赖[评审 P1-6]，示例:✅ 验收通过 @2026-09-01T22:00）
2. **工单表.xlsx = 生成物**（从工单库自动生成——禁止手写；手写=违例）
3. **两阶段实施**：
   - **3A 校对器**（先做）：`工单系统\审验员\sync-orders.mjs --check`——解析工单库状态行 vs 工单表实际内容 → 输出 diff 报告（缺失/不一致/过期 hash）——**第 1 步只校对不写表**（安全过渡）
   - **3B 单向生成器**：`sync-orders.mjs --sync`——库→表单向生成（表=全量重写自库）——生成后 `--check` diff=0 为成功条件
4. **映射规则**（设计定案）：卡标题→表 A 列（工单号）；状态行语义→表状态列（✅C 交付/验收/合 main/认领 hash——按现有 11 列口径对齐；**不确定的语义=输出警告不猜**）

## 二、验收判据

- S2-4 单源：改状态只在工单库一处；`--sync` 后 `--check` diff=0（机器对账）
- S2-6 校对器：手工造 1 处不一致（表 vs 库）→ `--check` 必报（diff 非空+精确位置）
- S2-7 生成器稳定性：`--sync` 连跑两遍结果一致（幂等）；表行数=库卡数（对账）
- S2-8 零手工：生成的表=纯生成物（`git diff` 不含手写痕迹——以生成时间戳标识）
- S2-9 审验.py/既往 SYS 物零回归（--verify-hash/--coverage 等）

## 三、红线

1. **只动**：`工单系统\`（sync-orders.mjs + README 说明 + 汇报）——**0027-mov/App 零接触**
2. **登记纪律不变**：状态登记=设计师唯一写点（从「写表」改为「写库」——表由机器出）
3. 校对模式先行（3A 必须**只读**，未评审通过前禁止 --sync 覆盖表）；生成门槛=3A 对当前存量 diff=0 一次
4. 字段语义不确定→**输出警告不猜**（防生成器造错误数据）
