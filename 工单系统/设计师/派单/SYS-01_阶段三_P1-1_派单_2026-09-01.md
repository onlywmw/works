## 三、目标：把"能力不倒退"从抽象概念落成**可检查的文档门槛**

### 1. 共享面变更声明（《共享面影响清单》）

凡工单改动涉及下列共享面之一 → 交付报告**必附**清单：
- MainActivity 注册表
- 工具面（公共函数/脚本/配置）
- 协议/接口定义
- 全局数据结构

清单写明：改哪个共享面 → 影响哪些下游调用方 → 为何无副作用 / 已做哪些回归。

### 2. coverage_status 三档（把"未覆盖"正式化）

```text
coverage_status:
  FULL    → 直接通过能力护栏
  PARTIAL → 必须写明：未覆盖维度 + 风险(低/中/高) + 是否允许合main(是/否) + 裁决人(设计师) + 裁决记录
  NONE    → 原则上「共享面变更 + NONE = 不允许合 main」
```

### 3. 收口 ③ PARTIAL 显式裁决记录（防"大家觉得应该没问题"）

PARTIAL **不能**由程序员或验收员单独放行——**必须存在设计师的显式裁决记录**，含 `decision / reason / decided_by / decided_at`：

```json
{
  "coverage_status": "PARTIAL",
  "uncovered": "协议异常重连路径",
  "risk": "medium",
  "merge_decision": "approved",
  "reason": "当前变更仅影响 UI 注册层，协议路径未改动；已有历史回归覆盖",
  "decided_by": "设计师",
  "decided_at": "2026-09-01T..."
}
```
