## 三、目标：新建两套结构 + 出单前查询强制

### 边界（生命周期干净，防互相污染）

```text
挂账登记表  = 未解决（待审池，已在处理中心）
已知坑库    = 已解决（沉淀）
复用件表    = 已验证可复用（已沉淀 + 更严字段）
```

**生命周期**：未解决 → 挂账；解决 → 自动沉淀 → 已知坑；过时 → 标过时。

### 落点 `设计师\知识库\`（新建）

#### 已知坑.md（回答「什么东西以前坑过我们？」）

条目字段：
- 坑名（一句话）
- 适用版本/日期
- 关联工单号
- 现象 → 根因 → 药方（已解决）
- 解决状态（已验证解决 / 疑似解决 / 已过时）
- 最后验证时间

#### 复用件.md（回答「什么东西已验证可直接复用？」——更严格，防变垃圾仓库）

条目字段：
```
component_id / 版本 / 适用范围 / 最后验证时间 / 关联工单 / 验证状态 / 使用次数 / 已知限制
```

### 自动沉淀（半自动，避免人工搬运遗漏）

挂账条目验证解决并转工单完成 → 半自动提取到"已知坑.md"；条目加"已解决→转入已知坑库"链接，**双向可追溯**。

### 出单前查询强制（派单模板改造）

派单模板加字段：**「已查坑位库/复用件库：是/否，命中条目：___」**
- 不填或填"否"且无说明 → **审验员可退回**。

## 四、与既有制度的关系（不重复、不覆盖）

- **挂账表**（`处理中心\挂账登记表.md`）= 未解决待审池 —— **不动、不替代**。
- **已知坑库** = P1-2 新建的「已解决」沉淀 —— 解决后由设计师/程序员半自动提取入库。
- 二者按"是否已解决"划边界，不重复收录。既有红线 10（挂账登记与转工单）流程不变，只在"转工单完成"节点加一步"沉淀进已知坑库"。
