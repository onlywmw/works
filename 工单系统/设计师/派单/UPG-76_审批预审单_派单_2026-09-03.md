## 二、一句话

LLM 先只读扫描输出结构化审批单（意图+步骤清单）→ 用户一次裁决（逐条勾选/批量批准，MONEY 永不预批）→ 整批执行：每步 dispatch 前比对批准清单（命中放行+扣减，计划外硬拦截转新 ASK），每步保留现行安全闸兜底。

## 三、施工范围（两阶段，顺序执行）

### 阶段一：PlanApproval 执行绑定（纯 JVM 机制层）

1. **新建 `PlanApprovalStore`**（app 侧 `com.hermes.dsh.tools`）：批准清单存储——键=`toolName + CanonicalCodec.sha256Hex(canonical(args))`（复用 engine 件）；值=剩余次数+runId+批准时间。Group 双状态机语义对齐执行引擎 v0.4 §8.3（Group: pending→partially_decided→completed|expired|stale；Node: approved|rejected|blocked|expired|stale）——**语义照 §8.3，实现落工具级，exec-engine 运行时不接线**（能力级接线=S5+ 另单）。
2. **执行绑定下沉 `ApprovalService.request`**（remembered 检查之后、FIFO 入队之前）：ASK 判定后先查清单——命中且次数未耗尽且未过期 → 放行+扣减（跳过弹窗）；未命中 → 走原 FIFO 弹窗。**only-once 工具不吃清单**（与 :350 豁免跳过同红线）；MONEY 类工具（payment.* 等 gate/sensitive 支付面）**永不在清单内**。下沉一处=对话面+MCP 面双面生效（McpServer ASK 路由同走 request）。
3. **时效与单次**：每条授权=恰好一次执行（扣减耗尽→同调用转新 ASK）；清单绑定 runId + 硬 TTL（过期=EXPIRED≠REJECTED，不复活，要跑=重新出单）。
4. **阶段一测试**：PlanApproval 套件（命中放行+扣减/计划外转 ASK/EXPIRED/单次执行/only-once 拒绝/MONEY 排除/Group 迁移含 partially_decided+stale）。

### 阶段二：扫描编排 + 审批单 UI

**触发口径（设计裁决 @2026-09-03，用户拍板选项 2——「先扫，只有 ≥1 写才续扫」）**：
- 每条消息**首轮正常跑**（全工具面，无扫描轮）——纯只读/闲聊**零增量**。
- 运行中**首个 ASK 级（写类）工具调用到达 dispatch 时暂停** → 触发**计划补全轮**：LLM 挂 READ-only 工具面输出后续完整结构化计划（含已确定的当前步）。
- 补全后计划含 **≥2 个审批级步骤** → 出预审单；**恰好 1 个** → 直接走现行单步弹窗（UPG-75 通道），不出单。
- 计划外调用硬拦截转新 ASK（钉子 2，不变）。
- **Token 申报口径**：纯只读/闲聊=零增量；办事型请求=+1 轮（计划补全轮）——钉子 3「简单请求零增量」按此成立，原「每条消息自动先扫描」表述作废。
- （候选·本单不做：设置页「预审单模式：自动/总是扫描/关闭」偏好，立项另评。）

5. **扫描/补全模式**（`MainActivity.kt:7797-7823` 单点）：过滤层加 `category=="read"`——schemas（:7805）与 allowedTools（:7823）**同源收缩**，补全轮写类工具对 LLM 不可见也不可执行；提示词 `:5352` 拼串处按补全/执行模式条件化（现成先例=codeSdk 按模式拼入），**`:5358`「禁止输出计划文本」指令补全模式必须反转、执行模式保持**。补全产出=结构化计划（步骤：工具/参数/理由/顺序）。
6. **出单门槛**：计划含 **≥2 个审批级（WRITE/MONEY 类）步骤**才出审批单；0/1 步直接转现行执行（单步走现行弹窗）；READ/无害类不上单、只推进度（「感知而不打扰」）。
7. **审批单 UI**（复用 UPG-75 件）：以 `showApprovalPanel` 行结构（:7293-7405）为清单卡骨架——步骤行用 `apprHumanPhrase`/`apprIconFor`（:7342-7344）、参数行用 `apprArgsSummary` 脱敏摘要（:7412-7428）；逐条勾选 + 批量批准（照 :7307-7328，only-once 行排除照 :7309-7310）+ **MONEY 行明示「含支付步骤，执行到该步单独实时确认」且不可勾选**（注册表现仅 `payment.pay`，按 toolName 前缀/riskLevel 自判）。
8. **执行模式**：批准后按计划执行；部分批准→被批步骤放行、依赖被据步骤 blocked、独立步骤放行（§8.1 EdgePolicy 语义）；**失败/拒绝=阻断下游，UI 与文案不承诺「撤销」，已执行项如实标「已执行」**。

## 四、红线（违反=打回）

1. **UPG-68 安全语义零改动**：only-once 任何模式只收 allowed-once（不吃清单/不吃豁免）；fail-closed 不变；MONEY 永不预批（执行到该步实时确认）。
2. **不造第三套**：Group 状态语义照 §8.3（禁 UI 层私设状态字段）；canonical/指纹复用 engine 件（禁第三份实现）；判定入口仍是 guard.decide 单源（UPG-77 不动）。
3. **不动 UPG-75 呈现层语义**（FIFO/弹窗/通知只复用不改语义）；不动 exec-engine 现有类。
4. **Token / KV Cache 影响必须申报**（AGENTS.md 硬规则 1）：触发口径=选项 2——纯只读/闲聊零增量、办事型 +1 轮计划补全（触发条件+量级如实申报）；提示词条件化增量（常驻 token 变化说明）；会话内前缀恒定。
