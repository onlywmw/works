## 范围
- **明确边界**：本轮**不建设组件运行时/注册机制**；只统一目录与形态层。
- **A1（核心）**：`前端设计/mov-vue/src/catalog/ui-components.json` 为唯一目录源（字段：version/id/name/kind/prefix/variants/defaultVariant/site/order/provider/semanticType；version+字段注释；semanticType/provider=现有目录元数据，不新增半截运行时字段）。`scripts/gen-ui-catalog.mjs` 生成：
  1. `app/src/main/java/com/mov/android/ui/catalog/UiComponentCatalog.kt`（CatalogEntry/ComponentVariant/ComponentSpec + 20 编号常量 + components 列表）
  2. `AppearanceApp.vue` 的 `COMPONENTS` 数组段
  3. 对账断言（schema⇄Kotlin⇄Vue 全等）
  **防漂移三层**：① 生成物文件头 `// AUTO-GENERATED ... DO NOT EDIT.`（断言检查）② pre-commit 钩子 ③ CI 步骤 `npm run gen-ui-catalog && git diff --exit-code`（证据落交付报告）。
- **A2**：SETTINGS 族形态类从 `SettingsPage.vue` scoped 迁入 tokens.css 形态层；**规范对齐先做影响面清单**（消费待对齐 token 的页面/组件+视觉差异说明）→ **用户裁决**：改代码对齐规范（视觉回归风险+回归测试）或改规范对齐实物（标「暂不调整」）；Motion/z/elevation/inset token 落库或删除（按实际使用裁决）；产出 `tools/ui-catalog-audit.mjs`（未接入页面清册）+ 对账表（**漂移项/处置结果/影响面**三列）。
- **A3（B 阶段，本单不做）**：统一页面宿主——**试点先行**：先 SettingsSheet 做 PageHost 试点（WebView+AssetLoader+Bridge+主题注入）→ 试点结论文档 → 拆多小单逐步替换；不一次重构 10 页。
