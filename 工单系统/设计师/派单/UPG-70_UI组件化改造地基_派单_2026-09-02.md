# UPG-70 UI 组件化改造 · 地基 —— 派单文本（2026-09-02 · 方案 v2.1）

## 单号
UPG-70 ｜ P2 ｜ M8 UI/交互（标签 M2 体系/治理）

## 一句话
把 UI 组件化体系的地基修好：组件目录单一数据源（消除 Kotlin/Vue 双写）、形态类归层、规范与实现对账。**本轮不建设组件运行时**（病根 3 明确延期=另立卡）。

## 依据（用户拍板 + 大神两轮评审）
2026-09-02 用户要求先调研 GitHub 成熟方案（Vant4 / Ark+UnoCSS / shadcn-vue）——结论：外部库解决「组件丰富度」，MOV 真正病根是本地工程结构；用户拍板**先修地基**。方案 v1 → 大神一轮（5 补强+3 前置全采纳）→ v2 → 大神二轮 **9.2/10 建议可开工**，4 口子+1 施工原则**全部钉死**（本单口径=方案 v2.1）。

## 范围
- **明确边界**：本轮**不建设组件运行时/注册机制**；只统一目录与形态层。
- **施工原则**：本卡解决「数据从哪里来」，不解决「数据本身是否正确」——A1 严禁顺手改组件名/variant/编号（另立单）。
- **A1（核心）**：`前端设计/mov-vue/src/catalog/ui-components.json` 唯一目录源（version/id/name/kind/prefix/variants/defaultVariant/site/order/provider/semanticType；version+字段注释；**order=唯一业务排序依据，生成器禁按 id/name 重排**）。`scripts/gen-ui-catalog.mjs` 生成：
  1. `app/src/main/java/com/mov/android/ui/catalog/UiComponentCatalog.kt`（CatalogEntry/ComponentVariant/ComponentSpec + 20 编号常量 + components 列表）
  2. `AppearanceApp.vue` 的 `COMPONENTS` 数组段
  3. 对账断言——**「全等」标准=业务字段集合及顺序语义一致（id/name/kind/prefix/variants/defaultVariant/site/order/provider/semanticType）；Kotlin 类型定义/Vue 导出包装/注释/import 路径=生成表示差异，不算数据漂移**
  **防漂移三层**：① 生成物文件头 `// AUTO-GENERATED ... DO NOT EDIT.`（断言检查）② pre-commit 钩子 ③ CI 步骤 `npm run gen-ui-catalog && git diff --exit-code`（证据落交付报告）。
- **A2**：SETTINGS 族形态类从 `SettingsPage.vue` scoped 迁入 tokens.css 形态层；**规范对齐先影响面清单**（消费待对齐 token 页面/组件+视觉差异说明）→ **用户裁决，处置结果三态 = 改代码 | 改规范 | 暂不调整（必须带原因）**；Motion/z/elevation/inset token 落库或删除；产出 `tools/ui-catalog-audit.mjs`（未接入页面清册）+ 对账表（漂移项/处置结果三态+原因/影响面）。
- **A3（B 阶段，本单不做）**：统一页面宿主——**红线=禁止一次迁 10 页**；先 SettingsSheet 做 PageHost 试点（WebView+AssetLoader+Bridge+主题注入+生命周期）；**试点验收=旧实现 vs PageHost 实现 5 项表**（WebView 创建/AssetLoader/Bridge 可复用；Theme 注入可复用或明确差异点；生命周期返回销毁无行为回归）→ 试点结论→拆多小单。

## 不做
- 不引 Vant/Ark/UnoCSS（下一阶段另议）
- 不建设组件运行时/注册机制（后续阶段另立卡）
- 不改 20 条编号/52 档数据（内容治理另立单；只改来源）
- 不改组件视觉（A2 token 对齐例外——先影响面评估+三态裁决）
- 不动 UPG-50 阶段 2 已派工作（feat/upg50-ph2）

## 验收锚
- A1-1 唯一目录源（grep 断言无第二份目录数据）
- A1-2 改 schema → 重新生成 → Kotlin+Vue 同步（按「全等=业务字段一致」判定）
- A1-3 手改生成物 → 断言红（亲杀）
- A1-4 CI `gen-ui-catalog && git diff --exit-code` 通过（日志/截图证据）
- A1-5 生成物顺序与 JSON `order` 完全一致（无 id/name 重排）
- A2-1 SETTINGS 形态类在 tokens.css、SettingsPage.vue scoped 无残留
- A2-2 影响面清单（消费待对齐 token 页面/组件 + 差异说明）
- A2-3 对账表三态（漂移项/处置结果[改代码|改规范|暂不调整+原因]/影响面）
- A3-0 PageHost 试点结论（5 项验证表全过或差异点明确）——通过才拆小单
