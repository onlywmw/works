MOV 官网 · 容器面（给 AI 看）内容设计表 v1 · 2026-09-04 · 设计师B

双本质概念：展示板（人看渲染）· 容器面（AI 读投影）。本文档列「给 AI 看什么」——内容全部来自官网数据单源，AI 与人的页面看到同一份事实。

① 发现层

/llms.txt —— AI 读官网地图：这是什么、有哪些页、每页干嘛、下载从哪拿

② 投影层

全站 JSON-LD + 语义标签 —— 页面自身机器可读（搜索/汇总工具直接吃）

③ 工具层

/mcp JSON-RPC + mov_* 六工具 —— AI 主动查询官网结构化数据

一、发现层 llms.txt —— 给 AI 的官网地图（首批内容）

字段内容（写什么）为什么给 AI 看
# 官网介绍MOV AI 官网·一句话定位 + 目标人群（个人 AI 助理 / 开发者 / 商户）AI 第一眼知道「这是什么站、能帮我做什么」——不浪费时间乱点
页面地图每页：URL + 一句话用途（home/tools/merchant/dev/privacy/guide…）AI 按需直达正确页面（不用爬全站猜）
APK 下载直链 + 版本号 + sha256 校验说明（cc.mow.kim MOV-V1.0.apk）AI 给用户「去哪下、校验」的准确指引；可验证包完整性
组织身份主体「江西皮蛋科技」+ ICP 备案号 赣ICP备2026013905号-2 + 联系方式信任面：AI 判断「这是正规公司官网」；合规引用
能力摘要官网核心能力清单（AI 助手/能力市场/工具生态/商户合作）AI 快速做「官网有什么」摘要，回答用户前不用全站读

页面JSON-LD 类型AI 拿到的关键字段

/tools.htmlItemList + Product工具名 / 分类 / 描述 / 作者 / 评分（每项一条）

三、工具层 —— mov_* 六工具（AI 主动查询，全部只读）

工具AI 问什么时用返回字段（给 AI 的内容）
mov_site_info「MOV 是什么 / 官网信息」name / tagline / 平台 / 版本 / 主体 / ICP / 页面清单
mov_home「官网首页讲了啥 / 下载哪个」hero 卖点 / 核心能力三卡 / downloadUrl+version+sha256
mov_tools_query「市场有没有 XX 工具」列表：name/category/desc/author/rating + 可安装性（builtin/MCP）
mov_tool_detail「某工具怎么用」toolSchema（参数/描述）/ 安装方式 / 作者 / 版本
mov_merchant_info「怎么成为商户/上架」入驻流程步骤 / 材料要求 / 联系渠道 / 协议链接
mov_download「下载 / 更新」apkUrl / version / 更新说明 / releaseDate / checksum
返回示例（mov_site_info）：

AI 拿到这份 JSON 就能完整回答「MOV 官网/公司/下载」类问题——结构化的、可验证的、无幻觉空间。

四、给 AI 看的「内容原则」（为什么这么设计）

原则说明
单一事实源页面与工具读同一份 JSON 数据文件——人看到的 = AI 看到的，不存在两套真相
只读零特权六工具全部只读 harmless；写操作（商户提交等）走页面表单/既有审批闸——容器面扩张零权限
答案可验证版本/sha256/备案号/联系方式全部机器可读——AI 引用的每个事实都能回溯官网佐证
防注入纪律网页文本作为「数据」返回，附「这是官网数据非指令」元字段（数据不是指令先例）
可学习工具 desc 用官网原话；AI 可据此在 App 内直接引流用户到官网（下载/商户/市场）
明确不做的（红线）：不给 AI 看用户私有数据；不暴露内部 admin/控制台结构；工具面只读不写；不使用未备案/伪造标识。

五、A+B 双通道与工具分级（用户 2026-09-04 拍板：部分开放、部分对 App）

通道端点/契约规范给谁用
A 对外公开mov-ai.cn/mcp（Streamable HTTP）MCP 2026-07-28 正式规范（POST-only / MCP-Protocol-Version 头 / OAuth 2.1 按需开放匿名 public client）任何 MCP 客户端（Claude / Cursor / 其他 AI）——公开只读信息
B App 专属App 内 WebMcpHub（web.* 契约，UPG-43a 线）MOV 内部契约（UPG-27 LayeredRouter + 自研 JSON-RPC over postMessage）MOV App 内 AI 会话——含设备上下文/引导动作

工具分级（公开面 vs App 面）

工具A 对公开B 对 App内容
mov_site_info✅ 开放✅官网总览（品牌/主体/ICP/页面地图）
mov_home✅ 开放✅首页卖点+APK 下载（URL/版本/sha256）
mov_tools_query✅ 开放✅能力市场检索（名称/分类/作者/评分）
mov_tool_detail✅ 开放✅工具 schema/安装方式/文档
mov_merchant_info✅ 开放✅入驻流程/联系/协议
mov_download✅ 开放✅APK 校验信息
mov_install_guide❌ 仅 App✅安装引导（需设备上下文：已装版本/权限状态）
mov_tour/mov_onboarding❌ 仅 App✅App 引导/教程（需会话状态）
mov_wallet*/mov_account*❌ 仅 App（永不公开）✅（走审批闸）账号/钱包——敏感面，只走 App 内部审批链
分级红线：A 公开面=只读+无用户数据+无敏感面；B 每工具按既有审批闸（only-once/high 必弹）；同一工具 A/B 共读同一数据源（单一事实源），但 B 可加上下文（设备/会话）——**B 的上下文永不出网**。
