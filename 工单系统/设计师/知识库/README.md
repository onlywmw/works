# 设计师 · 知识库（已知坑库 + 复用件表）

> **把踩过的坑沉淀成可查的库，出单前先查，减重复踩坑 + 重复施工。**
> 2026-09-01 建 · SYS-01 P1-2（零 APP 影响，纯 Markdown 结构，无脚本）

## 一、三库边界（生命周期干净 · 互斥，防互相污染）

```text
挂账登记表（处理中心） = 未解决   —— 待审池，已在红线 10 流程，不动
已知坑库（本目录）     = 已解决   —— 沉淀的坑（坑过我们 + 药方）
复用件表（本目录）     = 已验证可复用 —— 可直接拿来用的组件/脚本/产物（更严字段）
```

| 库 | 回答的问题 | 收录条件 | 边界判定 |
|---|---|---|---|
| `挂账登记表.md`（`处理中心\`） | 什么东西待解决？ | 工作中被动发现、未解决 | **未解决 → 挂账**，不进两库 |
| `已知坑.md` | 什么东西以前坑过我们？ | 现象→根因→药方齐，**已解决** | **解决 → 沉淀到已知坑** |
| `复用件.md` | 什么东西已验证可直接复用？ | 8 字段齐，**已验证可复用** | **过时 → 标过时**，不入两库 |

> 一个条目只在一个库：未解决挂账 → 已解决已知坑 → （可复用才升级复用件）。**不重复收录，不互相覆盖。**

## 二、生命周期

```
未解决 ──→ 挂账登记表（待审池）
  │ 设计师验证 ✅ → 转工单 → 完成
  ▼
已知坑（已解决）──→ 过时 → 标「已过时」（定期清理，不是删）
  │ 已验证可复用
  ▼
复用件（更严字段：component_id/版本/适用范围/最后验证时间/关联工单/验证状态/使用次数/已知限制）
```

## 三、半自动沉淀（防人工搬运遗漏）

挂账验证解决并**转工单完成后**（`处理中心\挂账登记与转工单规则.md` §四 追加一步）：

1. 设计师/程序员把该条挂账的「现象→根因→药方」半自动提取进 `已知坑.md` 新增一行
2. 挂账登记表原条目「施工/转工单」列追加：`→ 已解决，转入已知坑库（坑名: xxx）`
3. `已知坑.md` 条目「关联工单」列填：`挂账-<id> → 转工单 <UPG-xx>` —— **双向可追溯**（挂账 → 已知坑 ← 工单）

## 四、出单前查询强制（派单必填字段）

**设计师每次出单（派单文本）必先查两库**，派单文本元信息区必含字段：

```
已查坑位库/复用件库：是/否，命中条目：___
```

- 填「是」+ 命中条目 → 写明命中（如 `已知坑#2 工单表并发丢行`），并在施工范围引用/规避
- 填「否」+ 无说明 → **审验员可退回**（不填或否且无说明 = 出单不合规）
- 填「否」但有说明（如「本单无共享面/无既有坑位交集」）→ 审验员核对说明后放行

**权责**：设计师出单前必查并填字段；审验员核对字段；设计师维护时效（过时条目定期标过时）。

## 五、维护纪律

- 两库只收**已验证/已解决**事实，不收推测（「应该在」不算）
- 条目带时间戳（最后验证时间），防坑药方过期
- 过时条目标「已过时」，不删除（保留历史）
- 与红线 10（挂账登记与转工单）衔接：挂账表流程不动，只在「转工单完成」节点加一步沉淀
