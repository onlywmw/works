## 一、问题全景（W2 家族 · 预扫描实证）

### 1.1 根因（与 W2 同构）

```text
注册面（handler/工具/URL/密钥）与校验面（权限名单/白名单/加密）两套系统人工同步
  → 漏同步 = 安全机制静默旁路（人肉纪律已两次失效：approval.setMode/personalization.setEnabled）
```

### 1.2 商业直接面 5 项（★新发现）

| # | 缺口 | 实证 | 商业后果 |
|---|---|---|---|
| B1 | ★ `biz.*` 全套零登记 | biz.taskClaim/taskAction/bookingAction/onboardStart/Set/Photo/Scan/Submit/Status（MainActivity:3870-4106）注册 handler 但 guard 名单零条目 | **AI 免审批接单/变更订单权益/提交微信支付特约商户进件**（onboardSubmit 上传身份证+银行信息） |
| B2 | ★ PARTNER_AUTH_TOKEN 明文硬编码 | MainActivity:256-258（注释自认「试点期 token 内置」）partnerHttp:4696 携带 | **反编译即得商业后端全权令牌** |
| B3 | 已知挂账：vault.set/credSet/setPhoto/scanPhoto 免审批写入 | 四写类不在任何名单（writeTools 仅 vault.delete/credDelete:116） | AI 免审批写身份证/银行卡/平台密码；与 onboardSet 串联=免审批构建进件资料 |

## 二、范围（A~E · 一张单五子项）

| 子项 | 内容 | 判据 |
|---|---|---|
| **A 白名单自动闸**（原 UPG-68 主体） | ①单源：现有 `docs/ApprovalRegistry.json`（生成物）扩展 category/riskLevel 字段，**不新建第二份**（双源=契约管理本身要防的）②schema 文件 + 校验器 ③`guard()` 查询 registry，`UNKNOWN→ASK`（fail-closed——else→ALLOW 移除）④CI 注册即校验：新 handler 出现在工具面但未登记→CI 红 | V68-1~6 |
| **B biz.\* 补登记** | task/booking 写类→ASK；**onboardSubmit/onboardSet 敏感级**（进件=商业敏感，AI 免审批=最严重缺口） | V69-1 |
| **C PARTNER_TOKEN 去硬编码** | 迁 CredentialStore（Keystore）+ 服务端下发/本地配置；**源码零硬编码断言**（grep 硬编码 token=CI 红） | V69-2 |
| **D vault 全族收口** | set/credSet/setPhoto/scanPhoto 补登记 + **vault.get 伪放行修复**（handler 只认 allowed-once→allowed-remembered/turn 一致；browser 支付/登录审批同病一并） | V69-3 |
| **E 商业凭证明文治理** | mov_biz/mov_login token 迁 Keystore 加密存储（F4 方针落地） | V69-4 |

### 核心设计（A 的闸门三件套）

```text
docs/ApprovalRegistry.json（单源·现有生成物扩展）
   → guard() 查 registry：read=ALLOW / write=ASK / sensitive=DENY / 未登记=ASK
   → CI 校验器：新 handler 未登记 = CI 红（静态）+ 运行时未登记 = ASK（动态）
```

**与大神评审的呼应**：G1 机器可读化 + G2 一致性自动闸合并落地（一个校验器+一个 registry=最小闭环）——大神说「不是两件事」，照此执行。

### 7.3 时间重校（大神 · 接受）

**3~5 个工作日**（非「半天~1 天」）：A 1-2 天（schema+校验器+guard+CI）/ B 半天~1 天 / C 1 天起（CredentialStore+下发通道）/ D 半天~1 天（含状态机回归）/ E 1 天（纯迁移）。商业进场时间线按 3~5 天排。

### 7.4 商业进场门禁项（新增 · 大神 B5 要求）

**商业进场前必须**：`http.post/get` 加 **host 前缀限制**（至少商业相关请求限定白名单 host）——本批不做全量治理，但门禁成立（本批验收外，商业门禁清单项；随商业契约设计落实）。

## 八、二轮大神评审采纳记录（v3 · 9.1/10 可送审 · 补 A7 后冻结）

> **二轮结论**：「已从漏洞清单升级为真正的商业进场安全闸门」——可以送审，但还不能冻结开工；**唯一 P0 收紧项 = A7（Agent 副作用执行单入口不变量）**。

### 8.1 三项新增采纳

| 编号 | 大神要求 | 定夺 | 落点 |
|---|---|---|---|
| **A7（P0）** | Agent 副作用执行必须经过统一 Dispatcher → Guard → Handler；禁止 Agent→Handler/Biz API/Vault API/partnerHttp 绕过；CI/静态检查「不经 dispatch → 红」 | ✅ 采纳（**防「新入口根本没走 registry」——比漏登记更危险**） | 主设计 §2.4 + V68-7 判据 |
| **V69-2a** | PARTNER credential 只能由 CredentialStore 产生；partnerHttp 不接受裸 String token，只接受 Credential 对象/受控凭证句柄（防双入口） | ✅ 采纳（单入口从「加载点」升级为「产生点」） | V69-2 附加判据 |
| **Commercial Entry Gate** | 商业进场六条硬门禁（①UNKNOWN→ASK ②注册面⊆Registry ③Agent 副作用统一 Guard ④PARTNER 单入口+Keystore ⑤敏感操作 DENY ⑥HTTP Host Allowlist）→ **Commercial Ready = TRUE/FALSE** 单判据 | ✅ 采纳（任何人不翻 50 条验收，看 Gate 即知能否接微信支付） | §8.2 |

### 8.2 Commercial Entry Gate（正式）

```text
商业进场必须同时满足（缺一 = Commercial Ready = FALSE）：
  ① UNKNOWN → ASK（W2 自动闸）
  ② 注册面 ⊆ Registry（A1 枚举）
  ③ 所有 Agent 副作用统一经过 Guard（A7 单执行通道）
  ④ PARTNER Credential 单入口 + Keystore（V69-2a/C/E）
  ⑤ 商业敏感操作 DENY（onboardSet/Submit）
  ⑥ HTTP Host Allowlist 已落地（B5 硬门禁——本批不实现但禁止商业能力先于其开放）
```

**门禁顺序（大神 §七）**：UPG-68 主批 → 安全自动闸完成 → 商业契约设计 → HTTP Host Allowlist → 支付/进件开放。

### 8.3 V69-3 验收升级（大神 §三）

vault.get 状态机完整回归（不是只测「弹没弹窗」）：

```text
NONE → ASK → ALLOWED_ONCE → 消费 → NONE
ALLOWED_REMEMBERED → 下一轮 → 仍有效
TURN → turn 结束 → 失效
（跨 turn / 跨 round / 跨 session 回归必测——「审批过一次 ≠ 当前实际上有授权」）
```
