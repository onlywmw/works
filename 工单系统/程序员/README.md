## 工作顺序（多 agent 防撞，2026-08-16 定）

- **工单流转顺序**：设计师出单 → 程序员施工（登记上表）→ 验收员验收（代码层+真机层）→ 审验员审验（AI查证据链）→ 设计师合 main
- **合 main 单点**：只设计师合 main；同一时间一个 agent 执行；撞到→git 实证谁先完成→已完成方跳过、后到者确认不重复
- **合 main 前提**：全量绿 + 真机验收通过；**编译/测试 FAILED 必须停**（即使疑似文件锁先查真红），不得合
- **并发防锁**：同一文件/分支同一时间一个 agent（Windows 文件锁 + gradle 互锁）；多 agent 各用独立 worktree

## 领单认领规范（2026-08-17 定，**领单必读**）

> 多 agent 并发时，分支被 worktree 占用 = 该单已被认领。**领单开工前必须先登记认领**，避免占用歧义/重复施工。

1. **查工单表**该行备注：已有「认领:」登记 → 单已被认领，改领其他单；无 → 可领
2. **开工前登记**（工单表该行备注追加）：`认领: <agent名> worktree=<主仓库名>-<工单号> branch=<feat/x> @时间`
3. **worktree 命名强绑定工单号**：`<主仓库名>-<工单号>`（如 `<主仓库名>-r77`），废弃自由命名
4. **施工完成** → 提交 + 工单表改「✅C 完成」+ 备注交付信息（hash/测试/变异/报告名）
5. **撞单** → git 实证先完成者胜；后到者确认不重复、改领其他单

完整规则：`设计师\多agent并发领单认领规范_2026-08-17.md`

## 程序员职责

- 按工单施工（一名程序员按工单，不分 A/B/C）
- 交付报告（hash + 证据链 + 变异亲杀 + 全量绿）放 `交付报告\`；工单/派单文本放 `工单文档\`
- **完成后立即登记工单表**（README 红线 7：✅完成 + 备注分支/hash/报告名 + delivery_id 列）
- **交付绑定（2026-09-01 定 · SYS-01 P0-2）**：交付报告头部后加「交付绑定」固定节——`delivery_id: DEL-<工单号>-<YYYYMMDD>-<NNN>` + 三重 hash（code_commit_sha / artifact_sha / evidence_manifest_sha）+ `standard_id` + `evidence_manifest` 不可变清单；工单表 `delivery_id` 列同步登记。**delivery_id 不可原地改**，代码/产物/证据任一变化→新建 delivery。细则见 `SYS\交付绑定规范.md`；验收标准引用冻结版 `STD-<工单号>-v<n>`（见 `处理中心\验收标准冻结区\README.md`）
- **能力护栏（2026-09-01 定 · SYS-01 P1-1）**：改动涉及**共享面**（MainActivity 注册表 / 工具面 / 协议·接口定义 / 全局数据结构任一）→ 交付报告**必附**「能力护栏」固定节：`共享面影响清单`（改哪个面→影响哪些下游→为何无副作用/已做回归）+ `coverage_status` 三档。**FULL** 直接过；**PARTIAL** 必须写明 未覆盖维度+风险+merge_decision+裁决人（设计师）+裁决记录（缺设计裁决 → 验收打回）；**NONE** 原则上禁止合 main。固定节模板：
  ```yaml
  ## 能力护栏（P1-1）
  共享面影响清单:
    - 共享面: MainActivity注册表 | 工具面 | 协议/接口定义 | 全局数据结构
    - 影响下游: <调用方清单>
    - 回归说明: <为何无副作用 / 已做哪些回归>
  coverage_status: FULL | PARTIAL | NONE
  # PARTIAL 必附（缺裁决记录 → 验收打回）
  coverage_decision:
    uncovered: <未覆盖维度>
    risk: low | medium | high
    merge_decision: approved | rejected
    reason: <为何允许/禁止合 main>
    decided_by: 设计师
    decided_at: <ISO 时间>
  ```
  **全量回归 0 新增失败 ≠ 能力没倒退**——未测维度可能已坏，NONE 禁合 / PARTIAL 需显式裁决是硬门槛。红线 24 + 验收判定见 `验收员\文档\真机验收标准与方式方法.md` §1.5
- **发现缺陷可登记挂账**：施工/验收中被动发现缺陷/挂账（P2 以上或需跟进）→ `处理中心\挂账登记表.md` 登记「⏳挂账待审」（挂账号 `挂账-<描述>`，现象→证据→建议）→ **设计师验证**转工单（规则详见 `处理中心\挂账登记与转工单规则.md`，不主动收集挂账）
- **主文件夹不乱建登记表**：工单流转中心根目录只放核心流转文件；登记表/临时表放本报告处，**不堆主文件夹**；确需主文件夹新增表 → 交设计师评估
