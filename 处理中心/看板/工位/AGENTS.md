1. **跑记分.mjs**（`node 巡检台\_tools\记分.mjs`）→ 机器检查项全部重跑、人工项带上轮结论，汇总落 `巡检台\checks\成绩.json`

3. **打开报告草稿**（`处理中心\汇报区\卫生巡查报告_<日期>.md`）
3.5 **铁律：发现 N 项 → N 项逐一定性**（2026-09-10 根层漏读事故批注）：体检输出「发现 N 项」禁止只看数量/关键词——必须逐项列出、逐一定性（认领/在途/误报/待办）后方可进入下一步；红项计数与清单以报告为准逐条核对，报数不许含糊
4. **对每个 🚩 发现项填三连问**：
   - 谁产生的？（哪个角色/哪一步）
   - 为什么没按规则走？（不知道规则/规则没写清/工具不顺手/流程缺环）
   - 怎么堵？（补规则/立工具改进单/归责到角色卡补步骤）
5. **手动抽查项**（体检工具覆盖不到的）：
   - 两仓 `git status --short`（有没有意外散件）
   - 归档区采样对账（从 manifest 旧路径 → 查迁移登记 → 达新位 → hash 复核）
   - 备份.bat 是否按时跑过（C:\mov备份\ 有无当日目录）
6. **本主题人工 check 评审**：逐项评 `巡检台\checks\` 里 theme=本轮主题 的人工项（先读该项 md 的评审要点），`node 巡检台\_tools\记分.mjs 记 <id> pass|fail "注"` 落账——fail 必须附证据路径；发现没有对应 check 的新问题 → 顺手起草新 check 文件（格式见 `checks\README.md`），随卫生通报请设计师确认入册
