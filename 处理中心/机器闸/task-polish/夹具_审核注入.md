# 沙盒夹具 · 审核结果注入（UPG-551 · task-polish）

> 作用：开店链 s5/s8「等审核结果」的**审核态可按需注入**（通过/驳回）⇒ 驳回回流腿确定性重跑。
> 选型（dispatch 明许三选一）：**探针桩（主路＝服务端「窗内对切」`window_switch.py`）**；备用＝本地 partner 桩（零 server 触碰）。
> 红线：**测试账号（acc6c50…）限定**；不动生产用户数据；密钥不落仓/日志；注入与还原成文（本文）。

## 一、主夹具：服务端窗内对切（`审核注入.mjs` 薄封装）

| 层 | 机制 | 文件/落点 |
|---|---|---|
| **probe（造态）** | `GET /partner/applyment/*` 合成响应覆写（应用侧 `biz.onboardStatus` 读到的就是注入态：`REJECTED`⇒rejected／`FINISH`⇒done） | 服务端 `/home/ubuntu/a2a/applyment_probe.json`（消费码 `routers/partner.py::_probe_applyment`） |
| **row（模块行）** | 进件模块行状态直改（提交冲突闸用：行 ACTIVE 时提交 409」⇒ 重提前需复位） | 服务端 `a2a.db`·表 `wxpay_applyments`（工具 `window_switch.py row`） |

```
node 处理中心/机器闸/task-polish/审核注入.mjs show      # 看两态（probe/row）
node 审核注入.mjs reject    # 驳回注入：row→REJECTED＋probe→REJECTED（重跑前置）
node 审核注入.mjs pass      # 通过注入：row→REJECTED（防重提 409）＋probe→FINISH
node 审核注入.mjs row-reset # 只复位行（重提前跑——否则 s7 重提撞 409）
node 审核注入.mjs restore   # 回放快照（首用时自动落 `审核注入.snapshot.json`·恢复注入前环境）
```

- SSH 通道＝`云服务器管理/cert/服务器信息/ssh-ubuntu-key1.pem`（既有键·密钥不出本机）。
- **「通过」态（FINISH）注入通道（UPG-557·K3 官方化·2026-10-06）**：服务端 `window_switch.py` 的 `probe` 子命令 STATES 白名单只收窗内联调态（无 `FINISH`）且为多单共享工具（543/545/548 同源）——**不改服务端**；「通过」注入经 **probe 文件直写**（消费侧零白名单·原子 `os.replace`·即本封装 `pass` 子命令）——**此为官方通道**；`row`/驳回态仍走服务端 CLI（带事件留痕）。
- 生效时延：引擎 tick 15s（前台）⇒ 注入后 ≤15s 被探针读到。

## 三、跑批 runbook（确定性驳回腿）

1. `审核注入.mjs reject`（前置）——probe/row 双 REJECTED。
2. 建任务 → s1/s2 探针即解 → s3 确认（`task.answer confirm`）。
3. s4 提交（行 REJECTED ⇒ 受理；若行 ACTIVE ⇒ 409＝漏了 step 1 或上轮未复位）。
4. s5 读 **REJECTED** → s6 呈因。
5. `审核注入.mjs row-reset` → s6 确认 ⇒ s7 重提受理（**重提前必跑**）。
6. s8 读注入态 → DONE。
- 通过腿：`pass`（probe=FINISH）后 s4/s7 走 recheck 命中跳过、s5/s8 读 FINISH。

- 若用备桩：删设备 `mov-debug-config.json` 的 `partner_base_url` → `adb reverse --remove-all` → 停桩 → 重启 App。
- 自证：还原后 `show` 显示原态；`biz.onboardStatus` 不再落 `stub-log.jsonl`（若用备桩）。
