## 核心结论

1. **双形态**：服务号（触达+入口+身份层）+ 小程序（功能+交易容器）——经**同一开放平台 + unionid** 跨端打通
2. **前置**：企业主体 + 认证（年审制/年费）+ 备案域名 + 审核
3. **最大红线**：iOS 端虚拟商品不能走微信支付（Apple IAP 链路）
4. **互补**：服务号模板消息/客服 48h/菜单扫码 → 跳小程序闭环；群发每月仅 4 条
5. **微信外注意**：MOV 安卓 App 内 WebView 不能用 H5 支付——App 内收款需开放平台「移动应用+APP 支付」

## 关键红线速查

| 红线 | 说明 |
|---|---|
| 企业主体 | 个人主体不可微信支付 |
| 认证前提 | 网页授权/模板消息/JSAPI 支付全要认证（1 年+年费） |
| iOS 虚拟支付 | iOS 端数字商品走 Apple IAP（不是微信支付） |
| AppSecret | 绝不进小程序包/服务号回调密钥后台 |
| 群发 4 条/月 | 仅重大公告；日常走模板/客服消息 |
| 模板消息禁营销 | 40249 红线 |
| 5s 响应 | 被动回复超时断连（AI 对话即时应答+客服异步） |
| APP 内无 H5 支付 | App 收款=开放平台移动应用+APP 支付 |
