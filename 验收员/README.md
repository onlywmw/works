# 验收员（README）

> **验收证据的唯一落点**。验收员（原查验员+真机测验员合并）验收全部交付（代码层+真机层）→ 证据落数据区 → 总览表 → 结论落 ACCEPTANCE_LOG。

## 目录结构（2026-08-17 分类整理）

| 目录/文件 | 内容 |
|---|---|
| `证据数据\` | 真机证据（按日期建子目录，每工单一文件夹 + README 总结） |
| `文档\` | 真机验收标准与方式方法 / 验收员操作手册 / 交接 / 真机测验派单方案 / **桌面虚拟模拟器测验测试**（标准动作/证据规范/踩坑） |
| `总览\` | 真机验收总览 |
| `_tools\` | 验收工具脚本（截图 / OCR / 输入链 等） |

## 证据链入口（倒查用）
- 每工单的证据链索引随验收产物落在 `证据数据\` 对应日期目录；审验员抽查依据见 `审验员\工单证据链映射.md`

## 真机验收标准（红线 15 + 证据规范）
- ✅ = 截图/journal/命令**可重跑 + 可见目标达成**（非口头计划/机制触发/代码层）
- ⚠️ = 端到端未验 / ❌ = 失败误标 / 🔴 = 缺证据
- 无 UI/后端工单用命令/journal/产物/状态机验证（见文档\真机验收标准与方式方法 §四）

## 角色合并说明（2026-08-17）
- 原「查验员 + 真机测验员」合并为单一「验收员」——代码层（变异/全量/契约）+ 真机层（装机/截图/journal）一套验收
- 工单表验收员列是唯一验收列


## 与审验员衔接
- 验收员验收（标 ✅）后 → **审验员 AI 审验证据链**（`审验员\审验.py` 查 journal/截图/命令 对账）
- 审验发现证据链问题 → 登记 `处理中心\问题区` → 设计师处理（打回/补证）
- 验收员标 ✅ 须附可查证实物（审验可复现）
